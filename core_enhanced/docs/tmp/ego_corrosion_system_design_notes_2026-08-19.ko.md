> 엘리트·일반 보스·최종 보스에는 최대 HP 25% 피해를 초기 플레이테스트 값으로 적용한다.
> 차기 Breakdown 유예는 트라우마 100 이후 새 활동 노드 최초 입장의 규정 억제력 소모량으로 계산하며 초기 한계는 4다.

> 실제 코드와의 대조, 구현 설계와 최종 동결은 후속 작업이다.

## 목적과 개념

이 문서의 침식은 **에고 침식**을 뜻하며 유물 사본의 침식 변환과 구분한다.
에고 침식은 **직원의 트라우마 관리와 파편 사용 판단에 연결되는 운영 리스크**다. 환상체의 힘을 흉내 내던
직원이 잡아먹혀, 그 자리에 원본 환상체가 나타나 한 번 크게 터지고 사라지는 연출을 유지한다.
아군 무차별 공격은 채택하지 않는다.

기존의 세트 수집 기반 이스터에그 구상에서 발동 조건을 변경했다. 직원의 철수와 트라우마 100이라는
대가와 연출의 기본 방침은 유지한다. 최종 보스 유래 파편의 발동 대상 제외, 위험 표시, 판정 시점과 연출 배속은
후속 대화에서 아래와 같이 정했다.

개별 파편과 장비 설계는
[환상체 파편·장비 설계 메모](../skills/abnormality_skill_fragments_design_notes.md)가 소유한다.
이 문서는 침식의 공통 정책과 후속 구현 검토 항목을 다룬다.

## 발동 조건 — 대화 결정

다음 조건을 만족한 직원이 파편을 실제로 시전하면 **일반 파편 시전을 확률 없이 침식으로 대체**한다.

- 해당 직원의 **트라우마가 공통 임계치 이상**이다.
- **유효 입력 접수 시 공명이 만충**이다. 접수 시 전량 소비한 사실을 실행에 전달하며 다시 만충을 요구하지 않는다.
- 시전하는 파편이 침식 적용 대상이다. **최종 보스 파편은 제외**한다.
- 일반 파편 시전에 필요한 자격과 차단 조건을 통과한다.

트라우마 임계치는 침식 대상인 모든 직원과 파편에 공통으로 적용한다. 구체적인 숫자는 후속 밸런스
조정에서 정한다.

침식에는 같은 환상체의 파편·무기·방어구·액세서리 세트 **보유 및 장착 조건을 두지 않는다**.
이는 침식용 세트 조건의 제거이며, 일반 전투 참여나 파편 시전에 필요한 기존 장비 자격은 유지한다.
별도의 침식 버튼이나 추가 발동 입력도 두지 않는다.

차단 조건은 일반 스킬과 동일하다. Hard CC, Silence, Defense 태세, action lock, `FieldWorking`에 대한
침식 전용 예외를 만들지 않는다. 침식에 별도 자원을 추가하지 않으며, 전술 포인트를 소비하지 않는
기존 기본안을 유지한다.

## 판정 시점과 일시정지 — 대화 결정

침식 조건은 **시전 입력 접수 시점이 아니라 실제 파편 시전이 시작되는 시점**에 판정한다.
일시정지 중 파편 시전 입력을 받아도 그 입력만으로 침식이나 연출을 즉시 시작하지 않는다.

```text
일시정지 중 파편 시전 입력 접수
-> 일시정지 유지
-> 전투 재개
-> 실제 파편 시전 시 침식 조건 판정
-> 조건을 충족하면 침식으로 대체
```

따라서 '일시정지 중 입력하자마자 침식이 강제로 시작되고, 연출 뒤 이전 Pause로 복귀한다'는 흐름은
채택하지 않는다. 그 전제에서 제기했던 연출 종료 후 Pause 복귀 여부는 미정 항목에서 제거한다.

차기 [공명 규칙](../game_rules/combat.md#공명과-스킬-사용)은 유효 입력 접수 즉시 전량을 소비한다.
따라서 실제 침식 판정에는 접수 당시의 만충 자격을 전달하고 공명을 이중 소비하거나 0이라는 이유로 거절하지 않는다.
입력 접수와 침식 연출 실행의 시점은 구분하며 정지 중 연출을 즉시 시작하지 않는 기존 방침은 유지한다.

여기서 입력 접수와 실제 실행의 구분은 침식의 발동 시점을 설명한다. 일반 command 처리를 전부
Resume 이후로 미루거나 별도 입력 큐를 신설한다는 구현 결정은 아니다. 룰북의 `cast 시작`과 실제
침식 실행을 연결할 정확한 runtime 지점은 아래 구현 검토에서 확인한다.

## 진행과 처치 처리 — 기존안 및 유물 대화 결정 유지

다음은 플레이 결과와 연출의 개념 흐름이며, 내부 event 순서나 transaction 구성을 확정한 것은 아니다.

```text
실제 파편 시전 시 침식 조건 충족
-> 직원 runtime instance 즉시 Withdrawn (기존 철수 lifecycle)
-> 같은 자리에 원본 환상체가 나타나는 연출 + 현재 전장 일반 침식체 즉시 kill 및 엘리트·보스 별도 피해
-> 환상체 퇴장 (처치가 아닌 퇴장)
-> attempt-local 트라우마 100
-> 결과 commit에서 roster 반영 -> Breakdown -> 시한부 시작
```

- **철수:** 기존 lifecycle을 따른다. `FollowCaster` 효과와 aura는 종료하고, 이미 release된 projectile은
  독립적으로 유지한다.
- **즉시 처치:** 에고 침식은 현재 전장의 일반 침식체만 즉시 kill 판정한다. 원본 환상체의 일반 공격력이나
  일반 스킬 피해 계산으로 처치 여부를 결정하지 않는다.
- **엘리트·보스:** 엘리트·일반 보스·최종 보스에는 즉시 처치 대신 별도 피해를 적용한다.
  대상 최대 HP의 **25%**를 초기 검증값으로 쓴다. 방어력·일반 피해 감소를 무시하되 일반 보호막은 먼저 소모한다.
  무적·대상 지정 불가, 페이즈별 HP 하한과 필수 전환을 존중한다. 처치 가능한 상태이면 처치할 수 있지만 필수 페이즈를 건너뛰지 않는다.
  최종 보스 유래 파편의 발동 대상 제외와, 적 최종 보스에게 주는 피해 규칙은 별개다.
- **효과 미발동:** 침식에는 유물의 증폭·추가 효과·연쇄 발동을 적용하지 않는다. 침식 처치로 유물·장비·
  파편의 처치 시 효과나 적의 사망 시 효과를 발동하지 않는다.
- **전투 진행:** 죽은 적은 웨이브 정리, 다음 웨이브 진행과 승리 조건 검사에서 정상적인 처치로 인정한다.
  아직 등장하지 않은 적이나 남은 필수 웨이브까지 없애는 무조건 즉시 승리로 바꾸지 않는다.
- **직원 상태:** attempt-local에 반영한 뒤 결과 commit에서 roster에 한 번 반영하는 기존 규칙을 따른다.

원본 환상체의 등장·퇴장을 실제 `SummonedUnit`으로 표현할지, 침식 전용 연출 event로 표현할지는 구현
검토 대상이다. 등장 연출은 도감·보상·웨이브 authority를 새로 만들거나 승리를 막는 유닛을 추가하는
근거가 아니다. 기존 `authored corrosion skill` 구상을 일반 스킬의 효과 발동 경로로 그대로 해석하지 않는다.

## 대가와 횟수 — 기존안 유지

침식 후 **직원은 즉시 철수하고 트라우마가 100**이 된다. 트라우마 100은 살아 있는 Breakdown이며,
트라우마를 낮추기 전까지 전투에 다시 투입할 수 없다.

차기 Breakdown의 시한부 처리는 [직원 상태 규칙](../game_rules/results-and-save.md#breakdown의-유예)을 따른다.

- 트라우마 100 이후 새 활동 노드 최초 입장의 규정 억제력 소모가 누적 4에 도달하기 전까지
  트라우마를 99 이하로 낮추지 못하면 영구사망하는 초기 검증 기준을 사용한다.
- 실제 억제력이 0이어도 규정 소모량으로 유예를 진행한다. 같은 노드 재입장·전투 후퇴는 추가 차감이 없으며
  후퇴로 최초 입장 비용과 유예 진행을 반환하지 않는다. 트라우마 100 이전의 소모는 소급 반영하지 않는다.
- 트라우마를 99 이하로 낮추면 기존 카운터를 폐기한다. 이후 다시 100에 도달하면 새로 센다.
- 침식 전용 사망 규칙이나 회복 예외를 추가하지 않는다.
- 체크포인트는 당시 직원 상태·유예 누적량·억제력·최초 입장 기록을 함께 복원한다.

별도의 침식 횟수 상한은 두지 않는다. 한 직원의 같은 전투 재사용은 트라우마 100에 따른 재배치 자격
상실로 제한된다. 이는 전투 전체에서 모든 직원을 합쳐 한 번만 허용한다는 뜻이 아니다.
런에서 다시 사용하려면 기존 회복 수단으로 해당 직원을 재투입할 수 있게 해야 한다.

SavePoint 등 기존 트라우마 회복 규칙을 유지한다. 회복 후에도 공통 임계치 이상이라면 다음 전투의
파편 사용에서 침식 위험이 다시 생긴다. 반복 사용의 실제 부담은 임계치와 회복 자원을 함께 조정한다.

## 위험 표시 — 대화 결정

플레이어가 **다음 파편 시전에 침식이 발생할 상태인지 UI 변화로 알아볼 수 있게** 한다.
텍스트 경고는 필수가 아니다. 아이콘·색상·시전 UI 형태 등 구체적인 표현은 후속 UI 설계에서 정한다.

최종 보스 파편 제외와 실제 발동 조건을 반영한 표시여야 한다. 일시정지 중 위험 표시를 보여주는 것과
침식 자체를 실행하는 것은 구분한다.

## 연출 정지와 재생 속도

침식 연출 동안 battle tick을 정지시키는 기존 방침을 유지한다. 절망의 기사처럼 전장 적 머리 위에
무기를 소환하고 내려찍는 모습은 개별 연출의 참고 구상이며, 처치·효과 미발동 정책을 바꾸지 않는다.

기존 연출 정지 규칙은 다음과 같다.

- 서버가 침식 실행에 따라 연출 정지를 시작한다.
- 플레이어는 Resume으로 연출 정지를 해제하거나 연출을 건너뛸 수 없다.
- 연출 중 gameplay mutation을 거부한다. 실패한 command는 state, resource, event와 revision을 바꾸지 않는다.
- read-only 상태 요청과 preview query는 허용하며 revision을 증가시키지 않는다.
- authored 지속 시간이 만료되면 서버가 자동 해제한다. 클라이언트의 연출 완료 보고를 기다리지 않는다.

**침식 연출은 전투 배속과 무관하게 항상 기본 속도로 재생**한다. 전투가 2배속이어도 침식 연출을
2배속으로 재생하지 않는다. 연출 정지 중에는 battle time이 흐르지 않는다.

기존 Pause·clock 정지·resync 경로를 재사용하는 방향은 유지하되, 정확한 상태 모델과 연결 해제에 따른
자동 Pause와의 결합은 코드 검토에서 정한다. 이 문서의 연출 정지 규칙만으로 해당 경로가 구현되거나
검증됐다고 판단하지 않는다.

## 이전 구상에서 변경·폐기한 내용

| 이전 구상 | 현재 결정 |
| --- | --- |
| 같은 환상체의 파편·장비 4종 수집으로 열리는 이스터에그 | 세트 조건 없이 트라우마 관리와 파편 사용에 연결되는 운영 리스크 |
| 별도 명시적 침식 입력, 일반 시전 자동 대체 금지 | 실제 파편 시전 시 조건을 만족하면 확정적으로 침식 대체 |
| 자동 발동형을 검토 후 배제 | 파편 시전 조건에 따른 대체 발동을 채택 |
| 원본 환상체의 일반 스킬과 위력 등급 사다리 | 일반 침식체 즉시 kill·엘리트/보스 별도 피해, 부가 효과 미발동, 원본 등장은 연출 |
| 최종 보스 파편 적용 여부 미정 | 최종 보스 파편 제외 |
| 일시정지 중 침식 즉시 실행을 전제로 복귀 상태 논의 | 전투 재개 뒤 실제 시전 시 판정하므로 해당 전제 폐기 |
| 연출의 배속 연동 여부 미정 | 전투 배속과 무관하게 기본 속도 |

아군 무차별 공격과 환상체 세트의 스탯 시너지를 채택하지 않은 기존 방침은 유지한다.
이전 문서의 '장비 출처·세트 판정·별도 침식 command가 침식의 필수 선행 작업'이라는 목록은 새 발동
조건의 구현 요구사항으로 사용하지 않는다.

## 남은 수치와 콘텐츠

- **엘리트·일반 보스·최종 보스 피해:** 초기 최대 HP 25%의 체감과 반올림·처리 순서를 검증한다. 방어력/일반 감소 무시·보호막 우선·무적/페이즈 제한 유지 정책은 위와 같이 확정한다.
- **공통 트라우마 임계치의 숫자:** 후속 밸런스 조정에서 결정한다.
- **Breakdown 유예:** 규정 억제력 누적 소모 4를 초기 기준으로 검증한다. 기존 활동 노드 완료 횟수 기반
  `breakdown_collapse_node_limit`의 데이터·저장·실행 이행은 후속 구현 작업이다.
- **개별 환상체 연출과 authored 지속 시간, UI의 구체적인 외형:** 후속 콘텐츠·UI 설계에서 작성한다.

## 후속 코드·설계 검토

다음은 구현 검토 항목이며 새 사용자 정책이나 구현 지시가 아니다.

| 항목 | 확인할 내용 |
| --- | --- |
| 입력 접수와 실제 시전 | 룰북의 Pause 중 `cast 시작` 즉시 반영과 `pending cast resolve` 정지를 구분하고, 전투 재개 뒤 침식을 실행할 정확한 runtime 지점을 확인한다. |
| 조건과 자원 처리 순서 | 입력 접수 시 만충 자격과 전량 소비를 실행에 전달하고, 침식 대체에서 재검사·중복 소비하지 않도록 연결한다. |
| 적용 대상과 UI | 최종 보스 파편 제외, 공통 임계치와 침식 가능 표시를 기존 파편 데이터·상태 투영에 연결한다. |
| 철수·처치·결과 반영 | 기존 철수 lifecycle, 처치 부가 효과 차단, 웨이브 진행과 직원의 트라우마 반영을 함께 검토한다. |
| 연출의 표현과 시간 소유 | 실제 소환 필요 여부, 연출 데이터 위치, 지속 시간의 저장 위치와 서버 시간 기준을 정한다. |
| 정지·재접속 | 연출 정지와 플레이어 Pause 및 연결 해제에 따른 Pause의 상태·resync 경계를 검토한다. |
| event와 transaction | 등장·처치·퇴장 연출을 하나로 전달할지 순차 전달할지, 처치로 전투가 끝나도 직원의 대가가 결과에 반영되는 순서를 검토한다. |
| Breakdown | 새 활동 노드 최초 입장의 규정 소모량 누적, 무억제 중 유예 진행, 사망 및 저장 복구가 차기 룰북 계약을 충족하는지 확인한다. |

이번 기록은 임시 정책 문서 갱신이다. current canonical 승격, 코드 수정이나 최종 구현 동결은 수행하지 않았다.
