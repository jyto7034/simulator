# 테스트 분류 유지와 실행 묶음 적용

이 문서는 새 테스트 추가와 기존 테스트 변경 때 사용하는 작업 규칙이다. 분류 정보는 이 디렉터리에서 관리한다. CI, 기존 실행 담당자의 runner, 제품·게임 테스트 코드의 실행 설정은 변경하지 않는다.

## 단일 원본과 표

| 자료 | 역할 | 편집 방법 |
| --- | --- | --- |
| [policy.json](policy.json) | 분류 기준, 파일/시험별 예외, 실제 공유 자원과 근거 | 조건이 바뀔 때 수정 |
| [inventory.csv](inventory.csv) | 검토된 개별 테스트 선언 등록표 | 검사 도구로 생성. 직접 편집하지 않음 |
| [CLASSIFICATION.ko.md](CLASSIFICATION.ko.md) | 사람이 읽는 기준표·자원표·소스/조건별 등록표 | 위 두 자료에서 생성 |
| [source_snapshot.json](source_snapshot.json) | 검토 당시 소스·설정 식별 | 검토한 변경을 등록할 때만 갱신 |
| [check_inventory.py](check_inventory.py) | 새 선언·삭제·소스 변경·표 불일치 검사 | 빌드나 게임 테스트를 실행하지 않음 |

`lane`은 표시용 대표 분류다. 실행 제약은 **모든 일치 규칙의 합집합**이다. 예를 들어 한 시험에 새 프로세스와 조용한 호스트 조건이 동시에 붙으면 둘 다 지킨다. 높은 우선순위의 대표 분류 때문에 다른 조건을 버리지 않는다. `parallel_candidate`는 병렬 검증 후보이며, 실행 검증을 통과했다는 뜻이 아니다.

## 새 테스트·변경 테스트의 필수 절차

1. 테스트 작성자는 정상 입력·기대 동작과 함께 실행 환경, 공유 상태, 파일·포트·DB, 자식 프로세스, 시간·메모리 측정 여부를 확인한다. 호출하는 helper의 부수 효과도 포함한다.
2. 기존 모듈 규칙이 충분하면 그대로 상속한다. 다른 자원이나 격리 조건이 생기면 `policy.json`에 좁은 예외와 근거를 추가한다. 같은 파일 전체를 보수적으로 묶을 수도 있지만, 그 이유를 남긴다. 새 경로가 기본 분류로 잡혀도 안전성 검토를 생략하지 않는다.
3. 아래 읽기 전용 검사를 실행한다. 출력의 `added_declarations` / `removed_declarations`는 추가·삭제된 이름을, `changed_sources`는 helper·제품 코드·Cargo 설정을 포함한 검토 대상을 알려준다. 줄 이동만으로 새 시험으로 세지 않는다.
4. 편집자가 입력을 안정화한 시점에 변경의 분류 영향을 검토한다. 확인한 경로만 명시해 등록표를 갱신한다. 해당 파일에서 실제로 공유 자원·타이머·전역 상태가 추가되었는지 사람이 판단해야 한다. 자동 스캐너가 호출 그래프의 안전성을 증명하지는 않는다.
5. 다시 검사해 현재 입력과 표의 일치를 확인한다. 기능 시험 통과, 병렬 동등성 검증, 전체 회귀 완료는 각각 별도 결과로 유지한다.

저장소 루트에서:

```sh
python3 -B core_enhanced/docs/testing/parallel_preflight/check_inventory.py
```

분류 영향을 검토한 변경 등록 예시(경로는 실제 `changed_sources`로 바꾼다):

```sh
python3 -B core_enhanced/docs/testing/parallel_preflight/check_inventory.py --write \
  --reviewed-source core_enhanced/tests/example.rs
```

변경 경로마다 `--reviewed-source`를 한 번씩 사용한다. 삭제된 파일도 해당 경로를 명시한다. 정책이 달라졌다면 정책 근거도 검토한 뒤 `--reviewed-policy`를 함께 사용한다. 이 옵션들은 검토 사실의 선언이며 자동 승인이 아니다. 경로 누락·불필요한 경로·미확인 정책 변경은 갱신을 거부한다. 갱신 도중 입력이 달라져도 거부한다. 원인 확인 없이 실패를 없애려고 `--write`를 사용하지 않는다.

소스 변경을 인수하지 않고 **기존 검토 상태**의 문서만 다시 생성하려면:

```sh
python3 -B core_enhanced/docs/testing/parallel_preflight/check_inventory.py --render-table
```

작업 중인 소스가 기존 스냅샷과 다르면 검사 실패가 정상이다. 해당 작업을 되돌리거나 진행 중인 실행을 중단할 이유가 아니다. 다음 안전한 검토 경계에서 반영한다. `--render-table`로 만들어진 표를 현재 소스 승인으로 해석하지 않는다.

## 실행 묶음별 등록 정보

정적 선언표는 Rust의 `cfg`, 매크로 확장, 플랫폼과 실제 target을 확정하지 못한다. 실행 담당자는 기존 실행 manifest/설정에 다음 정보를 함께 둔다. 새 증거 문서를 시험마다 만들지 않는다.

| 필드 | 기록할 내용 |
| --- | --- |
| 구성 식별 | package, target, feature, profile, 플랫폼, 결과에 영향을 주는 환경 |
| 실제 시험 목록 | 해당 구성의 하네스 완전한 이름, ignore 여부, 선언/규칙 연결 |
| 선행 작업 | 재사용할 빌드·팩·fixture의 식별과 완료 조건 |
| 자원 | 적용 범위를 포함한 모든 공유/독점 자원 키 |
| 격리 | 새 프로세스 여부, 임시 경로·포트·DB의 분리 방법 |
| 측정 조건 | 기능 판정인지 성능 판정인지, 필요한 호스트 독점 범위 |
| 동시 실행 한도 | 빌드 job, 실행 프로세스, 프로세스 내부 thread 수를 각각 기록 |
| 결과 연결 | 명령, 입력 식별, 원시 결과, 실행/통과/실패/ignore 수, 소요 시간 |

구성마다 하네스가 실제 나열한 목록을 이 선언표와 대조한다. **미분류, 애매한 매핑, 중복 실행, 설명되지 않은 누락을 해결하기 전에는 병렬 실행 대상으로 승격하지 않는다.** 같은 선언이 여러 구성에 나타나는 것은 합법이므로 구성 식별을 포함한다. feature 때문에 비활성인 선언과 실제 실행에서 누락된 시험을 구분한다. `ignore`를 조용히 해제하거나 필수 ignored 시험을 누락하지 않는다.

doctest, 매크로로만 생성된 시험, 도구 폴더의 probe 크레이트와 외부 CLI/서버 시나리오는 현재 정적 스캐너의 범위 밖이다. 새로 추가되면 기존 실행 manifest에 위 필드를 등록하고 검증 범위에 포함한다. 정적 검사 `ok`만으로 이들까지 모두 분류됐다고 주장하지 않는다. 실제 하네스 자동 대조와 스케줄링은 현재 도구에 구현되어 있지 않다.

## 테스트 하나씩 실행하는 방식의 개선 순서

1. 기존 로그에서 준비·빌드·시험·결과 수집 시간을 구분한다. 같은 환경의 준비된 관련 시험을 한 호출에 묶는 것부터 적용한다. 개별 시험마다 Cargo, 전체 입력 보관, 인계 단계를 반복하지 않는다.
2. 실행 담당자는 한 명으로 유지하되 독립적인 시험을 제한된 동시 실행량으로 처리할 수 있다. 입력은 실행 중 고정한다. 빌드 출력 경로를 공유하는 빌드를 무리하게 병행하지 않는다.
3. `parallel_candidate`는 같은 바이너리 안에서 묶어 실행할 후보로 삼는다. 유효한 동일 입력의 직렬 기준 결과를 재사용하고, 부족한 범위만 추가 확보한다. 결과 비교는 출력 순서가 아니라 완전한 시험 이름별 판정으로 한다.
4. 동일 자원을 쓰는 시험끼리만 순차 실행한다. `process:` 자원은 프로세스가 다르면 분리될 수 있지만 `checkout:` 자원은 프로세스나 `CARGO_TARGET_DIR`만 바꿔도 계속 공유된다. 새 프로세스가 필요해도 호스트 독점 조건이 없다면 다른 격리 작업과 병행할 후보가 된다.
5. 타이밍·메모리·성능 측정은 요구되는 독점 범위를 확보한다. 같은 호스트를 사용하는 다른 작업과의 조정도 필요하다. 이 문서나 자원 키는 운영체제 잠금을 자동으로 제공하지 않는다.
6. 실패 항목만 좁혀 재현하고 원인에 따라 교정한다. 최종 전체 회귀·필수 구성별 검사·외부 실행·성능·독립 감사의 범위는 줄이지 않는다. 시간 절약은 실제 측정 후 보고한다.

## 분류 도구 자체 검사

```sh
python3 -B -m unittest discover \
  -s core_enhanced/docs/testing/parallel_preflight -p 'test_inventory.py' -v
```

임시 파일과 작은 합성 입력으로 분류 제약 결합, 변경 검토 차단, 선언 추가 감지를 확인한다. 게임 테스트나 현재 검증 세션을 실행하지 않는다.
