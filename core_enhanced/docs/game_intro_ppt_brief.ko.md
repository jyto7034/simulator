# 플레이어용 게임 소개 PPT 제작 지침서

작성일: 2026-09-26

사용처: 사용자가 선택한 GPT 웹사이트 대화에서 실행할 제작 요청.
이 문서를 첨부하거나, 아래 시작 요청으로 simulator 안의 이 문서를 읽게 한다.
이 문서는 PPT 제작 지침이며 게임 규칙의 새로운 원본이 아니다.

## 1. 복사해서 사용할 시작 요청

```text
“Codex with ChatGPT · simulator” 플러그인을 사용해줘.

simulator에 읽기 전용으로 접근해서 아래 파일을 읽고, 그 지침에 따라
플레이어 대상 게임 소개 PPT를 완성해줘.

core_enhanced/docs/game_intro_ppt_brief.ko.md

참고할 게임 설계와 콘셉트 UI의 경로는 지침서 안에 있어.
저장소는 수정하지 말고, 결과물은 이 대화에서 다운로드할 수 있도록 만들어줘.
한국어, 16:9, 8장으로 구성하고, 배치형 디펜스의 전술과 로그라이크 빌드,
강력한 스킬로 다수의 적을 쓸어버리는 쾌감이 함께 드러나게 해줘.
타겟팅 판정, 런타임, 데이터 계약 등 내부 개발 설명은 제외해줘.

콘셉트 UI는 파일명이나 설명만 읽지 말고, 가능한 이미지 열람 기능이나
내가 첨부한 이미지로 실제 그림을 확인해줘.
플러그인이 PNG를 열 수 없다면 지침서의 필수 이미지 6장을 한 번에 요청해줘.
텍스트 자료만 읽고 이미지를 확인했다고 말하지 마.

자료가 준비되면 구성안 제시에서 멈추지 말고 실제 PPTX 제작까지 진행해줘.
파일 생성 기능이 없다면 그 한계를 밝히고, 가능한 슬라이드 이미지와
완성 원고를 제공하되 PPTX를 만들었다고 말하지 마.
```

## 2. 목적과 독자

처음 접하는 플레이어가 아래 질문에 답할 수 있는 소개 자료를 만든다.

1. 어떤 방식으로 플레이하는 게임인가?
2. 전투 중 내가 판단하고 조작하는 것은 무엇인가?
3. 탐사와 획득한 보상이 다음 전투를 어떻게 바꾸는가?
4. 어떤 분위기와 쾌감을 기대할 수 있는가?

투자 설명, 개발 진행 보고, 상세 튜토리얼은 이번 자료의 목적에 포함하지 않는다.
최종 슬라이드에는 개발 용어, 소스 경로, 내부 문서의 상태 표를 넣지 않는다.
제작 근거는 별도 원고나 발표자 노트에 기록한다.

이번 PPT는 차기 목표 설계를 소개한다. 콘셉트 화면과 연출을 현재 구현된 실제
플레이 화면으로 표현하지 않는다. 표지에 작게 `게임 콘셉트 소개`를 표기하고,
화면 예시에는 `콘셉트 화면`, 새 연출에는 `콘셉트 연출`을 일관되게 표시한다.

## 3. 자료 접근과 읽기 순서

모든 경로는 simulator 루트 기준이다. Unity 프로젝트의 외부 경로를 사용할 필요가 없다.
현재 콘셉트 UI는 `core_enhanced/docs/ui-layout/`에 들어 있다.

| 순서 | 자료 | 읽을 목적 |
| --- | --- | --- |
| 1 | [차기 게임 설계서](game_rulebook.md) | 게임의 정체성, 탐사·전투·성장·직원 관리의 연결 |
| 2 | [환상체 스킬 파편 설계](skills/abnormality_skill_fragments_design_notes.md) | `설계 원칙`과 `눈의 여왕` 절: 핵앤슬래시 지향과 대표 빌드 |
| 3 | [장면별 UI 설계](ui-layout/ui-layout.md)와 아래 PNG 6장 | 실제 구도, 인물 비율, 공간, 색, 재질 |
| 4 | [환상체 조우 설계](skills/abnormality_design_notes.ko.md) | `눈의 여왕` 절: 위협과 플레이어의 대응 |
| 5 | [유물 콘텐츠 설계](skills/run_relic_content_design_notes.ko.md) | `눈의 여왕 전용 유물 — 이름 미정` 절: 조합의 결과 |
| 필요할 때 | [전투 규칙](game_rules/combat.md), [장비와 파편](game_rules/equipment-and-fragments.md), [성장과 보상](game_rules/growth-and-rewards.md), [결과와 직원 상태](game_rules/results-and-save.md) | 소개 문구의 사실 확인 |

긴 문서는 검색으로 해당 제목을 찾고 필요한 구간을 읽는다. 플러그인이 일부 줄만
반환하면 필요한 다음 구간까지 이어서 읽는다. 구현 코드·감사 보고서·과거 실행 기록까지
전수 조사할 필요는 없다.

### 자료가 충돌할 때

- 공통 게임 방식은 차기 설계서와 연결된 규칙 페이지를 따른다.
- 개별 환상체·파편·유물의 효과는 해당 콘텐츠 문서의 합의와 보류 표기를 따른다.
- UI 이미지와 과거 생성 프롬프트는 시각 참고다. 예시 수치·아이템 효과·재화 설명을
  최신 규칙으로 복사하지 않는다.
- 차기 문서에서 현행 비교 기준으로만 남긴 내용을 확정된 차기 특징으로 홍보하지 않는다.
- 미정 인원 상한, 세부 수치, 획득 확률, 출시 일정·플랫폼·가격은 쓰지 않는다.
- `archive/` 이미지와 예전 문구를 현재 참고 이미지보다 우선하지 않는다.

### 이미지 접근이 제한될 때

이 지침 작성 시 노출된 simulator 플러그인 도구는 목록·검색·텍스트 읽기를 제공하며,
별도 이미지 열람 도구는 확인되지 않았다. 연결 확인 호출도 내부 오류로 실패했으므로
웹 대화에서의 연결 성공과 PNG 열람 가능 여부는 실제 호출 결과로 확인해야 한다.

1. 연결된 작업 공간이 simulator인지 확인하고 필요한 문서를 읽는다.
2. 이미지 열람 기능이 있으면 아래 PNG를 실제로 연다.
3. 텍스트 읽기만 가능하면 필수 PNG 6장의 직접 첨부를 한 번에 요청한다.
4. 플러그인 자체가 연결되지 않으면 이 지침서와 차기 설계서, 사례의 해당 문서 구간도
   첨부로 요청한다. 내부 오류의 원인이나 접근 성공을 추측하지 않는다.
5. 이미지 도착 전에는 원고를 정리할 수 있다. 외형을 맞추는 최종 이미지 제작은
   실제 참고 이미지를 확인한 뒤 진행한다.

## 4. 게임을 설명하는 기준 문장

### 한 문장 소개

> 직원을 배치하고 지휘하며, 환상체의 힘과 장비를 조합해 봉쇄된 시설을 탐사하는
> 로그라이크 전술 디펜스 게임.

### 반드시 함께 전달할 세 가지 재미

- **전술:** 타일에 직원을 배치하고 방향·스킬·태세·이동·교대·철수와 재배치를 지휘한다.
  직원의 자동 공격과 저지를 바탕으로 적의 진입을 막고 보호 대상을 지킨다.
- **빌드와 화력:** 무기·환상체 스킬 파편·개화·유물로 역할과 전투 방식을 만든다.
  강력한 범위 공격과 효과의 조합으로 다수의 적을 쓸어버리는 쾌감을 추구한다.
- **탐사와 동료 관리:** 다음 방의 기회와 위험을 고르고, 부상·트라우마·자원을 고려해
  다음 전투에 내보낼 편성을 준비한다.

배치형 디펜스의 전장 구도와 조작을 유지하면서 핵앤슬래시의 화력·타격감을 표현한다.
핵앤슬래시 지향을 캐릭터 한 명의 자유 이동·구르기·연속 수동 평타 조작으로 바꾸지 않는다.
턴제, 카드 전투, 전투 시작 후 개입 없는 자동 전투, 거점 건설을 주된 방식으로 묘사하지 않는다.

참고 장르를 설명할 필요가 있으면 제작 과정에서 아크나이츠식 배치 전투를 떠올릴 수 있다.
플레이어용 슬라이드에서는 우리 게임의 행동과 장면을 직접 설명한다.

### 분위기

`낯선 시설의 불안 → 전선을 유지하는 긴장 → 강력한 스킬의 해방감 → 등불 아래의 안도`

이 감정 흐름은 소개용 연출 방향이다. 시설 진입 이유, 주인공의 신분, 탈출 결말처럼
문서에 없는 세계관 설정을 추가하는 근거로 사용하지 않는다.

## 6. 공통 미술·편집 지침

- 화면 비율 16:9. 슬라이드 이미지는 1920×1080 이상을 목표로 한다.
- 청회색과 숯빛의 시설, 호박색 랜턴, 얇은 금색 테두리, 청록색 선택 강조를 기본으로 삼는다.
- 콘크리트 균열, 낡은 철판과 배관, 젖은 바닥, 종이와 색실의 손에 잡힐 듯한 질감을 유지한다.
- 직원은 참고 이미지의 SD 비율을 유지한다. 전투와 휴식에서 같은 얼굴·머리·복장을 이어간다.
- 반복 등장 직원 2~3명을 참고 이미지에서 정해 일관되게 사용한다. 새 성격·관계·과거사를 쓰지 않는다.
- 전투는 사선으로 내려다보는 타일 전장으로 그린다. 저지하는 직원, 지원하는 직원,
  진입하는 적과 보호 대상의 관계가 이펙트 아래에서도 읽혀야 한다.
- 스킬 효과는 궤적·적중·범위의 차이가 느껴지게 만든다. 과도한 광원으로 전장을 덮지 않는다.
- 휴식은 따뜻하게, 환상체 조우는 압박감 있게, 빌드 장면은 시원하고 강력하게 표현한다.
- 한 장에 핵심 메시지 하나. 제목은 한 줄, 본문은 최대 두 문장, 보조 주석은 최대 세 개.
- 제목 32~44pt, 본문 20~26pt를 출발점으로 삼고 실제 슬라이드 크기에서 확인한다.
  작은 숫자와 툴팁을 읽어야 내용을 이해하는 구성을 피한다.
- 한글 제목과 본문은 가능하면 PPT의 편집 가능한 텍스트로 올린다. 일러스트에는 글자 자리를
  확보하고, 생성 이미지에 긴 한글 문장을 직접 그려 넣는 방식에 의존하지 않는다.
- 각 장의 구도를 내용에 맞게 바꾸되 여백·제목 위치·색·페이지 표시는 통일한다.
- 자료에 없는 게임 로고를 창작하지 않는다. 공식 게임명이 확인되지 않으면
  표지는 `게임 콘셉트 소개`와 장르 설명을 사용한다. `ARK` 같은 폴더명을 게임명으로 추정하지 않는다.

## 7. 슬라이드별 완성 원고와 장면 지시

아래 제목과 본문을 기본 원고로 사용한다. 의미를 유지한 범위에서 줄바꿈과 길이는 다듬어도 된다.

### 1장 — 배치하고, 지휘하고, 돌파하라

- **이해할 것:** 실시간 배치형 디펜스와 로그라이크 성장을 결합한 게임이다.
- **제목:** `배치하고, 지휘하고, 돌파하라`
- **본문:** `직원을 이끌고 봉쇄된 시설을 탐사하는 로그라이크 전술 디펜스.`
- **구도:** V1의 전장 구도를 바탕으로 적을 막는 전열과 스킬을 쓰는 후열을 크게 보여준다.
  제목이 놓일 여백을 확보하고 보호 대상과 적의 진입 방향을 식별 가능하게 남긴다.
- **연출:** 원경의 시설 규모, 근경의 직원, 다수의 적을 타격하는 스킬을 함께 표현한다.
  스킬은 아래 냉기 사례를 이용할 수 있다. 전장을 가리는 거대한 인물 초상은 피한다.
- **표기:** `게임 콘셉트 소개`와 `실시간 배치 전투 · 로그라이크 탐사 · 장비와 파편 조합`.

### 2장 — 다음 전투는, 지금의 선택으로 달라진다

- **이해할 것:** 탐사·전투·성장·정비가 한 흐름으로 이어진다.
- **제목:** `다음 전투는, 지금의 선택으로 달라진다`
- **본문:** `경로를 고르고, 전투를 치르고, 얻은 힘으로 편성을 바꿔 다시 도전한다.`
- **구도:** V3 → V1 → V5 → V4의 네 장면을 `탐사 → 전투 → 성장 → 정비`로 연결한다.
  화살표는 게임 흐름을 설명하는 편집 요소로 사용한다.
- **주의:** 매 방이 반드시 이 순서로 배치된다는 뜻으로 그리지 않는다. 지도 UI가
  슬레이 더 스파이어식 고정 분기 트리라고 임의로 바뀌지 않게 한다.

### 3장 — 전선을 만드는 것은 당신의 지휘

- **이해할 것:** 배치 이후에도 플레이어가 판단하고 개입한다.
- **제목:** `전선을 만드는 것은 당신의 지휘`
- **본문:** `적을 막을 위치를 정하고, 스킬과 이동·교대로 전투의 흐름을 바꾸세요.`
- **구도:** V1·V2를 바탕으로 전장 전체를 크게 배치한다. 같은 전투의 한 부분을 작은
  확대창으로 보여주고 `배치와 저지`, `스킬 사용`, `이동과 교대` 주석을 연결한다.
- **연출:** 전열이 적을 붙잡는 동안 후열이 공격한다. 지휘 강조용 화살표는 UI 버튼과
  구분되는 설명용 표식으로 쓴다. 모든 명령을 동시에 실행하는 장면으로 만들지 않는다.
- **제외:** 사거리 계산, 대상 선정 우선순위, 비용 공식, 초 단위 처리 규칙.

### 4장 — 더 얻을 것인가, 다음 관문으로 갈 것인가

- **이해할 것:** 필요한 성장과 직원 상태를 보고 탐사 위험을 선택한다.
- **제목:** `더 얻을 것인가, 다음 관문으로 갈 것인가`
- **본문:** `추가 전투의 보상과 동료의 상태를 살피며, 다음에 들어갈 방을 고르세요.`
- **구도:** V3를 주 이미지로 사용한다. 사진 카드와 색실을 살리고, 일반 전투와 정비처럼
  서로 다른 방의 성격을 짧게 보여준다. 직원 상태는 작은 별도 정보 영역으로 연결한다.
- **주의:** 모든 보스전을 건너뛸 수 있다고 표현하지 않는다. 방 개수, 방문 횟수 제한,
  특정 경로의 보상 수량과 확률은 쓰지 않는다.

### 5장 — 위협을 읽고, 대응을 바꿔라

- **이해할 것:** 환상체는 개성 있는 공격으로 배치와 대응을 바꾸게 한다.
- **제목:** `위협을 읽고, 대응을 바꿔라`
- **본문:** `눈의 여왕의 공격 예고를 읽고, 전선을 유지할 위치를 다시 정하세요.`
- **구도:** 시설의 타일 전장에 눈의 여왕과 직원들을 배치한다. 예고된 냉기 공격의 영역과
  위험에 놓인 직원을 보여주고, 적을 막는 다른 직원도 남겨 판단의 이유를 드러낸다.
- **근거:** 조우 문서의 전방 예고 공격과 배치 조정. 환상체의 외형 기준 이미지가 없으면
  문서의 얼음 왕관·눈꽃 모티프로 콘셉트 외형을 만들고 새 제안임을 제작 노트에 적는다.
- **주의:** 별도 구출 퍼즐, 소환 단계, 페이즈 변신을 추가하지 않는다. 눈의 여왕을
  최종 보스로 소개하지 않는다. 상세 공략이나 정확한 공격 범위를 확정하지 않는다.

### 6장 — 낯선 힘을, 나만의 전술로

- **이해할 것:** 파편과 장비·유물의 조합이 실제 전투의 화력과 방식을 바꾼다.
- **제목:** `낯선 힘을, 나만의 전술로`
- **본문:** `무기·파편·유물을 조합해 다수의 적을 쓸어버리는 힘을 만드세요.`
- **보조 문구:** `개화로 새로운 스킬 형태를 열고, 상황에 맞게 선택하세요.`
- **구도:** V5의 인물 표현과 V6의 정비 질감을 참고한다. 왼쪽은 같은 직원의 무기·파편·유물,
  오른쪽은 전장에 펼쳐지는 냉기 공격과 빙결 잔영의 폭발을 크게 보여준다.
- **사례:** 아래 8절의 눈의 여왕 조합을 사용한다. 스킬 아이콘만 나열하지 말고,
  여러 적을 타격하는 결과 장면을 슬라이드의 절반 이상으로 잡는다.
- **주의:** 이 냉기 조합을 눈의 여왕 파편의 개화 전후 차이라고 설명하지 않는다.
  구체적인 개화 효과는 이 사례에서 확정하지 않았다. 무한 연쇄 폭발도 그리지 않는다.

### 7장 — 다음 전투에 나설 동료를 위해

- **이해할 것:** 동료의 부상과 트라우마가 다음 편성의 판단으로 이어진다.
- **제목:** `다음 전투에 나설 동료를 위해`
- **본문:** `부상과 트라우마를 살피고, 장비와 편성을 정비하며 다음 도전을 준비하세요.`
- **구도:** V4의 랜턴과 직원들을 크게 보여준다. 쉬거나 장비를 손질하는 동작,
  피로한 표정과 서로 가까이 머무는 배치로 잠시 숨 돌리는 감정을 표현한다.
- **주의:** 휴식 장면만으로 모든 부상과 트라우마가 자동 회복된다고 약속하지 않는다.
  참고 이미지의 인원수를 게임의 확정 최대 인원으로 쓰지 않는다.

### 8장 — 다음 문 너머, 당신의 선택이 기다린다

- **이해할 것:** 전술·성장·탐사의 다음 도전을 기대하게 한다.
- **제목:** `다음 문 너머, 당신의 선택이 기다린다`
- **본문:** `동료를 이끌고, 낯선 힘을 다루며, 다음 위협에 도전하세요.`
- **구도:** 앞 장들에 등장한 직원들이 랜턴을 들고 다음 구역을 바라본다.
  시설의 차가운 원경과 직원 주변의 따뜻한 빛을 대비시킨다.
- **마무리:** `배치의 전술 · 조합의 쾌감 · 탐사의 긴장`을 짧게 배치한다.
- **주의:** 이 문을 탈출구나 최종 결말로 확정하지 않는다. 출시일·구매 버튼·스토어 로고는
  제공된 정보가 없으므로 넣지 않는다.

## 8. 6장에 사용할 구체적인 빌드 사례

아래는 설계 문서에 있는 합의된 방향을 소개용으로 요약한 것이다.
구현 완료를 뜻하지 않으며 이름이 가칭인 항목은 발표자 노트에 표시한다.

| 구성 | 소개할 효과 | 그림에서 보일 것 |
| --- | --- | --- |
| 서리 마검 — 가칭 | 떨어진 적에게 얼음 참격을 가하고 냉기로 둔화시킨다 | 높은 배치 지점의 검을 든 직원, 적 타일의 얼음 참격 |
| 빙설의 파도 — 가칭 | 전방에 광역 냉기 공격을 가한다. 직접 처치한 적은 빙결 잔영을 남긴다 | 여러 적을 타격하는 파도, 처치 지점의 얼음 형상 |
| 눈의 여왕 전용 유물 — 이름 미정 | 착용자의 파편 또는 무기로 냉기 둔화가 걸린 적이 죽으면 잔영을 만든다 | 냉기에 걸린 적을 동료가 마무리해도 생기는 잔영 |
| 빙결 잔영 | 적을 향해 움직이며 주변을 둔화시키고, 시간이 지나면 폭발한다 | 가까운 적 쪽의 얼음 형상과 범위 폭발 |

짧은 설명 흐름은 `냉기로 둔화 → 동료와 함께 처치 → 빙결 잔영 → 광역 폭발`이다.
잔영을 플레이어가 직접 조작하는 직원이나 저지 유닛으로 그리지 않는다.
서리 마검 사용자는 높은 배치 지점에서 원거리 공격하는 모습으로 표현한다.
원본 환상체의 조우 장면에는 플레이어 파편의 잔영 효과를 임의로 옮기지 않는다.
미정 유물 이름은 `냉기 조합 유물` 같은 설명용 표기로 대신하며 공식 이름처럼 만들지 않는다.

## 9. 제작 순서와 결과물

1. 필수 문서와 이미지 6장을 확인한다. 읽은 문서와 실제로 본 이미지를 구분해 기록한다.
2. 8장의 원고와 같은 직원이 이어지는 시각 기준을 먼저 고정한다.
3. 표지·조우·빌드·마무리에 필요한 콘셉트 그림을 만들고, 기존 UI는 장면에 맞게 크게 활용한다.
4. 그림·설명 도식·텍스트를 배치해 PPT를 완성한다. 원고와 제목은 편집 가능하게 유지한다.
5. 각 슬라이드를 이미지로 렌더링해 잘림·글자·전장 가독성·인물 일관성을 확인하고 고친다.
6. 아래 결과물을 대화에서 제공한다. 저장소의 소스와 문서는 수정하지 않는다.

### 요청하는 결과물

- `game_intro.pptx`: 16:9, 한국어, 8장. 가능하면 텍스트와 도식 편집 가능.
- `game_intro_preview.pdf`: 확인·공유용 미리보기.
- `game_intro_script.md`: 장별 최종 문구, 짧은 발표 메모, 근거 문서와 사용 이미지 목록.
- `slide_01.png`부터 `slide_08.png`: 최종 슬라이드 미리보기. 필요하면 묶어서 제공.

모든 형식을 만들 수 있다고 가정하지 않는다. 실제 제공 가능한 도구로 제작하고,
지원되지 않는 출력 형식은 명시한다. 슬라이드 이미지만 제공했다면 이를 PPTX로 부르지 않는다.
전부 이미지로 된 PPTX만 만들 수 있다면 텍스트가 편집되지 않는다는 점을 알리고 원고를 함께 제공한다.

### 최종 확인

- 첫 장부터 타일 배치형 전투라는 점이 보이는가?
- 배치 후 플레이어가 무엇을 지휘하는지 설명되는가?

- 내부 시스템 설명을 제외하고 플레이어가 할 행동과 경험으로 설명했는가?
- 모든 장에 일관된 인물·공간·색·글자 크기가 적용됐는가?

추가 질문은 누락된 이미지나 자료 접근처럼 결과를 만드는 데 실제로 필요한 항목에 한정한다.
