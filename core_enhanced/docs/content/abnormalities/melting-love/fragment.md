<a id="frag-획득과-퍼펙트-선택"></a>
## 획득과 퍼펙트 선택

- 일반 승리는 탱커 파편 `고기벽` 하나를 확정 지급한다.
- 퍼펙트 승리는 탱커 파편과 별도 identity인 딜러 파편 중 하나를 플레이어가 선택해 지급받는다.
  두 파편을 동시에 지급하거나 무작위로 고르지 않는다.
- 이 둘은 한 파편의 기본형·개화형이 아니라 같은 환상체에 대응하는 서로 다른 스킬 파편이다.
- 퍼펙트의 exact 판정, 이미 보유한 파편을 다시 선택했을 때의 repeat reward와 이후 반복 조우에서
  나머지 파편을 얻는 규칙은 open design이다.
- 현재 룰북의 exact `fragment_id` 단일 지급과 `ClaimAll` 규칙에는 이 선택형 보상의 canonical 반영이
  필요하다. 세부 선택·재획득 정책이 확정되기 전에는 live reward로 authoring하지 않는다.

## 탱커 파편 — 고기벽 (가칭)

> 검토 보류. 이하 내용은 기존 방어형 설계이며 이번 공격형 설계 종료에 포함하지 않는다.

무기로 모은 개인 방어 자원을 떼어 원하는 길목의 전장 방어 자원으로 바꾸는 스킬이다. 플레이어가
유효한 `walkable path tile` 하나를 지정하면 고기방패 스택 한 구간을 소비해 그 타일에 파괴 가능한
`고기벽`을 세운다.

**고기방패 구간 소비**

고기방패 스택은 현재 HP에서 파생되므로, 스킬은 현재 최상단 구간에 실제로 남아 있는 HP만 분리한다.

```text
구간 HP = H
시전 전 고기방패 HP = P
시전 전 고기방패 스택 = ceil(P / H) = S

분리 HP = P - (S - 1) x H
시전 후 고기방패 HP = (S - 1) x H
생성 고기벽 HP = 분리 HP
```

예를 들어 구간 HP가 `100`, 현재 고기방패 HP가 `150`이면 손상된 최상단 구간 `50`을 분리한다.
무기 소유자에게는 온전한 한 구간 `100`과 고기방패 1스택이 남고, 지정 타일에는 HP `50`인 고기벽이
생긴다. 새 시체로 최상단 구간을 먼저 수복할지, 급한 길목에 손상된 벽이라도 즉시 세울지가 실제
판단이 된다.

구간을 소비해 저지 수가 감소하면 무기의 기존 규칙에 따라 초과 blocker를 결정론적으로 풀어준다.
이미 시작한 공격 resolution은 스킬 시전으로 취소하지 않는다.

**다른 Shield에서의 HP fallback**

고기방패가 없는 다른 `Shield`에서도 파편 자체가 완결되도록, 사용할 고기방패 스택이 없으면 장착
유닛의 HP를 직접 비용으로 소비해 더 약한 고기벽을 만든다.

- 비용은 최대 HP의 authored 비율을 우선 후보로 둔다.
- HP 비용은 피해가 아니며 고기방패, 일반 보호막, 방어력·저항과 피해 감소를 우회한다.
- 비용으로 실제 소비한 HP와 authored 변환 계수로 고기벽 HP를 정한다.
- 비용을 지불하면 HP가 `0`이 되는 상태에서는 시전할 수 없고 공명을 소비하지 않는다.
- 녹아내리는 사랑 무기를 장착했지만 현재 고기방패가 `0`인 경우에도 같은 fallback을 사용한다.

전용 무기와 조합하면 감염 시체라는 재생 가능한 자원을 사용하고, 다른 `Shield`와 조합하면 자기
살을 떼어 길목을 막는 위험한 탱 스킬이 된다.

**고기벽 battlefield object**

고기벽은 아군 유닛이나 일반 summon이 아니라 HP를 가진 encounter/battlefield 방해물이다.

- 이동하거나 공격하지 않는다.
- 기존 Route와 pathfinding을 다시 계산하거나 적을 다른 길로 우회시키지 않는다.
- 지상 적은 원래 Route를 따라 고기벽 tile에 도착하면 이동을 멈추고, 고기벽을 파괴할 때까지
  공격한다.
- 공중 유닛은 고기벽을 무시한다.
- 고기벽의 방어력·저항은 시전 순간 장착 유닛 값을 snapshot하며 이후 시전자 상태와 함께 변하지
  않는다.
- 일반 회복, 지속 회복, 흡혈과 시체 흡수로 HP를 회복할 수 없다.
- 파괴되어도 고기방패나 장착 유닛 HP로 돌아오지 않으며, 전투 종료 시 남은 고기벽도 제거한다.
- 고기벽이 받은 피해는 시전자의 HP 피해, 피격 trigger 또는 resonance source가 아니다.
- 고기벽은 시체가 아니며 무기의 감염·시체 흡수 후보가 되지 않는다.

시전자가 철수·전술 이동·전투불능이 되어도 이미 세운 고기벽은 snapshot된 상태로 남는다. 단, 같은
시전자가 동시에 유지할 수 있는 고기벽 수에는 상한을 둔다.

**배치 제한**

고기벽은 authored placement range 안의 유효한 path tile에만 세운다. spawn, goal, portal, 고정
오브젝트, 다른 고기벽과 현재 점유 중인 tile은 거부한다. 고기벽은 경로를 영구 봉쇄하는 지형물이
아니라 도달한 적이 공격해 제거할 수 있는 바리케이드이므로, 배치 뒤 Route topology는 변하지 않는다.

open design:

- 파편과 스킬의 최종 이름, `rarity`, `equip_limit`과 exact compatibility
- 고기벽의 placement range, 동시 유지 상한과 tile eligibility
- 다른 `Shield`에서 사용할 HP 비용 비율과 고기벽 HP 변환 계수
- 고기벽이 snapshot할 방어력·저항 항목과 피해 type별 처리
- 지상 보스, 저지 불가 적, 돌진·관통 공격과 고기벽의 상호작용
- 고기벽 파괴·전투 종료·checkpoint/resync presentation과 cleanup
- 시전 중 고기방패 구간 소비, blocker release와 고기벽 생성의 원자적 commit 순서

<a id="frag-탱커-파편-개화형"></a>
## 탱커 파편 개화형

현재는 **두지 않는다.** 기본형의 고기방패 구간 소비, 다른 `Shield`에서의 HP fallback과 고기벽
배치만으로 파편의 전투 선택이 완결된다고 본다. 개화형은 당장 제작하거나 전제로 밸런싱하지 않으며,
추후 기본형의 선택 폭이 부족하다고 확인될 때 별도 설계로 재검토한다.

## 딜러 파편 — 포자 감염 (가칭)

> 상태: 2026-10-19 확률 감염·피격/사망 전파·위력 성장과 자연 감소·일제 기폭·유물 6개 구조 설계 종료 /
> 이름·확률·전파 범위·성장식·피해 수치·세부 판정은 후속 조정

| 항목 | 값 |
| --- | --- |
| `rarity` | open design |
| `equip_limit` | open design |
| `compatibility` | 적대적 기본 공격을 가진 무기 profile, exact open design |
| `cast_selection` | `self` |
| 역할 | 딜 / 증식형 전염과 전장 일제 기폭 |

이 파편을 장착하면 착용자의 무기에 `포자` 속성을 부여한다. 포자 속성은 새 damage type이 아니라
아래 감염·전파 trigger의 provenance이며, 무기의 기존 피해 type, 공격 범위와 targeting profile은
바꾸지 않는다.

**최초 감염**

- 포자 속성 무기의 eligible 기본 공격에 피격된 비감염 적은 대상별 deterministic proc roll을 한 번
  수행하고, authored 확률에 성공하면 해당 파편 instance가 source인 `포자 감염`에 걸린다.
- 한 공격 action의 여러 damage segment가 같은 적에게 여러 최초 감염 roll을 만들지 않는다. 광역
  기본 공격은 실제로 적중한 서로 다른 적마다 roll을 한 번씩 수행한다.
- 실패한 roll은 상태를 바꾸지 않는다. 같은 적을 후속 공격하면 새 action에서 다시 roll할 수 있다.
- 지속 피해, 반사, 장비 proc, 환경 피해와 파편의 기폭 피해는 최초 감염 roll을 만들지 않는다.

**피격과 사망 전파**

- 포자 감염 상태인 적이 같은 source의 포자 속성 무기 기본 공격에 피격되면 주변의 eligible 비감염
  적에게 포자를 퍼뜨린다. 이미 감염된 숙주에 대해서는 최초 감염 확률을 다시 굴리지 않는다.
- 포자 감염 상태인 적이 death finalization에 들어가면 마지막 공격의 소유자와 관계없이 같은 전파를
  한 번 발생시킨다.
- 하나의 lethal 기본 공격이 피격 전파와 사망 전파를 중복 발생시키지 않는다. 사망 전파 하나가
  우선하고, non-kill hit만 피격 전파를 사용한다.
- 전파 자체는 확률을 다시 굴리지 않고 authored 반경·대상 수 안의 비감염 적에게 포자 감염을
  부여한다. 후보가 많으면 거리, route progress와 stable unit identity를 사용하는 deterministic
  순서로 고른다. exact tie-break는 후속 판정에서 고정한다.
- 같은 전파 transaction에서 새로 감염된 적은 즉시 다시 전파하지 않는다. 이후 별도의 포자 무기
  피격이나 death finalization이 발생해야 다음 세대로 퍼진다.
- 공중 유닛, 환상체, 소환물과 보상·Wave authority가 없는 임시 유닛의 감염·전파 eligibility는
  authored filter가 명시한다.

**감염망과 지속 피해**

- 포자 감염은 battle-local이며 파편 instance별 source ownership을 가진다. 여러 source의 감염을
  하나의 전역 망으로 암묵 병합하지 않는다.
- 파편은 현재 살아 있는 감염체 수와 감염을 유지한 시간을 함께 반영하는 `감염 위력`을 소유한다.
  감염체가 많을수록 단위 시간당 위력이 더 빨리 증가하고, 감염망을 오래 유지할수록 감염 피해가
  강해진다.
- 감염 여부와 출처별 감염 위력을 구분한다. 한 숙주에 감염 스택을 여러 개 쌓는 구조가 아니며,
  감염 위력은 해당 출처의 감염체들이 함께 참조하는 연속 수치다.
- 각 감염체는 authored cadence마다 현재 감염 위력을 읽어 periodic 피해를 받는다. 위력 상한,
  감염 지속 시간, 재피격 갱신과 기본 피해 주기는 후속 조정한다.
- 감염체가 0명이 되면 위력 성장을 멈춘다. 즉시 초기화하지 않고 유예 시간 동안 현재 위력을
  보존한 뒤 서서히 자연 감소시킨다. 다시 감염체가 생기면 자연 감소를 멈추고 남은 위력에서 성장을
  재개한다. 유예 시간과 감소율은 미정이다.
- 유물의 지속 피해 주기 감소는 같은 현재 위력으로 더 자주 피해를 주어 DPS를 높인다. 위력 성장
  속도를 함께 올리지 않는다. 성장량 증가와 자연 감소 방지는 [별도 유물 연결](synergies.md)이다.
- Retreat와 전투 종료는 포자 감염, 감염 위력과 전파 진행을 폐기한다. Checkpoint/resync는 같은
  process의 현재 감염 source, 남은 시간과 위력을 그대로 투영한다.

**시전 — 일제 기폭**

- 공명 만충에서 별도 target 없이 시전하면 현재 source가 소유한 모든 포자 감염을 동시에 기폭한다.
- 시전 시 현재 감염 위력을 기준으로 폭발 기준 피해 `E`를 정한다. 각 감염 숙주의 위치에서 해당
  **타일 1칸**을 기본 범위로 폭발한다. 감염체 수는 폭발 지점 수와 위력 성장에 영향을 준다.
- 숙주 자체에는 `E`의 **2~4배 피해를 한 번** 가한다. 자신의 폭발 기본 피해 `E`를 별도로 더하지
  않는다. 이는 숙주가 받는 피해이며, 주변 대상 전체에 2~4배를 적용하거나 숙주를 즉사시키는 규칙이 아니다.
- 기본적으로 한 번의 일제 기폭에서 같은 적은 폭발 피해를 한 번만 받는다. 숙주 자신의 배율 피해도
  이 1회에 포함하며, 주변의 여러 숙주 폭발이 겹쳤다고 추가 피해를 받지 않는다.
- `중첩된폭발` 유물을 적용하면 서로 다른 숙주 폭발의 피해를 각각 받을 수 있다. 한 개의 폭발은
  큰 적의 여러 점유 칸에 닿아도 같은 적에게 한 번만 적중한다. 자기 폭발의 기본 피해를 별도로
  더하지 않는 규칙은 유지한다. `넓어진 지평`은 각 폭발을 중심 타일 기준 **3×3**으로 넓힌다.
- 기폭 resolution은 해당 source의 포자 감염과 감염 위력을 모두 소비한다. 기폭은 새 감염 roll이나
  사망 전파를 만들지 않으며, 플레이어는 무기 공격으로 감염망을 다시 구축한다.
- 감염체가 하나도 없으면 시전할 수 없고 공명, 상태와 battle revision을 바꾸지 않는다.
- 감염 위력 보존 유물도 시전 시의 감염·위력 전량 소비를 막지 않는다. 자연 감소만 막는다.
- 숙주 배율의 2~4배 내 최종값, 피해 type·산식과 Boss phase gate 등 세부 판정은 후속 조정한다.

죽을 나비의 장례는 적이 죽을 때 나비 스택을 사망 타일에 남겨 이후 그 **공간**을 폭발시킨다. 이
딜러 파편은 타일에 스택이나 오염을 남기지 않고 살아 있는 **숙주 사이**로만 전파하며, 사망 시에도
인근 생존 적에게 감염을 넘긴 뒤 원래 숙주와 함께 사라진다.

이 파편의 장착 중 포자 속성은 현재 룰북의 `Fragment는 passive 장비가 아니다` 원칙에 대한 예외다.
실제 구현 전 장착 intrinsic, 기본 공격 provenance와 active 기폭을 함께 가진 파편 문법을 gameplay
canonical과 runtime contract에 먼저 반영해야 한다.

open design:

- 파편과 감염·기폭의 최종 이름, `rarity`, `equip_limit`과 exact compatibility
- 최초 감염 확률, 대상별 proc roll identity와 deterministic RNG/checkpoint 보존
- 전파 반경·대상 수·후보 순서와 공중·환상체·Boss·소환물 eligibility
- 감염 지속 시간, periodic cadence, 감염 위력 성장식·상한과 감염망 소멸 시 유예 시간·자연 감소율
- 포자 무기 재피격이 감염 지속 시간이나 감염 위력을 별도로 갱신하는지
- 기폭 피해 type·기준 피해 산식·감염 위력 계수·숙주 배율의 최종값과 infection consumption 순서
- 큰 숙주의 폭발 중심 타일, 동시에 겹친 폭발의 선택·처리 순서와 Boss phase gate
- [합의한 유물 6개](synergies.md)의 등급·증가율·감소율과 중복 장착 세칙
- 탱커 무기의 별도 `감염도`와 딜러 파편의 `포자 감염`을 같은 loadout에서 함께 처리할 때의 UI와
  source ordering. 두 상태를 이름만 보고 암묵적으로 합치지 않는다.

## P5 작성 정책 보완 — 2026-10-22

2026-10-21~22의 통상 정책 위임에 따라 다음 세부 경계를 고정한다. 상기의 수치 공백을
공식 밸런스로 채우지 않으며 그래프의 미정값과 실행 시험 입력을 구분한다.

- 최초 감염과 전파는 같은 필터를 쓴다. 현 작성안은 살아 있는 지상 적·보스·환상체를 포함하고
  공중·소환물·Wave/보상 권한 없는 임시 유닛을 제외한다. 필터는 노드에서 변경 가능하다.
- 전파 순서는 거리 오름차순 → 경로 진행도 내림차순 → 안정 유닛 ID 오름차순이다.
  전파 대상 목록을 먼저 고정하므로 같은 트랜잭션의 새 감염으로 연쇄 증식하지 않는다.
  거리와 경로 진행도는 피격/사망 판정 시점의 이동 위치를 사용하며 이동 구간의 미래 끝 위치를 쓰지 않는다.
- 감염 자체는 별도 자연 만료 없이 배치 동안 유지하고 재피격으로 시간을 갱신하지 않는다.
  철수·전투불능·전투 종료 때 감염망과 위력을 함께 제거한다.
- 공유 위력은 `dP/dt = 살아 있는 숙주 수 × 숙주당 초당 성장량`으로 증가하고 작성 상한을
  적용한다. 0숙주는 작성 유예 뒤 선형 감소하며 주기 피해 간격과 별개다.
- 기폭은 중심 타일 하나를 사용하고 자기 숙주 배율의 작성 기본값은 합의 범위 안의 3배다.
  중심은 접수 시점의 숙주 위치로 고정한다. 이동 중이거나 몸체가 큰 숙주도 자기 폭발 피해를 정확히 한 번 받는다.
  피해 유형은 마법, 기준 피해는 현재 위력×작성 계수로 표현한다. 무효·면역·보스 phase gate는
  공통 피해 처리에서 판단하며 숙주 즉사로 바꾸지 않는다.
- 기본 겹침 모드는 자기 숙주 피해를 우선한다. 그 밖의 동일 대상 후보는 큰 피해 위력 우선,
  동률은 중심 타일·안정 ID 순으로 하나를 고른다. 폭발별 모드에서도 자기 폭발의 E를 추가하지 않는다.

출처별 표식·연속 위력·폭발 계획으로 작성하며, 작성 지원과 Core 실행 검증 상태는
[작업 파이프라인](../../../../../content_assembler/docs/skill-authoring-pipeline.tmp.md)에서 구분한다.
