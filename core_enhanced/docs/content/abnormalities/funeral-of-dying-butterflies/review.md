## 6 죽을 나비의 장례

**기존 방향:** 기본형은 이동 가능한 경로 타일에 나비를 배치한 뒤 폭발시킨다. 개화형은 적과 타일에 쌓은 나비를 모아 연속 폭발한다.

**조립안:** 기본형은 해당 경로 타일 목록 고정 → 폭발 지연 → 각 범위의 적 조회와 피해다. 나비마다 독립 유닛을 만들지 않는다. 겹치는 폭발의 동일 대상 피해 횟수는 범위 설계에서 명시한다.

개화형은 적중으로 대상 스택 축적 → 대상 사망 시 현재 타일로 스택 이전 → 시전 시 살아 있는 대상과 타일의 스택 합산 → 이번 폭발량 결정 → 소비 → 유한 반복 폭발이다. 다른 사본이 만든 나비는 섞지 않는 안을 추천한다.

**상태와 표현:** 대상 스택과 타일 스택은 서로 다른 저장 위치지만 같은 출처를 가진다. 액세서리의 처치 폭발도 원래 처치와 파생 폭발의 출처를 구분한다. 나비 비행은 효과 전달에 실제 시간이 필요한 경우에만 판정 지연을 가진다.

**기능 경계:** 스택 이전·합산·소비와 반복 범위 공격으로 구성한다. 경로 전체 배치에 일반 이동 AI는 필요하지 않다.

**검토:** 기존 초안은 스택 0일 때 기본 폭발 횟수, 일정 스택 이상에서 환산 횟수를 사용하는데 경계에서 횟수가 줄어들 수 있다. 추천은 스택 증가로 최종 횟수가 감소하지 않는 표로 정리하는 것이다. 합산 대상 범위와 소비 시점을 함께 정한다.

**태그와 유물 적용**

| 효과 단위                  | 태그 후보                        | 변경 후보 속성과 지켜야 할 경계                              |
| -------------------------- | -------------------------------- | ------------------------------------------------------------ |
| 경로에 배치한 나비         | `소환물·지연발동`                | 배치 위치·기폭 지연. 실제 유닛 이동이나 투사체를 뜻하지 않음 |
| 적의 스택과 사망 타일 축적 | 대상 `스택` / 타일 `소환물·스택` | 획득·이전·상한·합산 범위. 출처별로 별도 보존                 |
| 나비 폭발                  | `피해·범위·폭발`                 | 개별 폭발 위력·반경·횟수. 원래 배치물과의 관계 보존          |
| 개화형 연속 폭발 순서      | `다중타격` 여부 검토             | 독립 배치물의 피해인지 원본 직접 스킬 단계인지 먼저 결정     |

**유물 연결:** 기존 **소환물 범용 유물**은 나비에서 발생한 피해에 연결할 수 있다. 폭발 반경 증가는 새 범용 후보다. 반복 폭발이라는 이유만으로 **깊은 쐐기**를 적용하지 않는다. 타일 스택 합산량을 바꾸는 전용 후보는 총 횟수·소비와 함께 검토한다.

## 2026-10-19 원본 유지와 미채택 리워크

사용자는 원본 파편을 그대로 진행하기로 했다. 기본형의 경로 전체 폭발, 개화형의 전용 무기 피해로
스택 축적 → 사망 타일로 이전 → 유닛·타일 스택 합산 → 몫에 따른 등급·횟수 계산을 유지한다.

앞선 리워크에서 제안한 모든 무기의 기본 공격으로 스택 부여, 타일당 단발 폭발과 선형 피해 증가,
기폭 스택의 일괄 확정 소비, 기본형 2초 동시 폭발·시전 전체 대상당 1회 판정은 당시 채택하지 않았다.
후속 합의에서는 같은 폭발 차례의 타일 간 중복을 기본 1회로 제한하고, 중첩된폭발로 이를 해제한다.
전용 구체에 모은 스택은 소비하지만 일반 등급별 폭발의 소비는 미정이다. 나머지 미정은 원본대로 남긴다.
파편 사용 후 쌍권총 복귀 제안도 채택하지 않으며, 후속 무기 동반 승급 합의에서는 미니건을 유지한다.

## 이전 무기 — 공명 90% 형상변화

> 아래는 동반 승급 합의 이전 본문이다. 공명에 따른 형태 전환과 시전 후 복귀 미정은 현재 설계가 아니다.

> 상태: Platform 원거리 쌍권총·미니건 형상변화 구조 합의 / 이름·수치 미정

쌍권총이 미니건으로 **형상변화**한다. 전환은 공명 `90%`에서 자동으로 일어난다.

| 항목 | 값 |
| --- | --- |
| `range_role` | 원거리 |
| `weapon_archetype` | `Gun` |
| `deployment_affinity` | Platform 전용 |
| `block_capacity` | `0` |
| `defense_tile_range` | 긴 편 |
| 그 외 항목 | open design |

두 형태 모두 Platform에서 총으로 직접 공격하며 적을 저지하지 않는다. 관을 세워 적을 막거나 관을
해체해 무기를 꺼내는 구조와 연출은 사용하지 않는다.

**쌍권총**

기본 형태에서는 Platform에 배치된 착용자가 쌍권총으로 원거리 사격한다. 쌍권총도 피해를 입히면
나비 스택을 쌓는다.

**미니건**

공명이 `90%`에 도달하면 쌍권총이 미니건으로 형상변화한다. 배치 위치와 `block_capacity 0`은
변하지 않는다.

- 무한 관통
- 피격당한 적을 뒤로 조금씩 밀어낸다
- 피격 시 나비 스택이 `1` 쌓인다

**설계 근거**

쌍권총은 일반 원거리 사격으로 나비 스택을 쌓고, 미니건은 관통·넉백과 더 빠른 스택 부여로 다수의
적을 압박한다. 지상 저지 역할을 겸하지 않는 대신 두 형태의 화력 차이와 파편 폭발 시점에 집중하는
Platform 원거리 딜러다. 공명의 획득 원리는 현재 재작성 대상이며 이 절에서 확정하지 않는다.

파편 시전은 공명을 0으로 되돌린다. 시전 뒤 미니건을 유지하는지 쌍권총으로 돌아가는지는 아래
open design에서 정한다.

open design:

- 쌍권총의 스택 축적량과 미니건과의 차이
- 넉백 거리와 대상 판정
- 미니건 유지와 쌍권총 복귀의 정확한 규칙
- 두 형태의 사거리·공격 주기·targeting profile과 Platform Rest 판정
