# 최신 게임 정책과 기존 로드맵의 정합성 검토

2026-10-03 기준. 별도 검토 문서이며 기존 로드맵에 적용하지 않은 권고안이다.

기존 콘텐츠 제작 기반의 R 순서와 공통 엔진 기반은 유지할 가치가 있다. 다만 최신 정책을 구현하려면 **완료한 기반에 대한 제한적 후속 변경, 미착수 카드의 수용 조건 보완, 차기 원정의 별도 구현 범위**가 필요하다. 기존 R00–R24를 그대로 완료하는 것만으로 최신 게임 설계 전체를 구현했다고 판단할 수는 없다.

우선 차이는 승패 즉시 확정과 저장, 후퇴와 종료 복구, 공명 사용 수명, 에고 침식과 Breakdown, 모드와 난이도다. 유물 합성·활성·연쇄의 상당 부분은 이미 R13–R16 최신 지시서에 반영되어 있으므로 중복 작업을 만들 필요가 없다. 지도·전조·귀환·창고·화면은 각 기능을 실제로 완성할 책임을 추가로 배정해야 한다.

이 문서는 기존 로드맵·진행표·정식 계획·감사 원문을 수정하지 않는다. 제품 코드·RON 수정, 테스트 실행, 새 Goal 활성화도 수행하지 않는다. 아래의 작업 배정과 순서는 검토자의 제안이며 구현 지시나 완료 판정이 아니다.

## 검토 기준과 판단 범위

- 목표 정책은 [차기 설계서][policy]와 연결된 상세 규칙을 기준으로 한다. 차기 설계서 자체가 현재 구현 기준과 목표 설계를 구분하므로, 최신 합의를 과거 구현 계약에 소급 적용하지 않는다.
- 개발 상태는 [단일 현황][status]의 최신 설명과 연결된 감사 원문을 기준으로 읽었다. [9월 R 연구 카드][rmap]의 `proposed_not_implemented`는 작성 당시 표지다.
- [R08–R12 설계·수용표][r08handoff], [R13–R16 최신 지시서][r13handoff], 관련 R 카드와 정책 gate를 대조했다. 현행 구현 전체의 생산자·소비자 추적이나 실행 재검증은 이번 범위가 아니다.
- **문서 차이 확인**은 원문끼리 비교해 확인한 내용이다. **후속 변경 제안**은 필요한 책임과 수용 조건을 도출한 것이다. **구현 확인 필요**는 코드 조사 없이는 지원 여부나 수정량을 확정할 수 없다는 뜻이다.
- 기존 상태를 복제하는 새 진행 장부는 만들지 않는다. 실제 적용 시 현황과 정식 계획을 연결하는 방식은 [로드맵 운영 규칙][operating]을 따른다.

## 현재 개발 상태와 동기화 작업의 관계

[2026년 10월 3일 독립 감사][audit]는 R08–R12를 **Not Complete / F01**로 판정했다. 보스 action의 `CancelUnreleased` 또는 강제 state 이탈 뒤 미실행 Flow가 남는 취소 결함이며, 기존 계약 자체의 실패다. 최신 게임 정책을 도입해서 생긴 추가 요구와 구분해야 한다.

따라서 다음 개발 작업은 현황에 적힌 **R08/R10 취소 교정과 영향 검증, 독립 재감사**로 유지하는 것이 맞다. R13–R16은 선행 불충족으로 미착수라는 최신 설명을 인수한다. 이 검토 때문에 해당 교정에 차기 원정 전체를 합치거나 종속 구현을 먼저 시작할 이유는 없다.

현황 문서 안의 조회표에는 별도 정리할 불일치가 있다. `전체 진행표`의 R06/R07은 아직 독립 감사 대기이고 R08–R12는 후속 범위·완료 미확인으로 표시되지만, 상단에는 R06/R07의 과거 Complete / High와 R08–R12 최신 감사 결과가 있다. 이것은 **문서 조회 상태의 불일치**다. 이후 동기화에서 최신 근거로 표를 고치되 과거 감사의 대상과 판정은 보존해야 한다. 이번에는 수정하지 않았다. [근거][status]

## 우선 보완할 다섯 가지 경계

### 승패 확정과 저장을 결과 확인 버튼에서 분리

**문서 차이 확인.** [최신 결과 규칙][results]은 승패가 성립하는 즉시 직원 상태·보상·XP·기록·노드 소비를 함께 확정하고 저장한다. 결과 확인은 표시를 닫는 동작이다. 선택 보상은 획득 권리·후보·선택 대기 상태를 먼저 저장한다. 반면 [R20][r20]은 기존 각 기능의 저장·결과 계약을 교차 검증하는 카드이며, 이 새 정책을 처음 구현할 책임을 갖고 있지 않다. [R13–R16 지시서][r13handoff]의 X-02도 현행 저장 경계를 전제로 한다.

**후속 변경 제안.** 차기 노드 수명과 결과 저장을 담당하는 구현 단위를 먼저 두고 R20과 최종 원정 검증에서 함께 인수한다. 전투 terminal 판정, World 결과 반영, 영속 저장, 결과 화면의 역할을 구분해야 한다. 예전 시험 이름에 `result`, `retry`, `checkpoint`가 있다는 것만으로 새 정책이 검증됐다고 볼 수 없다.

판별 사례는 첫 전투에서 패배한 뒤 결과 화면에서 종료하는 경우다. 이어하기는 이미 소비된 노드와 확정 손실을 유지해야 한다. 결과를 확인하지 않았다고 패배 전으로 되돌아가면 최신 정책과 다르다. 저장 도중 실패·중복 요청에서도 일부 보상만 남거나 같은 보상을 다시 받지 않는 조건이 필요하다.

### 후퇴와 종료 복구를 별개로 유지

**최신 확정 정책.** 수동 후퇴는 승패 전 최대 2회다. 두 번째 후퇴 후 마지막 도전이 남으며, 어느 도전이든 승리나 패배가 확정되면 노드를 소비한다. 따라서 패배를 세 번 허용하는 정책이 아니다. 승패 전 게임 종료 복구는 후퇴 기회를 소비하지 않는 예외이며, 이미 쓴 후퇴 기회도 돌려주지 않는다. 종료·재실행까지 합한 절대 진입 횟수 상한으로 해석하면 안 된다. [근거][results]

| 경계 | 최신 정책에서 보존하거나 복원할 것 |
| --- | --- |
| 유효한 수동 후퇴 | 전투 손실 복원, 후퇴 사용 1회 보존. 최초 입장 비용·유예 진행·부화 비용 유지 |
| 두 번째 후퇴 | 노드는 미해결로 유지. 마지막 도전 허용, 추가 수동 후퇴 거부 |
| 승패 확정 | 즉시 노드 소비·상태·보상 저장. 결과 화면 종료나 재접속으로 취소 불가 |
| 승패 전 게임 종료 | 미확정 노드를 입장 전으로 복원. 비용·유예·창고 소비·부화 등 미확정 결과도 함께 복원하되 사용한 후퇴 횟수 유지 |
| SavePoint 복구 | 지정 과거 상태를 복원하는 별도 기능. 런당 최대 3회 정책과 후퇴 횟수를 혼동하지 않음 |
| 미완료 전조의 다음 층 재제안 | 동일 전조의 사용한 후퇴 횟수 유지. 승패 확정 전조는 재제안하지 않음 |

**후속 변경 제안.** 노드·조우·전조의 identity, 최초 입장 기록, 후퇴 카운터, 보상 선택 대기를 저장 계약에 명시한다. 게임 종료 복구·명령 실패 재시도·네트워크 재접속·패배 후 재도전은 서로 다른 의미로 시험을 분리한다. [R20][r20]의 `retry 새 attempt` 표현을 차기 정책의 패배 재도전 허용 근거로 사용하지 않는다.

### 공명 사용 수명을 action 수명과 구분

**최신 확정 정책.** 배치·재배치 공명은 최대치의 20% 내림, 자동 충전은 초당 1이 초기값이다. 공격·피격 기본 획득과 Rest 보너스를 제거한다. 유효 입력 접수 즉시 전량 소비하고, 기절·빙결 또는 스킬 사용 잠금 중에는 유물 등을 통한 추가 획득도 막는다. 취소·중단은 환불하지 않는다. [근거][combat]

발사체는 발사 동작이 끝나면 충전할 수 있지만 시간제 버프는 버프가 끝나야 한다. 독립 장판·소환물은 생성 동작 종료, 채널은 채널 종료가 기준이다. 따라서 R04/R08의 `Released`나 `EffectsSettled`, R10의 Flow 완료 중 하나를 모든 스킬의 공명 잠금 종료로 그대로 채택할 수 없다.

**후속 변경 제안.** R05 자원과 R09/R10/R11/R12의 접수·취소·채널·제어를 소비하는 공명 전환 작업을 둔다. 자동·수동 및 Pause 중 접수, 잘못된 입력, 시간제 버프 중 기절, 필수 대상 무효화, 재배치까지 한 계약으로 연결한다. R13 소환물과 R16 추가 획득 subscriber도 이 규칙을 인수해야 한다. 기존 코드의 실제 수정 지점과 호환 범위는 구현 조사로 확정한다.

### 에고 침식과 Breakdown은 기존 R09의 후속 변경

**문서 차이 확인.** [R08–R12 설계][r08handoff]의 R09는 현재 적 집합의 특수 처치와 완료 노드 기준 Breakdown을 다룬다. [최신 에고 침식][relics]은 일반 침식체만 즉시 처치하고 엘리트·일반 보스·최종 보스는 최대 HP 25% 피해를 초기값으로 둔다. 일반 보호막을 먼저 소모하고 무적·대상 지정 불가·페이즈 HP 하한과 필수 전환을 지킨다. [최신 유예][results]는 트라우마 100 이후 **새 노드 최초 입장의 규정 억제력 소모 누적 4**가 초기 기준이며, 실제 억제력 잔량 0에서도 진행한다.

**후속 변경 제안.** R09 successor에서 적 분류별 결과, 직원 대가, 공명 접수와 침식 실행의 결속, 강제 연출, 결과 저장을 함께 검토한다. 입력에서 이미 공명을 소비했더라도 받아들인 자격을 잃거나 침식 실행에서 이중 소비하지 않아야 한다. 침식의 실행 시점을 무조건 입력 순간으로 옮기는 결정까지 이 검토가 대신하지 않는다. 승패 성립·강제 연출 만료·결과 표시의 시점을 구분해 즉시 저장과 기존 강제 시계 계약도 함께 대조해야 한다.

R12 보호막, R18 보스 페이즈, R16 부가 효과 억제가 직접 소비자다. Breakdown은 노드 입장·규정 비용·사망·회복 순서와 연결하고, `노드 완료당 1 감소` 회귀의 단순 유지로 닫지 않는다. 최신 설계상 한계 도달 사망은 해당 노드에서 뒤이어 치료한다고 취소되지 않는다. 과거 R09 구현·감사 기록은 당시 계약의 근거로 보존한다. [근거][results] [상세 과제][open]

### 모드와 난이도의 목표를 새로 인수

**문서 차이 확인.** [R19][r19]에는 Certified 평가 모델·가중·캐시와 정책 profile이 포함된다. 최신 정책은 튜토리얼과 원정 두 모드, 깊이·지역·조우별 작성 난이도를 사용하고 편성·Certified·런 최고 전투력에 따른 적 강화는 제거한다. [근거][runmap] [난이도 규칙][growth]

**후속 변경 제안.** R19의 획득·등록·보상 선택·공식 콘텐츠 교체는 유지한다. Certified 난이도 소비와 과거 모드의 플레이 진입·저장 이행은 차기 모드 전환에서 제거 또는 대체 대상으로 분리한다. 내부 수치 평가가 설명·시연 등에도 쓰이는지는 조사해야 하므로, 모든 전투력 관련 코드와 ValueExpr 기반을 일괄 삭제하는 권고는 아니다.

튜토리얼은 자산·창고·영구 기록을 건드리지 않는 별도 진행을 검증해야 한다. 무억제 상태는 조우별 HP·공격력 1.5–2배, 지정 수량형 전투 승리 보상 2배를 적용하되 패턴·속도·사거리·저지 요구량과 파편·알·장비·유물·선택 횟수는 이 배율의 대상이 아니다. [근거][expedition]

R21의 대표 콘텐츠 C01–C07과 전체 요구 대응은 계속 유효한 출발점이다. 다만 새 정책을 시험 입력에 포함하고, 대체·폐기된 정책의 행은 근거와 함께 후속 대응을 남겨야 한다. 과거 수용표를 지우거나 옛 테스트 수를 새 정책의 보증으로 사용해서는 안 된다. [R21 원문][r21]

또한 본편 전용 기능과 공개 제작 기능의 경계는 [후속 공개 범위 합의][publicscope]를 따른다. 모든 전용 보스 서사를 범용 모드 기능으로 공개하는 의무를 새로 만들지 않는다. NEXT-20에서 RON 설정 대상으로 합의한 노드 정책은 설정·검증·실제 실행 경로를 입증해야 하며, 구체적인 공개 제작 API 범위는 상세 설계에서 구분한다. R22의 data-only 인수와 본편 원정 완성도는 이 경계에 맞추어 따로 검증한다.

## 권장 작업 배치와 의존성

다음은 동기화 적용 시의 묶음 제안이다. 새 R 번호나 정식 Goal ID를 부여하지 않는다. R13–R16의 기존 구현 권한과 선행 요구도 이 문서로 변경하지 않는다.

| 작업 묶음 | 먼저 필요한 입력 | 해당 묶음에서 닫을 책임 |
| --- | --- | --- |
| 기존 F01 교정과 재감사 | 최신 감사의 공개 취소 재현과 교정 수용 조건 | 기존 R08/R10 계약 회복. 정책 개편과 별도 target·판정 |
| 차기 실행 계약의 차이 확정 | 이 검토, 최신 규칙, 교정 후 실제 코드와 현재 계획 | 어떤 차기 정책을 어느 실행 범위에 채택할지 명시. 공명 사용 종료·침식·노드 commit·저장 형식의 후속 계약과 호환 범위 확정 |

**순서 권고.** F01 교정 뒤 곧바로 차기 원정 전체를 구현할 필요는 없다. 다만 새 정책을 R13–R16에 함께 넣을지, 현행 계약으로 먼저 완성한 뒤 후속 변경으로 넣을지는 구현 계획에서 명시해야 한다. 두 정책을 같은 완료 주장에 섞는 것이 가장 큰 위험이다. 불필요한 재작업을 줄이려면 공명·침식·결과 저장의 차이와 소비자 목록을 R13–R16 재개 전 확보하는 편이 좋다.

공명 사용 수명은 R13/R16 소비자에게, 침식 피해는 R12/R18에게, 노드·자산 저장은 R19/R20에게 필요한 입력이다. 지도 구조 전체나 모든 보스 서사가 이들 기반의 필수 선행은 아니다. UI도 전체 R24 완료 뒤에만 시작해야 하는 것은 아니며, 필요한 명령과 조회 계약이 안정된 기능부터 배정할 수 있다.

[모드 검증 및 실행 안전성 계획][safety]의 `모드`는 사용자 제작 mod를 뜻한다. 튜토리얼·원정 두 게임 모드로 정리한다는 이유로 이 계획을 폐기하지 않는다. 본편 mod 적용 전 검증·오류 격리의 잠정 의존성을 유지하고, 새 승패 commit과 전투 오류 처리의 경계는 영향 조사에 넣는다. 기존 20분 시험 제외와 실행 안전 한도·gameplay 상한의 구분도 유지한다.

| 같은 조우에 다른 편성·장비·과거 최고 전투력 | 작성 난이도 유지. 무억제 변화와 보상 2배는 지정 필드에만 적용 |
| 같은 층 같은 계열 방 이동과 전조 패배 | 추가 전조 생성 없음. 패배도 경험 완료·노드 소비, 성공 보상 없음. 미완료 전조 재제안은 사용한 후퇴 횟수 계승 |
| 엘리트 최초 파편 분쇄 후 같은 종류 재격파 | 최초 파편 재지급 없음, 알 생성 없음. 새 원정의 최초 보상과 일반 보스 부활 보상은 별도 |
| 알려진 보스 방으로 새 원정 시작 | 위치·정보는 보이되 이번 원정 선행 전까지 잠김. 흉탄은 이번 원정 마탄 완료 전 잠김 |
| 창고와 소지 재료를 섞은 개화 후 복구·실패 | 소비와 개화 결과 동시 복원, 원래 출처 유지. 원정 실패 시 사용한 재료·반입 사본과 보관 자산의 손실 경계 일치 |
| 깊이 2와 3의 Gate·소진, 최종 보스 승리 후 계속 탐사 | 귀환 자격 구분. 보상은 현 원정에서 사용 가능하나 실제 귀환 전 반출되지 않음. 이후 실패는 원정 자산 손실·확정 영구 기록 유지 |
| 튜토리얼 반복 후 원정·첫 성공 귀환 | 튜토리얼 자산·기록 격리, 원정 직원·기본 예산 새 지급, 첫 귀환 VN 1회와 다음 원정 이행 |
| UI 미리보기 후 대상 이동·저지 관계 변경 | 현재 판정 정보와 실제 실행 결과를 각각 정확히 표현. 미래 명중을 보장하지 않으며 오래된 표시로 실행 결과를 조작하지 않음 |

## 보류와 초기 수치를 유지할 항목

합의가 끝난 구조를 다시 정책 대기로 돌릴 필요는 없지만, 모든 수치가 확정된 것은 아니다. [남은 결정][open]을 그대로 입력으로 사용한다.

- 로스터 카드의 입력 중 위치 고정과 흉탄 본체의 전투 구조는 보류다. 카드 고정을 새 완료 조건으로 추가하거나 보상 무기 두 종류를 보스의 2단계 전투로 채택하지 않는다.
- 공명 20%·초당 1, 에고 침식 25%, Breakdown 규정 소모 4, 재료 환급 50%, 대여·회수량, 중반 레벨 3·최종 보스 전 레벨 6은 해당 문서의 초기 검증값 또는 목표로 취급한다. 구현은 설정 가능성과 일관성을 검증하고 밸런스 완료는 플레이 근거로 판단한다.
- 억제력 초기량·노드별 비용·황금가지 보충량, 보상 수량·상점 가격, 지원 배치·정비와 SavePoint의 정확한 간격은 경로와 경제를 함께 검증해야 한다. 아직 없는 수치를 이 검토가 공식값으로 만들지 않는다.
- 순수 치유 무기의 수치·범위·주기, 파편 개화 비용과 개별 recipe, 유물 보상 후보 부족·생략·재추첨 세부는 남은 범위를 확인한다. 이미 결정한 구조와 미정 콘텐츠 값을 같은 이유로 막지 않는다.
- 무억제 강화와 부활 단계 강화의 구체적인 중첩 계산은 남은 검증 과제다. 임의 곱셈식을 이번 검토의 확정 정책으로 쓰지 않는다.
- 옛 모드·숙달·새 노드 상태와 저장 형식의 이행은 구현 조사 대상이다. 기존 저장을 자동 삭제하거나 손실을 승인한 것으로 해석하지 않는다.

## 추후 로드맵에 적용할 때의 변경안

1. 현황 조회표의 R06–R12 표시와 R09 정책 대기 설명을 최신 인계·감사에 맞춘다. 과거 시점으로 명시된 문장은 역사로 보존한다. 현재 다음 개발 작업은 F01 교정으로 유지한다.
2. R13–R16 재개용 문서에는 이미 반영한 유물 합의를 유지하면서 이번 공명·침식·저장 변경을 어디서 인수할지 연결한다. 원래 제외한 원정·상점·보상 활동·GUI를 묵시적으로 완료 범위에 추가하지 않는다.
3. R19는 등록·획득·선택 책임을 유지하고 Certified 난이도와 옛 게임 모드의 대체 범위를 구분한다. R20은 각 owner가 구현한 최신 저장·후퇴 계약의 통합 검증으로 유지한다.
4. 지도·원정 수명·경제와 자산·보스별 진행·UI에 별도 구현 책임과 수용 조건을 배정한다. 실제 R 번호·Goal 분할·정확 순서는 생산자와 소비자를 조사한 정식 계획에서 정한다.
5. R21/R22의 최신 콘텐츠·공개 제작 범위와 새 정책 대응을 보완하고 R23/R24의 회귀·감사 입력으로 연결한다. 콘텐츠 제작 기반 완료와 차기 게임 전체 완료를 구분한다.
6. [PG 정책 gate][gates]의 옛 미정 사항은 후속 합의로 해소된 부분, 최신 정책으로 대체된 부분, 실제 미정 부분을 구분해 새 인계에 명시한다. 연구 원문·완료 target·감사 기록은 덮어쓰지 않는다.

권장 첫 적용 범위는 **현황 정합성 정리와 정책별 구현 책임 배정**이다. 그다음 선택한 구현 범위의 계약과 수용표를 갱신하면 된다. 이번 문서는 그 판단 자료까지 제공하며 로드맵 적용과 구현은 수행하지 않았다.

## 근거와 검토 한계

상태와 구현 관련 서술은 연결된 현황·인계·감사 문서에 귀속한다. 이번 검토에서 해당 감사의 테스트·성능 수치나 현재 코드의 동작을 재현하지 않았다. 코드 전수 조사, 공식 콘텐츠 전종 이행, 옛 저장 변환 방식, 일정·작업량 추정은 남아 있다. 문서의 상대 링크와 형식을 점검하고 기존 로드맵 파일의 보존을 확인하는 것은 제품 검증과 별개다.
