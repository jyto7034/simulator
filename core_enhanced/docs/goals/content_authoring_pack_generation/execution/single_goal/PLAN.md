## GEX-10 pass 001 — explicit resolver closure, before its implementation

Each manifest has pack_id/version, explicit Global or Named namespace, latest content contract, required capabilities, declared dependency pack IDs, typed relative catalog inventory, and explicit Replace/Remove operations. Full payload without an operation is Add. A writer is exactly (pack_id, DefinitionKey(kind, canonical id)); duplicate payloads/operations are structural errors. Replace requires exactly one same-key full payload; Remove forbids that payload. Operations list explicit `after` writer pack IDs for that same target; every edge must name a selected declared dependency ancestor and an actual target writer. Dependencies merely establish availability; they never add writer edges. Duplicate/missing/cyclic dependencies and writer edges fail even for eventual losers.

Every target has exactly one base Add. All subsequent writers must explicitly descend from it. Replace-after-Remove and any multi-parent operation after a tombstone fail in that causal branch. A sibling Remove does not invalidate an independent Replace branch. The one maximal writer is selected, or the host must explicitly select one maximal writer when multiple heads remain. Duplicate/unknown target selections, unknown/non-maximal winner and unselected packs fail. Explicit merge after multiple full-definition writers is allowed. After graph selection, only winning payloads enter the typed assembly/final reference and compile checks. Removed targets have no catalog/index entry.

The runtime order key is the base Add's catalog, pack ID, normalized relative file path and numeric authored definition ordinal. Replace keeps this position but retains its own real source locator; Remove drops the position. Pack/file enumeration never breaks conflicts or defines execution order. Actual final collection array order is hashed. Named Add IDs must already spell namespace::local; globals are exact delimiter-free keys. No automatic prefix/reference rewriting. Reference-keyed recipes and adapter-extracted fixed floor/enum/singleton keys are exempt from independent namespace ownership, while Replace/Remove target exact existing canonical keys. Existing UUID owner checks remain unchanged.

Separate read-only reviewer `/root/roadmap_intake_review` found no confirmed policy deviation and identified sibling tombstone scoping, one writer/payload per pack/key, graph validation of losers, numeric ordering and original replacement locations as required discriminators. Root accepted all.
