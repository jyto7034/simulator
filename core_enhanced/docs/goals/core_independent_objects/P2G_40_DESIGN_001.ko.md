# U07 실행 경계

Bound Freeze FPF-CIOB-001. Changes/obligations/resolutions/supersessions explicit empty; parallelization none approved.

DEFINITIONS는 strict 작성/컴파일/source 설명의 의미를 닫는다. CREATION은 해당 입력을 기존 SpawnKernel candidate에서 소비하고 object/actor/source/lifetime의 생성 원자성을 소유한다. SPATIAL은 실제 geometry/target/contact와 친구/벽/field 행동, SEGMENTS는 기존 shield remaining과 비용+벽 생성의 단일 transaction을 소유한다. PUBLIC은 같은 Core 자격과 owner를 현재 DTO·정상 application/trial/host·restore 경계에서 소비한다. VERIFY는 실제 제품 전체의 현재 실행과 독립 감사 evidence를 닫는다.

각 노드 내부 strict producer/consumer와 clone/accounting 전환은 함께 수행한다. 노드 사이에는 기존 kernel candidate/unit/damage/shield/application이라는 stable seam이 있으며 공통 파일 공유만으로 큰 atomic group을 만들지 않는다. 정의만 존재하는 중간 상태를 runtime 지원 완료로 광고하지 않는다. 한 PHASE-CIOB-01에서6노드를 순차 수행하고 전체20 acceptance/10차원/161선행+31R06을 독립 Complete/High로 닫은 뒤 U08로 간다.

GEX는 TD01–08 안의 exact enum/container/event/geometry/DTO와 초기 밸런스 값을 기록한다. 작은 strict/clone/extent/fault 검사→기능별 native→정상 외부 RON/CoreApplication/trial/host→최종 통합 순으로 검증한다. 선행 U06 exact target과 현황 delta는 PREDECESSOR_INTAKE_001이 소유하고 원본 oracle/실패를 보존한다. live battle process-save, Unity, 개별 최종보스·전체 감염/시체 생산자를 새 범위로 추가하지 않는다.
