## GEX-10 detailed design — CREATION owner and transaction

새 `IndependentObjectState`는 live object map, source/copy/family counter, 단조 ID sequence 및 마지막 종료 receipt를 소유한다. map의 key는 공통 SpawnKernel의 `UnitInstanceId`를 재사용하지만 trap은 units map에 등록하지 않는다. actor/wall만 각기 Combatant/IndependentWall adapter를 만든다. definition은 immutable database ID로 참조하고 runtime에 compiled definition을 복제하지 않는다. source snapshot에는 생성 당시 Attack/Defense/Resistance, fragment/equipment/cast/authored observation을 보관하되 action/delivery/resource/use-control 실행 권한을 제거한다. 생성 action ordinal은 별도 진단값으로 보관한다. family counter key는 실제 creator instance + fragment copy + equipment runtime copy + authored family이고 evolution은 total/alive를 증가시키지 않는다.

공통 커널 source에 stable authored payload를 추가하며, 중복 재처리는 현재 점유를 다시 읽기 전에 기존 exact stable payload와 비교한다. 새 요청은 현재 타일·범위·점유·상한·cost를 검사한 뒤 common candidate 안에서 비용, IDs, adapters, object state 및 timer를 함께 commit한다. public effect는 cast/step/effect/flow occurrence를 request identity로 사용한다. 지원하지 않는 repeat/delivery 조합은 strict validation에서 거절하고 성공 no-op으로 처리하지 않는다. 새 소유 상태는 생성 전 retained/entity admission, CloneShape/clone-reuse, fingerprint 및 retained scan에 즉시 연결한다. 소멸 후 live record/source는 회수하고 total counter만 전투 수명 동안 남겨 authored max_total을 보존한다. 마지막 종료 receipt 하나는 query용 bounded owner이며 전체 순서는 기존 bounded facts/log가 소유한다. queue는 object ID/epoch를 사용하고 stale callback은 다른 형태를 변경하지 않는다. 초기 작은 검증은 source credential 분리·counter/epoch·clone 독립·retained growth/rollback이며, 이후 정상 opcode 소비를 연결한다.
