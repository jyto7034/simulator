# 감사 전 실행 설계

원본 제품은 변경하지 않는다. 현재 입력을 복사한 /tmp/u164-independent-audit001에만 PROBES.rs를 기존 u164_stress 모듈 끝에 추가한다. 기존 배치 helper의 합법 scout/guard 방어 전략을 재사용하며 기대값은 별도로 계산한다.

- 다중 웨이브: 첫 라운드에 정상 AtTimeMs(30000) 추가 웨이브를 작성한다. 20초에는 라운드 미완료, 추가 적까지 실제 처치 후에만 선택, 철수 보상10.
- 보상: 정상 작성 공격80, 라운드 XP/가루1..5. 실제 출전 두 직원은 기본10+누적15=25, 비출전 medic0. 무억제는 내부 상태 수정 없이 입장비용12로 최초 억제력12를 소진하고 공개 Continue 선택; 성공 XP50/가루30/통화300, 정상25/15/150. 중간 지급 없음.
- 후퇴: 위 정상 무억제 진입→1라운드 실제 완료→계속→진행 중 후퇴. 진입 자산 복원/누적 상실/노드 소비와 Core checkpoint 복원 확인. 실제 파일 IO/새 프로세스 증거로 주장하지 않는다.
- 작성 경계: 라운드당 통화1,000,000,000은 개별2배 검사를 통과하나 총5,000,000,000은 u32를 초과한다. 로더 승인 및 정상 전투 최종 정산 경로를 확인한다. 실패하면 입력·원문을 보존하며 실제 지원 작성 오류로 분류한다.

기존 dev 빌드49초/집중9개9초 근거. 첫60초에 진행 확인, 5분 이상이면 CPU/로그 진단. 제품 성능 판정용 실행이 아니다. 9개 기존 집중검사와4개 감사검사를 한 번의 cargo 선택으로 실행한다.

최초 probes001에서 경계검사만 실패(12pass/1fail). 후속 exact 진단은5라운드 진입까지1..4완료를 명시하고 최종 정산 오류/같은tick재시도/상태무변경/후퇴가능성을 확인한다. 오류 재현 assertion 통과를 제품 기능 PASS로 계산하지 않는다. 공개 package_official_content도 공식 입력에서5개 보상량만 바꿔 승인 여부를 대조한다.
