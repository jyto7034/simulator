범위: F-U164-IA001 교정의 실제 소비자 및 A05/A08 보강. 제품 수정 없음.

- 정상 RON 작성으로 5라운드 보상에 가루 전용/예약 재료 alias를 교대로 사용하고, 별도 환상체 파츠를 동시에 지급한다. 각각 합계 2,147,483,647, 시작 보유량 0. 다섯 값은 429,496,729 네 번 + 429,496,731 한 번이다. 마지막 라운드에 유물 1개만 포함한다.
- 기존 감사 양성의 합법 배치·공격80 작성 편대와 입장비1/12를 사용한다. 12비용은 초기 억제력12를 소진하고 공개 Continue를 선택해 무억제를 만든다. 내부 적 삭제·보상/억제력 state 수정은 하지 않는다.
- 매 라운드 실제 처치 후 completed_rounds를 확인하고 1–4라운드에는 가루/파츠/유물 미지급, 같은 battle UUID, waiting을 확인한다. Continue 후 5라운드 완료에서 정상2,147,483,647/무억제4,294,967,294를 잔고별로 관찰한다. 유물은 양 모드 모두1개이며 node 완료와 Core checkpoint import 후 잔고/사본을 대조한다. 후속 동일 StressCombatAct는 거절되고 잔고가 불변이어야 한다.
- 교정의 원시16+25와 패키징 양/음성은 hash/입력/소비자 검토 후 재사용한다. 이번 focused 실행은 현재 영구12 + 과거 양성replay4 + 신규1이다. 테스트 수를 기존 full baseline에 더하지 않는다.

## 추가 XP 가설 (첫 실행 입력은 변경하지 않음)

공통 Employee::add_experience_with_policy는 레벨 비용 소비 전에 u32 saturating_add를 한다. 따라서 무억제에서 개별배율 경계2,147,483,647의 XP보상은2배4,294,967,294 자체는 유효해도 기본 생존XP20과 더하면19를 잃을 수 있다. 정상지원RON에서 첫라운드에만 이XP를 작성하고 정상/무억제 첫성공철수로 대조한다. 성장정책의 레벨당 비용은 지원RON으로1,000,000,000을 작성하여 반복을4회로 제한한다(검증량·기대총량은 유지). 기본생존XP10, 초기레벨1/XP0은 그대로다. 기대 누적XP는 정상2,147,483,657/무억제4,294,967,314이고 u64(level-1)*1,000,000,000+잔여XP로 외부계산한다. 기존 실행 종료 후에만 사본에 추가하고 exact 신규검사만 실행한다. 실패하면 기존 공통owner 문제와 U16-4의 노출을 구분한다.

probes001 종료(exit101): 기존16개 통과, 신규 가루/파츠 시험은 전투 이전 fixture 준비에서 실패했다. 공식 relic catalog가 비어 있는데 첫 항목을 가정했다. 제품 finding이 아니다. 원본PROBES와 실패로그를 보존하고 기존 지원RON fixture의 유물 정의를 로더에 공급한다. 정상 진입/수량/5라운드/복원 oracle은 유지한다. 첫 실행 종료 후 이 준비 교정과 XP probe를 사본에 반영하고 신규2개만 실행한다.
