# 프로젝트 지도 제작 — 판단과 미확인 사항

## 현재 작업 상태

`investigation_only` 조사와 [지도](../../project_map.ko.md) 작성을 완료했다. 작성 후 별도 읽기 pass에서
M01~M10과 원문을 대조했으며 [완료 검토](COMPLETION_AUDIT.md)에 근거를 기록했다.
추가 사용자 결정 없이 승인된 범위에서 완료했다. 아래 준비 단계 판단은 보존하고 실제 발견을 뒤에 구분한다.

## 범위와 작성 판단

- 주요 독자는 신규 정책 구현 전 설계를 검토할 AI다. 일반 온보딩용 파일 목록보다 책임·실행 흐름·정책
  영향·추가 근거 위치를 우선한다.
- 코어는 깊게, 서버·데이터는 코어와 연결되는 경계까지 조사한다. 서버 전체나 콘텐츠 전체 감사는 하지 않는다.
- Unity 계약은 사용자가 명시적으로 제외했다. 지정된 범용 실행 지침만 작업 절차의 참고로 사용했다.
- 테스트 실행 제외는 사용자 지시다. 명령·로그·테스트 수의 추가 제출을 요구하지 않으며 문서 검증으로 한정한다.
- 지도는 `docs/project_map.ko.md` 하나를 전달 입구로 한다. 긴 과정 기록과 중복 정책 전문은 Goal·정책
  원문에 두고 지도에는 필요한 근거와 해설을 제공한다.
- 검토 AI는 압축된 프로젝트 코드 또는 GitHub 링크로 원문에 직접 접근한다. 지도는 구조·영향·읽기
  순서와 관련 원문 위치를 안내한다. 전달할 코드와 지도 조사 기준을 맞추며, 미커밋 변경을 주의해서 기록한다.
- 사용자는 필요시 전면 재작성도 검토할 의향을 밝혔다. 후속 AI는 현재 구조 유지·부분 재설계·전면
  재작성을 비교할 수 있다. 지도는 현재 구조의 근거를 준비하며 재작성 결정이나 실행 승인을 대신하지 않는다.
- 범용 지침의 구현·정책 폐쇄 요건을 이 조사 Goal에 적용하지 않는다. 정책 보류와 현재 불일치를 기록하는
  것이 목적에 부합한다. 새 구현 Goal·Phase·P2G Freeze를 생성하지 않는다.
- 별도 에이전트는 사용하지 않았다. 최종 문서 검토도 별도 읽기 pass로 가능하며 위임이 필수는 아니다.

## 2026-09-06 추가 확인 — 데이터 기반 콘텐츠 제작

- 사용자는 커뮤니티 제작자가 엔진이 지원하는 명령·행동을 조합해 보스·장비·파편·유물을 RON으로 만드는
  목표를 확인했다. 지원 범위를 넓히는 엔진 기능 확장은 허용되는 방향이다.
- 지도는 현재 조합 방식과 데이터/공통 코드/개별 콘텐츠 코드의 경계를 준비한다. 표현력의 충분함과
  엔진 확장 방향을 판단하는 것은 고성능 AI의 후속 검토다. 상세 기준은 PLAN 1절·7절이 소유한다.
- 명령·효과 전체 목록이나 모든 콘텐츠의 구현 가능성을 별도로 감사하지 않는다. 현재 흐름 조사에서
  주요 정의·실행·공유·확장 위치를 연결한다.
- 제작 도구 기능, 외부 콘텐츠 직접 불러오기·무재빌드 적용·배포 방식은 확정하지 않았다.
  이 목표를 해당 기능의 구현 승인으로 해석하지 않는다.

## 기준 상태와 기존 기록 보존

- Git root는 `/mnt/f/work/simulator`이고 core·server·resources는 같은 Git 작업 트리 안에 있다.
- 문서 준비와 실제 실행 조사·검토의 HEAD는 `f318414fb0156a67e04c5479000c2a2683fc0c09`다.
- 기존 수정·삭제·미추적 파일이 많다. 준비 단계의 쓰기는 Goal 네 문서였고, 이번 실행 쓰기는 그 네 문서와 지도 한 파일이다.
- 생성 직전 `docs/goals/project_architecture_map/`, `docs/project_map.ko.md`는 미점유였다.

  다르며 당시 지도는 현재 없다. 이전 PLAN을 수정하거나 그 근거를 현재 조사 결과로 재사용하지 않는다.

  설계 대상이라는 상태를 확인해 입력 문서에 연결했다. 전체 콘텐츠 검토나 새 정책 승인으로 해석하지 않는다.

## 실행 조사에서 확인한 차이와 판단

상세 근거 링크는 지도 6절의 D01~D07과 각 실행 흐름에 있다. 이전 대화의 구조 설명을 재확인 없이
현재 증거로 가져오지 않았고, 현재 파일의 양쪽 경계를 직접 읽었다.

| 결과 | 판단과 영향 |
| --- | --- |
| D01 서버/코어 API 단절 | 서버 actor/main/store가 이전 `GameCore`·loader·rollback 표면을 사용한다. 현재 `CoreApplication`·검증 token·test 한정 포트와 일치하지 않는다. 기존 core runtime 계약도 core-only cutover로 외부 migration PASS를 제외한다. 의도된 범위 경계를 코드 전체 통합 성공으로 바꾸지 않음 |
| D02 Breakdown 시한부 | 룰북의 node countdown·저장 요구와 달리 현재 직원 condition·RunPolicyData/live 필드·node 완료·checkpoint에는 해당 counter가 없다. trauma100 자격 차단 자체와 구별하며 침식 직원 대가의 후속 연결 질문으로 남김 |
| D03 codec 문서 | data loading 계약은 strict core V4를 기술하고 현재 core runtime 계약/codec은 V5 writer·V4 import를 사용한다. host envelope V4는 별도 축. 기존 계약은 수정하지 않음 |
| D04 설계와 live 상태 | 장비·파편 설계 완료와 active 전환·성장 모델 적용 완료는 다르다. live placeholder·방어구 강화 및 현재 파편 강화/자동 개화 선택을 현재 사실로 기록 |
| D05 신규 유물·침식 | 조사한 catalog/owner/장착/실행/저장에 신규 유물 aggregate와 직원 침식 자동 대체·연출 정지 경로가 없다. `GameDataBase.corroded_employee_data`의 적 데이터와 구분. 관련 정의·호출·소비까지 확인한 범위의 부재 |
| D06 상태 수명 | runtime item source 기반 proc cooldown/횟수, cast/delivery/event 출처는 유물 사본별 재배치 보존·연쇄 순환 제한의 구현 증거가 아니다. 새 BattleCore·새 runtime ID·같은 process 보존을 구분 |
| D07 데이터와 실행 지원 | Boss schema의 `RepathToProtectedObjective`는 compile에서 거부된다. reference RON이나 특정 ID lookup의 존재를 전체 콘텐츠 지원 또는 전용 행동 분기의 증거로 확대하지 않음 |

주요 해석 경계:

- 물리적 `GameCoreState` 필드와 run-local 수명은 구분한다. root roster·attempt roster·runtime unit은 서로 다른 owner다.
- 준비 cast 수락은 Pause에서도 가능하지만 실제 ability/step·공명 소비는 별도 시점이다. 침식 실행 위치나 새 입력 큐를 결정하지 않는다.
- `UnitDied` command는 현재 무처리다. HP/death finalization, 효과 발동, wave/terminal을 묶어 읽어야 침식의 처치 효과 억제 목표를 검토할 수 있다.
- outer draft commit과 commit 후 공개 result projection은 구분한다. 실패 결과를 모두 rollback이라고 설명하지 않는다.
- SavePoint durable 저장, entry rollback, live checkpoint/resync, permanent profile은 서로 다른 복원 범위다.
- 현재 RON의 embedded loading과 공통 task/effect 해석 경계는 확인했다. 엔진 표현력의 충분함이나 외부 pack 제작·배포 체계는 평가하지 않았다.

## 남은 미결정·미확인과 의도적 비범위

- 미결정: 대표 유물/정식 태그/수치/분쇄량/전투력 가중, 유물 획득, 일반 보스 재조우 방식·빈도·보상,
  파편 기존 진행/보상/저장 전환, 개화 추가 재료, 침식 임계 숫자·연출 duration·개별 표현.
- 미확인·비범위: 실제 빌드/runtime/성능/배포, 외부 서버 adapter 전환·통합, Unity 소비,
  모든 콘텐츠·명령의 표현력, 제작 도구·외부 pack·배포 방식.
- 필수 경로를 조사하지 못해서 남긴 공백은 없다. D01은 양쪽 원문에 접근하여 확인한 단절이며
  구현을 고쳐 연결하는 것은 이번 완료 조건이 아니다.
- 사용자 전체 테스트 통과 보고를 유지한다. 재실행하거나 로그를 요구하지 않았으며 이 보고만으로
  신규 정책 검증이나 서버 통합 일치를 결론내리지 않는다.
- 후속 AI는 지도와 일치하는 원문 상태를 받아 유지·부분 재설계·전면 재작성을 비교한다.
  이번 작업은 어느 선택도 채택하지 않았고 새 구조·구현 Goal·Freeze를 만들지 않았다.
