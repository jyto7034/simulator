# S2 pre-mutation implementation decisions

Authority: CONTINUOUS_REQUEST_20261004, frozen TD05–07 and PE08–12. These are GEX technical choices, not changes to safety policy, completion conditions, content identity, command/result/save semantics or RNG. Product mutation follows this record. Full validation and independent GEX-20 remain pending.

- `runtime-observation` is a non-default Core/host Cargo feature. Core owns fixed-size observations and a bounded standard-library channel only; metrics libraries remain optional host dependencies. Observer is owned by CoreApplication, outside its cloned GameCore. No observer means no timing/queue/metric work; feature off compiles hooks away.
- Queue capacity1024; worker batch128. Only worker records histograms. A batch is followed immediately by synchronous standard PrometheusHandle::run_upkeep, independently of scrape. Classic explicit buckets, finite operation/outcome/reason labels; no identity label or global recorder installation. Standard exporter owns metrics format and HTTP. No exporter fork or custom chart.
- Exact optional direct host dependencies: metrics=0.24.6, metrics-exporter-prometheus=0.18.3 (defaults off, http-listener), crossbeam-epoch=0.9.21. The last package is the exact metrics-util0.20.4 retirement implementation, MIT OR Apache-2.0, declared Rust1.61. Existing source and probe metadata/archives are captured. Whole product graph is rechecked after integration; preserve existing locked versions when resolvable.
- A batch retirement fence uses the same crossbeam default collector. After run_upkeep, defer a fixed atomic completion flag and flush. Do not record another batch until this fence completes. Idle iterations do bounded pin/flush work; they never spin until success. A stalled epoch reader therefore suspends observations, not gameplay. This also covers deferred heap retention, rather than equating clear_with with immediate deallocation. Source review: AtomicBucket.clear_with retires every detached block and flushes before returning; crossbeam queues sealed bags FIFO, invokes expired bag callbacks, and cannot advance past pinned old readers. Concurrent collection may have an already-popped callback in flight: storage bound includes one in-flight retirement batch per participating thread plus the gated batch; a paused callback cannot accumulate more callbacks on that thread. Product collector runtime has one runtime worker and max_blocking_threads1 for standard HTTP renders. Logical unconsumed histogram values≤128×histogram-values-per-summary; finite handles/distributions and fixed buckets; pending deferred blocks bounded by the above batches, including partial blocks per finite handle. All count/storage constants and actual heap receipts will be reported at verification; the preliminary probe is not V10 completion.
- Core top-level operation guard keeps one TLS fixed-size accumulator during the synchronous operation. Native scope teardown snapshots accepted work/clone/admission totals; existing extent calculation supplies the already-computed retained extent. O(1) owner count seams supply peaks without new owner scans. Guard finalization uses returned public error, once; fixed reasons are native fault codes or finite ApplicationErrorKind. Native first-fault latching is not changed. Duration is monotonic wall time, simulation time a separate field.
- Commit-only usage is staged after existing reconciliation and published at the sole GameCore live-root replacement. PreparedNonBattleApplication detaches TLS before returning; it owns a pending observation until consuming commit or drop. Drop emits a discarded attempt and its peaks without commit/gauge advancement or invented native fault. Another application's operation on the same thread cannot join the detached preparation.
- Each observed application has one non-cloneable lease and fixed atomic latest-commit state/interval peaks. Host holds weak leases, not historical session records; dead leases are pruned on registration and worker polls. Queue messages contain identity numbers, not strong lease references. Thus full queues cannot keep sessions alive or suppress ended-battle cleanup. Latest state uses a bounded-retry atomic sequence read; a concurrent write can defer one observation poll, never block Core. Aggregate sum/max operates on active leases only. Queue drops and duplicate consumption are explicitly tested.
- Selection owns slot0 and ring300. Session/battle UUID and selection wall timestamp are metadata only, with explicit boundaries on selection/end. Host loopback diagnostic endpoints provide selection and ring metadata; Grafana uses the standard Prometheus datasource/dashboard, with a link to this metadata. Diagnostic endpoints do not export metric format or draw charts. Default snapshot200ms, scrape1s/dashboard1s, Prometheus retention24h. Separate bounded observability.ron; HTTP opt-in loopback. Exporter startup/runtime failure is host observation status and cannot change gameplay results.
