# Independent source review — U04 audit 001

This is an audit of the frozen target, not a new implementation. Direct source inspection was combined with independently validated existing final executions. No full suite was rerun merely because the auditor is fresh. The executable audit probes check integrity, exact receipt/selector bindings, numeric interpretation, public raw records and restoration.

## Result, receipt and choice ownership

`world/combat.rs` commits the existing settlement planner at terminal transition, captures the authoritative result and summary, and enters CombatResult. `CompleteCombatResult` takes the stored receipt and changes display phase; it does not call settlement. The same planner applies employee injury/trauma and death cleanup, XP, common grants, authored participant context and node consumption. Ordinary defeat consumes the node and does not grant victory assets. Valid SavePoint recovery remains prior to final run failure. Private candidate failure cannot publish a partial result.

`world/reward.rs` keeps the current participant context and fixed candidates/seed across selected and claimed continuation. Nonempty ChooseOne requires a choice, an empty authored pool is represented explicitly, and the phase/candidate checks prohibit out-of-pool, repeated and after-claimed grants. The current selected entitlement remains distinct from unconditional terminal grants. Final-node pending choices survive until resolved; terminal runs without pending entitlement invalidate Continue. The real process probes include result-before-ack and select/claim restart, a stale second actor, and repeated deterministic battle identity after a legitimate rewind.

## Four restoration lifetimes

`active_run/continuation.rs` owns current committed continuation, optional SavePoint, unfinished-node pre-entry state, compact receipt, pending reward/context and current VN. Every currently interactive node enters through pre-entry capture. An unfinished Event battle restores the whole Event entry on process Continue; successful retreat uses the battle-entry snapshot and overlays its counter onto unfinished Continue. Successful retreat is bounded at two, and invalid/refused actions consume no counter. This distinguishes pre-entry, battle-entry and explicit SavePoint restoration instead of using a single rollback representation.

Continue exports current stable progress before the first SavePoint, does not consume loads, and restores unfinished pre-entry state while preserving successful retreat usage. Explicit load validates the live seed, restores SavePoint-scoped run/economy/UUID/RNG and rewinding VN roots, and increments the host-monotonic load count. SavePoint capture cannot erase that count; latest-generation backup recovery retains load3. Permanent profile union and explicitly nonrewinding VN history remain outside rewind. SavePoint recovery applies ceil(15%) trauma recovery to living employees, with Critical/Breakdown handled and Dead untouched. The checkpoint field inventory and macro cover currently introduced roots; no future owner schema was added.

The strict V10 wire decoder requires each nullable field, validates original content/graph/economy/RNG identities, candidate catalog/participants, receipt phase/outcome/next-state and terminal entitlement, retreat/load bounds and SavePoint seed. `Current {}` is only a wire sharing optimization. Decoding reconstructs an independently owned SavePoint, not mutable aliasing. Fresh serde monolith capacity is registered before the first controlled clone; the registration expands existing known provenance and cannot bless unknown imported owners. The actual 64-entry regression distinguishes 851 from the previously undercharged 595 slots; exact-cap, one-short and unknown-provenance assertions execute in the final suite. General graph validation and resource accounting still precede installation.

## Prepared application and publication

Public `PreparedApplication` exclusively borrows the application and is consumed by commit. Command, elapsed/host tick and admin share `world/application.rs`'s sole prepare/commit path. Candidate cloning, operation, reconciliation, continuation refresh, profile capture and post-poll output validation happen before the one root replacement. Dropping the token publishes neither candidate nor observer termination. There is no host reconstruction of gameplay grants or an additional production commit owner.

The actor obtains shared profile then active-store locks consistently, prepares the complete output, checks conditional active revision and accepts a durable intent before infallible Core commit. Unchanged profile/checkpoint tick candidates avoid writes. Before intent rename an I/O failure is unaccepted and leaves Core/files at the prior boundary; after rename the accepted result is retained and advertised as recovery pending. Recovery installs the same successor idempotently. Command/tick/admin/session/fault management gates cover pending state; actor stop's `merge_and_persist` refuses Pending, Protected and Fatal, so stop cannot overwrite an accepted intent. Profile-only mode still deliberately uses its existing dirty/retry semantics when no active store is configured; this must be distinguished in the host documentation.

`active_run_store.rs` uses V5 revisions and terminal tombstones. Expected-revision CAS rejects stale choices and missing/terminal ABA; backup/current are repaired to the latest accepted generation, not an older checkpoint with optimistic metadata. `application_intent.rs` validates both current and backup versions before writes, protects old/unsupported current/backup/journal originals, and clears intent only after profile and active recovery copies are durable. Sixteen actual child-process exit stages exercise intent, profile, active, backups and clearing; a second recovery is idempotent. These are file-adapter tests, not a simulated transaction map. Crash proof is Linux process/file evidence, not a Windows or power-loss deployment claim.

## U03 fault and observation boundaries

`CoreApplication` retains the original first trusted runtime fault outside candidate rollback while normal command/resource/profile refusals remain recoverable. Prepared host ticks use the same classifier and first-origin authority. All current public mutation/late tick/management/reconnect/stop gates preserve that owner. Faults create no result or save; Quit/new actor/valid Continue is retained. Candidate-level retries and authoring trials remain private and retryable. U03 F01/F02 real producer regressions remain exact current named passes.

Observer work belongs to the attempt; successful root publication and terminal end belong to commit. Dropped terminal preparation neither creates a fictitious successful commit nor ends the active observed battle. The actual five-mode fault values compare equal for none/detached/queue-full/on/off. The collector/config/service inputs and three reused service audit artifacts are byte-exact, so reuse is limited to unchanged plumbing; the changed producer lifetime has current executions. No new deployed service/browser claim is made.

## Inherited semantics and performance

The battle kernel, boss execution, effect routing, authoring/value-expression machinery and public amount queries are unchanged U04 source except the narrowly reviewed fresh capacity hook. U04 changes the lifetime at which terminal world state commits, not the battle's calculation/order. The 112-condition ledger retains original meanings; 31 R06 acceptances separately map to current IVA selectors/PC576. Changed inherited test bodies were compared to actual before bytes: schema-path updates, a test-only explicit SavePoint helper and the explicitly approved old-format retirement account for the differences. F09 retains strict graph/identity validation in V10; F10's historical V7/V8 conversion still deterministically produces V9 and preserves originals, but that output is no longer current resumable data. This is an authorized U04 acceptance14 transition, not a claim of unchanged old-save behavior. Seven retired split-write host tests have current paired-intent/version-protection replacements under acceptance12/14.

PC576 current/immediate non-timing structure compares exactly after removing only the specified timing fields. Original compatibility comparison is preserved by its source-bound command/input receipt. The 16 compatibility procedures remain selected. R05's current raw exit101 is retained: only concurrent peak 9,299,316 versus 9,030,188 bytes exceeds its inherited cap (+269,128), exactly the approved warning; retained bytes/operations and event-heavy hard guards pass. Allocator-instrumented timing is not a latency gate. Plain snapshot/export byte and latency guards retain original caps. Allocation staging at 128/8192 retained entries has five identical samples each: 627 allocations, zero reallocations, 74,834 peak bytes, zero retained bytes.

## Structural and documentation result

The implementation reuses the existing grant engine, sole prepared owner, profile union and validated capture/restore machinery. No global forever-seen battle ID, full live battle/EventLog save or fixture-only production success branch was found. Legacy SavePoint-only Continue, ack settlement and independent paired-store publication are explicitly superseded. Historical private rollback compatibility is not the current host publication path.

The canonical Core/runtime/data/rulebook changes are present and restorable. However `game_server/docs/unity_bridge_protocol.md` is an explicitly required canonical surface and remains unchanged, outside all target source/record/reference membership. It still advertises V4/V9, older-payload backup rotation and universal independent-profile write-after-gameplay semantics. It omits the new result/receipt-choice, retreat/Continue/SavePoint and acceptance/recovery/conflict contract. This is finding F01 and prevents structural completion. Passing runtime evidence cannot substitute for the specified canonical consumer contract.
