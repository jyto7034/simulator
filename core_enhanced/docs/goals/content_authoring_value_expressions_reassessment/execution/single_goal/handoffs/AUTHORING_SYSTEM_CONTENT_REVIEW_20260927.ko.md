# 환상체 파편·장비에서 도출한 작성 체계 검토

2026-09-27 · 정적 문서 검토 및 설계 제안. §9는 후속 사용자 합의다. 나머지 제안 전체의 승인이나 구현 지시서·완료 판정은 아니다.

개발 현황의 단일 진입점은 [ROADMAP_STATUS](../../../../../roadmaps/content_authoring/ROADMAP_STATUS.md)다.
이 검토가 R 순서·의존성, 동결된 R06 목표 또는 구현 타깃을 변경하지 않는다.
현재 대화에서 검토·계획하고 실제 구현은 별도 대화에서 진행하는 경계를 유지한다.
후속 모델 설계와 최신 콘텐츠 정책은 [스킬 작성·실행 모델](../../../../../skills/skill_authoring_model.ko.md)을 따른다.
이 문서 §8의 다음 검토 제안은 §10의 후속 작업 순서로 보완됐다.

## 1. 입력과 결론

사용자 요구: 게임에 맞는 기본 기능을 조합하여 프로그래밍 방식으로 스킬을 작성하고 싶다.
마인크래프트 문법 복제는 원하지 않으며, 제작자 공통 함수 정의·인자·반환값은 당장 필요하지 않다.

[환상체 스킬 파편 설계 노트](../../../../../skills/abnormality_skill_fragments_design_notes.md)의
본문 1–4502줄을 기본형·개화형·침식형·무기·방어구·액세서리·미정 사항까지 읽었다.
읽은 파일은 311,420 bytes, SHA-256
`dfbfbe4f52d7b08fb51777586c3c9b5c3e6f8f9774c7479354e337c0584e2ff6`이다.
문서에 연결된 외부 게임 자료를 새 정책 근거로 조회하지 않았다. 원작 재현이 아닌 이 문서의 게임 설계를 분석했다.

권고는 **게임 전용의 사건·상태·절차 작성 체계**다. 필요한 구성은 다음과 같다.

- 언제 시작하는지: 시전, 기본 공격, 실제 적중·HP 손실·회복·사망, 시간·범위 변화, 플레이어 재입력.
- 무엇을 읽는지: 시전자, 대상, 효과 출처, 스택·시간, 앞서 확정된 결과, 타일·연결망의 유한 집합.
- 어떤 순서로 실행하는지: 순차 실행, 조건 선택, 횟수·대상별 반복, 대기, 병행 시작과 필요한 완료 대기.
- 무엇을 기억하는지: 카운터·타이머·선택 대상·형태와 그 상태의 소유자 및 보존 기간.
- 무엇을 바꾸는지: 피해·회복·제어·자원·modifier·공격 교체·투사체·영역·설치물 등의 공개 게임 연산.
- 어떻게 조합되는지: 효과의 명시적 분류와 수정 가능한 속성, 출처와 공유 상태를 보존하는 변형.

이 요구들로부터 제작자용 임의 함수·호출 스택·재귀 호출·일반 객체 조작을 필수로 도출할 수는 없다.
엔진의 공통 연산 구현, 콘텐츠 정의 ID 참조와 공통 데이터 재사용은 계속 가능하다.
현재 문서의 미정 항목까지 모두 실행 가능하다고 판정한 것은 아니며, 아래 구조는 충분성을 검증할 설계안이다.

일반적인 피해식의 주 입력은 시전자의 유효 공격력이다. 다만 여왕벌의 대상 최대 HP처럼 명시된
대상 참조와 흡혈의 실제 피해 결과는 필요하다. Magic 피해라는 이유로 계수를 SpellPower로 바꾸지 않는다.
현재 공격력 참조도 지연 전달에서는 언제 읽는지 별도다. 예약·release 때 고정하라는 효과와
impact/tick에서 읽는 효과를 같은 전역 기본값으로 덮지 않는다. 콘텐츠별 미정 시점은 미정으로 남긴다.

## 3. 함수 없이도 반드시 필요한 값의 연결

공통 함수의 반환값은 요구하지 않더라도, **앞선 연산의 결과를 다음 연산에서 읽는 기능**은 필요하다.

| 사례 | 기억하거나 전달해야 하는 값 |
| --- | --- |
| 풍운승려 | 이번 범위 공격의 유효 적중 존재 여부. 여러 적에게 맞혀도 자기 회복은 한 번 |
| 미미크리 흡혈 | 이번 기본 공격이 실제 감소시킨 HP 합계. overkill을 제외하고 공격당 상한 한 번 |
| 탐욕의 팔찌 | 선택한 효과와 실제 소비 수량. 소비 뒤 0이 된 현재 스택을 읽어 버프를 0으로 만들면 안 됨 |
| 고기벽 | 소비 전 구간 상태, 실제 분리/지불 HP와 생성 결과. 비용과 생성의 부분 성공 금지 |
| 흑조 | 이번 방어 효과가 실제로 감면한 양, 패링 성공과 소비한 축적량 |
| 허수아비 | 준비를 사용한 정확한 기본 공격의 identity. 나중에 다른 공격의 처치로 보상하면 안 됨 |

권장 표현은 효과에 이름을 붙여 결과 필드를 참조하는 정도다. 예를 들어 아래는 **개념 문법**이며
현재 RON schema나 새 opcode 제안의 확정안이 아니다.

```text
시전 시:
    물어뜯기: 고정한 지점으로 범위 공격을 전달한다
        피해량 = 시전자의 공격력 × 작성된 계수
    물어뜯기의 피해 판정 완료를 기다린다
    물어뜯기의 유효 적중 수가 0보다 크면:
        자신을 최대 HP × 작성된 회복 비율만큼 한 번 회복한다
```

유효 적중의 보호막·완전 무효 판정 등 원문 미정 사항은 이 예시로 확정하지 않는다.
작성자는 공통 함수 시그니처를 만들지 않는다. 시스템이 대상·시전자·현재 사건·앞선 결과를 정해진
범위에서 제공하고, 컴파일러가 미래 결과 참조·범위 밖 참조·순환 의존을 거부하는 방향이다.
값을 임시로 고정하는 기능과 지속 상태의 변경을 구분하면 임의 가변 변수 체계도 당장 필수가 아니다.

## 5. 기존 계획과 반드시 대조할 경계

### 5.1 광역 동시 계산과 관통 순차 계산

R06 [D02](../../../CODE_REVIEW_003.ko.md)는 같은 effect의 모든 대상 값을 먼저 평가하여
앞 대상의 mutation이 뒤 대상의 입력을 바꾸지 않도록 한다. 이는 일반 광역 공격에 유용하다.
반면 마탄(2667–2695줄)은 앞 대상의 실제 명중·처치 결과가 같은 탄환의 다음 피해를 바꿔야 한다.

따라서 모든 다수 대상 공격에 하나의 평가 방식을 강제하면 표현력이 부족하다.
권고: 광역 effect의 기존 규칙을 유지하고, 순차 관통은 전달 경로상의 타격 occurrence와
delivery 귀속 누적 상태를 연결한다. 다음 타격은 직전 결과가 확정된 뒤 평가한다.
집계를 위한 identity 정렬을 탄환의 공간 충돌 순서로 사용하지 않는다. R10/R11과의 계약 대조가 필요하며
R06 전체를 순차 mutation 방식으로 변경하거나 R06에서 관통 기능 전체를 구현하라는 뜻이 아니다.

### 5.2 허용된 처치 연쇄와 순환 차단

나비 액세서리(1451–1494줄)는 같은 효과가 새로 처치한 적마다 다시 발동한다.
흉탄(2696–2734줄)도 세대와 탄환 수가 제한된 확산을 요구한다.
반면 R16 카드의 `(copy,effect)` 경로 재방문 금지를 모든 장비에 일괄 적용하면 이들을 막을 수 있다.

이미 [CA00 추적 기준선](../../../../../roadmaps/content_authoring/records/CA00_NEXT-0002_REQUIREMENTS.ko.md)
§4는 장비의 허용 재귀와 유물 경로 재방문 차단을 분리하고 있다. 새로 누락됐다고 단정할 항목은 아니다.
권고: R16 상세 설계에서 이 구별을 실제 수용 시험으로 보장한다. 동일 사망 중복 방지, 같은 시전의
생성 횟수, 확산 세대, 인과관계와 실행 한도를 함께 다룬다. 지연만 넣어 새 root로 위장하는 것은 해법이 아니다.
이것은 일반 재귀 함수를 노출할 근거가 아니라, 사건 기반 전파를 도메인 규칙으로 제공할 근거다.

### 5.3 사후 반응과 피해 처리 중재

흡혈·처치 보상은 확정 결과를 읽으면 된다. 패링·가호·쉴드·HP1·death-prevent는 피해가 확정되기
전에 그 처리 과정에 참여해야 한다. 이미 죽은 뒤 회복하거나, HP를 직접 고쳐 사망을 취소하면
원문의 처치·공명·보상 규칙을 훼손한다. R12의 명시적 처리 단계와 결과를 공통 기반으로 삼는다.
감면 출처별 축적과 짚 완충의 소비 조건은 어떤 단계의 값을 읽는지도 필요하다.

### 5.4 집계 입력과 소유 관계

D04의 `ResolvedTargets`는 실제 피해/회복 대상 목록이다. 다음 입력을 모두 대체하지 못한다.

- 적이 없는 타일에 남아 있는 나비 스택과, 그 위 유닛들의 스택.
- 특정 파편 사본에서 비롯된 살아 있는 감염체와 감염 상태.
- 여러 대상에게 발생한 실제 피해·회복 결과.
- 자신이 가진 소비 가능한 효과와 그 효과를 제공한 자원의 실제 소유자.

시전자·수혜자·상태가 붙은 대상·원천 사본은 구분해야 한다. 대상의 장비 목록에서 사본 하나를
임의 선택하여 group owner로 삼는 설계는 이 요구를 만족시키지 않는다.
권고: 먼저 유한 입력의 종류와 필드를 정하고, 실제 의미가 있는 키로만 묶는다.
타일·상태·연결망 입력 생산은 R10/R13/R17 등의 책임과 연결하며, R06은 그 값의 계산 계약을 제공한다.
모든 source×owner 조합 지원 또는 대상 Attack 집계를 R06 완료의 자동 조건으로 삼지 말고,
동결된 D04 요구와 대조하여 유지/교정/후속 연결을 명시적으로 결정해야 한다. 이번 검토만으로 제거하지 않는다.

### 5.5 시전 외 입력과 게임 진행

두건의 창별 조준은 긴 계산식이 아니라 입력을 기다리는 다단계 행동이다.
팔찌와 수신기는 장비의 사용 가능한 행동이고, Hello는 기존 활성 상태에 대한 재입력이다.
Core는 선택 종류·후보·현재 단계·확정 가능한 command를 노출하고 결과를 검증할 필요가 있다.
Unity 화면 구현은 별도이며, 이번 문서로 새로운 active 슬롯 수나 입력 정책을 정하지 않는다.
기존 R10/R11/R03의 어느 산출물이 이를 소유하는지 보완하고 현재 의존성 순서를 먼저 보존한다.

현상금 node·승리 수금, 직원 영구 손실·변태, 미래 run 이스터에그는 전투 내부 flow만으로 닫히지 않는다.
R19/R20 등 기존 세계 진행·결과 계약과의 연결을 명시해야 하며, 임의 스크립트 저장소 수정으로 우회하지 않는다.

### 5.6 공유 자원의 경합

포큐버스는 피해가 들어오는 여러 아군이 하나의 잔량을 소비한다. 고기방패 무기와 웃음 방어구는
한 시체를 서로 소비할 수 있으므로, 소유자별 독립 handler가 모두 보상을 지급하면 안 된다.
공용 pool의 순차 소비, 시체의 단일 claim과 결정론적 중재가 필요하다.
시체 경합 우선순위는 원문 미정이다. 구현 순회 순서로 게임 정책을 대신하지 않는다.

## 6. 기존 로드맵에 적용하는 방향

[실행 모델](../../../../../roadmaps/content_authoring/roadmap/architecture/03_RUNTIME.ko.md)은 이미
구조화 flow, owner×lifetime, 결과, 수정 가능한 효과 속성, 사건 인과관계를 제안한다.
따라서 별도 범용 언어 로드맵을 신설할 필요가 확인된 것은 아니다.

## 7. 설계 충분성을 확인할 시나리오

아래는 향후 수용 시험 제안이며 이번에 실행한 제품 시험이 아니다. 미정 수치는 시험용으로 명시하고
원문에 없는 밸런스·정책을 확정하지 않는다.

1. 나무꾼: 한 시전 3타·같은 적 타격 인덱스·마지막 타격 위력. 스킬 처치와 기본 공격 처치 구분.
2. 풍운승려/미미크리: 다수 대상 뒤 자기 회복 1회와 실제 HP 손실 합계 흡혈을 각각 표현.
3. 루돌타: 빈 투하 회차 소모, 이동한 시전자와 고정 탐색 구역, 공격 속도와 독립된 주기.
4. Hello/허수아비: 자연 만료와 재입력, release 전후 취소, 강화된 정확한 기본 공격의 지연 처치.
5. 여왕/늑대 탈/미미크리: 사본 Run 횟수, 사본 형태, 직원 Run 부활 기록을 이전·재배치·Retreat에서 구별.
6. 포큐버스/고기벽: 공유 잔량 600에서 피해 400·350을 처리, 손상 구간 분리와 실패 시 부분 소비 방지.
7. 나비/포자: 빈 타일의 스택도 포함, 원천 A/B 감염 분리, 같은 전파에서 신규 감염의 즉시 재전파 금지.
8. 마탄: 직전 적을 죽인 경우에만 다음 타격 증가가 달라짐. 집계 입력 순열 시험과 공간 충돌 순서를 혼동하지 않음.
9. 나비 연쇄/흉탄: 서로 다른 새 사망은 이어지고 같은 사망 재처리는 막힘. 지연 뒤에도 출처·세대 보존.
10. 흑조/짚 완충: 특정 감면량만 축적, 패링된 타격의 반사 중복 없음, HP 손실 없는 쉴드 피격은 완충 미소비.
11. 두건/팔찌: 선택 도중 대상 소실·취소, 사용 가능한 입력과 확정 시점, 비용과 결과의 원자적 처리.
12. 선물자루/주시 증폭: 피해 범위만 변경하고 회복·탐색·상태는 보존. 최초 스택 부여만 증폭.

새 성능 숫자를 여기서 정하지 않는다. 기존에 합의한 실험실·모드 검증 및 안전 설정/관측 계획을
소비하며, 20분 시험과 안전 초과에 따른 자동 스킬 취소를 추가하지 않는다.

## 8. 다음 검토 범위와 미정

다음 R06 설계에서는 `입력 종류 → 읽을 값/소유자 → 집계 기준 → 평가 시점 → 실제 소비 경로`를
한 표로 대조하는 것이 적절하다. 읽는 입력과 그룹 키가 정해진 뒤 schema/adapter를 설계한다.
기존 D04 동결 요구와 이번 표현력 목표 사이의 변경 여부를 기록한 다음 구현 지시서를 작성한다.
진영·직원 우선 구현/장비 사본 유예라는 앞선 선택을 사용자가 승인했다고 간주하지 않는다.

현 단계의 검토를 끝내기 위해 새 gameplay 결정을 요구할 필요는 없다. 다음 항목은 해당 기능 상세
설계에서 필요할 때 질문한다: 시체 경쟁, 사건 인정·동시 순서, 수치·stack 정책, 입력 취소/타임아웃,
부활/변태의 보존 범위, 타일/유닛 stack 소비, 사용자 보류된 보호막 범위·식 등.

최초 검토의 변경 범위는 이 검토 메모 하나였다. 후속 §9 합의는 로드맵 현황에도 연결한다.
콘텐츠 원문·동결 계획/증거·게임 소스를 변경하지 않는다.
제품 빌드·회귀·성능 시험·동결 타깃 currentness 재검증을 수행한 것으로 주장하지 않는다.

## 9. 후속 사용자 합의 — 본편 전용 기능과 공개 작성 기능의 분리

사용자는 두건·래티씨아·흉탄의 매력을 보존하기 위해 본편에 필요한 전용 시스템을 허용하고,
어려운 시스템의 내부를 실험실 제작 도구에 개방하지 않는 방향을 채택했다.
기능 축소에 앞서 공개 작성 범위를 줄인다. 이는 모든 공식 콘텐츠를 전용 코드로 만들라는 지시가 아니다.

- 공통 피해·회복·상태·출처·수명·결과 처리 기반은 본편과 모드가 함께 사용한다.
- 고유한 진행 제어는 필요한 본편 전용 모듈로 구현할 수 있다. 별도 피해 엔진이나 검증 우회 경로를 만들지 않는다.
- 실험실에서 실행·시험·관측할 수 있다는 것과 내부 동작을 편집·재조합할 수 있다는 것을 구분한다.
- 모드 제작자는 공개 기능 범위에서 엔진 수정 없이 새 스킬을 작성한다. 공개하지 않은 내부 연산의 임의 호출은 지원하지 않는다.
- 전용 기능의 범용화는 실제 재사용 필요와 검증 가능성이 생겼을 때 검토하며, 지금의 필수 완료 조건으로 두지 않는다.

초기 분류 후보는 두건의 창별 조준/정지 진행, 래티씨아의 관계망 활성화, 흉탄의 사망 위치·방향·세대에
따른 분기다. 공통 투사체·피해·설치물까지 함께 비공개로 묶는 것은 아니다. 정확한 경계는 상세 설계에서 정한다.

기존 [정책 U01·U03·U06](../../../../../roadmaps/content_authoring/roadmap/POLICY_GATES.ko.md)과의 관계:

- U01의 콘텐츠별 전용 실행 코드 금지는 **공개 기능으로 지원한다고 약속한 조합**에 적용한다.
  본편 전용 기능까지 모두 범용 데이터 작성으로 표현해야 한다는 해석은 이번 합의로 변경한다.
- 공식 콘텐츠의 표현력 대조는 공통 기능/전용 기능/미지원으로 구분한다. 전용 기능의 실행 성공을
  제3자의 공개 기능 재조합 성공으로 계산하지 않는다. R21/R22 상세 인수 기준에 이 구분을 반영해야 한다.
- U06의 공식 콘텐츠 추가·변형·교체 및 획득 경로 변경 권한은 철회하지 않는다.
  공식 스킬을 공개 기능으로 작성한 새 스킬로 교체하는 것과 전용 모듈 내부를 수정하는 것은 구별한다.

남은 설계 권고는 **완성된 공식 스킬의 재사용과 명시적으로 공개한 조정값만의 변경**을 지원하는 것이다.
어느 전용 스킬을 어떤 실행 주체에서 재사용할지, 어떤 수치·구조를 변경할지는 지원 계약과 시험을
확인한 뒤 기능별로 명시한다. 모든 전용 스킬의 무제한 재사용·내부 편집을 승인한 것으로 해석하지 않는다.

현재 R 순서·의존성과 R06 WP02 부분 구현 상태는 유지한다. 다음에는 §8의 D04 요구 대조표에
공통 작성 기능과 본편 전용 소비 경로의 구분을 추가한다. 공개 범위를 줄였다는 이유만으로 D04의
동결 요구를 삭제하거나 완료로 표시하지 않는다. 필요한 계획 변경과 구현 지시서는 별도 검토한다.

## 10. 후속 합의와 모델 설계

사용자는 §9의 완성된 전용 스킬 재사용·명시적 조정값 공개 권고를 채택했다.
이후 부분 구현을 계속하기 전에 **스킬 모델을 먼저 정하고 대표 콘텐츠로 검토한 뒤 모델에 맞춰 구현**하는 순서를 선택했다.
따라서 다음 작업을 곧바로 D04 구현 지시서 작성으로 해석하지 않는다.

[스킬 모델 기준안](../../../../../skills/skill_authoring_model.ko.md)에 공통 구조·전용 모듈 계약·대표 7종·정적 시나리오를 모았다.
래티씨아의 연결망은 이번 모델 검토 중 사용자 결정에 따라 공격 가능한 친구만 공격·소비하고 나머지는 유지한다.
그 밖의 미정 gameplay와 모델의 기술 제안을 모두 사용자 승인으로 취급하지 않는다.
모델과 기존 동결 요구의 차이 대조 및 필요한 계획 변경 뒤 R06 구현 지시서를 작성한다.
