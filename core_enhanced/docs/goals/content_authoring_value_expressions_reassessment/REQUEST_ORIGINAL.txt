  R06의 기존 산출물을 보존하면서 P2G-00부터 새로 검토하고, 기존 결과와 비교하여 더 나은 구현 계획으로 최종 취합해줘.

  이번 요청은 계획 전용 bounded_pipeline이다. 필요한 P2G-00부터 P2G-60까지 수행하고, 필수 검증과 계획 인계를 완료하면 정상 종료하라. GEX 인수·activation·게임
  구현·완료 감사는 시작하지 않는다.

  2. P2G-00부터 시작하는 방법

  기존 Working Policy와 immutable artifact를 덮어쓰거나 초기화하지 않는다.

  이번 R06 재검토를 위한 별도 Working Policy Document와 새로운 identity·미점유 경로 생성을 승인한다. 경로는 core_enhanced/docs/goals/ 아래 P2G 규칙에 맞게 정하
  고, 기존 R06 문서와의 재검토·최종 취합 관계를 기록하라. 같은 요청의 재개에서는 새 문서를 반복 생성하지 않는다.

  P2G-00에서는 요청·승인 범위·기존 자료의 원문 또는 정확한 참조를 고정한다. 기존 정책의 의미 판단과 코드 검토는 각각 해당 후속 단계에서 수행한다. 이미 결정된
  정책이나 code_reviewed 상태를 새 초기 Working Revision에 그대로 주입하지 않는다.

  기존 문서·검토·검증 결과·실패·미완료 기록은 삭제·이동·덮어쓰기 없이 보존하고 비교 자료로 사용한다.

  3. 단계별 재검토와 비교·취합

  각 단계는 현행 P2G의 진입·종료 조건에 따라 다시 수행한다. 기존 단계가 완료됐다는 이유만으로 새 검토를 생략하거나, 새 문서라는 이유만으로 기존 결론을 폐기하지
  않는다.

  기존 결론은 현재 요구사항·코드·의존성·검증 근거로 재평가한다. 유효한 조사와 근거는 현재성을 확인하여 재사용하고, 부족하거나 달라진 부분에 검토를 집중한다.

  관련 단계의 기존 기록 안에 다음을 연결하라.

  - 기존 결론과 정확한 근거 위치
  - 새 검토에서 확인한 사실
  - 유지·보완·교체·제외 판단과 이유
  - 영향받는 요구·소비자·설계·시험
  - 최종 채택 내용과 소유 artifact

  기존 사용자 합의는 승인 근거로 존중하고, 기존 AI의 해석·제안·위임 결정은 그 근거와 적용 조건을 확인한다. “더 나은 계획”을 이유로 사용자 정책을 임의 변경하거
  나 요구를 축소하지 않는다.

  기존 9개 요소라는 숫자를 맞추는 것을 목표로 삼지 않는다. 실제로 분해·병합이 필요하면 P2G의 정상 절차와 대응 관계를 통해 처리하고 누락 없는 coverage를 검증한
  다.

  단계마다 하나의 검증된 결과를 current로 선택하라. 서로 모순되는 두 계획을 병렬 최종본으로 남기거나, 서로 다른 basis의 artifact를 섞지 않는다. 기존 문서에는
  없는 새 내용을 과거 결론처럼 소급 기록하지 않는다.

  4. 구현 계획의 품질

  후속 구현 모델이 사용할 수 있도록 다음 내용을 구체화하라.

  - 변경 파일·주요 symbol과 책임
  - 주요 타입·입출력·공유 계약
  - 처리 순서와 구현 순서
  - 상태 소유·수명·저장·복원·취소·오류 처리
  - 기존 코드 재사용·교체와 관련 소비자 전환
  - 시험 입력·기대 결과·실패 경계·실행 수단
  - 선행 조건과 구현 전 준비 점검

  R06의 식 처리, snapshot/live, Attack/SpellPower·무기 성장, resource/result 참조, preview/explain/save/cache 경계를 함께 검토하라.

  핵심 알고리즘·공유 계약·시험 기대값을 일괄적으로 “구현자가 결정”으로 남기지 않는다. 선행 구현이나 실제 관찰이 있어야 확정할 수 있는 사항은 이유·담당 owner·확
  인 조건을 명시한다. P2G-60 완료와 구현 준비 완료를 혼동하지 않는다.

  5. 원본 보존과 인계 기준선

  기존 비교 자료는 정확한 revision·파일 해시와 원본 위치로 식별한다. 변경 중인 다른 작업자의 파일이 있으면 일관된 관찰 범위를 확보하고 충돌하는 쓰기를 하지 않
  는다.

  계획 종료 시 다음을 기존 인계 기록에 연결하라.

  - exact Final Freeze·Phase Plan·Goal Set·Handoff
  - 단계별 검증 결과와 기존 대비 주요 개선점
  - Git branch·HEAD·status와 관련 파일별 SHA-256
  - manifest 자체의 해시
  - 비교·복원이 가능한 원본 또는 패치 위치
  - 미결 설계·선행·제약과 다음 owner

  dirty·untracked 파일은 HEAD만으로 복원된다고 가정하지 않는다. 해시만 남기지 말고 실제 이전 내용을 읽을 수 있는 원본을 보존한다. 기존 유효한 보존 자료는 재사
  용한다.

  계획 종료 시점의 기준선과 후속 구현 직전 기준선을 구분한다. 구현 모델이 mutation 전에 현재 상태와 대조할 수 있도록 안내한다.

  6. 진행과 종료

  통상적 정책 판단과 기술적 계획 선택은 현재 AUTORUN/P2G의 위임 조건 안에서 결정·기록하고 진행한다. 단계 전환마다 승인을 다시 묻지 않는다. 사용자 선택이 필요한
  정책 변경이나 해결할 수 없는 필수 근거 문제가 있을 때만 해당 규칙에 따라 질문·중단한다.

  기존 산출물이나 현황의 더 넓은 실행 지시보다 이번 요청의 계획 전용 범위와 종료점을 우선한다. 현재 인수·현황에는 새 재검토 문서와 종료점을 연결하되 과거 실행
  기록·formal artifact는 보존한다. P2G/GEX 본문·검증기·AGENTS·전역 설정은 수정하지 않는다.

  필요한 P2G-60 종료 조건, 기존 대비 비교·취합, 상세 설계와 기준선 인계를 모두 마치면:
  “R06 P2G 재검토·계획 인계 완료 / 구현 요청 대기”
  로 보고하고 이번 계획 Goal을 완료하여 종료하라.

  최종 답변에는 최종 계획과 Handoff 위치, 기존 대비 개선점, 실제 검증 결과, 남은 제약, 다른 모델이 사용할 구현 요청 예문을 제공하라.

  R06 게임 구현·감사가 남았다는 이유로 계속하지 않는다. 자동 재개·컨텍스트 압축·일반적인 “계속”·모델 변경으로 GEX에 진입하지 않는다. 구현은 사용자가 명시하는
  별도 요청에서만 시작한다.
