## Completed Experiment Coverage

- Confirmed the existing Event scene graph is reusable as a VN graph source.
- Confirmed the existing Event session/runtime is not global enough for HQ/map/loadout/battle overlays.
- Confirmed current presentation authoring is single-speaker and must change for multi-character scenes.
- Confirmed battle VN cannot depend only on state snapshot because live battle transport is `battle_update` based.
- Confirmed the server root snapshot wrapper flattens `RunSnapshotDto`, so root-field changes must be covered by server snapshot tests.
- Confirmed Phase 0 completion baseline: current code has no global VN DTO/runtime/command; Event node and VN-like presentation are still coupled through selected Event state; battle VN delivery remains undecided pending Phase 5 transport work.
- Confirmed Phase 1 contract skeleton: root `visual_novel` exists and serializes as explicit null when inactive, while Event-node state remains separate and is not copied into a dual VN display source.
- Confirmed Phase 2 Event-node schema/runtime refactor: `script_ids[]`, scene `reward_effects`, choice `immediate_effects`/`staged_effects`, and event-started combat reward commit policy are implemented and covered by focused tests.
- Confirmed Phase 3 policy direction: VN uses dedicated graph and trigger catalogs, explicit text/background/speaker-position enums, checkpointed active/queued sessions, separate trigger history, and no Event-node shortcut trigger fields.
- Confirmed Phase 3 implementation backbone: `VisualNovelDefinition` live data loads through `GameDataBase`, active VN sessions project to root `visual_novel`, and active/queued VN runtime state rewinds through run checkpoints.
- Confirmed Phase 4 command/gating behavior: global VN commands advance/select independent of Event-node content, blocking VN gates background commands in core, and non-blocking VN keeps background actions while adding VN progression commands.
- Confirmed Phase 5 battle transport behavior: battle-time VN uses `battle_update.visual_novel`, VN progression during active battle uses battle-update side-message transport, and blocking battle VN pauses live tick simulation.
- Confirmed the inactive `visual_novel` battle transport shape through a real WebSocket smoke probe against a live server.
- Confirmed Phase 6 cannot start safely without user policy decisions for trigger repeat, consumption, priority, queueing, and battle timing.
