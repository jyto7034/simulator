## Blocking finding R03-AUDIT-F01

**Required simulation source-byte receipt is absent.** [CRA P05, line 118](../../CODE_REVIEW_001.ko.md) explicitly requires the receipt to contain “content semantic fingerprint와 exact source bytes receipt”. This is consumed by the Goal's reviewed P01–P07 implementation boundary, C03's content receipt, SC04's observation/receipt owner and E03's reproducible public trial. It is an existing R03 obligation, not a later universal causal tracing feature or a new requirement to change the semantic fingerprint.

The actual loader already retains the correct `SourceReceipt` with each immutable generation (`src/game/data/content_pack/mod.rs:138`). `validation_receipt` and `describe` read that same owned receipt (`src/authoring/query.rs:57,113,122,154`). However, `TrialState::initialize_in_scope` serializes `Initial` with only `ContentIdentity`, input hash/size, authority/profile and usage (`src/authoring/trial.rs:666–695`); there is no source receipt. `StepPayload` and preparation-ready likewise lack it. `TrialSession::receipt_documents` emits only those documents. CLI `simulate` directly calls `authoring::simulate` and then emits these receipts; it does not emit the separate validation receipt (`src/bin/author_content.rs:161–175,268–270`). A caller can separately request describe before/after a library trial, but the required simulation receipt and standalone CLI result do not carry that exact byte basis. The CLI process exits after emitting it.
