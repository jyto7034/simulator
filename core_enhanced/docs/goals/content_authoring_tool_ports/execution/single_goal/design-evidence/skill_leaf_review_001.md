## Current baseline and smallest useful delta

At the inspected source, `sim::build_skill_step_commands` is Result-returning and charges its effect scan, each effect, produced commands and effect-target work (S:2012+). Instant and instant/persistent-area repeats have `skill_step_repeat` charges (S:2340,2430,2551). `process_event` charges dispatch and polls after the inner event (S:2596–2610). `EventQueue::push` already charges and admits pending events before growth and refuses enqueue on sticky failure (E:16–23). Do not count those mechanisms as missing.

The inspected P and A files import control but each contains only the post-command `skill_commands_consumed` poll (P:902; A:689). K contains no control calls. Missing leaf families are projectile repeats/candidate construction/impact fanout, tile geometry and target scans, area tick policy/history scans and copies, cast child maps/impact contexts/deferred release, and admission before actual cast/projectile/area creation. A guarded queue and an effect builder run after much of this work has already happened.

The smallest consistent connection keeps the deterministic ID allocators unchanged. Add admission to their actual creators immediately before the first ID counter mutation, and propagate sticky stop to a caller which polls before interpreting a partial count/bool/Option. Private helpers with exactly one caller can instead return Result to avoid fabricated values. In either style, every refused operation remains a poisoned disposable candidate; ordinary calls outside an active scope keep the current ordering and results.

## Tile-area geometry and targets

`valid_tile_area_tiles` A:80–96 is used by instant resolution A:299–341, persistent registration A:446–605, persistent tick A:607+, and usefulness preflight U:124–132. `tile_area_projection_facing` A:65–78 is shared by those paths too. Thus a seam only at command application misses scans used to decide whether a skill is useful or may be cast.

- `TileRangePattern::validate/affected_tiles` (R:61–146) scan authored row characters, locate the anchor, create affected cells, sort and dedup. `TileReachQuery::try_new` validates again, and materialization calls affected_tiles again (R:212–268). With no facing, `is_rotation_invariant` runs up to four projections/sorts (R:150–166). Preflight row count and total valid ASCII cell/byte size before these materializations; reserve/charge the actual number of projection passes and admitted affected-cell upper size. Poll between passes if implementing a narrow checked helper. A one-unit geometry charge misses authored footprint size.
- **Do not inject ordinary control Err inside `affected_tiles` while leaving `TileReachQuery::{contains,materialize_valid_cells}` unchanged.** Those functions use `expect("TileReachQuery stores a validated pattern")` (R:239–268). The small safe approach is admission before constructing/using the validated query in the BattleCore helper, then execute a bounded complete projection. A deeper fallible change must propagate through these exact wrappers; a sticky sentinel with an invariant-breaking error would panic.
- Range membership during `choose_skill_target_by_rule` goes through `is_target_in_tile_range_policy` → `tile_reach_query_for_unit` → `TileReachQuery::contains` (Q:76–107). This also materializes a footprint, even though the caller asks for a bool. Area projection checks alone do not cover this path. Precharge the pattern work at the range membership helper or its skill target caller without changing membership rules.
- `collect_tile_area_targets_at` A:266–297 scans all `units`, filters delivery eligibility, samples a body, and calls `affected_tiles.contains`. Charge visited units and the membership-comparison bound, not only returned targets; admit target Vec growth before push and retain bytewise-ID sorting. Changing the implementation to a HashSet membership lookup could reduce work but is optional and must preserve sorted output/eligibility; no such refactor is required to add a sound bound.
- To retain the present Vec/Option API, a helper can stop and return empty/None on sticky failure, but all direct consumers must immediately poll before treating it as no valid geometry/no targets. `resolve_instant_tile_area_targets` and `register_persistent_tile_area` chain multiple such helpers. In S, `let Some(...) else continue` and registration's false result currently mean normal gameplay; once control is added, insert a poll after the helper and before those decisions or use a Result<Option<_>>/Result<bool> sibling.

Preflight arithmetic should be checked in the active-control path and must not itself allocate a second footprint just to count it. Validated row String byte lengths are enough to obtain a conservative cell upper bound without running `chars().count` a second time. Charge the row walk too. These are logical work/shape bounds, not a measured CPU deadline.

### Nested usefulness cost and deterministic accounting

U is a directly traversed dependency of these target helpers. `skill_has_useful_automatic_cast_target` U:159–234 walks skill steps and can retarget by calling K again with DeliveryStep usefulness. `preview_skill_step_final_damage` U:285–337 folds effects; several payload/usefulness predicates walk effects too (U:385–456). Those calculations precede S's charged effect builder. An outer candidate-unit charge alone does not cover unit × steps × retarget/area-scan × effects work. Either add checks to the shared usefulness helpers or precharge a conservative source-sized block at their skill call sites, preserving the current finite Cast→DeliveryStep relationship and ordinary rule evaluation.

Several scans iterate HashMap values while `.any` and early returns short-circuit. Accepted gameplay tie-breakers currently restore stable chosen IDs, but charging only actual short-circuit visits can expose iteration-order-dependent usage. If reproducible work usage/failure receipts are part of the adopted contract, precharge known collection lengths/upper predicate work deterministically and use in-loop polls only for cancellation, or explicitly canonicalize only the accounting traversal without changing selection semantics. This report does not claim that a numeric work cost model is already frozen or measured.

## Resource accounting facts and failure transport

`control::admit(Resource::RetainedEntities, current, additional, site)` (C:316–374) only checks the provided `current + additional`; it neither tracks live allocations nor automatically totals every runtime container. It records a peak of that supplied request. If the documented retained cap is total runtime entries, callers must supply an aggregate that includes the child structures above. Separate per-container limits can yield a finite product bound but must not be reported as a single global memory cap. Neither is an exact allocator-byte measurement.

`active_projectiles.remove` temporarily detaches an entity; area tick holds a cloned runtime alongside the original; context update holds map and last copies. These lifetime facts affect both admission counts and peak temporary work. Work charge is nonrefundable attempted work, but occupied-size admission must distinguish new insert, replacement, deletion and reinsertion. Keep accounting arithmetic and extra traversal in the active scope so absent-control behavior stays unchanged.

Result conversion is smallest for P's private motion/accept/spawn helpers because their caller set is narrow. Public-within-core Option/Vec/bool helpers can preserve signatures if checks return harmless partial/default values only inside a sticky-failed candidate, and direct parents poll before consuming them. In particular add these polls:

1. S after `resolve_skill_step_context`, projectile dispatch, instant-area resolution and persistent registration, before evaluating normal no-target/zero-count branches or allocating IDs.
2. P advance after fixed motion/acceptance and after enqueue inside impact iteration; P dispatch after each spawn.
3. A after geometry/target helpers, context update and delivery resolution, and before tick rescheduling/history continuation.
4. K finalize/resolve after record/release; K target selection immediately after nested range/usefulness work and before fallback.

The existing S::process_event post-inner poll remains the outer error oracle for P/A void handlers (S:2705–2741); return from recording closures allows normal cause-stack cleanup. No panic-based control flow and no fabricated IDs are needed. A refused gameplay/work/mandatory-output operation discards the candidate under the root owner; an optional trace gap does not use these failure paths.

## Focused validation seams for root (not executed here)

- A projectile repeat large enough to exceed work with zero valid targets must stop even though it produces no command or event; a positive repeated launch must fail before the denied ID increment and must be polled before begin-delivery counts.
- Fixed projectile candidate and prior-hit scans must be bounded with a single advance event; preserve impact ordering by time, distance and ID when allowed. Homing remains a one-target path.
- Large footprints must be admitted before rotation-invariance/materialization, including cast usefulness and range membership. Force controlled failure at these seams without tripping TileReachQuery's validated-pattern expects.
- EveryTick, OncePerArea and OnEnter cases must exercise raw-target/history comparisons and replacement/growth accounting; bounded allowed runs must retain their original hit behavior and IDs.
- Many pending deferred steps with none ready must consume work; a release queue failure must stop and remain sticky before normal finalize/cleanup success. Existing step ordering and damage gates must remain unchanged.
- Replacement of one impact context should not monotonically add permanent map entries; both retained hit-vector copies and temporary clone work remain visible to the selected bound.
- Compare absent-control and sufficiently permissive-control public outcomes/RNG for accepted cases. Optional trace disabled/full/overflow-gap configurations must produce the same gameplay admission/work usage and mandatory result; do not instrument optional trace with the gameplay fuel.

No all-opcode coverage, new-feature completion, numeric performance limit, broad R23 safety or fresh test PASS is asserted. This report gives the remaining narrow leaf seams at the recorded source snapshot.
