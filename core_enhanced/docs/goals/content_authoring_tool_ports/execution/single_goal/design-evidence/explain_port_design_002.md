## Conclusion

The current validated generation already has enough immutable data for a useful complete final inventory, exact final definition/source lookup across the 42 existing DefinitionKinds, actual skill effect/origin explanation, and readonly boss compiled-graph explanation. No second database, retained raw-text copy, reparse, recompilation, runtime forecast evaluator, new mutable port or additional editable operation is needed.

The remaining code delta is an authoring query/DTO adapter, bounded serialization, a single-source enumeration of DefinitionKind for describe, and explicit serialization projection for compiled boss/summoned structures which currently do not implement Serialize. The adapter must label ordinary payloads as resolved definitions and boss payloads as compiled graphs. It cannot promise original authored RON reconstruction, non-winning definition payloads, removed-writer field addresses, or authored node ordinals that were not retained.

GOAL:35–40/44–72 requires the current support descriptor, definition/effect/origin/compiled graph explanation, missing/unsupported rejection and readonly behavior without fake forecasts. PLAN:76–78 and the immutable-metadata design require the actual SourceTable final key/source and unchanged WriterReceipt semantics; compiled index is not authored source position. Those are the boundaries used here.

## Small public surface and ownership

Suggested shape, with names owned by root:

- `AuthoringContent::describe(...)` returns current contract/capabilities, current effect-edit support, supported definition kinds/catalogs, and bounded final inventory from this token.
- `AuthoringContent::explain(ExplainQuery, ...)` takes a strict tagged query such as Definition `{ key }`, Effect `{ site }`, Origin `{ site }`, Writers `{ key }`, or CompiledGraph `{ key }`. Unknown variants/keys or unsupported kind/query combinations are explicit errors. Do not accept arbitrary Rust/JSON-path queries into authority.
- Each response binds `token.identity()` and the exact requested key/site. A borrowed record or transient bounded DTO/JSON response reads `token.database()` and `token.source_metadata()`; no independent owned content registry or cache is built. Output may own bounded strings/bytes needed by a caller, but must not become a parallel database or retained raw-text archive.

The current `AuthoringContent` (AUTHORING:48–59) owns one opaque ValidatedGameData plus validation usage. `ValidatedGameData::database`, `identity`, `source_receipt` and `source_metadata` (DATA:239–263) already return immutable references. No CoreApplication mutation, trial advance, skill invocation, RNG call or file reopen belongs in these static queries. Public CLI should call the same adapter and serialize its actual result; it should not independently interpret support or content.

A source-metadata-unavailable token must be reported as such, not as an empty inventory or guessed source. External successful loader publication currently sets Some(metadata) (CONTENT:137–143); explicit bare fixture generations have None. Querying through AuthoringContent makes normal external metadata available, but an internal invariant check still should not manufacture provenance.

## Describe: exact current support, not parsed future vocabulary

1. `ContentContract::current()` (SCHEMA:18–28) is the actual parser/executor/fingerprint contract. For a particular token, use `token.identity().contract` as its bound value.
2. `PackManifest::SUPPORTED_CAPABILITIES` (SCHEMA:80–86) is exactly `gameplay_catalogs_v2`, `literal_effect_authoring_v1`, `boss_runtime_v1`, `summoned_units_v1`. Keep this list tied to the production validator; do not duplicate it in CLI.
3. `CatalogKind::ALL` (RAW:80–105) has 24 catalog kinds. `DefinitionKind::catalog()` is generated by the raw `definitions!` macro (RAW:142–163), whose invocation has exactly 42 variants (RAW:165–208; mechanically counted for this report). **There is currently no `DefinitionKind::ALL`.** Smallest maintenance-safe delta: generate an associated readonly ALL slice in that same macro. An exhaustive authoring match can then fail compilation when a new kind needs a projection. Do not infer supported kinds from whatever happens to occur in one selected pack.
4. `ability::authoring::EFFECT_SUPPORT` (EFFECT:157–170) is the entire existing editable support descriptor: skill/Instant Damage and skill/Instant Heal. Damage Amount is NonnegativeI32, unit `base damage`, editable=true; DamageType has type DamageType and editable=false. Heal Amount is SignedI32, unit `signed HP delta`, editable=true (EFFECT:121–155). Use the exact serializable descriptor, not a second declaration.
5. `effect_support(op, delivery)` (EFFECT:172–184) returns None for every non-Instant delivery and for operations other than Damage/Heal. `set_effect_amount` (SKILL:258–329) also rejects non-Amount properties, and Target/Delivery belong to the shared action. Explaining an existing projectile/buff/stat effect is permitted read-only; it does not make that combination editable.
6. A raw enum variant is not proof of implemented support. For example BossPatternSelectorData contains PriorityEligible and WeightedEligible, but the compiler explicitly rejects both (BOSS:2576–2605); only the existing compiled FixedSequence behavior should be represented. Do not generate a capability catalog merely by enumerating every parser enum variant.

No generic schema-reflection/field-editor promise is needed. Describe can expose supported content kinds as load/explain kinds and expose editable properties only through EFFECT_SUPPORT. `CatalogKind::official_path()` names the built-in packaging catalog mapping, not the actual selected external source path; actual source comes from immutable metadata.

## Final inventory and writer/origin provenance

`ContentSourceMetadata` (CONTENT:25–50) owns two existing vectors:

- `definitions() -> &[(DefinitionKey,DefinitionSource)]`: final definitions only, in SourceTable's actual final collection order, including a replacement's inherited slot (RAW:566–583).
- `writers() -> &[DefinitionWriter]`: actual resolver WriterReceipt, including non-winning and Remove writers.

`DefinitionKey` has `{kind,id}`. `DefinitionSource` has `{pack_id,source_file,field_path}` (RAW:211–223). Inventory rows can return those exact fields plus `kind.catalog()`; no scan of the filesystem or reconstruction from a displayed path is required. Keep the source row's order if exposing an ordinal, and label it an inventory ordinal; it is not an authored child-node ordinal. Prefer no additional ordinal if the consumer does not need it.

WriterReceipt has only `{ target, pack_id, operation: Add|Replace|Remove, after: BTreeSet<String>, selected }` (WRITERS:19–49). Filter this slice by exact DefinitionKey and preserve its receipt order/edges. `after` means explicit predecessor writers, not a fabricated chronological edit history. Selected Remove can have no final definition, so Writers should distinguish `known target with selected remove` from `unknown target`, while Definition should reject absence from the final inventory. Do not serialize a default empty DB container as a removed definition.

The final source can be joined with `token.source_receipt().files` by exact captured path and pack ID to expose its original byte_count/sha256 (RECEIPT:10–22). No current file content is needed; moved/changed files after publication do not rewrite A's explanation.

**Actual metadata gaps:** WriterReceipt does not retain source_file, field_path, the manifest operation ordinal or nonwinning payload. SourceReceipt records file-level pack/path/bytes/hash only. Therefore a nonwinning or removed writer's exact definition location/body cannot be reconstructed from this metadata; return only the actual writer fields, and unknown location as unavailable. A final winner does have source_for(key). This is a concrete metadata limit, not a reason to create a second raw archive. The complete original PackManifest (namespace/dependencies/required-capabilities/etc.) is also not retained as a queryable authored object; the semantic identity binds it, but hashes cannot reconstruct those fields. Describe uses current supported capabilities, not an invented selected-manifest capability receipt.

## Effect and origin explanation

`SkillDatabase::effect(&EffectSite)` (SKILL:223–233) is the exact existing lookup. EffectSite contains ActionSite `{definition_id,action_id}` and `effect_id` (EFFECT:11–23). It finds the actual skill, step ID, and effect ID, without selecting by tags or ordinal.

A useful Effect response reads:

- containing `SkillDef.id/name/kind/cast_targeting/focus...` and containing `SkillStepDef.id/delay_ms/target/targeting/when/repeat/delivery/presentation` as needed (ABILITY:722–761), clearly separating shared action fields from effect-edit properties;
- `AuthoredSkillEffect.id/tags/origin/op`, `literal_amount()`, and `effect_support(&effect.op,&step.delivery)`;
- `effect.source()` as an explicit provenance sidecar, plus final DefinitionSource for the containing skill and matching source-file hash when available.

This explicit sidecar is necessary: AuthoredSkillEffect.source is serde(skip) (EFFECT:45–55). Serializing SkillDef or AuthoredSkillEffect alone drops it. `bind_definition_sources` creates actual EffectSource `{source_file,site,field_path,origin_definition_id,origin}` using retained selected skill root plus real step/effect indices (SKILL:185–218; RAW:920–934). Reuse it; do not append inferred indices to a raw path in the query adapter.

Origin is authored attribution, not an executed inheritance operation or runtime grant. `EffectOrigin::Original` resolves origin_definition_id to the containing skill. `Added { source_definition_id }` names another current Skill definition; validation checks that skill exists (SKILL:711–726). Origin query can return that exact ID and its final DefinitionSource, plus the containing effect's current source and writer receipt. It cannot claim a specific origin action/effect: those IDs are not in EffectOrigin. Do not infer a chain from matching effect IDs/tags, assume the body was copied, or fabricate a future composition/relic instance. Two effects with the same tag remain separate exact sites.

`EffectPredicate/EffectSelection` exist for matches_effects, but they are not needed for the minimum exact explain query. If root later exposes a read-only selection helper within this approved scope, it must preserve the existing SameEffect versus EachExists meaning; it does not imply new execution or edit support. Unknown definition/action/effect must be an explicit not-found error rather than a successful empty effect.

## Compiled graph DTO: exact fields and safe references

`BossRuntimeDatabase` keeps compiled vectors/maps and public immutable getters, while authored catalogs exist only under test/debug/test-fixtures (BOSS:782–856). Default release therefore must read compiled fields. `CompiledBoss*` and `CompiledSummonedUnitDefinition` are Debug/Clone, not Serialize, at this snapshot. Avoid using Debug strings as the public graph format or adding a recursively expanded Arc serialization of the whole DB. Create small explicit borrowed/owned DTO projections that use stable definition/node IDs and references to other graphs.

### Pattern

`get_pattern(BossPatternId)` returns the existing Arc<CompiledBossPatternDefinition> (BOSS:809–813). Project:

- id; parameters `{id, parameter_type}`; outcomes; entry_state_index plus the corresponding states[index].id; states `{id,tasks,transitions}` (BOSS:521–552).
- Each task variant and its actual fields (BOSS:554–590): RouteCombat id; AcquireTarget id/query; MoveToTarget/RejoinForwardRoute id/timeout; Wait id/duration; Summon definition_id/count/batch_handle/placement/occupancy/on_insufficient_space/route/lifetime/removal_signal; EmitSignal signal_id.
- Durations and queries are Literal(value) or Parameter(index) (BOSS:607–615). Show the compiled index and, by checked lookup in parameters, the actual parameter ID. Do not invent a resolved runtime value when only a parameter slot exists.
- Transitions retain id/priority/condition/target/loop_guard (BOSS:619–638). Resolve State(index) to states[index].id and Outcome(index) to outcomes[index]; ContinueState stays that actual variant. Loop exhausted target follows the same mapping.

### Actor behavior

`get_actor_behavior(BossActorBehaviorId)` returns CompiledBossActorBehaviorDefinition (BOSS:642–646,815–822). Project id, entry node index/ID and nodes:

- State: id, actual task list and transitions `{id,priority,condition,target_node_index/ID}`.
- PatternCall: id, ordered candidates `{pattern_id, argument_frame, cooldown}`, repeat, outcome routes `{pattern_id,outcome_index/outcome_id,target_node_index/ID}`, no_eligible_node_index/ID (BOSS:676–711).
- Each candidate already holds `pattern: Arc<CompiledBossPatternDefinition>` and `argument_frame: Arc<ResolvedBossArgumentFrame>`. Reference the pattern by ID; map frame.values positions to that pattern's parameter IDs for display. Values are already ResolvedBossParameterValue::DurationMs or TargetQuery (BOSS:536–544). Show actual values; do not execute selection or forecast future eligibility.

### Encounter

`get_encounter(BossEncounterRuntimeId)` returns CompiledBossEncounterDefinition (BOSS:714–750,824–831). Project id, actor_slots, entry phase index/ID; phases with id, actor behavior bindings `{actor_slot_index/actor_slot_id,behavior_id}`, and transitions `{id,priority,condition,timing,target_phase_index/ID}`. References avoid repeating each actor/pattern graph for every binding. Compiled actor bindings are explicitly sorted by slot index (BOSS:3037), so their vector position is not evidence of an authored array ordinal.

### Summoned unit and signal

`get_summoned_unit` returns CompiledSummonedUnitDefinition with id/base_uuid/display_name/combat_profile/max_alive/max_total/on_summoner_removed/actor_behavior_id (SUMMON:70–80). UnitCombatProfile already implements Serialize (PROFILE:392–415). This is a compiled definition, with a behavior reference, not a runtime spawned unit or graph of actual events. BossSignalDefinitionData only has id (BOSS:68–72), and `declares_signal` confirms the compiled declaration set; this can be explained exactly without resurrecting a removed authored catalog.

For all graphs, root DefinitionSource is exact and node/task/transition IDs are real compiled semantic identities. A `compiled_index` is a compiled reference only. **Do not produce source paths such as `source.field_path + ".states[index]"` from compiled ordinals.** The graph has no retained authored child source ordinals, and compiler transformations/sorting make that unsafe. Checked `.get` can report an internal explanation inconsistency if an index is invalid; never silently generate a false ID or panic in a query.

These graph explanations report structure/conditions/values present in the compiled catalog. They do not evaluate a future battle, perform targeting, claim a transition happened, provide a damage forecast, or introduce future R06/Rxx chain gameplay.

## Readonly, bounds and narrow validation seams

Use a separate query operation/bounded output owner without advancing TrialSession state, RNG, revision or its accepted input/receipt. Final inventory and writer scans are O(final definitions/writers); public getters use existing indexes or bounded vector finds. GameDataBase initializes normal indexes at publication (DATA:940–961), but query code should not promise zero allocations merely because it borrows data. Graph traversal should visit only the requested graph and emit references, avoiding repeated recursive Arc expansion. Finite query/output limits must reject an oversized mandatory explanation explicitly; do not silently truncate it into a complete-looking answer.

Optional runtime trace is unrelated to these static payloads. Its overflow remains gap-only and cannot change gameplay work/admission or mandatory trial receipt. A static explanation does not manufacture runtime occurrences to fill missing optional trace.

Useful root validation seams, none executed here: external replacement/remove inventory/source hash consistency; final-membership checks on singleton collections; 42-kind exhaustive adapter against isolated valid external content; R01 descriptor positive/unsupported negatives; exact effect source sidecar/Added origin lookup; release compiled Pattern/Actor/Encounter/Summoned queries without fixture APIs; graph reference consistency and unavailable authored ordinal honesty; changed/deleted original files after load leave A explanations stable; API/CLI byte-semantic parity; repeated query then same public command/clock continuation unchanged; unknown key/query and bounded-output error leave token/session unchanged. Historical PLAN test counts are source text read, not this helper's execution or fresh PASS.

The only identified data gaps are listed explicitly above. They do not require broad new editable support or a parallel authored database to fulfill the minimal current explanation contract.
