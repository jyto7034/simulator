## Recommendation

Preserve all existing raw public fields and native HashSet Clone semantics. Use one tiny private insertion-history sidecar for BattlefieldLayout.static_obstacles. The seven other named set fields have a source-backed tombstone-free invariant in the fresh opaque application flow; count their current capacity through an explicitly named tombstone-free bucket envelope. No generic OwnedHashSet framework is necessary for these owners.

This is an owner/provenance claim. It is not a property of arbitrary std HashSet values, nor of arbitrarily mutated public VisualNovelTriggerRuntimeState values. Public BattlefieldLayout can be mutated with remove_static_obstacle, so the sidecar makes its private accounting valid even beyond the narrower application flow.

## Exact native bucket model and clear caveat

Root's exact local Rust 1.91.1 manifest requests hashbrown0.15; its lock pins 0.15.5 and archive checksum 9229cfe53dfd69f0609a49f65461bd93001ea1ef889cd5529dd176593f5338a1. The locally available archive has that checksum. No alternate installed hashbrown version was substituted.

The exact archive member hashbrown-0.15.5/src/set.rs contains HashMap<T,()> (114–115), clones that map (118–127), and delegates capacity/retain/clear/insert/remove (269–270,368–372,430–431,1092–1093,1175–1179). Its SHA256 is cd7d05424d731f0ad5eb4cf255e9a4d970b96fb68398cc904481af942a106fb4. This is an in-memory archive read, not an extracted or installed dependency.

Pinned raw/mod.rs shows:
- capacity is items + growth_left, explicitly a lower bound (1277–1284).
- erase may write DELETED without increasing growth_left (3095–3151).
- clear_no_drop fills EMPTY and restores full growth (3053–3058).
- **clear returns immediately when len==0 (850–854). A set emptied by deletion can retain tombstones even after clear. Clear is not a universal history reset.**
- native Clone allocates the source bucket count and copies its control/table state (3155–3184; the Copy specialization at 3271–3282 bulk-copies bucket records). len is insufficient even for immutable/deletion-free tables with spare allocation.

For a proven tombstone-free set, current capacity is full usable capacity and therefore a valid input to a conservative bucket envelope. Reusing the existing checked envelope is sufficient: E(0)=0; otherwise E(c)=max(16,checked_next_power_of_two((checked(c*2)*8)/7)). The factor-two conservative form matches MapCloneHistory::bucket_bound (owned_collections.rs:26–37); it is not claiming capacity itself equals physical bucket count. A smaller source-derived tombstone-free formula is possible but not needed for the proposed seam.

For a history-tracked obstacle set, use P equal to cumulative insert-attempt credit since empty construction, surviving clear/removal; apply the same E(P). reserve_rehash_inner requests at most twice the insertion credit before load-factor rounding (raw/mod.rs:2627–2677), and capacity_to_buckets handles small tables and 7/8 load-factor rounding (103–159). Arithmetic failure is an unprovable admission bound and must reject the opted-in fork before Clone, while ordinary mutation remains non-failing/saturating as existing MapCloneHistory::inserted does. A duplicate insert can harmlessly overcount; do not perform a second lookup or rehash merely to avoid that credit.

A set that starts fresh and only inserts/clears remains tombstone-free: clear on an empty table preserves an already-good state; clear on a nonempty table restores EMPTY. This induction does not apply to a set with unknown imports or any deletion-capable untracked path.

## Minimal implementation seams; proposed, not implemented here

1. Add a private static_obstacles_clone_history: MapCloneHistory to BattlefieldLayout. Initialize beside the empty set in new. In add_static_obstacle, validate the tile first, record one insertion credit, then call the unchanged native insert once. remove_static_obstacle and clear leave the history intact. Existing derived Clone copies both the native table and history. Public constructors and method signatures, the HashSet representation, ordering, hasher and cloning behavior stay unchanged. BattlefieldLayout has no Serialize/Deserialize implementation in the inspected owner, so there is no new serde migration to implement here.
2. Expose a crate-private owner-level clone accounting helper that sums the immutable valid_tiles envelope and the obstacle history envelope. Do not expose a raw mutable set escape. The helper should name the tombstone-free precondition for valid_tiles explicitly.
3. For VN, ScenarioRuntimeState, boss runtime/pattern and employee attempts, keep the native fields. Private owner visitors may apply the tombstone-free capacity helper with the specific source invariant above documented at the call. If new retain/remove/raw imports are introduced later, revise the proof or add owner history before relying on that call.
4. Count table bucket records separately from each occupied key's recursively owned data. Position and UnitInstanceId do not justify treating all String-backed trigger/group/signal/handle keys as one primitive record. This report identifies table storage seams; key-child accounting remains the structural visitor's responsibility. Charge/poll before native Clone using the existing authoring control, rather than cloning to measure.
5. Sidecar history is not gameplay state: do not include it in any new Debug/equality/serde/fingerprint projection. Keep the default outer Clone::clone_from replacement behavior if the sidecar owner later acquires a custom Clone implementation; do not silently replace it with underlying native clone_from without covering a possibly larger retained destination allocation.
6. No global cache, allocator introspection, V6 substitution, guessed private-layout byte multiplier, native HashSet-to-new-set compaction, or public raw-field type change is required.
