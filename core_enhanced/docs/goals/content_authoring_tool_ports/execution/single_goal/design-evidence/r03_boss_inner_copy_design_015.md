## Remove temporary deep copies with detached immutable owners

- **Phase/selected phase transition:** B:440–442 clones a transition containing owned ID/condition data, although it then uses only Copy timing and target_phase_index. Extract those scalars. B:526 clones the entire phase, including its ID, actor-binding Vec and transition Vec. Instead retain a local Arc clone of self.definition and borrow its phase while mutating self. Selected behavior clones at 535/549 are Arc handles. Both surrounding functions already return Result.
- **Control node:** B:1082 clones the entire CompiledBossControlNode. Its State variant owns task/transition Vecs; PatternCall owns candidate/cooldown/outcome-route data (D:675–711). Keep the existing detached behavior Arc at 1077, borrow nodes.get(...), match references, copy repeat/no_eligible_node_index scalars and pass the borrowed candidate. enter_control_node already uses that arrangement at B:582–604. Keep validation order: current code validates behavior/node before taking the active-pattern branch. Keep enumeration and max_by_key tie behavior unchanged.
- **Active pattern and transition:** B:1242 and 1291 copy an ActiveBossPattern, not merely its immutable definition. They copy active tasks, loop_counters, batch_handles and cleared_batch_handles (B:127–144,231–233). Borrow the current active pattern to choose the winner and capture scalar indexes/activation plus local definition/frame Arc handles. Release the self borrow; then borrow selected transition and next-state tasks from that local definition for resolve_loop_target/admit_state_tasks. This removes both full pattern copies and transition.clone at 1266. Outcome routing can compare with the borrowed local definition.id, eliminating pattern_id.clone at 1318.
- **Preserve cancellation semantics:** cancel_current_state(false) clears active tasks while retaining pattern metadata; true removes the pattern (B:1716–1747). The detached Arc must outlive that cancellation. ContinueState must consume the selected transition's condition exactly as before. CompiledBossPatternTransitionTarget contains only usize/unit variants (D:627–632); its clones at B:1358/1370/1373 allocate nothing. They can remain, or be replaced with equivalent scalar matching. The loop-counter key to_string at 1367 is a separate retained String allocation that needs admission.
- **Target query:** resolve_target_query at B:2163–2176 clones literal/frame query Vecs even though admission only reads the query. Return Result<&'a BossTargetQueryData, GameError>, with both value and optional frame carrying 'a. They come from the detached definition/frame owners; retain current invalid-parameter errors. Query filters/order_by are owned Vecs (D:127–135), so this removes real work.
- **Route cells:** B:1431–1439 clones a Vec used only for reading by poll_actor_once (:968), select_rejoin_route_index (:1408), and boss_movement_directive (:2000). Use fn route_cells_for_actor<'core>(&self, core: &'core BattleCore, actor_index: usize) -> &'core [Position]. Actual storage is exclusively under core.units or core.scenario; self contributes only the actor's unit ID. Tying the output to core alone allows poll_actor_once's later mutable self borrow. Preserve fallback and authored order. Geometry/path scans remain separate work.

Arc clones above never duplicate compiled graphs. Existing controlled_clone(&arc), if required by accounting, visits the handle only; it does not require a new CloneShape implementation for the compiled pointee. activate_actor_behavior currently needs only behavior.entry_node_index (B:559–571), so accepting that Copy scalar can also remove redundant Arc transfers.

## Retained task and summon state still needs admission

**Task admission (B:617–814):** active_tasks allocates before the loop. Every task retains an owned task ID. Summon additionally retains definition ID, batch handle, optional zone/route String, optional occupancy Vec and removal-signal ID; its request_id is formatted before these clones at 758–774. Count/time/lifetime mode are fixed values (D:230–281). These owned fields cannot simply borrow the temporary task reference without changing the runtime representation.

Complete a borrowed projection for the selected tasks/output storage and generated request-ID bytes before native allocation/copy, or admit each actual allocation separately before it occurs. Do not measure an already constructed task. Existing B:260–295 native visitors cover active task/view fields. admit_state_tasks/admit_pattern already return Result, so controlled source-field copies can propagate with ?. Keep the checked activation allocator and exact request string. The cooldown group ID retained at B:1209 also needs its own admitted copy; definition/frame clones at 1219–1220 are Arc-only. Map growth and effect/Vec construction remain distinct admissions.

**Task views (B:1494–1538):** summon_task_views clones each pending summon payload into a Vec, then sorts request IDs. The consumer S:152–174 moves those views into the pending map after registering triggers; persistent ownership is required across later self mutation and boss-pattern cancellation. Minimal signature change: Result<Vec<BossSummonTaskView>, GameError>, with all selected payload/output projection completed before native copies, sorting work accounted separately, and a final poll. Consumer already returns Result: transpose the optional Result and default only when the runtime is absent.

summon_request_is_active need not create or sort any owned view. Traverse borrowed actors/pattern/state/tasks and preserve existing eligibility (unit/behavior/control/pattern present, Summon kind, task.result absent) and all six identity comparisons: request, actor runtime key, behavior/pattern/state/task activation IDs. If scan control becomes fallible, return Result<bool> and propagate through the already-fallible S:177 caller; never turn interruption into false/inactive.

**Pending settlement (S:177–238,292):** a detached PendingSummonRequest is needed because settlement mutates self. Control the map-value clone at 182, then borrow &pending.view locally instead of cloning it again at 185. End that borrow before moving pending to commit_summon_batch. The compiled summoned definition at 225 and behavior at 473 are Arc-only.

**Batch keys and clear notification:** B:1583 retains a cloned batch ID in a native map; B:1614 clones it into cleared_batch_handles. The former function already returns Result. note_summon_batch_cleared can return Result<(), GameError>, propagated by reconcile_summon_batches (S:505,624). Its caller currently marks cleared_emitted before invoking it, so failure requires outer rollback or reordered admission; do not swallow that error as successful clearing.

**Summon route/zone consumers:** S:321–338 copies a route into an owned ScenarioSpawnGroup used across mutable spawn callbacks. That actual owned route needs controlled_clone(&route.cells) in the existing Result/transpose path. ## Failure ownership and minimal propagation

plan_next already controlled-clones its runtime at B:395. A new error in phase/node/pattern/task work drops local next and effects; it must not mutate the original runtime. run_boss_runtime_boundary then owns a complete staged BattleCore (B:1859–1897), including summon processing, and replaces self only at 1888.

S:296–503 also captures before for commit_summon_batch, but **not every Err restores it**. Explicit restore branches cover selected trigger/spawn failures; bare ? at task-result update (461–465), actor attachment and recording can escape after mutations. A new route/key-copy error must not be described as universally restored by this inner function. The outer staged boundary is the actual complete rollback owner; otherwise wrap the entire inner operation and restore before on every Err.

Task signal emission has an adjacent retained key clone in note_signal_emitted (B:1627–1630). If connected here, either pre-admit that second key in the fallible planner or make the private note/plan.commit chain return Result, propagated at B:1894. The final staged replacement currently has no explicit final control poll; add one before replacement when completing these control connections. Do not introduce a poll halfway through mandatory restoration or refund shared attempt accounting.

These proposals preserve ordinary values/order while removing temporary copies or adding opt-in admission to real copies. They do not prove all boss scans, queues, constructors, imported-state provenance or public Session final atomicity complete. Optional trace remains gap-only and must not affect these gameplay/control decisions.
