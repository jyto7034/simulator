# 전투 규칙

[게임 설계서](../game_rulebook.md) · [조작과 화면](battle-controls.md) · [저지와 타겟팅](blocking-and-targeting.md)

## 전투 목표와 전장

전투는 `DefenseRoute` 실시간 배치 방어다. 직원은 배치 위치에서 경로를 따라 오는 적을 공격하고
무기의 저지 수만큼 막는다. 일반전과 보스전은 전장·배치·웨이브의 같은 기본 규칙을 사용한다.

모든 필수 웨이브와 적을 처리하고 보호 대상을 지키면 승리한다. 보호 대상 파괴나 개별 전투의
실패 조건은 패배를 만든다. 생존전은 같은 모드에서 지정한 시간을 버티면 남은 적과 무관하게
승리하도록 작성한다. 공통 시간 제한에 따른 암묵적 무승부는 없다.

전장마다 경로·장애물·출현 구역·배치 구역이 다르며 비사각형도 가능하다. 배치와 공격 범위의
후보는 타일을 사용하고 이동·충돌은 연속 좌표를 사용한다. Ground·Platform에 대한 무기 적성을
지켜야 한다. 아군 직원과 방어 대상은 각각 타일 하나를 점유하므로 다른 아군이 있는 타일에
배치하거나 이동할 수 없다. 적과의 겹침은 허용한다.

작은·중간·큰 전장이 있으며 보스는 기본적으로 큰 전장이다. 노드 형태는 콘텐츠 분류이고
SplitRoom을 별도 전투 모드로 취급하지 않는다. 전장 구조와 실제 스폰은 진입 때 확정한 전투
설정을 따르며 브리핑의 요약 문구로 다시 구성하지 않는다.

## 전술 포인트와 전투 시간

| 항목 | 규칙 |
| --- | --- |
| 시작 / 최대 | 전투마다 20 / 99 |
| 자연 회복 | 전투 시간의 온전한 1초마다 1 |
| 최초 배치 기본 비용 | 10 |
| 재배치 기본 비용 | 최초 기본 비용의 150%를 올림 |
| 전술 이동 / 교대 | 각각 명령당 5, 직원별 전술 이동 대기 10초 |
| 개별 철수 | 비용·환불 없음 |

한 전투의 아군 전체가 같은 포인트를 쓴다. 항상 0~최대치 안에 있으며 초과 회복을 비축하거나
부족한 비용을 부분 지불하지 않는다. 배치 비용 감소는 최초·재배치 모두에 적용하고 이동·교대에는
적용하지 않는다. 스킬은 명시된 양만 증감할 수 있으며 DefenseFocus·Rest는 포인트를 만들지 않는다.
현재 정책에는 최대치 변경, 전투별 최대치 예외와 암묵적인 환경 소모가 없다.

전투 시간은 일시정지 중 흐르지 않는다. 공격·스킬 해결·버프 시간·회복·재배치·이동 대기·작업도
함께 멈추며 재개할 때 정지한 시간을 보충하지 않는다. 전투 종료·후퇴 때 포인트를 폐기하고 다음
전투는 다시 20으로 시작한다.

## 배치와 철수

별도의 출전 명단이나 전투 등록 상한 없이 보유 인원 최대 10명 전원을 전투 중 배치 후보로 둔다.
현장 작업 중인 직원을 포함해 **동시에 전장에 배치할 수 있는 직원은 최대 8명**이다.
이 상한은 한 전투에 참여한 서로 다른 직원의 누적 수를 제한하지 않는다.
철수·전투불능 등으로 배치 자리가 비면 다른 미배치 인원을 투입할 수 있다.
각 인원의 최초 배치·재배치 비용과 재배치 대기를 따르며, 철수한 직원의 대기를 다른 인원에게 적용하지 않는다.
미배치 인원을 포함해 전투 중 장비·파편·유물은 변경할 수 없다.

무기를 장착하고 출전 가능한 직원만 배치한다. 배치 가능 구역·장애물·무기 적성·아군 점유와
동시 배치 상한·비용을 모두 만족해야 한다. 실패하면 자원·위치·대기시간을 바꾸지 않는다.
최초 배치와 재배치는 공격 태세로 시작하고 일반 태세 전환 대기 1.5초를 시작한다.
작업 칸에서는 즉시 작업을 시작하며 완료 후 공격 태세가 된다. [현장 작업](#현장-작업)을 따른다.

배치된 직원은 공격 준비·스킬 집중·군중 제어·침묵·작업 중에도 자발적으로 철수할 수 있다.
사망·전투불능·이미 철수한 직원에게 다시 철수를 적용하지 않는다.

- 철수 즉시 전장에서 제거하고 저지를 해제한다. 발사 전 기본 공격과 아직 방출하지 않은
  스킬 시전·집중은 취소한다.
- 이미 발사된 기본/스킬 발사체와 독립적인 고정 장판은 원래 수명을 따른다. 철수한 직원을
  향한 적대 발사체는 유효한 대상이 없어 빗나간다.
- 시전자·대상 추종 효과, 오라·채널·집중과 적용자/대상이 철수한 버프·디버프는 종료한다.
- 자발적 철수 후 대기는 30초, 전투불능 후 대기는 90초다. 모두 전투 시간이다.
- 자발적 철수의 다음 배치 HP는 철수 시점에 `min(최대 HP, 현재 HP + floor(최대 HP × 30%))`로
  고정한다. 대기 중 추가 회복이나 이후 최대 HP 변화로 소급 변경하지 않는다.
- 전투불능이 될 때마다 [부상과 트라우마](results-and-save.md#직원-상태)를 누적한다.
  그 결과 여전히 출전 가능해야 재배치 후보가 되며 시작 HP도 최신 상태로 계산한다.

재배치는 같은 직원의 새 전투 개체다. 최신 지속 상태·확정 장비와 파편·유효한 전투 단위 효과를
적용하고 배치 초기 공명과 배치 시 효과를 다시 적용한다. 이전 개체의 버프·공명·대상·시전·저지·
오라·대기시간은 이어받지 않는다. 유물의 전투당 사용 기록은 [별도 수명 규칙](relics.md#상태-보존)을 따른다.

## 공격과 방어 태세

일반 태세 전환은 비용 없이 양방향으로 가능하며 직원별 1.5초 대기를 사용한다. 이미 같은 태세,
대기 중 전환, 강한 군중 제어 중 전환은 거절한다. 침묵·공격 준비·시전·집중은 전환 자체를 막지 않는다.

| 상태 | 새 기본 공격·스킬 | 방어 효과 |
| --- | --- | --- |
| Attack | 허용 | 없음 |
| Ground의 Defense | 시작하지 않음 | 무기별 저지 수 증가·받는 피해 감소 |
| Platform의 Defense | 시작하지 않음 | 1초마다 HP 3 회복, 저지 수 0. 공명은 공통 자동 충전 |

방어 전에 이미 시작한 공격 준비·스킬 시전·발사체·지연 효과·추가타는 취소하지 않는다.
수동·자동 새 스킬은 막지만 패시브·반응형 효과는 계속 작동한다.

Ground의 피해 감소는 타입별 감소와 합산한 뒤 0~100%로 제한한다. 저지 수가 줄면 경로 진행도가
높은 순, 스폰 순, 유닛 ID 순으로 기존 상대를 남긴다. 새 적이 기존 상대를 밀어내지 않는다.
강한 군중 제어 중 저지는 0이 되지만 방어의 피해 감소는 유지한다.

Platform Rest는 방어 진입 뒤 온전한 1초부터 시작한다. 조건을 잃었다가 다시 얻으면 새 1초를
기다린다. 최근 피격 제한·부활·회복 비축은 없다. 같은 시각의 확정 피해를 먼저 처리하며 사망을
회복으로 취소하지 않는다. 강한 군중 제어는 HP 회복을 건너뛴다. Rest 전용 공명 보너스는 제거한다. 회복 주기는 유지하고 놓친 회복을 보충하지 않는다.

## 전술 이동과 자리 교대

전술 이동은 같은 전투 개체를 배치 구역의 새 위치·방향으로 즉시 옮긴다. 교대는 두 직원의 현재
위치를 한 번에 맞바꾸며 각자의 도착 방향을 고른다. 공격·방어 어느 태세에서도 요청할 수 있다.

성공하면 이동 직원 또는 교대 양쪽 모두 **강제 방어 1.5초 뒤 자동 공격 태세**로 전환한다.
수동으로 일찍 해제할 수 없고 이전에 방어였어도 자동 공격으로 간다. 일반 방어 버튼에는 이 타이머를
적용하지 않는다. 시간은 최종 성공부터 계산하고 정지 중 멈추며, 철수·전투불능·전투 종료된 직원을
다시 활성화하지 않는다. 포커스의 0.5배속에서는 실제 약 3초가 걸린다.

- 양쪽 모두 필요한 이동 대기가 끝나야 한다. 강한 군중 제어, 발사 전 기본 공격 준비/스킬
  시전·집중과 교대의 독점 이동 구간은 막는다. 침묵과 기존 저지는 막지 않는다.
- 목적지는 유효한 배치 타일이어야 하며 각 무기의 Ground/Platform 적성을 검사한다.
  이동은 자신, 교대는 두 참가자만 점유 검사에서 제외한다. 제3의 아군은 목적지를 차지할 수 없다.
- 같은 위치·방향 이동은 거절한다. 같은 위치에서 방향만 바꾸는 것은 같은 비용과 대기로 허용한다.
- 비용은 교대도 전체에 5를 한 번 지불하고 두 직원의 이동 대기 10초를 동시에 시작한다.
  실패·취소 시 어느 한 명의 위치·방향·태세·효과·비용·대기만 바뀌는 결과를 남기지 않는다.
- HP·버프·공명·전투 개체와 이미 진행한 공격/스킬 대기를 보존한다. 철수 회복이나 재배치
  초기 효과를 받지 않는다. 점유를 중간에 겹치게 만들거나 걸어서 통과하는 동작이 아니다.
- 기존 저지를 해제한 뒤 양쪽 최종 위치에서 저지·공격 대상·범위·오라를 다시 계산한다.
  추적 발사체·추종 효과는 이동 위치를 따르고 고정 발사체·장판은 기존 좌표를 유지한다.
- Ground↔Platform은 두 타일 profile이 있는 Any 무기만 허용한다. 최종 타일의 방어 효과를
  적용하고 새 Platform Rest는 온전한 1초부터 시작한다. 같은 타일의 방향만 바꾸는 이동은
  기존 Rest 주기를 재시작하지 않는다. 교대도 각 직원의 최종 타일에서 같은 규칙을 적용한다.

작업 칸에 도착하면 강제 방어 타이머를 취소하고 즉시 작업한다. 작업 완료 후에는 공격 태세가 된다.
이동 전 태세를 저장·복원하지 않는다. 일반 태세 대기와 이동 명령의 세부 경계는 NEXT-14의 구현 과제다.
입력 순서와 취소는 [고스트·방향 선택](battle-controls.md#배치와-전술-이동)을 따른다.

## 군중 제어와 침묵

Stun·Freeze는 강한 군중 제어(Hard CC), Silence는 침묵이다. 같은 제한을 주는 효과가 하나라도
남아 있으면 제한을 유지한다. 강한 군중 제어의 해제 시점은 남은 효과 중 가장 늦은 만료다.

- Hard CC는 새 기본 공격·자동/수동 스킬·이동·공명 증가를 막고 발사 전 공격과 방출 전
  스킬 시전·집중을 취소한다. 양쪽 중 하나가 걸리면 저지도 즉시 해제한다.
- 이미 방출한 발사체·지연 스킬·독립 장판·확정 파생 효과는 계속 진행한다. 소비한 공명과
  시작한 효과 대기는 환불하지 않는다. 피해·지속 효과·패시브·반응형 발동·전투 시간 대기는 계속된다.
- Silence는 새 자동/수동 스킬 시작만 막는다. 이미 시작한 스킬·기본 공격·이동·저지·피해·
  공명 획득·철수는 유지한다. 둘이 겹친 스킬 거절 사유는 Hard CC가 우선이다.

## 공명과 스킬 사용

공명 최대치·필요량은 파편별로 정한다. 최초 배치와 재배치 모두 `floor(최대 공명 × 20%)`로 시작한다.
배치되어 살아 있는 직원은 전투 시간 **1초마다 공명 1**을 자동 획득한다. 이는 초기 플레이테스트 값이다.
공격·방어·작업·침묵 중에도 충전하며, 정지·철수·전투불능 중에는 충전하지 않는다.
초과량과 충전이 막힌 동안의 시간을 비축하거나 나중에 보충하지 않는다.

기본 공격 방출·가한 피해·받은 피해에 따른 기본 공명 획득과 Rest의 초당 공명 5 보너스는 제거한다.
파편·유물이 명시한 추가 획득은 유지하되, **Stun·Freeze 또는 스킬 사용 잠금 중에는 모든 양수 공명 획득을 막는다.**
일반 공격이 없어도 치유 직원은 같은 자동 충전 규칙을 사용한다.

최종 입력이 유효하게 접수되면 현재 공명을 즉시 전부 소비하고 시전부터 스킬 사용 종료까지 획득을 잠근다.
잘못된 대상·조건 실패·미리보기 취소에는 소비하지 않는다. 종료 후 별도의 1초 잠금은 두지 않는다.

| 스킬 유형 | 사용 종료와 충전 재개 기준 |
| --- | --- |
| 즉발 | 효과 적용과 사용 동작 종료 |
| 발사체 | 발사 동작 종료. 명중까지 기다리지 않음 |
| 연속 공격 | 마지막 공격 동작 종료 |
| 일정 시간 버프 | 버프 지속시간 종료 |
| 채널링 | 채널 종료 |
| 독립 장판·소환물·지속 피해 | 생성·부여 동작 종료. 생성물 소멸까지 기다리지 않음 |
| 영구 버프 | 부여 동작 종료 |

기절·빙결은 시전·연속 공격·채널을 취소하고 공명을 환불하지 않는다. 행동을 자동 재개하지 않으며,
군중 제어가 끝나고 다른 잠금이 없으면 다시 충전한다. 이미 적용한 시간제 버프는 기절 중에도 유지되고
전투 시간에 따라 만료하므로, 버프가 남아 있으면 그 사용 잠금도 유지한다. 침묵은 새 스킬 시작만 막는다.
시전 중 필수 대상이 무효가 되면 해당 사용을 취소하며 환불하지 않는다. 다른 잠금이 없으면 즉시 충전을 재개한다.
이미 발사·생성한 독립 효과는 기존 수명을 따르며, 무효 대상의 직접 효과를 새 대상에게 자동 이전하지 않는다.

이 공통 규칙은 공명 획득·소비·잠금 정책이다. 오케스트라의 공용 충전이나 개별 사격 횟수처럼
별도로 정한 콘텐츠 자원을 자동 삭제하지 않는다. 기존 파편 정의의 이행은 개별 콘텐츠 작성에서 검증한다.

## 수동 스킬

스킬은 효과 대상과 별도로 선택 방식을 명시한다. 자신·자동 유닛 선택은 별도 대상 입력 없이
사용하고, 플레이어 유닛 선택·타일 선택은 해당 종류의 명시적 대상을 요구한다.
누락·다른 종류를 자동 대상으로 바꾸지 않는다.

- 수동 사용 가능 여부, 공격 태세, 행동 제한, 군중 제어·침묵과 가득 찬 공명을 먼저 검사한다.
  유닛은 효과가 요구하는 아군/적·공중 자격·효과 유효성·사거리를, 타일은 유효 타일·사거리를 만족해야 한다.
  타일에 적이 없어도 타일 선택은 가능하다.
- 대상 미리보기는 상태를 바꾸지 않는다. 최종 사용은 최신 조건을 다시 검사하고 실패하면
  선택 상태·배속·공명을 유지한다. 취소는 비용 없이 선택을 끝낸다.
- 성공 시 고른 대상을 고정한다. 나중에 무효가 된 유닛의 직접 효과는 다른 적에게 옮기지 않는다.
  유닛 기준 범위와 지정 타일의 범위는 접수 시점의 타일을 유지하며 빈 곳이 되어도 환불하지 않는다.
- 플레이어 지정 스킬의 단계별 자동 재지정은 허용하지 않는다. active skill 전용 추가 대기나
  수동 기본 공격은 없다. 선택 감속·정지 복원은 [공통 포커스 규칙](battle-controls.md#포커스와-배속)을 따른다.

## 현장 작업

작업물은 지정된 칸에 직원을 두어 완성하는 별도 전장 요소다. 작업 가능한 칸에 도착하면
[즉시 작업 연출](battle-controls.md#도착과-작업-연출)을 시작한다.

작업 칸에서는 강제 방어 1.5초를 기다리지 않고 즉시 작업하며 해당 타이머를 취소한다. 작업량 규칙은 다음과 같다.

- 작업량은 직원이 아닌 작업물에 남는다. 적격 직원마다 전투 시간 1ms에 1ms씩 기여하고 여러
  칸의 작업을 합산한다. 필요량에서 멈추며 직원이 모두 떠나도 감소·초기화하지 않는다.
- 작업 중 새 기본 공격·스킬·저지·일반 태세 전환·DefenseFocus·Rest를 사용하지 않는다.
  피해를 정상적으로 받으며 적의 겹침·피격만으로 배정을 취소하지 않는다.
- Hard CC는 배정과 누적량을 유지하면서 해당 직원의 기여만 멈춘다. 정지 중 작업도 멈추고
  놓친 시간을 보충하지 않는다. 철수·이동·교대는 허용한다.
- 최종 점유에서 작업자를 다시 정한다. 필요량에 처음 도달할 때 한 번 완료하고 효과를 한 번
  실행한다. HP가 이미 가득 찬 대상의 수리도 소모·완료된다. 완료한 칸은 일반 타일로 돌아간다.

작업 중에도 공명은 자동 충전한다. Hard CC·스킬 사용 잠금은 공통 획득 금지를 적용한다.
작업을 완료한 직원은 공격 태세로 전환하며 작업 전 방어 태세를 복원하지 않는다.

## 웨이브와 적

일반전은 침식 직원, 엘리트·보스·특수 조우는 환상체가 중심이다. Normal에는 주 환상체와 환상체
보너스 목표가 없고 Elite·NormalBoss·FinalBoss에는 주 환상체가 정확히 하나 있다.

웨이브는 전투 시간, 선행 무리 처리, 지정 개체의 HP·사망·지점 도달 조건으로 한 번 발동한다.
필수 웨이브가 아직 출현하지 않았으면 승리를 보류한다. 선택 웨이브는 승리를 막지 않는다.
현재 구성은 전투 중 다시 생성하거나 재접속으로 재발동하지 않는다. 같은 시각에 기본 조건과
기한이 겹치면 기본 조건을 사용하며 순환 의존은 콘텐츠 오류다.

실제 종류·수량과 조건 결합의 구현은 [데이터 계약](../data_loading_contract.md)과
[런타임 계약](../core_runtime_contract.md)이 소유한다. `ReferenceFinalBoss`, CWBS,
Little Red runtime reference는 구현 검증용 구분이며 차기 캐릭터·보상 정책의 근거가 아니다.
소환된 유닛은 일반 웨이브·보스 보상·파편·도감 등록의 원천이 아니며 승리를 막지 않는다.

## 전투 능력치와 HP

전투 중 최대 HP가 증가해도 현재 HP를 자동 회복하지 않는다. 최대 HP가 줄어 현재 HP가 상한을
넘으면 새 상한으로 낮춘다. 그 결과 HP가 0이 되면 일반 사망과 같은 처리를 한 번 적용하며
살아 있는 0 HP 상태로 남기지 않는다. 원인 유닛이 있으면 그 유닛이 처치자로 기록되고,
원인 유닛이 없는 시스템 효과는 처치자를 만들지 않는다.
능력치 변경→HP 변경→사망의 이벤트 순서와 attribution은 [런타임 계약](../core_runtime_contract.md)이 소유한다.

## 정지와 명령 처리

정지는 시간을 멈추지만 배치·철수·태세·이동·교대·스킬 시작·배속 변경·전투 후퇴를 정지 자체로
금지하지 않는다. 최신 상태에서 평상시 자격을 검사하고 성공은 즉시 반영한다.
한 명령의 응답을 받은 뒤 다음 명령을 보낸다. 뒤의 실패로 앞의 성공을 되돌리지 않으며
명령 계획을 쌓아 재개 때 일괄 실행하는 기능은 없다.

연결이 끊기면 자동 정지한다. 같은 서버 프로세스가 유지되는 동안 시간 제한 없이 상태를 보존하고,
재접속 후 명시적으로 재개해야 진행한다. 프로세스 종료 후 이어하기는 진행 중 노드의 미확정 상태를 노드 입장 전으로 복원하며
전투 도중 상태를 재개하지 않는다. 결정된 승패와 노드 소비는 결과 확인 버튼과 무관하게 즉시 저장·유지한다.
승패 전 종료 복구는 수동 후퇴 횟수를 쓰지 않으며 이미 사용한 후퇴 횟수는 유지한다. 이 경계는
[저장과 복구](results-and-save.md#저장과-복구)의 목표와 NEXT-10을 따른다.

전투 상태·연출·결과는 Core가 계산한 상태를 따른다. Unity가 공격이나 피해를 재계산하지 않는다.
이벤트 순서·revision·스냅샷 형식·최대 HP 변경과 사망 확정의 구현은
[런타임 계약](../core_runtime_contract.md)과 외부 Unity 전투 계약이 소유한다.
