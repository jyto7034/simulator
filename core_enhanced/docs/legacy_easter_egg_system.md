# 레거시 이스터에그 시스템

이 문서는 이전 런에서 플레이어가 진심으로 돌본 직원의 흔적이 이후 런에서 단 한 번 나타나는 희귀 이벤트를 정의한다. 이 시스템은 일반 반복 콘텐츠가 아니라, 게임의 정체성과 감정선을 강화하는 설치/계정 단위 1회성 이스터에그다.

## 목적

- 반복 탐사가 단순 리트라이가 아니라 이전 탐사의 흔적 위를 다시 걷는 경험이 되게 한다.
- 직원 신뢰도, 성장, 장비 투자, 파편 투자가 감정적 결과로 남게 한다.
- 플레이어가 키웠던 직원을 적으로 다시 만나는 충격을 만든다.
- 보상보다 기억, 후회, 회수, 기록이라는 테마를 강조한다.
- 전투 난이도 상승이 강제 손해처럼 느껴지지 않도록 선택형으로 제공한다.

## 핵심 원칙

- 계정 또는 설치 단위로 한 번만 발생한다.
- 아무 사망 직원이나 고르지 않는다.
- 신뢰도, 성장, 장비, 파편, 출전 기록 등으로 플레이어가 애정을 쏟은 직원만 후보가 된다.
- 후보 기록은 최대 3개만 저장한다.
- 3개 슬롯이 모두 찬 상태에서 새 후보가 들어오면 가장 오래된 기록을 제거한다.
- 실제 이벤트 발생 빈도는 매우 낮아야 한다.
- 이벤트가 뜨더라도 전투 난이도 상승은 플레이어가 직접 선택해야 한다.
- 플레이어가 거절하면 이스터에그를 소비하지 않는다.

## 레거시 직원 기록

직원이 사망했을 때 바로 저장하지 않는다. 사망 직원 중 아래 조건을 통과한 직원만 레거시 후보가 된다.

정확한 기준은 나중에 정책으로 정한다. 지금은 다음 요소를 후보 점수에 반영하는 방향만 확정한다.

- 신뢰도
- 직원 성장도
- 출전 횟수
- 보스/정예 전투 참여 여부
- 장착했던 스킬 파편
- 장착했던 무기와 장비
- 치료, 휴식, 파편 강화 같은 투자 이력
- 직원이 부탁한 선택을 들어준 기억
- 사망한 노드, Act, 사망 원인

저장 데이터 예시:

```text
FormerEmployeeLegacyRecord
-> employee_id
-> name
-> grade
-> final_level
-> trust_band
-> traits
-> equipped_skill_fragment_ids
-> notable_equipment_ids
-> death_context
-> memory_tags
-> run_id
-> act_index
-> node_id
-> created_at
```

이 기록은 전투 유닛을 그대로 복사하기 위한 데이터가 아니다. 이후 침식된 전 직원 엘리트, 생존일지, 회수 보상, 대사 연출을 만들기 위한 감정적 원본이다.

## 저장 슬롯 정책

레거시 직원 기록은 최대 3개만 보관한다.

```text
LegacyMemoryVault
-> slots: [FormerEmployeeLegacyRecord; max 3]
-> insertion_policy: FIFO
```

정책:

- 빈 슬롯이 있으면 새 기록을 추가한다.
- 슬롯이 가득 찼으면 가장 오래된 기록을 제거하고 새 기록을 추가한다.
- 점수 미달 직원은 저장하지 않는다.
- 저장된 기록이 이벤트에 사용되더라도 전체 기록 보관소에서는 아카이브 기록으로 남길 수 있다.

## 발생 조건

이 이벤트는 일반 전투 난이도를 몰래 올리면 안 된다. 반드시 전투 진입 전 특수 선택지로 노출한다.

발생 후보 조건:

- 이스터에그가 아직 발생하지 않았다.
- `LegacyMemoryVault`에 후보 직원 기록이 있다.
- 해당 직원이 사망 당시 환상체 스킬 파편을 장착하고 있었다.
- 현재 전투 노드가 그 파편의 원천 환상체 또는 관련 계열 환상체 조우다.
- 레거시 이벤트 예산이 허용된다.

발생 모드와 시점은 아직 확정하지 않는다. 일반 모드, 끝없는 탐사, 특정 Act 이후, 특정 위험도 이상 같은 조건은 추후 정책으로 다시 정한다. 현재 확정된 핵심은 "플레이어가 애정을 쏟은 사망 직원 기록"과 "그 직원이 장착했던 환상체 파편과 관련된 조우"를 연결한다는 점이다.

레거시 이벤트 예산:

```text
LegacyEventBudget
-> install_or_account_once: true
-> daily_charges: 0 or 1
-> max_per_run: 1
-> consumed: bool
```

초기 정책:

- 설치/계정당 실제 발생은 1회로 제한한다.
- 단순 노출만으로는 소비하지 않는다.
- 플레이어가 특수 진입을 선택하고 전투가 시작될 때 소비한다.
- 플레이어가 표준 진압을 선택하면 다음 적절한 조우에서 다시 뜰 수 있다.

## 진입 전 선택지

일반 전투 노드 preview 또는 NodeConfirm에서 비정상 신호를 감지한다.

예시 연출:

```text
본부 통신:
"비정상 신호가 감지됩니다.
해당 조우에는 등록되지 않은 개체가 있습니다."
```

선택지:

```text
표준 진압
-> 기존 전투 그대로 진행
-> 이스터에그 미소비

잔향 추적
-> 전투에 침식된 전 직원 엘리트 추가
-> 위험 경고 표시
-> 이스터에그 소비
```

`하드모드`라는 이름은 사용하지 않는다. 추천 명칭은 `잔향 추적`이다. 전투가 어려워진다는 사실은 경고하되, 이름은 감정적이고 세계관적인 방향으로 둔다.

경고 문구 예시:

```text
"이 절차는 표준 진압 난이도를 초과합니다.
회수 실패 시 추가 보상은 보장되지 않습니다."
```

## 전투 변화

`잔향 추적`을 선택하면 원래 전투 노드에는 없던 엘리트 적이 추가된다.

```text
기존 환상체 전투 노드
+ 침식된 전 직원 엘리트
```

엘리트 설계:

- 원본 직원의 이름과 일부 외형 흔적을 가진다.
- 사망 당시 장착한 환상체 파편의 원천에 맞춰 왜곡 스킬을 사용한다.
- 원본 직원을 그대로 복사하지 않고 침식된 엘리트로 변형한다.
- 난이도는 오른다.
- 기존 전투 목표를 망가뜨리지 않아야 한다.

예시:

```text
사망 직원: 강민재
장착 파편: Red Shoes 계열
성향: 반항적
신뢰도: 높음

등장 적:
침식된 강민재
-> 빠른 돌진
-> 붉은 신발 파편 기반 왜곡 스킬
-> 후열 압박
```

## 대사와 연출

핵심은 플레이어가 즉시 알아차리되, 문자 그대로 너무 노골적으로 설명하지 않는 것이다.

전투 시작 연출 예시:

```text
초상화가 깨짐
이름 일부가 노이즈로 가려짐
대사 로그가 깨져 출력됨

"이번엔... 제가... 먼저... 갑니다."
```

문자 그대로 매번 깨끗하게 출력하지 않는다. 초상화 침식, 글자 깨짐, 통신 노이즈, 대사 일부 누락으로 표현한다.

대사 방향은 성별 고정보다 신뢰도, 성향, 기억 태그 기반이 좋다.

예시 감정선:

- 애착형: 관리자에 대한 그리움, 기다림, 놓지 못함.
- 동료애형: 함께 싸운 기억, 등을 맡겼던 신뢰.
- 반항형: 원망으로 시작하지만 끝에는 인정.
- 순종형: 마지막까지 명령을 기다림.
- 신중형: 두려움과 후회, 그래도 돌아오길 바람.

## 보상

처치 성공 시:

- 직원이 사용하던 무기 또는 변질된 장비.
- 생존일지.
- 해당 파편 또는 원천 환상체 연구도 대폭 증가.
- 아카이브 기록 해금.

보상 장비는 원본 그대로보다 잔향이 남은 변질 장비가 좋다.

```text
원본: 낡은 진압봉
회수 후: 녹슨 진압봉 - 잔향
```

실패 시에도 일부 감정 보상을 남기는 편이 좋다.

- 생존일지 일부 페이지.
- 파편 연구도 소량.
- 다음 런에서 관련 브리핑 문구 변화.

## 생존일지

생존일지는 본사로 회수되는 기록물이며, 관리자 블랙박스/녹화 데이터와 연결된다.

시작 문장:

```text
관리자가 죽었다.
```

이후 내용은 직원이 무너지는 과정을 기록한다.

방향:

- 처음에는 상황 보고에 가깝다.
- 중반에는 본부 통신 두절, 직원의 판단, 공포, 후회가 섞인다.
- 마지막에는 플레이어가 돌본 직원의 감정선이 드러난다.
- 성별 고정 감정보다 성향, 신뢰도, 기억 태그에 따라 문체를 바꾼다.

마지막 문장 예시:

```text
기록 장치의 배터리가 얼마 남지 않았다.
만약 이 기록을 당신이 듣고 있다면,
이번에는 나를 두고 가지 말아줘.
```

## 아카이브

이 이벤트는 한 번 발생하면 기록 보관소에 영구 저장되는 편이 좋다.

아카이브 항목:

- 회수한 생존일지.
- 침식된 직원 이름.
- 사망한 런, Act, 노드.
- 마지막 장착 파편.
- 마지막 장비.
- 회수 성공 여부.
- 전투 시작 대사/노이즈 로그.

## 구현 메모

즉시 구현 대상은 아니다. 현재 우선순위는 일반 3 Act 루프, 보상 체계, 전투 조우 데이터 안정화다.

나중에 구현할 때 필요한 축:

- `MetaProgressionState`
- `LegacyMemoryVault`
- `FormerEmployeeLegacyRecord`
- `LegacyCandidatePolicy`
- `LegacyEventBudget`
- `LegacyEchoEncounterModifier`
- `SurvivalLogArchive`

주의:

- 이벤트 코드를 일반 조우 생성 로직에 흩뿌리지 않는다.
- 일반 전투가 몰래 어려워지면 안 된다.
- 선택지만 보고 거절한 경우 이스터에그를 소비하지 않는다.
- 숫자 조건을 UI에 과하게 공개하지 않는다.
- 이 시스템은 반복 콘텐츠가 아니라 희귀한 기억 이벤트다.
