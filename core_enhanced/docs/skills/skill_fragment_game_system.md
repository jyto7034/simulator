# 스킬 파편 게임 시스템 설계

## 목적

스킬 파편은 직원이 전투 중 사용할 수 있는 액티브 스킬을 획득하고 장착하는 시스템이다.

이 문서는 코드 구현 상태가 아니라 게임 규칙과 장기 설계 방향을 기록한다. 현재 구현 상태는 `current_handoff.md`에서 관리한다.

## 핵심 전제

- 플레이어가 사용하는 전투 유닛은 환상체가 아니라 직원이다.
- 직원은 기본적으로 고유 스킬을 갖지 않는다.
- 직원은 스킬 파편을 장착해야 액티브 스킬을 사용할 수 있다.
- 환상체는 플레이어 기물이 아니라 적군/조우 대상으로 등장한다.
- 환상체를 격파하거나 격리하면 그 환상체에서 파생된 스킬 파편을 얻을 수 있다.
- 환상체의 원본 스킬과 직원이 사용하는 파편 스킬은 같은 원천에서 파생되지만 별도의 스킬 데이터다.

## 스킬 파편의 정체성

현재 기준에서 스킬 파편은 패시브 장비가 아니다.

```text
스킬 파편
-> 직원에게 액티브 스킬 사용 권한을 부여
-> 전투 중 해당 액티브 스킬이 발동
-> 발동 결과로 피해, 버프, 평타 강화, 스탯 변화, 공명 변화 등이 발생
```

따라서 아래 효과들은 상시 적용 효과가 아니라 액티브 스킬의 결과로 취급한다.

- 평타 강화
- 일시적 스탯 증가
- 조건부 버프
- 공명 변화
- 특수 상태 부여

초기 설계에서는 `패시브 파편`, `스탯 파편`, `평타 강화 파편`처럼 파편 자체의 카테고리를 넓히지 않는다. 그런 효과가 필요하면 액티브 스킬 내부 효과로 표현한다.

## 장착 원칙

현재 합의된 방향:

- 액티브 스킬 파편은 직원당 최대 1개로 고정한다.
- 스킬 파편 교체는 가볍지 않아야 한다.
- 장착 선택은 직원의 빌드 정체성을 결정하는 무거운 선택이어야 한다.

이 방향의 의도:

- 직원 하나가 여러 환상체 스킬을 동시에 난사하는 구조를 피한다.
- 직원마다 대표 스킬과 역할이 분명해진다.
- 파편 획득과 장착 선택이 장기적인 빌드 결정으로 작동한다.

## 액티브 1개 고정 방향

현재 게임의 목표는 많은 유닛을 두루두루 성장시키는 것이 아니라, 소수 엘리트 직원에게 자원을 집중해 탐사를 성공시키는 것이다.

따라서 스킬 파편은 여러 슬롯을 조합하는 장비 퍼즐보다, 직원의 대표 액티브 스킬을 결정하는 무거운 선택으로 설계하는 편이 적합하다.

```text
직원
-> 액티브 스킬 파편 1개
-> 장비/성장/트라우마/기프트가 그 스킬 운용을 보조
-> 남는 파편은 강화/정제/교체/연구 자원으로 전환
```

이 방향의 장점:

- 직원의 정체성이 선명해진다.
- 전투 중 이해해야 할 스킬 수가 줄어든다.
- 밸런싱 범위가 관리 가능해진다.
- 보상 요구량이 과도하게 늘어나지 않는다.
- 노드 반복 요구가 줄어 플레이 피로도를 낮출 수 있다.
- 자원을 누구에게 몰아줄지에 대한 선택이 더 무거워진다.

여러 슬롯 구조는 다음 장점이 있다.

- 빌드 가능성이 크게 늘어난다.
- 직원별 세부 튜닝이 가능하다.
- 파편 보상의 소비처가 많아진다.

하지만 현재 목표와는 충돌 가능성이 크다.

```text
액티브 + 패시브 + 평타 강화 + 스탯 파편
-> 조합 수 증가
-> 필요한 보상/자원량 증가
-> 더 많은 노드 반복 요구
-> 직원별 관리 비용 증가
-> 밸런싱 난이도 증가
-> 플레이 피로도 증가 가능성
```

따라서 초기 설계에서는 여러 파편 슬롯을 열지 않는다.

스킬 파편 하나만으로 깊이를 만들기 위해서는 그 액티브 스킬이 직원 빌드의 중심이 되어야 한다.

좋은 파편 액티브 스킬의 기준:

- 직원의 전투 포지션을 바꾼다.
- 직원의 역할을 바꾼다.
- 특정 장비, 성장, 공명, 기프트와 강하게 맞물린다.
- 리스크와 보상이 있다.
- 강화 방향에 따라 운용이 달라질 수 있다.
- 단순 피해 스킬이 아니라 플레이어가 기억할 만한 행동 패턴을 만든다.

## 시스템 역할 분담

스킬 파편에 모든 빌드 기능을 몰아넣지 않는다.

권장 역할 분담:

```text
스킬 파편
-> 직원이 어떤 액티브 스킬을 쓰는지 결정

장비
-> 지속 효과, 전투 보정, 특정 스킬 운용 보조

직원 성장
-> 기본 스탯, 생존력, 성장 방향

기프트 / E.G.O
-> 특수 패시브, 강한 개성, 희귀한 운용 변화

트라우마 / 부상
-> 리스크, 제약, 장기 탐사 압박
```

패시브, 평타 강화, 스탯 보정이 필요하더라도 스킬 파편 슬롯을 늘려 해결하지 않는다.

우선은 다음 방식으로 처리한다.

- 평타 강화는 액티브 스킬 발동 결과로 표현한다.
- 일시적 스탯 증가는 액티브 스킬 발동 결과로 표현한다.
- 지속 패시브가 필요하면 장비, 기프트, E.G.O, 성장 시스템에서 다룬다.
- 직원의 장기 성향은 파편 슬롯이 아니라 성장과 장비 조합으로 만든다.

아직 미정인 항목:

- 교체 비용
- 기존 장착 파편의 보존/파괴 여부
- 교체 비용이 특정 노드/재화/부작용과 연결되는지 여부

## 닼던식 정책 초안

스킬 파편 정책은 다키스트 던전의 장신구/원정 준비 철학을 참고한다.

핵심은 “안전한 정비 구간에서 선택하고, 위험 구간에서는 그 선택을 들고 버티는 것”이다.

```text
정비 구간
-> 직원 편성
-> 장비 조정
-> 액티브 스킬 파편 장착/해제
-> 다음 노드 진입

노드/전투/보상 처리 중
-> 파편 장착 변경 불가
-> 현재 빌드로 결과를 감당
```

초기 정책:

- 액티브 스킬 파편은 직원당 1개만 장착한다.
- 액티브 슬롯이 비어 있으면 장착할 수 있다.
- 이미 액티브 파편이 있으면 바로 다른 파편으로 교체할 수 없다.
- 교체하려면 먼저 해제한 뒤 다시 장착해야 한다.
- 장착/해제는 준비 창에서만 가능하다.
- 전투, 노드 내부, 보상 처리 중에는 장착/해제가 불가능하다.
- 파편 획득은 보유 수량으로 누적한다.
- 분해/정제는 아직 비활성화한다.

현재 코드 기준 준비 창:

- `ViewingMap`
- 전투/Boss 노드의 `NodeConfirm`

의도:

- 노드에 들어가기 전 선택의 무게를 만든다.
- 전투나 이벤트 결과를 보고 즉석으로 최적화하는 플레이를 막는다.
- 단일 액티브 슬롯의 정체성을 유지한다.
- 반복 획득한 파편을 인벤토리 수량으로 누적하고, 사용하지 않는 파편을 같은 rarity 조합 재료로 활용할 수 있게 한다.
- 비용/분해/강화/연구 규칙이 바뀌어도 정책 레이어에서 교체할 수 있게 한다.

정책은 고정 상수가 아니라 바뀔 수 있는 게임 규칙으로 취급한다.

```text
SkillFragmentLoadout
-> baseline + active slot 구조만 책임

ActionScheduler
-> 현재 GameState에서 가능한 액션 종류를 책임
-> 파편 장착/해제/강화/개화 가능 시점은 action gate에서 처리

SkillFragmentPolicy
-> equip policy
-> stacking policy
-> composition policy
-> dismantle policy
```

나중에 확장 가능한 정책 후보:

- `교체 무료`: 정비 구간에서는 자유 교체.
- `교체 비용`: 기억 잔재 같은 재화가 필요.
- `노드 전용 교체`: 연구/정비/지원 노드에서만 가능.
- `기존 파편 파괴`: 교체 시 기존 장착 파편 소모.
- `추가 획득 자동 전환`: 이미 보유한 파편 추가 획득분은 자동으로 정제 재화로 전환.
- `분해 허용`: 미장착 파편을 정비 구간에서 분해 가능.

## 파편 조합 강화와 개화

동일한 환상체가 한 회사 안에 여러 번 존재하는 구조는 세계관상 어색할 수 있다. 따라서 성장의 기본 재료는 `동일 파편`이 아니라 `같은 등급의 다른 스킬 파편`으로 둔다.

```text
첫 획득
-> 액티브 스킬 장착 가능

같은 rarity 파편 획득
-> 대상 파편의 강화 재료 후보

같은 rarity 파편 조합
-> 대상 파편의 수치 강화
-> 개화 진행도 증가

개화 조건 충족
-> 별도 액션으로 개화 확정
-> 개화 후에는 별도 awakened skill 사용
```

의도:

- 사용하지 않는 파편도 성장 재료로 의미 있게 만든다.
- 같은 환상체를 반복해서 등장시켜야 하는 보상 구조를 피한다.
- 소수 엘리트에게 자원을 몰아주는 구조와 맞물린다.
- 단일 액티브 슬롯이어도 스킬 성장 깊이를 확보한다.

기본 조합 정책:

```text
재료 허용
-> 대상 파편과 같은 rarity 파편만 가능
-> 대상 파편 자신은 재료 불가
-> 장착 중인 파편은 재료 불가
-> 마지막 1개만 남은 파편은 재료 불가

일반 강화
-> 같은 rarity 재료 파편 1개 소모
-> upgrade_level +1
-> awakening_progress +1
-> max_upgrade_level = 10

개화 가능
-> awakening_threshold = 7
-> awakened_skill_id가 있는 파편만 개화 가능
-> threshold 도달 시 awakening_available = true
-> 자동 개화 없음

개화 확정
-> 별도 액션으로 확정
-> 일반 개화 확정 비용 없음
-> 되돌리기 불가
-> 개화 후에도 upgrade_level 유지

조기 개화
-> threshold 미달이어도 가능
-> 부족 awakening_progress 1당 같은 rarity 파편 1개 추가 소모

개화 후 강화
-> 계속 가능
-> 같은 rarity 파편 2개 소모
-> upgrade_level은 max 10까지 증가 가능
-> awakening_progress는 계속 누적 가능
```

개화 결과는 파편별 데이터가 결정한다. 어떤 파편은 원본 환상체 스킬에 가까운 상위 모방 스킬로 개화할 수 있고, 어떤 파편은 완전히 다른 직원 전용 스킬로 개화할 수 있다.

```text
개화 전
-> base_imitation_skill_id + upgrade scaling

개화 후
-> awakened_skill_id 사용
```

`완전 모방` 또는 `개화`는 모든 파편이 원본 환상체 스킬을 그대로 복사한다는 뜻이 아니다. 파편별 데이터에 따라 원본에 가까워질 수도 있고, 완전히 다른 방향으로 변이할 수도 있다.

현재 코드 구조:

```text
SkillFragmentInventory
-> fragment_id별 count 저장
-> fragment_id별 progress 저장
   -> upgrade_level
   -> awakening_progress
   -> awakening_available
   -> awakened
```

현재 구현됨:

- 같은 rarity 재료 파편 기반 강화 액션
- `SkillFragmentInventory`의 count/progress 저장 구조
- `PlayerBehavior::UpgradeSkillFragment`
- `PlayerBehavior::AwakenSkillFragment`

아직 미구현:

- 강화 결과가 `SkillDef` 또는 파편 효과에 반영되는 방식
- 개화 후 실제 전투 효과/연출/위험성 변화

## 파편 획득

기본 획득처:

- 환상체 격파
- 환상체 격리
- 희귀 보상
- 향후 추가될 종속 개념 보상

환상체 격파 보상은 해당 환상체의 원본 스킬을 그대로 복사하는 것이 아니다.

```text
환상체 원본 스킬
-> 환상체가 직접 사용하는 고유 스킬

환상체 파생 스킬 파편
-> 직원이 모방해서 사용하는 별도 액티브 스킬
```

예시:

```text
One Sin 환상체
-> 원본 스킬: one_sin_penitence
-> 파편 스킬: fragment_one_sin_penitence
```

둘은 테마와 원천은 공유하지만 밸런스, 조건, 수치, 연출, 대상 규칙은 독립적으로 조정할 수 있다.

## 남는 파편 문제

직원당 액티브 스킬 파편을 1개만 장착한다면, 진행 중 여러 환상체를 격파하면서 사용하지 않는 파편이 생긴다.

이 파편들을 단순히 보관만 하게 두면 보상 가치가 낮아질 수 있다. 따라서 남는 파편은 별도 성장 루프로 연결하는 것이 좋다.

## 권장 처리 방식

### 1. 분해/정제

사용하지 않는 파편을 공용 재화로 전환한다.

가능한 재화 이름 후보:

- 파편 가루
- 기억 잔재
- E.G.O 잔향
- 관측 잔재

용도 후보:

- 장착 파편 강화
- 스킬 파편 교체 비용
- 직원 성장 보조
- 특수 연구 진행
- 희귀 보상 해금

장점:

- 가장 안정적인 기본 처리 방식이다.
- 어떤 파편을 얻어도 최소한의 가치가 보장된다.
- 랜덤성에 기대지 않고 장기 성장 자원으로 연결할 수 있다.

### 2. 파편 강화

남는 파편이나 분해 재화를 사용해 장착 중인 파편을 강화한다.

강화 방향 후보:

- 피해량 증가
- 쿨다운 감소
- 발동 조건 완화
- 추가 효과 해금
- 공명 소모량 감소
- 스킬 연출/범위 강화

주의점:

- 강화 수치가 너무 강하면 초반에 얻은 파편 하나에 지나치게 고착될 수 있다.
- 강화가 핵심이 되면 새로운 파편 획득의 설렘이 줄어들 수 있다.
- 강화는 수치 상승만이 아니라 선택형 변형이나 부가 효과 해금과 섞는 편이 좋다.

### 3. 희생형 교체

새 파편을 장착하거나 기존 파편을 교체할 때 비용을 요구한다.

비용 후보:

- 기존 장착 파편 파괴
- 남는 파편 N개 소모
- 분해 재화 소모
- 특정 지원/연구 노드 방문
- 직원에게 부작용 또는 피로 누적

장점:

- “교체가 어렵다”는 의도와 잘 맞는다.
- 장착 선택에 무게가 생긴다.

주의점:

- 너무 가혹하면 플레이어가 새 파편을 실험하지 않게 된다.
- 최초 장착과 교체의 비용은 다르게 설계하는 편이 안전하다.

### 4. 연구/해금

사용하지 않는 파편을 연구 재료로 투입한다.

해금 후보:

- 환상체 정보
- 파편 도감
- 직원 훈련 옵션
- 시설 효과
- 장착 슬롯 관련 기능
- 특정 환상체 계열 보상 확률 증가
- 다음 보상 풀 확장

장점:

- 전투 외 성장축을 만들 수 있다.
- 파편이 단순 전투 스킬 이상의 세계관 자원으로 작동한다.

### 5. 제한적 랜덤 조합

랜덤 조합은 메인 처리 방식보다는 특수 기능으로 두는 편이 좋다.

권장 형태:

```text
특정 관리/연구 노드 방문
-> 불필요한 파편 N개 투입
-> 같은 위험 등급 이하 또는 관련 계열 파편 후보 1~3개 제시
-> 플레이어가 하나 선택
```

완전 랜덤 결과보다 `랜덤 후보 제시 + 선택`이 낫다.

이 방식은 플레이어에게 변수를 제공하면서도 빌드 통제권을 완전히 빼앗지 않는다.

## 권장 기본 흐름

초기 구현 목표로 삼기 좋은 흐름:

```text
환상체 조우 / 관련 전투 노드
-> 확률적으로 완성 액티브 스킬 파편 획득 가능
-> 완성 파편을 얻지 못해도 연구도/분석 데이터 획득
-> 연구도 임계치 도달 시 pending research delivery 등록
-> 다음 안전 노드에서 본사 송신으로 파편 자동 수령
-> 장착 / 보관 / 분쇄 / 강화 / 개화 재료로 활용
```

장기적으로는 다음 흐름까지 확장할 수 있다.

```text
보유 파편
-> 장착 파편
-> 분해 재화
-> 강화/교체/연구/조합
-> 직원 빌드와 시설 성장에 반영
```

## 현재 우선순위

1. 스킬 파편은 우선 액티브 스킬 제공 장착물로 고정한다.
2. 직원당 액티브 스킬 파편은 최대 1개로 설계한다.
3. 완성 파편 직접 획득은 확률 보상으로 두고, 연구 진행도는 안정적인 장기 획득 루트로 둔다.
4. 연구 완료 파편은 전투 직후 즉시 지급하지 않고 pending 상태로 보관한 뒤, 안전 노드에서 본사 송신으로 자동 수령한다.
5. 수령 가능한 안전 노드 범위는 `ResearchDeliveryPolicy` 같은 정책 allowlist로 관리한다. 현재 기본값은 `Support`, `HeadquartersContact`, `Shop`, `Reward`이고, `Combat`, `Boss`는 제외한다. 기존 `Event` 노드는 제거되었으므로 안전 노드 목록에 포함하지 않는다.
6. 남는 파편은 먼저 Maintenance 분쇄/정제 재화로 처리하고, 강화/개화 재료로 활용한다.
7. 랜덤 조합은 즉시 핵심 시스템으로 넣지 않고, 특수 노드 또는 연구 기능으로 후순위 검토한다.

## 아직 결정해야 할 질문

- 파편 교체는 언제 가능한가?
- 최초 장착에도 비용이 필요한가?
- 장착된 파편을 교체하면 기존 파편은 사라지는가?
- 격파와 격리에서 얻는 파편의 성격은 달라야 하는가?
- 연구 완료 임계치와 초과 연구도 처리 방식은 어떻게 할 것인가?
- pending research delivery를 런 종료, Act 전환, 끝없는 탐사 모드에서 어떻게 유지할 것인가?
