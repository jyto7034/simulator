# 로드맵 검토 발견 사항

검토 기준은 Core 우선·Unity 후속·고유 최종보스 제외다. 아래 F 번호는 **이번 문서 검토 내부 식별자**이며 과거 감사의 F01 또는 로드맵 요구 F01과 다르다. 확인된 문서 문제와 설계상 위험을 구분한다. 제품 실패·기존 감사 무효·현재 구현 차단 판정은 아니다.

## F01 현재 상태 안내가 실제 작업 문서를 따라가지 못함

**구분:** 확인된 문서 현재성 문제. **우선순위:** 중간. **담당:** U00 현황 관리, 완료 카드의 후속 인수.

[로드맵](../../ROADMAP.ko.md) 상단은 U11 완료를 안내하지만 v4 본문은 U08 현재 작업으로, U07-M 카드 상태는 등록·대기로 남아 있다. 상단이 아래 이력보다 우선한다고 명시돼 있어 과거 완료를 뒤집는 모순은 아니지만, 읽은 위치에 따라 현재 작업을 오해하기 쉽다.

[최신 인수인계](../../execution/HANDOFF_LATEST.ko.md)는 U12 P2G-20을 안내하는 반면, 읽은 시점의 [Working Policy](../../../../goals/core_expedition_lifecycle/WORKING_POLICY.ko.md)는 WR008 및 GEX-10 진입을, [실행 PLAN](../../../../goals/core_expedition_lifecycle/execution/single_goal/PLAN.md)은 구현 계약을 기록한다. 이번 대화의 초기 설명도 오래된 인수인계를 따라 잘못 안내했다.

**권고:** 단일 현황에서 최신 owner 문서로 직접 연결하고 로드맵 본문에는 작업 범위·순서만 유지한다. 상태를 남길 때는 과거 시점임을 명시한다. 기존 이력과 동결 기록은 보존한다. 별도 개발 현황 장부를 만들지 않는다.

**해소 확인:** 단일 진입점·최신 인수인계·작업 문서의 현재 위치가 같은 대상을 안내하고, 완료 카드의 과거 상태가 현재처럼 읽히지 않는다.

## F02 U12에서 먼저 닫는 최소 기능의 후속 인계가 흐림

**구분:** 상세 계획과 로드맵 사이의 인계 보완. **우선순위:** 중간. **담당:** U12 → U13/U14/U16, U17 소비.

[U12 코드 검토 T04/T05](../../../../goals/core_expedition_lifecycle/CODE_REVIEW.ko.md)는 실제 최초 입장 소모·소진 선택·깊이별 귀환과 유료 채용 가격/횟수·공통 eligibility를 U12에서 닫는다. 로드맵 U14는 비용·소진을, U16-1은 유료 채용을 구현 범위로 적고 있으나 **U12의 어느 계약을 재사용하고 무엇을 확장하는지**는 카드 수준에서 충분히 특정되지 않는다.

이것은 U12가 U16/U19 전체를 기다려야 한다는 순환 결함이 아니다. 기존 fixed tutorial executor와 정상 공용 활동을 사용하는 최소 실행 계획이 있으므로 순서는 유지할 수 있다. 읽은 시점의 [회복 경로 함수](../../../../../src/game/world/combat.rs)와 [채용 명령 함수](../../../../../src/game/world/headquarters.rs)의 차이는 U12 상세 검토에 이미 알려진 전환 대상이다.

**권고:** U12 완료 인수에서 first-entry/소진 선택/귀환 cause, 채용 가격·queue·eligibility, 회복 판정과 실제 명령의 공유 지점을 연결한다. U14는 같은 identity에 유예·황금가지·무억제 배율을 더하고 U16은 같은 유료 채용 경로에 전체 지원 활동을 연결한다. U13 지도 변화 및 U21 납치 등으로 가능한 행동이 바뀌면 회복 가능성도 같은 기준으로 갱신한다.

**해소 확인:** 후속 계획에 재사용 계약·변경되는 의미·영향 검증이 명시되고, 별도 입장 비용/귀환/채용 판정기를 중복 도입하지 않는다. 미래 전체 기능을 U12로 당기지 않는다.

## F03 고정 지도와 필수 전조 자리의 인계 계약이 필요함

**구분:** 설계상 위험, 생성 실패를 재현한 결과 아님. **우선순위:** 높음 — U13 상세 설계에서 확인. **담당:** U13 → U20, U17/U21 노드 대체 소비.

[지도 규칙의 노드 종류 배정](../../../../game_rules/run-and-map.md#노드-종류-배정)은 시작·Gate·고정 보스·SavePoint·정비·초반 유물을 보호한 뒤 특수 노드를 배정한다. 같은 페이지는 3–7층 계열 첫 진입 방에 미완료 전조 후보가 있으면 반드시 배정하고, 호환 노드 확보와 처리 순서의 결합은 별도 설계한다고 명시한다.

U13 카드의 예약 충돌 검증과 U20 카드의 필수 배정 사이에는 **누가 어떤 자리의 호환성을 보장하는지**가 구체적으로 배정되지 않았다. 지정 방에 남은 호환 자리가 없을 때, 고정 노드를 덮어쓰거나 필수 전조를 누락하는 구현으로 흐를 위험이 있다. 로드맵 전체의 후속 확장 원칙은 존재하므로 U20 기능 전체를 U13 전에 구현할 이유는 없다.

**권고:** U13 상세 설계에서 예약 보호와 전조 후보 수용 조건을 정의하고 U20이 그 계약을 실제 배정에 소비하도록 한다. 모든 방에 전조를 미리 생성하는 방식으로 확정하지 않는다. 초기 데이터 검증과 U20 도입 시 재검증의 책임을 나눈다.

**해소 확인:** 후보 없음/있음, 이미 같은 층에서 배정됨, 진입 가능한 여러 첫 방, 지원·고정 노드 예약 포화, 재방문, 부화 노드 대체를 조합해 필수 배정·예약 보호·원정별 결정론을 확인한다.

## F04 모든 노드 RON 요구의 개별 책임을 착수 때 좁혀야 함

**구분:** 상세화 권고. **우선순위:** 중간. **담당:** U13–U17/U20/U21 → U27/U29.

[남은 결정 NEXT-20](../../../../game_rules/open-decisions.md#후속-설계구현-작업)은 모든 노드 유형의 정책·수치를 RON으로 설정하는 확장을 요구한다. 로드맵 §8.4는 도입 owner에 parser·검증·실행을 배정하고 U27이 합성하도록 해 책임 자체는 있다. 다만 지도 배정 RON, 활동 실행 정책 RON, 외부 제작자가 바꿀 수 있는 공개 범위가 다르다는 점을 작업별로 좁힌 목록은 아직 없다.

**권고:** 각 도입 단계의 기존 계획에 그 노드의 작성 항목·고정 규칙·허용값·실제 명령 소비·저장/세대·공개 여부를 짧게 적는다. 예를 들어 비용과 보상 후보만 작성 가능하다고 후퇴·완료 정책까지 전부 지원하는 것으로 집계하지 않는다. 반대로 RON 작성 요구를 본편 모든 서사의 자유 프로그래밍 권한으로 확대하지 않는다.

**해소 확인:** U27이 최초 구현을 맡지 않고 각 owner의 실제 근거를 합성할 수 있으며, U29는 허용된 변경과 금지/미지원 입력을 엔진 수정 없이 확인한다. 전체 미래 schema를 지금 동결하거나 별도 범용 노드 엔진을 선구현할 필요는 없다.

## F05 최초 전투 화면과 활성 전투 콘텐츠 전체의 완료 경계를 보강해야 함

**구분:** 화면 구현 책임의 구체성 보완. **우선순위:** 높음 — U26-A 상세화 전. **담당:** U21/U27의 조회·표현 계약 → U26-A/B → U26-C.

[로드맵 U26-A](../../ROADMAP.ko.md)는 starter 전투와 스트레스 화면을 구체적으로 요구한다. U26-B는 원정·경제·고유 도구 선택, U26-C는 기존 화면 통합을 맡는다. §7.4 MAIN-UI C와 부록 A는 활성 콘텐츠 표시를 요구하므로 전체 화면 목표가 없는 것은 아니다. 그러나 소환/진화·빙벽·개인 방어막·원천별 감염/연결망·일반 보스 형태 전환·특수 전장 작업의 **최초 화면 구현 완료를 어느 카드가 닫는지**는 starter에 비해 덜 구체적이다. C01/C06/C09/C10의 Unity 후속 열도 비어 있다.

**권고:** U26-A 내부에서 starter 연결을 첫 도달점으로 두고, 활성 전투 표현·입력이 필요한 기능군의 후속 완료 묶음을 명시한다. 전투 중 고유 선택은 U26-B와 소유를 정한다. U26-C는 이 산출물을 통합·복구 검증한다. 새 Unity 선행 단계나 Core 이전 조기 구현을 제안하는 것이 아니다.

**해소 확인:** 지원 콘텐츠 표에서 전투 기능군별 필요한 조회/이벤트·자산 참조·표시/입력 owner·실제 장면 검증으로 이동할 수 있다. 기믹마다 완성 아트를 지금 만들거나 내부 상태를 모두 UI에 노출할 필요는 없다. 실제 판단에 필요한 가시성·자격·예고를 검증한다.

## F06 일반 후퇴 메뉴 안내에 스트레스 예외 연결이 없음

**구분:** 확인된 상세 문서 연결 누락. **우선순위:** 중간. **담당:** U16-4/U26-A, 조작 규칙 문서.

[전투 조작의 설정과 전투 포기](../../../../game_rules/battle-controls.md#설정과-전투-포기)는 남은 후퇴 횟수 최대2와 0회 비활성 안내만 적고 있다. [유물 보상 노드](../../../../game_rules/relic-reward-nodes.md#스트레스-전투)는 전투 중 후퇴하면 상태를 복원하지만 노드를 소비하고 재도전할 수 없다고 명시한다. U16-4/U26-A 카드는 이미 이 예외의 실제 결과를 검증하므로 로드맵 전체에서 빠진 기능은 아니다.

**권고:** 조작 규칙에 명시 예외 링크를 추가하고, UI는 공통 2회 문구를 고정하지 않고 해당 활동의 후퇴 자격·결과를 표시하도록 상세화한다. 라운드 사이 ‘보상 받고 철수’와 전투 중 ‘미수령 보상 없이 후퇴’를 분명히 구분한다.

**해소 확인:** 일반전·전조의 2회 후퇴, 스트레스 전투 중 종료, 라운드 사이 성공 철수, 고유 후퇴 금지에서 메뉴 자격·안내·Core 결과가 일치한다.
