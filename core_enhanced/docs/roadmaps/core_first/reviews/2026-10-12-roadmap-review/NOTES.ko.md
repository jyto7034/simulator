# 로드맵 검토 메모

## 시작 시점

- 사용자는 검토 중 발견·메모의 지속 기록과 각 로드맵 단계 검토 종료 시 결과 문서화를 요청했다.
- Unity 조기 개발 제안은 검토 전제에서 제외한다. Core 명령·조회 준비와 후속 화면 연결을 검토한다.
- 작업공간에는 누적 제품·문서 변경이 있다. 검토 산출물은 이 디렉터리에만 작성한다.
- 최신 인수인계는 U11 완료와 U12 P2G-20 진행을 기록한다. 다만 현재 작업공간에는 U12 관련 소스·시험 파일도 존재하므로, 그 문구로 현재 제품 미착수를 단정하지 않는다. 이번 범위는 로드맵 설계 검토다.

## U00부터 U11까지 첫 대조

- 확인: 로드맵 상단은 U11 완료를 안내하지만 v4 본문의 ‘현재 상태’와 일부 카드의 ‘등록·대기’는 U08/U07-M의 과거 상태를 유지한다. 상단 안내로 해석 가능하지만 읽는 위치에 따라 다음 작업을 잘못 선택할 수 있다. 개발 단일 현황·최신 인수인계로 연결하고 역사 표제를 명시하는 정리를 권고한다. 완료 기록 자체의 오류로 판단하지 않는다.
- 유지: U04에서 미래 상태를 미리 모두 구현하지 않고 도입 owner가 저장 계약을 확장하도록 한 경계는 타당하다.
- 유지: U06은 Unity 없이도 명령·시간·타겟 조회를 요구한다. 화면 미구현을 이유로 전투 로직 완료를 막을 필요가 없다.
- 후속 확인: U07-M/U11의 개발용 측정·승인 기준을 U30-C/U30-P의 배포 적정값과 구별해야 한다. 현재 로드맵도 이를 명시하므로 새 차단 사유가 아니라 인계 의무로 다룬다.

## U00부터 U11까지 검토 종료

- U07-M 포함 13개 카드의 결과를 stages에 작성했다. 취소→한도/오류→결과/저장→전투→생성/유물→실제 mod 적용의 순서를 유지한다.
- F01을 확인된 문서 현재성 문제로 정리한다. 제품 완료의 취소나 재감사 사유로 확대하지 않는다.
- U12 Working Policy의 WR008·GEX-10 진입을 확인했다. 최신 인수인계의 P2G-20 안내는 뒤처진 조회 정보다. U12 실제 구현 완료 여부는 이번 검토에서 판정하지 않는다.

## U12부터 U17까지 대조와 판단 변경

- 최초 의심: U12 튜토리얼의 상점·정비·채용·보스가 U16/U19 이후 기능을 기다려야 하는 순환인가.
- 후속 확인: U12 `CODE_REVIEW.ko.md` T04/T05와 실행 PLAN은 기존 fixed tutorial executor·공용 활동을 재사용하고, 최소 실제 원정·유료 채용·입장 소진/귀환을 직접 닫도록 한다. U13 전체 graph·U14 전체 억제력·U15 미래 재료 vault는 제외한다. 순환으로 확정하거나 U12를 뒤로 옮기는 제안은 철회한다.
- F02: 상세 계획에서 U12가 직접 도입하는 유료 채용/최소 소진 계약을 U14/U16 후속 카드가 인수하는 지점이 충분히 구체적이지 않다. 새 담당자가 같은 자격/receipt/정산을 재구현하지 않도록 완료 시 실제 API·저장·시험 링크를 후속 카드에 인계할 것을 권고한다. 제품 결함 판정은 아니다.
- 정적 코드 대조: `world/combat.rs::recovery_node_ids_and_path_exists`는 읽은 시점에 selectable SavePoint/Gate 중심이며 `headquarters.rs::handle_recruit_employee`에는 채용가격 차감이 없다. U12 상세 검토가 이미 이 차이를 다루므로 새 미발견 제품 버그로 보고하지 않는다. 후속 지도·채용 확장이 같은 실행 자격을 소비해야 함을 확인하는 근거로만 사용한다.
- F03 후보: 룰북은 3–7층 계열 첫 방에 전조 후보가 있으면 반드시 배정한다. U13은 고정 지도/예약, U20은 나중 전조 배정을 소유한다. U13 카드의 예약 충돌 시험에는 전조 호환 자리 확보가 명시되지 않았다. U20 상세 계약과 함께 검토해 문서상 인계 공백인지 판단한다.
- 유지: 유료 보상 후보가 없으면 비용 전 거절, 무상 보상 후보0은 선택 생략이라는 차이가 U16에 정확히 배정됐다.
- 유지: 스트레스 수동 후퇴는 상태 복원과 노드 소비를 동시에 수행하는 명시적 예외다. 일반 2회 후퇴 규칙과 다르지만 충돌로 보고하지 않는다.
- 후속 확인: 일반 조작 문서의 후퇴 메뉴 안내에는 스트레스 예외 연결이 없다. U26-A 카드에서는 별도 종료 결과를 이미 요구하므로 화면 정책의 참조 일치를 확인한다.

## U18부터 U21까지 검토 종료

- U18의 완성 거미줄 재사용과 공통 감염/source 공개 범위, U19의 공통 보스와 최종보스 본체 제외가 일관된다.
- U21은 이미 실제 불가분 콘텐츠 묶음 단위 상세화를 요구한다. ‘범위가 크므로 한 Goal을 나누라’는 새 지적은 중복이므로 채택하지 않는다.
- F03은 U13→U20 예약/호환 인계 보완으로 남긴다. 신규 전조 엔진을 U13에 선구현시키거나 현재 생성기 결함으로 확대하지 않는다.
- F05는 전체 화면 목표 누락이 아니라 최초 구현 owner의 구체성 문제다. §7.4 MAIN-UI C와 부록 A의 화면 요구가 있으므로 ‘Unity에 고유 콘텐츠 지원이 전혀 없다’고 판단하지 않는다.
- 일반 마탄/흉탄 cameo, 공통 자격, 독립 보상 trial, 실제 최종보스 격파 획득을 구분하는 현재 구조는 유지한다.

## Core 최종 검증 구간 검토 종료

- U27은 지원/획득 정합성, U28은 복합 저장, U29는 독립 외부 작성, U30-C는 기술 비용, U32는 원정 종단, U33은 독립 판정을 소유한다. 목적이 달라 일괄 중복 삭제하지 않는다.
- §6.3/6.4/8.7은 변경 영향에 따른 증거 재사용과 불필요한 반복 금지를 이미 규정한다. 추가 검증 체계 대신 실제 계획에서 이 원칙을 지키도록 권고한다. 이번 검토에서는 과거 테스트 재실행 횟수·실행 시간의 과잉을 계량하지 않았다.
- U29 엔진 고정 뒤 U30-C 최적화는 영향을 받은 증거만 새 기준으로 확인하는 순환 없는 재검증으로 설명돼 있다. 단계 재배열 필요를 확인하지 못했다.
- NEXT-20은 담당 자체가 누락된 요구가 아니다. F04를 착수 시 개별 작성 범위/소비자 명세 보강 권고로 한정했다.

## Unity와 플레이 구간 검토 종료

- Unity 최초 구현은 U33 뒤에 유지한다. 지금 소규모 Unity를 선행 개발하는 제안은 하지 않는다.
- F05는 U26-A/B 내부에 활성 전투 표현·고유 입력의 최초 완료 책임을 명확히 하는 제안으로 확정했다. C 단계에서 모든 화면을 처음 만드는 방향은 기존 제외와 충돌한다.
- F06은 일반 후퇴 조작 문서의 예외 연결 누락으로 확정했다. 스트레스 규칙·U16-4·U26-A의 기능 요구는 이미 존재하므로 새로운 정책 결정을 요구하지 않는다.
- U30-P에는 딜러 무제한 반복/담보/재고와 스트레스 계속·철수 비교가 이미 있다. 기존 밸런스 조절 범위를 존중하고 새 판수 제한이나 무료 회복을 제안하지 않는다.
- 총 34개 활성 카드의 문서 검토 결과를 각각 작성했다. U16-1/2/3/4는 U16 결과와 상세 정책에서 검토했으며 별도 상위 단계 수로 더하지 않았다. 비활성 U22–U25/XF는 제외 경계만 검토했다.

## 산출물 확인과 종료

- 로드맵의 활성 작업 카드 ID 34개와 단계별 결과 파일 34개가 정확히 일치했다. U07-M·U26-A/B/C·U30-C/P를 포함하며 비활성 U22–U25를 완료 수에 넣지 않았다.
- Markdown 38개 안의 로컬 문서 링크 165개가 모두 존재하는 파일로 연결됨을 확인했다. 모든 결과에 판단·발견·권고·근거가 있다.
- 시작 때 기록한 룰북·상세 규칙·로드맵·단일 현황·인수인계의 해시가 종료 확인 때 동일했다. 원본 정책·제품을 수정하지 않았다.
- 추가로 참고한 U12 문서와 두 코드 파일의 종료 시점 해시도 INPUTS에 기록했다. 해당 파일 전체를 감사했다는 뜻은 아니다.
- 제품 빌드/테스트·성능 측정·독립 감사·Unity 실행은 하지 않았다. 이번 요청의 문서 검토와 기록 작성을 완료했다.
