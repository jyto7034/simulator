# Core 우선 로드맵 연속 실행 요청

2026-10-04 · 근거: 사용자가 이 대화에서 보낸 동일 제목 경로의 명시적 연속 구현 요청.

대상은 [활성 로드맵](../ROADMAP.ko.md)의 §5 순서와 활성 요구다. U00 인수와 U01 F01 교정부터 시작한다.
사용자 중단 요청, 승인 범위 완료 또는 현재 권한·환경에서 해결할 수 없는 실제 장애까지 진행한다.
정책·계획·구현·감사 문서를 읽었다는 사실만으로 완료를 주장하지 않는다.

## 위임과 종료 경계

- 필요한 P2G 정책 정리·코드 검토·계획·Goal·인계와 GEX 구현·자체 검증·독립 감사를 포함한다.
- 감사 finding의 교정·재감사를 포함하고, 선행 통과 뒤 다음 작업의 선택·실행을 허용한다.
- 단계 전환·감사 인계에서 재승인을 요구하지 않는다. 이번 요청에는 중간 사용자 단계검토 정지가 없다.
- 감사 대상의 구현에 참여하지 않은 별도 에이전트를 사용한다. 모델은 `gpt-6-astra`, 추론 강도는 `high`로 지정한다.
- 종속 구현은 선행 감사가 통과한 뒤 시작한다. 감사 중 제품 교정을 섞지 않으며 교정은 별도 GEX-10 pass로 수행한다.
- 승인 범위와 기존 명시적 합의 안의 필요한 정책 판단을 위임한다. 선택·이유·영향·실제 위임 근거를 해당 정책 문서에 기록한다.
- 정식 정책/완료 기준을 바꾸면 해당 P2G owner에서 불변 successor·검토·동결·인계를 갱신한 뒤 GEX를 재개한다.
  owner 반환은 자동 사용자 질문 대기가 아니다. 이번 상위 요청은 필요한 P2G 변경과 재검증까지 포함한다.
- 기존 계획과 유효한 증거는 재사용하고 전체 로드맵을 일괄 상세 설계하지 않는다. U 번호와 Goal을 1:1로 강제하지 않는다.
- 기존 사용자 변경·동결 target·감사 원본은 보존한다. 전체 저장소 commit/reset이나 개인 파일 삭제 권한으로 확대하지 않는다.
- 진척 보고는 계속하되 보고만 하고 종료하지 않는다. 중단 때 완료·미완료·현재 기준·정확한 재개 위치를 기록한다.

적용 원문: [P2G](../../../policy_to_goal_pipeline_revised_v2.md),
[GEX](../../../goal_execution_pipeline%281%29.md),
[로드맵 사용 가이드](../../content_authoring/guides/policy_to_goal_pipeline_roadmap_usage_v2_1.ko.md).
이 요청은 이번 활성 로드맵의 실행 권한이며 위 원문이나 과거 요청·감사 bytes를 소급 수정하지 않는다.

## 유지할 범위와 인터페이스 방향

Core 우선, Unity 후속, 개별 최종보스 고유 구현 제외를 유지한다. 공개된 미구현 최종방은 원래 공개 조건과
지도 연결을 보존하고 Core가 입장을 거절한다. 임의 귀환·격파·보상으로 우회하지 않는다.

기능별로 기존 CoreApplication 경계의 명령·결과·오류·조회를 함께 구현하고 실제 호출로 다듬는다.
미래 전체 command 목록을 지금 고정하지 않는다. Unity 접합 전 공개 계약을 정리·버전 관리하고,
선택한 실제 연결 경로의 소비자 검증을 수행한다. 서버와 네이티브 양쪽 지원을 자동 필수화하지 않는다.

## 현재 실행의 인수

[U00 인수](u00_20261004_001/INTAKE.ko.md)와 [정책 결정](DECISIONS_20261004.ko.md)을 따른다.
첫 제품 변경은 기존 `GS-CARX-001 / GOAL-CARX-01 / HA-CARX-001`의 F01 교정이다.
후반 원정 정책을 F01 교정 범위에 합치지 않는다.

## 2026-10-04 후속 사용자 요청 — 운영 지침 개정 인수

사용자가 네 단계와 구현 품질을 유지하는 효율 개선 검토 뒤, 실시간 구현과 병행하여 관련 문서를 한 묶음으로
수정하고 구현 담당 AI를 위한 기록을 남기도록 요청했다. 정확한 변경·구/신 revision·적용 경계·검증 근거는
[운영 개정 인수 기록](workflow_efficiency_update_20261004_001/RECORD.ko.md)이 소유한다.

기존 연속 실행·교정·독립 감사 권한과 모델/독립성 요구를 유지한다. 다음 안전한 pass 경계에서 변경을 인수하고,
원래 완료 조건과 고정 근거를 보존하면서 형식 사전 점검·공통 도구/fixture·위험 우선 검증·조건별 재사용을 적용한다.
진행 중 명령의 일괄 중단, 새 P2G 초기화, 기존 감사의 일괄 무효화 또는 제품 테스트 전부 재실행을 요구하지 않는다.
실제 변경 영향이 있거나 불명확한 부분은 원래 GEX currentness/교정 규칙으로 처리하며 자동 PASS로 바꾸지 않는다.


## 2026-10-05 사용자 요청 — 구현 중지와 다른 AI 인수인계

> 잠깐 작업을 정지하고, 문서에 지금까지 한걸 적어줄래? 이후 할 것도.
> 다른 ai 에게 구현을 인수인계할거라서 말이야.

이 요청에 따라 구현을 중지하고 [현재 인수인계](HANDOFF_20261005.ko.md)를 작성했다.
U00–U05 완료 이력, U06 P2G 완료/GEX-10 부분 구현, exact 현재 검증과 미완료를 분리했다.
중지 이후 제품 변경·새 제품 검증·후속 감사/구현을 실행하지 않았다. 재개는 후속 사용자 요청에 따른다.


## 2026-10-05 재개 후 두 번째 사용자 인계 요청 — 현재 중지

> 구현을 다른 ai 에게 인계할거야.
> 지금까지 한것과 앞으로 할 것을 문서에 남겨줄래?

첫 인계 뒤 연속 요청으로 U06을 독립 Complete / High까지 완료하고 U07 P2G/GEX 구현을 이어갔다.
이번 요청에 따라 제품 수정을 멈추고 [최신 인수인계](HANDOFF_20261005_002.ko.md)를 작성했다.
U07은 PC의 실제8MiB 예산 회귀를 교정 중이며 마지막12파일 변경은 포맷·컴파일·테스트 전이다.
현재 source/patch/문서 이전본은 [중지 상태](u07_pause_20261005_001/STATE.json)에 결속한다.
진행 중인 구현·검증 명령이나 U07 감사는 없다. U08 미진입. 중지 이후 제품 변경·새 테스트·새 감사는 수행하지 않았다.


## 2026-10-05 후속 사용자 요청 — U07 이후 실측 기반 실행 예산 준비

> 일단 지금은 구현이 진행중이라서, u07 의 후속 구현으로 남겨야겠다. 내용을 준비한 뒤, 문서를 한 번에 변경해줄래?

이번 요청은 진행 중인 U07에 제한 완화나 새 완료 조건을 끼워 넣는 지시가 아니다.
[U07-M 후속 작업](u07_memory_budget_followup_20261005_001/FOLLOWUP.ko.md)을 로드맵 §5에 U07 독립 완료 뒤 U08 전 준비 구현으로 등록한다.
정확한 변경·인수 경계는 [발행 기록](u07_memory_budget_followup_20261005_001/RECORD.ko.md)이 소유한다.
현재 담당자는 다음 안전한 pass 경계에서 인수하고 U07의 기존 구현·교정·검증·독립 감사를 계속한다.
이 문서 갱신을 이유로 현재 runner를 중단하거나 전체 P2G/테스트/감사를 재시작하지 않는다.
현재 U07의 exact 목표·한도·실패 원본·감사 target은 소급 변경하지 않는다.

U07-M은 기존 연속 실행 권한 안의 후속 선택 대상으로 남기며 이번 문서 작업에서 제품 구현을 시작하지 않는다.
실제 시작 시 기존 승인/현재성·필요한 P2G/GEX를 확인하고, 계획·구현·독립 감사 역할은 당시 최신 명시 사용자 지시를 따른다.
개발용 유한 측정 프로파일·bounded 수집·재현·조정 경로를 먼저 만들고, 최종 예산 수치는 U30-C와 U30-P에서 실제 근거를 쌓아 정한다.
전체 제한 해제·현재 실패 면제·측정값을 게임 권위로 사용·실행 중 자동 예산 변경은 이번 등록에 포함하지 않는다.
Unity 실제 플레이를 U07-M 완료의 선행으로 요구하지 않는다. 이후 별도 지시가 없으면 로드맵 §5의 갱신된 순서를 따른다.
