# Core-first 인수인계 — U07 비용 회귀 교정 중 사용자 요청 중지

## 가장 먼저 읽을 현재 상태

사용자가 다른 AI에게 구현을 넘기기 위해 작업 기록을 요청했다. **제품 수정을 중지했다. 이 문서는 완료 보고가 아니다.**
중지 요청 이후에는 인계 문서와 보관본만 작성했으며 제품 코드 변경, 포맷, 빌드, 테스트, 새 감사는 하지 않았다.
확인 당시 실행 중인 이 작업의 cargo/rustc/runner는 없었다. `u06_audit` 에이전트는 U06 감사 완료 후 유휴 상태이며 U07 감사는 시작하지 않았다.

- **U00–U06: 독립 완료를 인수한다.** U06 최종 `target/u06_002`, 독립 재감사 Complete / High, 열린 finding 0.
- **U07/B13·C01: P2G-00→60 및 GEX-00 완료, GEX-10 미완료.** 객체·진화·분절 HP·공개 소비자를 구현했다. 전체 기능 검증 뒤 PC 성능 검증에서 실제 예산 회귀를 발견했고, 교정 코드를 일부 적용한 상태다.
- **현재 마지막 12개 파일 교정은 포맷·컴파일·테스트 전이다.** 앞선 통과 결과를 지금 소스의 통과로 읽으면 안 된다.
- **U07 최종 증거 선정·GEX-10 완료·target 동결·독립 감사는 아직 없다. U08은 미진입이다.**
- 다음 AI의 첫 작업은 아래 §4의 부분 교정을 검토하고 작은 검증 및 PC 회귀 재측정을 완료하는 것이다. U00/U01/U06이나 U07 P2G부터 재시작하지 않는다.

이 문서가 최신 인계다. [첫 인계](HANDOFF_20261005.ko.md)는 U06 부분 구현 당시의 역사적 원본으로 보존했다.

- 독립 actor의 실제 진영·Stationary/Path·자기 basic/auto cast. 함정의 현재 trigger/피해 footprint·생성 Attack snapshot·성공 공격 후 단일 소모. 함정은 unit/HP adapter가 아니다.

## 4. 중지 직전 부분 적용한 교정 — 아직 검증 전

현재 source hash: `eeb3897087d6a44c472892e4f3970362737603457173050dcf7626b1a89aa460` (388파일).
[현재 manifest](u07_pause_20261005_001/PRODUCT_CURRENT.json), [기계 판독 상태](u07_pause_20261005_001/STATE.json), [미검증 변경 patch](u07_pause_20261005_001/UNVERIFIED_CORRECTION.patch)를 인수한다.
patch는 이미 작업 트리에 적용된 변경의 기록이며 다시 적용하는 명령이 아니다.

적용 내용:

- `game/battle/runtime_facts.rs`의 별도 `independent_object` 및 `reinput` 포인터를 하나의 optional `Arc<ExtendedSourceObservation>`으로 묶었다. 일반 source는 기존 inline 크기로 돌아가도록 의도했다. 실제 compiler 크기는 미확인이다.
- 공유 저장소가 필요한 경우 `extended_source_observation`에서 allocation 전에 `size_of +64`를 admit한다. CloneShape와 retained extent에 wrapper/실제 payload를 포함했다.
- `independent_object()`와 `reinput()` getter, 원래 공개 JSON 필드/생략/순서를 유지하려는 수동 Serialize의 borrowed projection을 추가했다.
- `independent_origin()`을 fallible Result로 바꿨다. reinput을 제거하면서 object provenance를 보존해야 할 경우 저장소 admission을 먼저 수행한다. 실행 자격 제거는 유지한다.
- basic/trap/skill 생성, command source 전달, queue의 EMPTY, reinput producer/reader, action source validation, 관련 시험 호출을 기계적으로 연결했다.

## 5. 정확한 재개 순서

1. 현재 manifest와 작업 트리, 실행 중 프로세스를 다시 대조한다. 중지 시 구현/검증 명령은 모두 종료돼 있었다. U06 최종 감사를 인수하고 U07 P2G/기존 기능을 재작성하지 않는다.
2. §4의 교정을 먼저 검토한다. 전체 repository에서 옛 field 접근과 Result 호출 누락을 확인한다. JSON의 공개 필드/순서/생략, 원래 resource/action/flow/reinput 권한, object 원본 provenance, CloneShape와 admission 실패 전 무변경을 확인한다.
3. 형식/컴파일을 작게 점검하고 source provenance·기본/auto cast·trap·reinput Goodbye·독립 pool·native late-failure 집중 검증을 수행한다. 공통 source 크기와 legacy JSON 보존, origin+reinput 공존 후 reinput만 제거, wrapper allocation 거절의 무변경을 의미 있는 시험으로 보강한다.
4. **전체 통합을 다시 돌리기 전에 PC 회귀를 재확인한다.** `C/prepare_pc.py`를 새 label로 실행해 현재 source와 일치하는 새 isolate를 만든다. 기존005 isolate `/tmp/r06-completion-pc-ga76ibws`는 교정 전이므로 새 소스의 증거로 사용하지 않는다. 기존 계측/입력은 그대로 유지한다.
