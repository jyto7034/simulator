# U16 현재 판정 — Complete / High, XP 성능 개선은 비차단 기록

사용자는 XP 비용 문제가 일반적인 플레이에서 확인된 결함이 아니라 극단적인 제작 입력으로 재현된 것임을 확인한 뒤, **“응 문서로만 기록하고, 넘어가자.”**라고 지시했다. 이에 따라 F-U16-FINAL-001은 문서에 남기는 비차단 성능 개선 항목으로 전환한다. 코드 교정·리팩토링·새 테스트는 이번 요청에 포함하지 않는다.

현재 U16 판정은 **Complete / High / 열린 완료 차단 0건 / 비차단 개선 기록 1건**이다. 근거는 기존 종합 감사의 나머지 65개 수용 조건 및 정상/대표 확장 비용 검증, 이번 사용자 수용 결정이다. U16-4 A10의 정상/대표 확장 비용 근거는 유지하며, 극단적인 XP 수치의 효율 개선을 현재 완료에 필요한 추가 교정 조건에서 제외한다. 새 감사를 수행했거나 XP 코드를 고쳤다는 의미는 아니다.

## F-U16-FINAL-001의 현재 처분

- **상태:** 기록 후 보류, U16 완료 비차단. 기존 P2·필수 교정·필수 재감사 지정은 현재 판정에서 철회한다. 자동 후속 작업으로 예약하지 않는다.
- **발생 근거:** 지원 RON 작성 경로는 맞다. 외부 파일/메모리 임의 변조 전용 사례로 재분류하지 않는다. 다만 재현에는 XP 요구량1과 최대1억 XP 보상이라는 극단적인 조합을 사용했으며, 일반 콘텐츠/플레이에서 성능 장애가 확인된 것은 아니다.
- **관측 사실:** 같은5라운드의 마지막 전투 tick·정산 전체가 개발 빌드에서 약0.111/0.518/4.397초였다. XP 함수 단독 시간은 아니다. 약87.8만 native work도 전체 연산의 계량값이며 XP 반복 횟수와 같은 단위가 아니다. 두 생존자의 약2억 회 레벨업 반복은 계량에 반영되지 않는다. 산술 결과와 요청 heap 회수는 세 변형 모두 정확했다.
- **향후 참고:** 실제 콘텐츠에서 큰 XP 지급을 도입하거나 성장 계산을 정비할 때, 작성 곡선의 유한 구간과 반복 tail의 나눗셈/나머지 처리를 검토할 수 있다. 현재 구현 일정·완료 선행 조건으로 지정하지 않는다.
