# Core 우선 로드맵 최신 인수인계 — 현재 상태

현재 상태의 단일 진입점이다. 상시 규칙은 [연속 실행 지시서](CONTINUOUS_EXECUTION_INSTRUCTIONS_REVISED.ko.md), 과거 발화·인계는 [이력 안내](EXECUTION_HISTORY.ko.md), 상세 수용 조건은 [PLAN](../../../goals/core_expedition_lifecycle/execution/single_goal/PLAN.md), 실제 실행은 [EXPERIMENTS](../../../goals/core_expedition_lifecycle/execution/single_goal/EXPERIMENTS.md)가 소유한다. 별도 STATE 장부를 만들지 않는다.

문서 갱신: 2026-10-13 05:40 UTC. 직전 최신본은 [HANDOFF_20261013_003](HANDOFF_20261013_003.ko.md)에 원문 보존했다. 최신 사용자 요청 “마저 진행해줄래?”에 따라 **연속 실행 중**이며 사용자 정책 판단·checkpoint 대기가 아니다. U12 GEX10의 구현·독립 시험·공개/정상 host·비용 검증을 마치고 최종화·비참여 감사와 다음 승인 로드맵까지 이어간다. P2G20–60/GEX00 및 WR-CEXL-008/FPF-CEXL-001/GS-CEXL-001은 재시작하지 않는다.

## 실제 마지막 실행과 바로 다음 행동

이번 재개 확인에서 Sol이 기존 `release_compile006` session `25883`을 회수했다. 도구 wrapper는 **exit143**, 같은 세션 재조회는 Unknown process였다. [release006 원문](../../../goals/core_expedition_lifecycle/execution/single_goal/product_parts/release_compile006/)에 RESULT와 SOURCE_AFTER가 없어 실제 Cargo 종료 코드·child reaped·빌드 성공을 주장할 수 없다. 마지막 collector 관측은 **2026-10-13 05:27:59 UTC / monotonic240.023초**, compiler CPU233.79초·RSS2,162,057,216바이트다. 이 시각 이후 실행 지속 시간을 추정하지 않는다.

현재 /tmp public binary가 보이지 않아 기존 Sol이 캐시·산출물 가시성과 복구 경로를 확인 중이다. 새 sandbox의 가시 /proc만으로 이전 namespace의 전체 프로세스 종료를 단정하지 않는다. 중복 빌드는 시작하지 않았고 중단 원문을 보존한다. 정확한 다음 행동은 **같은 Sol이 기존 실행의 회수 결과와 환경을 정리하고, 격리·입력 보존이 확인된 방식으로 필요한 빌드를 복구**하는 것이다. 새 실행은 기존 것과 구별된 원문을 남긴다.

검토된 후속 묶음은 유효 release public/normal_host 확보 → 같은 공식 입력·유한 한도의 Tutorial complete003 → 성공 시 영향받는 Expedition complete002 한 번 → 이미 검토된 별도 정상 승인 입력 준비기 실행이다. 일반 빌드/검사마다 메인 새 승인을 기다리지 않으며 의미 있는 변경·실패·수용 경계에서 Astra 검토한다. 시험 측 실패는 독립 Astra에게, 제품 결함은 Sol에게 반환한다. worker/calibration 전에는 아래 실제 durable 시험 누락을 묶어 보완한다.

## 현재 유효 결과와 남은 실패

- Core 기능 검사는 [EXPERIMENTS](../../../goals/core_expedition_lifecycle/execution/single_goal/EXPERIMENTS.md)의 functional010–013 및 각 이전 실행의 정확 범위로 재사용한다. 마지막 HQ 교정 두 사례는 functional013에서 실제2통과했다. 별도 invocation들을 하나의 전체 통과로 합치지 않는다.
- `public_hq003`과 `public_save002`는 현재 공식 외부 pack으로 출발·3역할·HQ/첫 전투·SavePoint·새 CoreApplication Continue를 실제 수행했다. DirectHost Continue는 같은 프로세스의 새 application 복원이며 별도 OS 프로세스 검증으로 표시하지 않는다.
- `public_expedition_complete001`은 공식3층·실제3전투·3HQ·3SavePoint 뒤 깊이3 **Exhaustion Return**을 수행했다. 정확6장비/3파편 vault 이관, sequence1·active marker None·story Pending·Continue None 및6개 checkpoint byte 동일 쌍을 메인이 확인했다. Gate 귀환·story ACK·다음 출발·normal approval까지 검증한 결과가 아니다.
- `public_tutorial_complete002`는9.793초/exit1/reaped,73명령·3212tick으로 둘째 전투에서 기존3000tick 한도에 도달했다. 세 역할의 공동 배치는 성공했으나 optional Dealer 치료를 endpoint보다 우선해 적의 최종 위치를 공격하지 못했다. 실제 공개 preview에는 endpoint와 Tank 치료를 만족하는 조합이 존재한다. 실패 원문과 /tmp→durable 동일 bytes·입력 불변을 보존했다.
- 독립 Astra의 [endpoint 우선 교정](../../../goals/core_expedition_lifecycle/execution/single_goal/test_parts/tutorial_endpoint_priority001/)을 메인이 전체 diff로 검토했다. lib.rs30,556바이트 SHA `cdaa1248baa828bcfd5e67072c1eb55bcbe30578bf4404c84d7696ad671da715`; 점수 순서·tuple 해석·주석만 변경했다. 제품/콘텐츠/수치/3000tick·512decision 한도는 바꾸지 않았다. 이 교정의 빌드·Tutorial 완주 검증은 아직 완료되지 않았다.

## 역할·소유와 입력

메인 `/root/core_main_astra`는 `gpt-6-astra/high`로 계획·실제 코드/증거 검토·품질 수용을 맡는다. 제품 및 유일 실행 담당은 기존 `/root/u12_product_resume2` (`gpt-6.1-sol/xhigh`), 독립 시험·fixture·probe 작성/교정은 `/root/u12_tests_resume` (`gpt-6-astra/high`)다. 기존 작성·참여 이력은 보존한다. root는 사용자 소통을 지원한다. 최종 감사는 이 Goal의 계획·제품·시험·교정·수용 전 검토에 참여하지 않은 별도 Astra high에게 배정한다.

현재 제품/시험 writer0이며 Sol은 중단된 세션과 환경을 회수 중이다. 마지막 release006 입력은619파일 manifest SHA `a0f1812196efd64ec9ba658bb88b9ffb68da3f2b10aa927ffe4334ab83f826e6`; release005 이후 유일 delta는 위 probe lib다. 보조 Python·정상 입력 profile은 별도 결속 기록을 재사용한다. 빌드는 지원 `tools/cmva_build.py`의 plain release·동일4package dependency graph를 사용한다. 기존 collector의60초 child/descendant 진단과 합의된 중단 기준을 유지하며 빌드 CPU/RSS를 게임 비용으로 해석하지 않는다.

작업공간 `/mnt/f/work/simulator`의 누적 dirty를 보존한다. HEAD만으로 실제 source를 식별하지 않으며 기존 baseline·preimage·원시 실패를 재사용한다. 전체 reset/clean/stash, 동결 문서·과거 artifact 재생성은 하지 않는다.

## 다음 필수 묶음과 재사용 경계

[독립 시험 계획](../../../goals/core_expedition_lifecycle/execution/single_goal/test_parts/TEST_PLAN_001.ko.md)의38수용/19통합/10차원/3최종 노드가 기준이다. Tutorial 고정3층 실제 완주 및 원정으로 얻은 nonempty profile 불변, 정상 승인 host의 실제 출발·채용·전투·귀환·대여·story ACK·다음 인스턴스, 별도 프로세스 저장/복원과 accepted crash가 남았다. 기존 server 시험의 Abandon/reset crash와 초기 stale Start만으로 **실제 획득품 loan/Return·profile-only story ACK의 durable/CAS 경계**를 대체하지 않는다. 독립 author가 이 관련 누락을 worker calibration 전 묶어 보완한다.

별도 정상 승인 준비기는 실제 성공 HQ6명령의 `Normal`/`preparation=None` 입력을 만들며 현재 공식 RON과 정확 runtime profile을 보존한다. 아직 실행·paired worker calibration·adoption·normal admission은 없다. 이 짧은 기능 승인 문맥은 실제 전체 normal gameplay 및 G11 비용 검증을 대체하지 않는다.

G11은 별도 trusted 측정 pack의 기존6개 적·funding160·geometry/encounters·roster16/500/1000·배치1/8/8·60×1000ms recipe를 유지한다. 일반 official의 밸런스 근거와 구분하며 현재 준비·실측·비용 판단은 미완료다. 실제 source 영향에 필요한 회귀, canonical 문서/제거 계약, 수용 coverage, Astra 수용 검토, 정역 복원·exact target·비참여 전체 감사 후 다음 승인 작업으로 이어간다.

정책·계약 판단은 [Working Policy](../../../goals/core_expedition_lifecycle/WORKING_POLICY.ko.md), [P2G60](../../../goals/core_expedition_lifecycle/P2G_60_HANDOFF_001.json), [기술 판단](../../../goals/core_expedition_lifecycle/execution/single_goal/EXPERIMENT_NOTES.md)을 필요한 범위만 읽는다. 기억·신뢰 제거는 확정이며 재질문하지 않는다. 선행 U11 독립 완료는 [완료 인수](u11_closure_20261012_001/RESULT.ko.md)와 기존 감사가 소유하되 U12 변경을 과거 PASS로 덮지 않는다.
