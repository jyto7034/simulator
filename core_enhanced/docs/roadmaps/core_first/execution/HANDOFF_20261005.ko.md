## 7. 가장 가까운 미완료·발견 사항 — 먼저 확인할 것

다음 항목은 **구현/수정하지 않은 상태**다. 마지막 대화의 계획을 완료된 코드로 오해하지 않는다.

1. **Heal footprint retained extent 누락 확인 필요/수정 대상.**
   `game/battle/core/sustained.rs::basic_extent`는 기존 defense range/delivery만 합산한다.
   새 BasicAttackAction::Heal의 동적 footprint를 overlay용 basic_bases에 보관할 때 추가해야 한다.
   일반 clone 시험 통과가 이 새 조합의 비용 완결을 증명하지 않는다. admission 실패·복원도 집중 검증한다.
2. **Heal + BasicAttackOverlay의 소비 계약 확인.**
   overlay는 기본 delivery를 바꿀 수 있고 현재 Heal resolve는 Instant다.
   non-Instant overlay와 Heal 조합을 정상 자격/시작에서 명시 거절하거나 정책 내 일관된 지원 경로로 닫아야 한다.
   범위만 바꾸는 overlay와 순수 치유 의미를 함께 검토한다. 이 조합은 아직 시험하지 않았다.
3. **버서커의 시간제 흡혈 / 최후의 전선의 시간제 피해 감소 미구현.**
   현재 BasicLifesteal은 장비 OnAttack snapshot에만 있고 BuffKind는 CC/DoT뿐이다.
   PLAN 마지막 `GEX-10 STARTER consumer 보완`은 설계 기록이며 제품 반영은 시작하지 않았다.
   제안: R05 Sustained owner에 CombatModifiers를 추가하고 같은 expiry/cancel/withdraw/death/use_lifetime을 쓴다.
   피해 감소는 방어력 증가로 대체하지 않고 damage reduction 계산에 연결한다.
   흡혈은 실제 HP loss 기준이며 순수 기본 치유에는 적용하지 않는다.
4. 위 설계의 구체적 연결점:
   `ability/sustained.rs` typed schema/validate/view;
   `core/sustained.rs` Record/CloneShape/retained/begin/query/expiry;
   `core/damage_runtime.rs::damage_source_snapshot_for_unit`, `execute_committed_damage`, `finish_basic_lifesteal`;
   `battle/damage.rs::BasicLifestealSnapshot`와 `DamageSourceSnapshot::fact_retained_extent`.
   optional `Arc<RuntimeFactSource>::observation()`으로 파편/작성 site 관측 출처를 보존하는 안을 기록했다.
   이 API는 delivery/finite-child/resource 권한을 제거한다. 새 source와 snapshot의 실제 저장/clone 비용을 함께 입장시켜야 한다.
5. AllySingle은 현재 Instant만 지원한다. public authoring/정상6세트 테스트로 strict 음성 입력과 actual active 회복을 더 검증한다.
   현재 두 ally 시험은 selector/자격 검증이며 정상 active skill 전 과정 인수의 대체물이 아니다.

- 역할 대응 후보(아직 데이터 미작성): field_medic=단일 치유, maintenance_tech=영역 치유,
  breach_guard=방패, containment_trainee=대검, scout_runner=총, records_clerk=검. hq6도 대응한다.

- 기본 세트는 총/아드레날린, 검/버서커, 방패/최후의전선, 대검/돌파(전방 피해+짧은 자기 shield),
  단일 지팡이/강한 단일 회복, 영역 지팡이/약한 선택 영역 회복이다.
- **수치/기간/범위 RON 값은 아직 확정·작성하지 않았다.** 위임된 초기 조절값을 PLAN에 기록하고 실제 플레이로 검증한다.
  현 WeaponArchetype에는 Sword/Spear/Shield/Bow/Gun/Staff가 있다. 대검의 별도 archetype 추가 여부도 아직 제품 결정이 아니다.
- `employee.rs::EmployeeInitialLoadout`에는 현재 equipment_ids와 baseline_skill_fragment_ids만 있다.
  별도 optional active fragment ID를 도입하고 strict reference/compatibility 검증을 추가하는 방향이다.
- `data/validation.rs::validate_starter_employee_loadout_references`는 현재 starter baseline을 필수로 본다.
  새 active 사본과 기존 명시적 baseline fixture 경로를 구분해야 한다. active를 baseline list에 넣으면 실행되지 않는다.
- `world/helpers.rs::initialize_selected_starter_employees`의 정상 reward grant→장비 paired assignment를 공통화하고,
  `world/headquarters.rs::handle_recruit_employee`에도 같은 initial loadout owner를 적용한다.

  `validate_equip_skill_fragment_payload`는 일반 UI 컨텍스트 gate를 포함하므로 초기화 시 통째로 호출하는지 주의한다.

- 시작/채용은 전체 transaction 내에서 직원·장비·파편·UUID·node 완료를 함께 commit해야 한다.
- starter 변경으로 기존 시험 입력이 바뀌면 원래 무기/passive/수치와 oracle을 explicit fixture로 보존한다.
  새 공식 세트의 실제 grant/active/이전 검증은 별도로 한다.
- 동시 배치8은 현재 `state::deployment_candidate_eligibility`에 없다. condition 우선→무기/zone→TP/개인대기/상한을 공통 query/최종 gate에 연결한다.
  누적 participant 수와 live deployed 수를 혼동하지 않는다. roster10도 현재 채용 경계에서 확인한다.
