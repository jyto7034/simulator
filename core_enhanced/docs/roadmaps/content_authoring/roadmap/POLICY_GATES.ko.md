# 정책 결정 목록

개정일: 2026-09-09 / 계획 v2.1. 아래의 PG는 구현 선행 결정 지점이지 이미 통과한 승인 기록이 아니다. 기존 사용자 결정은 다시 질문하지 않는다. 이번 로드맵 작성은 구현 실행이나 모든 미정 gameplay의 동결을 뜻하지 않는다.

## gate 운영

기술적인 자료구조·파일 배치·정적 인덱스·캐시 선택은 구현자가 제안할 수 있다. 플레이어가 보는 결과나 저장 데이터 손실 의미가 달라지면 정책 선택으로 취급한다. 기존 숫자와 문서의 예시를 묵시적인 승인으로 사용하지 않는다.

미정인 동작은 지원할 정책 옵션의 타입·검증·테스트를 만들 수 있으나 공식 profile의 기본값을 몰래 선택할 수 없다. Gating된 작업은 `policy_decision_required`로 기록하며, 의존하지 않는 독립 Goal은 별도 실행할 수 있다. 필수 대표/공통 기능에 필요한 gate가 미해결이면 최종 제작 기반 완료를 주장하지 않는다. 공식 전체 밸런스·획득 빈도는 이번의 별도 비범위로 남겨둘 수 있다.


## v2: 정책 gate와 설계 준비 점검은 다르다

P는 사용자 결정이다. R은 본 패키지의 권장 구조이고 L은 코드 기반 상세 설계다. PG07의 정확한 manifest/namespace/hash 형식, PG08의 계측 방법 등 기술 사항은 이미 승인된 방향 안에서 구현 AI와 검토자가 결정할 수 있다. 실제 저장 손실·플레이 결과·성능 목표가 달라지는 선택은 해당 정책 owner와 확인한다.

A03/A04가 제안한 milestones, closure·층화, branch ancestry·true join, 공개 transaction boundary의 fault 처리는 코드 기반 대조 후 채택하는 R이다. 설명에 등장했다고 미정 PG가 통과한 것이 아니다. 반대로 내부 container 선택까지 PG를 이유로 사용자에게 미루지 않는다.

각 CA의 DG는 관련 생산자·소비자·상태·테스트를 확인하고 exact L 설계를 기록하는 단계다. 계획·DG·구현·실행 검증·완료는 각각 다른 상태다. 공유 계약 변경은 DESIGN_DELTA로 소비자 영향과 실제 회귀를 기록한다.
