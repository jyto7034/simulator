# CA15 — 연결망·상태 전파·공간 집계

계획 v2.1 · 2026-09-09 · 단계 M5 · **실행·DG·구현·프로젝트 검증 모두 미수행**

계획상 선행 후보: CA13, CA14  
공유 계약: K05, K06, K08, K09  
권장 설계: [03_RUNTIME.ko.md](../architecture/03_RUNTIME.ko.md) / [04_COMPOSITION.ko.md](../architecture/04_COMPOSITION.ko.md) / [08_WORKED_EXAMPLES.ko.md](../architecture/08_WORKED_EXAMPLES.ko.md)

> **순서 근거:** 위 선행은 계획상 후보다. [의존성 기준](../DEPENDENCIES.ko.md)에 따라 선택 범위의 실제 코드·중간 상태를 P2G-20/40에서 검토하고, GEX 인수에서 current 선행 결과를 확인한다. 이 카드는 정식 Goal·실행 준비 증거가 아니다.

## 1. 목표와 범위

설치물 연결, 원천별 감염망, 타일별 축적을 캐릭터 전용 코드 없이 구성한다.

근접 relation, 연결 node 집합, 선 통과/접근 사건, 결정론 순서·유한 전개·node 소비를 지원한다. 원천별 status membership과 살아 있는 대상 집계·시간 축적을 resource에 연결한다. 전파 transaction 내 신규 member의 즉시 재전파를 막고 lethal hit의 전파 우선순위를 적용한다. 타입화된 group-by tile, sum/max, source 제한과 일제 소비/발동을 지원한다. 래티씨아 전용성은 definition/형태 selector이고 연결 알고리즘은 일반 기능이어야 한다.

## 2. 권장 구조와 선택 이유 — R

**채택안:** RelationStore의 node/edge와 StatusMembership/ResourceAggregator를 구분해 사용한다. 전파·기폭은 source-scoped 집합 snapshot과 transaction이다.

**이유:** 모든 감염을 global network로 합치거나 트리거마다 재귀 확장하면 원천·사망 우선순위·소비 의미가 깨지기 때문이다.

## 3. 실제 코드에서 확인할 질문 — D1

공간 조회·line crossing·movement event, status cleanup/death receipt, object evolution과 delayed child 상태를 조사한다.

연결 후보: `core_enhanced/src/game/battle/core/spatial.rs; battle/core/skill_runtime/area.rs; battle/core/death_runtime.rs; CA04 resource store; CA06 events; CA13 chains; docs/skills/abnormality_skill_fragments_design_notes.md의 래티씨아·포자 감염·죽을 나비`

위 경로는 조사 입구다. 실제 선택 작업에서는 관련 호출자·검증기·소비자·상태·테스트를 모두 연결해 읽고 확인한 범위를 적는다. 새 설계 타입을 현재 API로 가정하지 않는다.

## 4. 구현 전에 작성할 상세 설계 — D2/DG

edge/node key·invalidation, propagation transaction set, source-scoped aggregate, consumption order·fan-out bound, join/root와 suppression matrix.

공통 [설계 절차](../DESIGN_WORKFLOW.ko.md)의 DG 표를 충족한다. R을 변경하면 현 코드 근거·대안·영향 소비자·P 정책 보존 여부를 기록한다. exact 함수·자료구조는 구현자의 L 설계이며, K 의미 변경은 L1 검토, gameplay 변화는 L2/PG다.

## 5. 구현·시험 묶음

node relation → 접근/선 사건 → ordered consume → infection membership → tile aggregate·detonation.

새 상태의 snapshot/rollback/save 영향은 이 작업에서 동반한다. CA19에 모든 저장 구현을 미루지 않는다. 작업 범위에 해당하지 않으면 “해당 없음”과 근거를 적는다.

## 6. 정책 결정 지점

PG02–PG06. 연결망 소비 범위·공간 tie-break·여러 원천 시체 소유권은 미정 상태를 보존한다.

이미 합의한 사본별 개화·외부 팩·레거시 없음 등의 P 정책은 재질문하지 않는다. 미확인 구현 사실은 D1 조사로 해결한다.

## 7. 필수 검증과 완료 증거

T16. 같은 source의 감염만 기폭·소비한다. 기폭 자체는 새 감염·사망 전파를 만들지 않는다. 타일과 유닛 스택은 타일 단위로 집계한다. 연결 node가 삭제·진화해도 stale 링크가 재발동하지 않는다.

**v2 추가 기준:** E06과 포자/나비 최소 fixture로 노드 제거·원천 분리·같은 transaction 재전파 차단을 검증한다. 미정 전체 소비를 암묵 확정하지 않는다.

완료 증거는 실제 revision·명령·실행 수·기대/실제 상태·semantic trace·팩 fingerprint·남은 제약을 포함한다. DG 완료와 test PASS를 혼동하지 않는다.

## 8. 금지·비범위

전역 감염망 합치기, 콘텐츠 이름별 분기, 연결 전체 소비를 미정인데 확정, node당 효과를 무제한 재귀.



## 9. 인수 산출물

relation/membership/aggregate primitive와 세 구조의 최소 재조합 fixture. 공식 전체 데이터 이식은 CA20 범위와 구분한다.

추가로 현재 코드 조사 기록, 채택한 L 상세 설계, DG 검토 근거, 발생한 설계 변경 이력, 실제 검증·완료 검토를 연결한다. 해당 파일명은 현재 저장소 workflow에 맞춘다. 이 카드 자체는 실행 기록이 아니다.
