# CA18 — 파편 침식과 직원 대가의 특수 경계

계획 v2.1 · 2026-09-09 · 단계 M6 · **실행·DG·구현·프로젝트 검증 모두 미수행**

계획상 선행 후보: CA06, CA09, CA10, CA13, CA16  
공유 계약: K04, K06, K09  
권장 설계: [03_RUNTIME.ko.md](../architecture/03_RUNTIME.ko.md) / [05_BOSS_AUTHORING.ko.md](../architecture/05_BOSS_AUTHORING.ko.md)

> **순서 근거:** 위 선행은 계획상 후보다. [의존성 기준](../DEPENDENCIES.ko.md)에 따라 선택 범위의 실제 코드·중간 상태를 P2G-20/40에서 검토하고, GEX 인수에서 current 선행 결과를 확인한다. 이 카드는 정식 Goal·실행 준비 증거가 아니다.

## 1. 목표와 범위

일반 효과와 구분되는 침식 처형을 도입하면서 wave·결과·직원 상태의 정확성을 보존한다.

일반 시전 자격과 실제 실행 시점을 연결해 trauma 임계·공명·대상 파편 조건을 평가한다. 공식 최종 보스 파편 제외·세트 무관을 유지한다. 직원 Withdrawn, 현재 전장 적의 집합 캡처·kill finalize, 부가 trigger 억제, attempt trauma100 반영을 결과 확정 전에 처리한다. 미출현 wave를 제거하지 않는다. 코어의 강제 연출 정지와 host elapsed 입력을 battle-time/배속과 분리하고 읽기만 허용한다. Breakdown node countdown·회복·사망을 최신 승인 정책에 연결한다. 침식된 유물 variant와 별도 기능으로 유지한다.

## 2. 권장 구조와 선택 이유 — R

**채택안:** 침식은 일반 damage flow가 아닌 특수 cast replacement transaction이며 DeathReceipt의 bookkeeping과 부가 effect dispatch를 분리한다.

**이유:** 거대한 Damage/Despawn으로 표현하면 증폭·OnKill·wave 진행·직원 대가 중 일부가 잘못 처리되기 때문이다.

## 3. 실제 코드에서 확인할 질문 — D1

pause 중 cast 접수/실행, resonance commit, withdraw cleanup, death/wave/terminal ordering, attempt trauma/Breakdown/result와 clock 포트를 읽는다.

연결 후보: `core_enhanced/docs/tmp/ego_corrosion_system_design_notes_2026-08-19.ko.md; src/game/world/combat.rs; battle/core/sim.rs의 시전 경계; battle/core/death_runtime.rs; wave_runtime.rs; world/state.rs::BattleEmployeeAttemptState; employee.rs; world/node_flow.rs; src/application.rs`

위 경로는 조사 입구다. 실제 선택 작업에서는 관련 호출자·검증기·소비자·상태·테스트를 모두 연결해 읽고 확인한 범위를 적는다. 새 설계 타입을 현재 API로 가정하지 않는다.

## 4. 구현 전에 작성할 상세 설계 — D2/DG

실제 대체 지점, target set snapshot, cost·withdraw·trauma·kill transaction, effect suppression 종류별 matrix, forced host-clock 입력, terminal guard와 node collapse.

공통 [설계 절차](../DESIGN_WORKFLOW.ko.md)의 DG 표를 충족한다. R을 변경하면 현 코드 근거·대안·영향 소비자·P 정책 보존 여부를 기록한다. exact 함수·자료구조는 구현자의 L 설계이며, K 의미 변경은 L1 검토, gameplay 변화는 L2/PG다.

## 5. 구현·시험 묶음

cast gate → special kill path → attempt 대가 → clock → wave/result/Breakdown 조합.

새 상태의 snapshot/rollback/save 영향은 이 작업에서 동반한다. CA19에 모든 저장 구현을 미루지 않는다. 작업 범위에 해당하지 않으면 “해당 없음”과 근거를 적는다.

## 6. 정책 결정 지점

PG04, PG06, PG09. 임계치·연출 길이·동시 노드 회복/사망 순서는 미정 숫자/의미를 분리한다.

이미 합의한 사본별 개화·외부 팩·레거시 없음 등의 P 정책은 재질문하지 않는다. 미확인 구현 사실은 D1 조사로 해결한다.

## 7. 필수 검증과 완료 증거

T19. Pause 입력만으로 침식하지 않는다. 일반 damage amplifier·OnKill·적 OnDeath 없이 현재 적 처치가 wave에 반영된다. 전투가 즉시 끝나도 직원 대가가 한 번 반영된다. 강제 정지 중 mutation 실패는 무변경이며 release된 기존 projectile 수명은 기존 정책을 따른다.

**v2 추가 기준:** 죽음을 관찰하는 모든 subscriber를 무작정 끄지 않는다. wave·필수 bookkeeping은 유지하고 금지된 전투 부가 효과만 억제한다. kill과 전체 승리를 구분한다.

완료 증거는 실제 revision·명령·실행 수·기대/실제 상태·semantic trace·팩 fingerprint·남은 제약을 포함한다. DG 완료와 test PASS를 혼동하지 않는다.

## 8. 금지·비범위

거대 damage나 Despawn을 처형으로 대체, 무조건 승리, 시각용 소환에 wave authority 부여, game_server/Unity 구현 및 네트워크 통합 PASS 주장.



## 9. 인수 산출물

코어 침식 처리와 forced-clock 계약, fake host clock·terminal·직원 상태 검증. 실제 영상·클라이언트 재생은 제외.

추가로 현재 코드 조사 기록, 채택한 L 상세 설계, DG 검토 근거, 발생한 설계 변경 이력, 실제 검증·완료 검토를 연결한다. 해당 파일명은 현재 저장소 workflow에 맞춘다. 이 카드 자체는 실행 기록이 아니다.
