# CA05 — 계산식·집계·스탯 성장

계획 v2.1 · 2026-09-09 · 단계 M2 · **실행·DG·구현·프로젝트 검증 모두 미수행**

계획상 선행 후보: CA04  
공유 계약: K02, K05, K06  
권장 설계: [02_AUTHORING_AND_COMPILER.ko.md](../architecture/02_AUTHORING_AND_COMPILER.ko.md) / [03_RUNTIME.ko.md](../architecture/03_RUNTIME.ko.md)

> **순서 근거:** 위 선행은 계획상 후보다. [의존성 기준](../DEPENDENCIES.ko.md)에 따라 선택 범위의 실제 코드·중간 상태를 P2G-20/40에서 검토하고, GEX 인수에서 current 선행 결과를 확인한다. 이 카드는 정식 Goal·실행 준비 증거가 아니다.

## 1. 목표와 범위

Attack/SpellPower와 HP·자원·시간을 참조하는 효과량을 데이터로 계산한다.

상수, 승인된 stat/resource/time/result 참조, 합·곱·비율·clamp 및 유한 집합 count/sum/max 등을 타입화한다. 단위, 범위, overflow·0 나눗셈, 반올림과 snapshot/live 평가 시점을 검증한다. 대상 최대 HP·결손 HP·남은 시간·선택한 자원값을 식에 연결한다. 직원/무기 공격력·주문력의 최종 stat 구성을 한 번만 계산한다. 공격 속도 포인트와 attack interval을 별개로 다루고 기존 scale_attack_interval_ms를 재사용한다. max(5,3,2)=5와 타일 단위 집계는 서로 다른 연산으로 표현한다.

## 2. 권장 구조와 선택 이유 — R

**채택안:** ValueExpr를 유한 typed AST로 컴파일하고 evaluation moment를 포함한다. stat composition은 직원·무기·modifier를 한 번만 계산한다.

**이유:** 고정 피해 enum 확장만으로 Attack/SpellPower·남은 시간·집계를 연결할 수 없으며 모든 percent를 같은 수학으로 다루면 의미가 달라지기 때문이다.

## 3. 실제 코드에서 확인할 질문 — D1

UnitStats·stat_pipeline·weapon profile 적용 순서, scale_attack_interval_ms, damage/heal 산술과 overflow·반올림을 현재 코드에서 대조한다.

연결 후보: `core_enhanced/src/game/stats.rs::StatId, UnitStats; battle/types.rs::UnitCombatProfile, scale_attack_interval_ms; battle/stat_pipeline.rs; battle/damage.rs::DamageModifiers; ability.rs::SkillEffectDef`

위 경로는 조사 입구다. 실제 선택 작업에서는 관련 호출자·검증기·소비자·상태·테스트를 모두 연결해 읽고 확인한 범위를 적는다. 새 설계 타입을 현재 API로 가정하지 않는다.

## 4. 구현 전에 작성할 상세 설계 — D2/DG

식/단위 타입, 합법 연산, 참조 scope·snapshot/live, checked arithmetic 실패, 집계 grouping/empty set, stat authority·cache dependency와 설명 형식.

공통 [설계 절차](../DESIGN_WORKFLOW.ko.md)의 DG 표를 충족한다. R을 변경하면 현 코드 근거·대안·영향 소비자·P 정책 보존 여부를 기록한다. exact 함수·자료구조는 구현자의 L 설계이며, K 의미 변경은 L1 검토, gameplay 변화는 L2/PG다.

## 5. 구현·시험 묶음

상수/stat 식 → resource/result 식 → 집계 → weapon 성장 연결 → 수치·단위 경계 시험.

새 상태의 snapshot/rollback/save 영향은 이 작업에서 동반한다. CA19에 모든 저장 구현을 미루지 않는다. 작업 범위에 해당하지 않으면 “해당 없음”과 근거를 적는다.

## 6. 정책 결정 지점

PG01 산술 합성, PG03 평가 시점, PG05 성장·자원. 주문력은 피해 type Magic과 동의어가 아니다.

이미 합의한 사본별 개화·외부 팩·레거시 없음 등의 P 정책은 재질문하지 않는다. 미확인 구현 사실은 D1 조사로 해결한다.

## 7. 필수 검증과 완료 증거

T06. 공격형/주문형/혼합형이 각 입력에만 반응하고 무기 stat을 이중 합산하지 않는다. snapshot 이후 stat 변경은 이미 고정된 전달 결과를 바꾸지 않는다. 집계 owner·대상 단위가 달라지면 혼합 입력은 오류다.

**v2 추가 기준:** Attack 100에 이미 포함된 weapon 40을 다시 더하지 않는다. Max stacks와 Sum stacks가 다른 값이며 attack speed는 폭격 cadence를 바꾸지 않는다.

완료 증거는 실제 revision·명령·실행 수·기대/실제 상태·semantic trace·팩 fingerprint·남은 제약을 포함한다. DG 완료와 test PASS를 혼동하지 않는다.

## 8. 금지·비범위

외부 코드 eval, 모든 Percent의 일괄 곱셈/합산, 가장 큰 스택 대신 전체 합, 공격 속도가 모든 시간 효과를 가속하도록 처리.



## 9. 인수 산출물

ValueExpr·집계 계약 및 interpreter/compiler, 성장 산술 테스트, 수치 변경 explain.

추가로 현재 코드 조사 기록, 채택한 L 상세 설계, DG 검토 근거, 발생한 설계 변경 이력, 실제 검증·완료 검토를 연결한다. 해당 파일명은 현재 저장소 workflow에 맞춘다. 이 카드 자체는 실행 기록이 아니다.
