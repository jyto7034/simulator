# CA08 — 가역 modifier·오라·집중·기본 공격 교체

계획 v2.1 · 2026-09-09 · 단계 M3 · **실행·DG·구현·프로젝트 검증 모두 미수행**

권장 설계: [03_RUNTIME.ko.md](../architecture/03_RUNTIME.ko.md) / [08_WORKED_EXAMPLES.ko.md](../architecture/08_WORKED_EXAMPLES.ko.md)

> **순서 근거:** 위 선행은 계획상 후보다. [의존성 기준](../DEPENDENCIES.ko.md)에 따라 선택 범위의 실제 코드·중간 상태를 P2G-20/40에서 검토하고, GEX 인수에서 current 선행 결과를 확인한다. 이 카드는 정식 Goal·실행 준비 증거가 아니다.

## 1. 목표와 범위

지속 효과가 종료될 때 자신의 변경만 제거하며 재입력과 원상 복귀를 표현한다.

modifier handle을 원효과와 source activation에 연결한다. channel은 준비 focus와 별도 activation으로 두고 행동 lock의 소유와 해제 범위를 추적한다. aura는 membership으로 파생되며 진입·이탈·종료 시 제거/적용한다. 기본 공격 profile override와 복귀, 다음 공격 1회 강화, 기본 공격 전용 피해/속도 modifier를 지원한다. 재입력은 현재 activation에서 허용된 분기로 처리하고 원래 source를 보존한다. 일반 기본 공격의 영역·방향성·관통 전달도 동일 hit identity를 유지하며 도입한다.

## 2. 권장 구조와 선택 이유 — R

**채택안:** ModifierLedger/ActionLease/ChannelActivation/AuraMembership과 BasicAttackOverlay를 source handle로 소유한다. 종료는 자기 handle 제거다.

**이유:** 반대 수치를 더해 복구하면 다른 modifier와 반올림을 손상시키고, 긴 cast 준비로 channel을 흉내 내면 행동·취소가 달라지기 때문이다.

## 3. 실제 코드에서 확인할 질문 — D1

기본 공격 start/release/recovery, pending cast와 focus lock, modifier 적용, tactical movement·withdraw, area 추종·tick cleanup을 확인한다.

연결 후보: `core_enhanced/src/game/battle/core/basic_attack.rs; basic_attack_projectile.rs; tactical_stance.rs; types.rs::ActionLocks; sim.rs의 pending cast; battle/stat_pipeline.rs; docs/skill_target_contract.md`

위 경로는 조사 입구다. 실제 선택 작업에서는 관련 호출자·검증기·소비자·상태·테스트를 모두 연결해 읽고 확인한 범위를 적는다. 새 설계 타입을 현재 API로 가정하지 않는다.

## 4. 구현 전에 작성할 상세 설계 — D2/DG

lease와 override data shape, allowed reinput payload·activation 매칭, natural/reinput/cancel 전이 표, aura 갱신 trigger, snapshot 적용 시점, ordinary attack 전달 확장.

공통 [설계 절차](../DESIGN_WORKFLOW.ko.md)의 DG 표를 충족한다. R을 변경하면 현 코드 근거·대안·영향 소비자·P 정책 보존 여부를 기록한다. exact 함수·자료구조는 구현자의 L 설계이며, K 의미 변경은 L1 검토, gameplay 변화는 L2/PG다.

## 5. 구현·시험 묶음

가역 modifier → membership → channel → Hello/Goodbye → next-attack override → 함께 종료 시험.

새 상태의 snapshot/rollback/save 영향은 이 작업에서 동반한다. CA19에 모든 저장 구현을 미루지 않는다. 작업 범위에 해당하지 않으면 “해당 없음”과 근거를 적는다.

## 6. 정책 결정 지점

PG01, PG03, PG04, PG05. 태아의 집중 중 저지 정책 등 미정 항목은 자동 확정하지 않는다.

이미 합의한 사본별 개화·외부 팩·레거시 없음 등의 P 정책은 재질문하지 않는다. 미확인 구현 사실은 D1 조사로 해결한다.

## 7. 필수 검증과 완료 증거

T09. Hello 자연 만료는 Goodbye를 만들지 않는다. 재입력 분기는 추가 공명을 소비하지 않고 한 번 종료한다. 태아의 범위 이탈·집중 종료 시 자기 modifier만 제거된다. 다른 source lock과 이미 발사된 공격은 보존된다.

**v2 추가 기준:** E04/E05를 trace로 설명한다. basic override는 skill proc로 둔갑하지 않고 공격 속도 적용 경계가 기존 windup을 소급 변경하지 않는다.

완료 증거는 실제 revision·명령·실행 수·기대/실제 상태·semantic trace·팩 fingerprint·남은 제약을 포함한다. DG 완료와 test PASS를 혼동하지 않는다.

## 8. 금지·비범위

매 틱 ModifyStats 누적로 오라 흉내, 긴 focus_time으로 channel 흉내, 끝날 때 역수/반대값으로 모든 modifier 제거.



## 9. 인수 산출물

지속 action·modifier 계약, Hello/Goodbye와 태아의 최소 RON 실행 및 취소·재진입 테스트.

추가로 현재 코드 조사 기록, 채택한 L 상세 설계, DG 검토 근거, 발생한 설계 변경 이력, 실제 검증·완료 검토를 연결한다. 해당 파일명은 현재 저장소 workflow에 맞춘다. 이 카드 자체는 실행 기록이 아니다.
