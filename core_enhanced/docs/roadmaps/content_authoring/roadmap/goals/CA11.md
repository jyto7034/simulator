# CA11 — 유물 소유·장착·회수·분쇄

계획 v2.1 · 2026-09-09 · 단계 M4 · **실행·DG·구현·프로젝트 검증 모두 미수행**

계획상 선행 후보: CA04, CA10  
공유 계약: K01, K03, K05, K07  
권장 설계: [03_RUNTIME.ko.md](../architecture/03_RUNTIME.ko.md) / [04_COMPOSITION.ko.md](../architecture/04_COMPOSITION.ko.md)

> **순서 근거:** 위 선행은 계획상 후보다. [의존성 기준](../DEPENDENCIES.ko.md)에 따라 선택 범위의 실제 코드·중간 상태를 P2G-20/40에서 검토하고, GEX 인수에서 current 선행 결과를 확인한다. 이 카드는 정식 Goal·실행 준비 증거가 아니다.

## 1. 목표와 범위

유물 효과와 독립된 소유·관리 aggregate를 완성한다.

RelicCopy와 definition을 분리하고 공식 규칙 profile의 직원당 공용 3슬롯, 동일 사본 독점, 중복 정책, 직원 단위 비호환, Safezone/Maintenance 이전·무료 장착을 구현한다. 요구 효과가 없다는 이유로 장착을 거부하지 않는다. 사망 시 공용 보관함 회수, 판매 금지, Maintenance 확인 후 장착 해제·분쇄→기존 장비 가루를 연결한다. 슬롯 수 등 수정 가능한 공식 정책은 profile에서 공급하고 engine safety invariant와 구분한다. 신규 상태는 snapshot/checkpoint에 즉시 반영한다.

## 2. 권장 구조와 선택 이유 — R

**채택안:** RelicCopy 관리와 효과 합성은 분리한다. 장착은 사본·슬롯·비호환을 검사하고 효과 요구 미충족은 휴면으로 표현한다.

**이유:** 효과 활성 여부와 소유·슬롯 유효성을 합치면 미리 장착하기와 무기 변경의 승인 정책을 어기기 때문이다.

## 3. 실제 코드에서 확인할 질문 — D1

EquipmentLoadoutTransition·inventory 양방향 장부, 사망 회수·분쇄 confirm·snapshot/save와 rule profile을 추적한다.

연결 후보: `core_enhanced/src/game/resources/inventory.rs; resources/equipment_loadout.rs; world/maintenance.rs; world/helpers.rs; world/state.rs::GameCoreState; world/snapshot.rs; reward.rs; data/run_policy_data.rs`

위 경로는 조사 입구다. 실제 선택 작업에서는 관련 호출자·검증기·소비자·상태·테스트를 모두 연결해 읽고 확인한 범위를 적는다. 새 설계 타입을 현재 API로 가정하지 않는다.

## 4. 구현 전에 작성할 상세 설계 — D2/DG

RelicCopy/slot schema, instance exclusivity·duplicate/negative constraints, atomic equip/transfer/dismantle, activation report 포트, rule profile과 공식 3슬롯 분리.

공통 [설계 절차](../DESIGN_WORKFLOW.ko.md)의 DG 표를 충족한다. R을 변경하면 현 코드 근거·대안·영향 소비자·P 정책 보존 여부를 기록한다. exact 함수·자료구조는 구현자의 L 설계이며, K 의미 변경은 L1 검토, gameplay 변화는 L2/PG다.

## 5. 구현·시험 묶음

관리 aggregate → 장착/이전 → 회수/분쇄 → 저장/휴면 report 연결.

새 상태의 snapshot/rollback/save 영향은 이 작업에서 동반한다. CA19에 모든 저장 구현을 미루지 않는다. 작업 범위에 해당하지 않으면 “해당 없음”과 근거를 적는다.

## 6. 정책 결정 지점

PG01 비호환 효과 정의, PG06 분쇄량·획득 수치. 침식된 유물 상태의 세부 변형은 PG09의 범위만 구현한다.

이미 합의한 사본별 개화·외부 팩·레거시 없음 등의 P 정책은 재질문하지 않는다. 미확인 구현 사실은 D1 조사로 해결한다.

## 7. 필수 검증과 완료 증거

T12. 세 슬롯·직원별 중복·순서 독립 비호환·사본 회수·거부 시 무변경을 검증한다. 다른 직원의 유물 조합을 직원 내 비호환으로 막지 않는다. 무기를 해제해도 유물 장착은 유지한다.

**v2 추가 기준:** 다른 직원의 유물에 직원내 비호환을 적용하지 않고, 미충족 상태도 슬롯을 점유한다. slot count를 runtime memory safety 제약과 혼동하지 않는다.

완료 증거는 실제 revision·명령·실행 수·기대/실제 상태·semantic trace·팩 fingerprint·남은 제약을 포함한다. DG 완료와 test PASS를 혼동하지 않는다.

## 8. 금지·비범위

장비 Weapon/Armor/Accessory를 유물 슬롯으로 재사용, 장착 순서 마지막 값 승리, 획득을 레벨업으로 변경, 미정 획득 빈도 창작.



## 9. 인수 산출물

유물 관리 aggregate와 공식 규칙 profile, 소유/관리/저장 통합 검증.

추가로 현재 코드 조사 기록, 채택한 L 상세 설계, DG 검토 근거, 발생한 설계 변경 이력, 실제 검증·완료 검토를 연결한다. 해당 파일명은 현재 저장소 workflow에 맞춘다. 이 카드 자체는 실행 기록이 아니다.
