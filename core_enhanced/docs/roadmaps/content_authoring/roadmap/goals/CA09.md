# CA09 — 공유 보호막·생존·방어 중재·제어

계획 v2.1 · 2026-09-09 · 단계 M3 · **실행·DG·구현·프로젝트 검증 모두 미수행**

계획상 선행 후보: CA06, CA08  
공유 계약: K05, K06  
권장 설계: [03_RUNTIME.ko.md](../architecture/03_RUNTIME.ko.md) / [08_WORKED_EXAMPLES.ko.md](../architecture/08_WORKED_EXAMPLES.ko.md)

> **순서 근거:** 위 선행은 계획상 후보다. [의존성 기준](../DEPENDENCIES.ko.md)에 따라 선택 범위의 실제 코드·중간 상태를 P2G-20/40에서 검토하고, GEX 인수에서 current 선행 결과를 확인한다. 이 카드는 정식 Goal·실행 준비 증거가 아니다.

## 1. 목표와 범위

피해 감소·흡수·차단·HP 바닥·비용을 서로 다른 기제로 지원한다.

개인/공유 shield source를 CA04 자원으로 만들고 최종 감쇄 피해→pool 소비→초과 HP 손실로 연결한다. 참여자와 초기량 변경을 분리한다. timed slow/root/taunt/pull 등 목표에서 요구되는 제어, parry window와 성공/실패 사건, HP 1 보장과 일반적인 death-prevent의 승인 범위를 구현한다. 지급된 HP 회복과 shield 재충전을 분리한다. 액세서리/유물의 초기량 변경은 source 생성에 한 번만 적용한다.

## 2. 권장 구조와 선택 이유 — R

**채택안:** 공유 shield는 원천 ResourcePool과 membership이고, 피해 해결은 감쇄→흡수→HP·생존 중재의 명시 pipeline을 사용한다.

**이유:** 개인 buff 복제나 MaxHp 증가로 보호막을 대체하면 잔량·피격·회복·비용 의미가 바뀌기 때문이다.

## 3. 실제 코드에서 확인할 질문 — D1

실제 피해 reduction·HP update·death prevent·trigger 순서, control/movement/block 관계를 확인한다. 현재 hook만으로 어느 처리를 재사용할지 판단한다.

연결 후보: `core_enhanced/src/game/battle/damage.rs; battle/core/damage_runtime.rs; battle/core/death_runtime.rs; battle/buffs.rs; battle/core/movement/blocking.rs; docs/skills/abnormality_skill_fragments_design_notes.md의 포큐버스·흑조·샤덴프로이데·고기방패`

위 경로는 조사 입구다. 실제 선택 작업에서는 관련 호출자·검증기·소비자·상태·테스트를 모두 연결해 읽고 확인한 범위를 적는다. 새 설계 타입을 현재 API로 가정하지 않는다.

## 4. 구현 전에 작성할 상세 설계 — D2/DG

shield source/recipient/reference, initial modifier 적용점, 소비 정렬·overflow, DamageReceipt 분해, control별 capability, parry/survival/cost 중재와 PG 결정.

공통 [설계 절차](../DESIGN_WORKFLOW.ko.md)의 DG 표를 충족한다. R을 변경하면 현 코드 근거·대안·영향 소비자·P 정책 보존 여부를 기록한다. exact 함수·자료구조는 구현자의 L 설계이며, K 의미 변경은 L1 검토, gameplay 변화는 L2/PG다.

## 5. 구현·시험 묶음

pool 흡수 → 초기량·membership → 종료/중첩 → 생존·제어 primitive → E03 조합.

새 상태의 snapshot/rollback/save 영향은 이 작업에서 동반한다. CA19에 모든 저장 구현을 미루지 않는다. 작업 범위에 해당하지 않으면 “해당 없음”과 근거를 적는다.

## 6. 정책 결정 지점

PG03, PG04. 개인·공유 shield 우선순위, 비용과 HP 1의 관계, parry와 lethal hit의 의미를 승인한 뒤 구현한다.

이미 합의한 사본별 개화·외부 팩·레거시 없음 등의 P 정책은 재질문하지 않는다. 미확인 구현 사실은 D1 조사로 해결한다.

## 7. 필수 검증과 완료 증거

T10. shared 잔량 600에 감쇄 후 A 400/B 350이면 잔량 0, A HP 손실 0, B HP 손실 150이다. 참가자 증가는 원천량을 복제하지 않는다. 원천 만료·자원 소진이 한 번만 종료한다. HP 비용은 shield를 우회하되 승인된 생존 규칙을 따른다.

**v2 추가 기준:** 600/400/350 fixture, 피해 감소 중복 방지, shield와 HP 비용·회복의 분리, 소진/만료 단일 종료를 검증한다.

완료 증거는 실제 revision·명령·실행 수·기대/실제 상태·semantic trace·팩 fingerprint·남은 제약을 포함한다. DG 완료와 test PASS를 혼동하지 않는다.

## 8. 금지·비범위

보호막을 최대 HP 증가로 구현, 모든 제어를 Stun으로 처리, 무적·감쇄·생존 보장을 같은 분류로 합치기.



## 9. 인수 산출물

피해 중재·제어 primitive, 포큐버스·parry·생존 구조의 시험 fixture와 정책별 경계 검증.

추가로 현재 코드 조사 기록, 채택한 L 상세 설계, DG 검토 근거, 발생한 설계 변경 이력, 실제 검증·완료 검토를 연결한다. 해당 파일명은 현재 저장소 workflow에 맞춘다. 이 카드 자체는 실행 기록이 아니다.
