# CA13 — 연쇄 실행·경로별 재방문 차단

계획 v2.1 · 2026-09-09 · 단계 M4 · **실행·DG·구현·프로젝트 검증 모두 미수행**

계획상 선행 후보: CA06, CA12  
공유 계약: K06, K08, K10  
권장 설계: [03_RUNTIME.ko.md](../architecture/03_RUNTIME.ko.md) / [04_COMPOSITION.ko.md](../architecture/04_COMPOSITION.ko.md)

> **순서 근거:** 위 선행은 계획상 후보다. [의존성 기준](../DEPENDENCIES.ko.md)에 따라 선택 범위의 실제 코드·중간 상태를 P2G-20/40에서 검토하고, GEX 인수에서 current 선행 결과를 확인한다. 이 카드는 정식 Goal·실행 준비 증거가 아니다.

## 1. 목표와 범위

생성 효과의 발동은 허용하면서 한 경로에서 같은 유물 사본의 같은 효과로 되돌아오는 것만 막는다.

원인 occurrence와 branch-local chain context, visited (copy_id,effect_id)를 상태로 전달한다. projectile·timer·area·후속 생성 등 비동기 자식도 정해진 인과 맥락을 보존한다. 기본 공격 등의 진짜 독립 사건과 유물 자신이 만든 지연 사건의 root 정책을 구분한다. sibling path를 전투 전체 visited set으로 합치지 않는다. 사망·피해 해결 중 직접 재귀 호출 대신 정해진 큐/단계로 확장을 수행한다. 연쇄 fan-out은 CA22 예산 계측에 포함한다.

## 2. 권장 구조와 선택 이유 — R

**채택안:** root와 ancestor frame을 갖는 branch-local ChainContext를 queue request/delayed child에 전달한다. reactive 실행은 직접 재귀 호출하지 않는다.

**이유:** 전역 visited나 cooldown은 승인된 경로별 제한을 표현하지 못하고 timer마다 새 root를 만들면 순환을 우회하기 때문이다.

## 3. 실제 코드에서 확인할 질문 — D1

trigger occurrence→proc→skill→projectile/area→death→후속 event 경로에서 source·cause가 유지/유실되는 지점을 찾는다.

연결 후보: `core_enhanced/src/game/battle/core/triggers.rs::TriggerOccurrenceContext; sim.rs::should_fire_triggered_ability; battle/core/commands.rs; battle/core/types.rs::AbilityProcKey; battle/event_log.rs::BattleEventCause; skill_runtime/`

위 경로는 조사 입구다. 실제 선택 작업에서는 관련 호출자·검증기·소비자·상태·테스트를 모두 연결해 읽고 확인한 범위를 적는다. 새 설계 타입을 현재 API로 가정하지 않는다.

## 4. 구현 전에 작성할 상세 설계 — D2/DG

frame/handle 구조, 방문 전 검사·추가 위치, delayed propagation, producer root 권한, 실제 join ancestry 합성, budget과 context 회수.

공통 [설계 절차](../DESIGN_WORKFLOW.ko.md)의 DG 표를 충족한다. R을 변경하면 현 코드 근거·대안·영향 소비자·P 정책 보존 여부를 기록한다. exact 함수·자료구조는 구현자의 L 설계이며, K 의미 변경은 L1 검토, gameplay 변화는 L2/PG다.

## 5. 구현·시험 묶음

즉시 A/B chain → forks → delayed delivery → join/주기 정책 → trace/예산.

새 상태의 snapshot/rollback/save 영향은 이 작업에서 동반한다. CA19에 모든 저장 구현을 미루지 않는다. 작업 범위에 해당하지 않으면 “해당 없음”과 근거를 적는다.

## 6. 정책 결정 지점

PG02. 합류·전파·반복 발생의 root/branch 정책이 미정이면 해당 family만 gate한다.

이미 합의한 사본별 개화·외부 팩·레거시 없음 등의 P 정책은 재질문하지 않는다. 미확인 구현 사실은 D1 조사로 해결한다.

## 7. 필수 검증과 완료 증거

T14. A1.e→B1.e→A1.e는 차단, 다음 독립 공격에서는 재허용, A2 사본·A1의 다른 효과는 구별한다. 지연시키거나 새 투사체를 만들어 순환 제한을 우회할 수 없다. 출처 태그는 기본 공격에서 새 proc로 무조건 상속되지 않는다.

**v2 추가 기준:** A1.e→B1.e→A1.e만 차단하며 A2·다른 effect·별도 독립 공격은 구별한다. log eviction과 timer delay가 제한을 초기화하지 않는다.

완료 증거는 실제 revision·명령·실행 수·기대/실제 상태·semantic trace·팩 fingerprint·남은 제약을 포함한다. DG 완료와 test PASS를 혼동하지 않는다.

## 8. 금지·비범위

쿨다운을 순환 방지로 대체, 유물당 전투 1회 전역 visited, 시간 이벤트마다 무조건 새 root, 로그 history eviction으로 보호 정보 소실.



## 9. 인수 산출물

연쇄 dispatcher와 진단, 사본·분기·지연 전파의 양성/음성 시험.

추가로 현재 코드 조사 기록, 채택한 L 상세 설계, DG 검토 근거, 발생한 설계 변경 이력, 실제 검증·완료 검토를 연결한다. 해당 파일명은 현재 저장소 workflow에 맞춘다. 이 카드 자체는 실행 기록이 아니다.
