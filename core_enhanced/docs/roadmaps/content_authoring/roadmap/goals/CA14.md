# CA14 — 설치물·장애물·소환의 구분된 실행

계획 v2.1 · 2026-09-09 · 단계 M5 · **실행·DG·구현·프로젝트 검증 모두 미수행**

계획상 선행 후보: CA04, CA07, CA09, CA10  
공유 계약: K01, K04, K05, K06, K09  
권장 설계: [03_RUNTIME.ko.md](../architecture/03_RUNTIME.ko.md) / [05_BOSS_AUTHORING.ko.md](../architecture/05_BOSS_AUTHORING.ko.md)

> **순서 근거:** 위 선행은 계획상 후보다. [의존성 기준](../DEPENDENCIES.ko.md)에 따라 선택 범위의 실제 코드·중간 상태를 P2G-20/40에서 검토하고, GEX 인수에서 current 선행 결과를 확인한다. 이 카드는 정식 Goal·실행 준비 증거가 아니다.

## 1. 목표와 범위

소환물 태그 아래 서로 다른 매개체를 공통 생성 기반 위에서 올바르게 표현한다.

공격·이동·HP·피격·저지·명령 가능 여부가 다른 actor/trap/field object를 구분한다. 배치 유효성, 정지 개체, 자기 작은 함정 타일의 진화 예외, 수량 제한, 생성 실패 원자성, source snapshot과 summoner removal을 구현한다. 고기벽은 일반 summon이나 지형 우회가 아니라 해당 타일에서 적이 파괴하는 방어 object로 처리한다. 공용 shield·고정 회복 영역을 HP actor로 강제하지 않는다. spawn kernel의 생성·identity·점유 처리를 공유하면서 reward/wave/compendium authority는 별도 명시한다.

## 2. 권장 구조와 선택 이유 — R

**채택안:** 공통 생성 request는 사용하되 Actor/Trap/FieldObject/Area/Shield를 각 capability·state shape로 표현한다. 진화는 명시 transaction이다.

**이유:** 소환물 태그로 동일 Unit model을 강제하면 정지 함정·고기벽·공유량에 잘못된 이동/보상 권한이 붙기 때문이다.

## 3. 실제 코드에서 확인할 질문 — D1

SpawnKernel·summon compile·occupancy·pathing·static defense object·wave authority·removal과 source profile snapshot을 추적한다.

연결 후보: `core_enhanced/src/game/data/summoned_unit_data.rs; battle/core/summon_runtime.rs; battle/core/spawn_kernel.rs; battle/core/build.rs; battle/battlefield/; battle/core/movement/; docs/skills/abnormality_skill_fragments_design_notes.md의 래티씨아·고기벽`

위 경로는 조사 입구다. 실제 선택 작업에서는 관련 호출자·검증기·소비자·상태·테스트를 모두 연결해 읽고 확인한 범위를 적는다. 새 설계 타입을 현재 API로 가정하지 않는다.

## 4. 구현 전에 작성할 상세 설계 — D2/DG

매개체별 schema, placement/occupied exception, form transition identity·edge invalidation, resource split/create atomicity, provenance·lifetime·reward 권한.

공통 [설계 절차](../DESIGN_WORKFLOW.ko.md)의 DG 표를 충족한다. R을 변경하면 현 코드 근거·대안·영향 소비자·P 정책 보존 여부를 기록한다. exact 함수·자료구조는 구현자의 L 설계이며, K 의미 변경은 L1 검토, gameplay 변화는 L2/PG다.

## 5. 구현·시험 묶음

actor 재사용 → stationary trap → evolve → field barrier·HP fallback → lifecycle 시험.

새 상태의 snapshot/rollback/save 영향은 이 작업에서 동반한다. CA19에 모든 저장 구현을 미루지 않는다. 작업 범위에 해당하지 않으면 “해당 없음”과 근거를 적는다.

## 6. 정책 결정 지점

PG05, PG06의 해당 원본 세부. 근거 없는 HP/저지/이동 default를 만들지 않는다.

이미 합의한 사본별 개화·외부 팩·레거시 없음 등의 P 정책은 재질문하지 않는다. 미확인 구현 사실은 D1 조사로 해결한다.

## 7. 필수 검증과 완료 증거

T15. 작은 친구→큰 친구가 사본 2개 생성으로 처리되지 않는다. HP 비용과 벽 생성 중 하나만 commit되지 않는다. 철수 뒤 유지하는 object는 snapshot대로 남고, 유지하지 않는 효과는 종료한다. actor summon과 wave 승리 권한은 독립이다.

**v2 추가 기준:** 기본 생성·진화는 유물 합성·연쇄 전체 완성을 기다리지 않는다. 그 통합은 CA15/CA20이 소유한다. 비용·생성 실패와 stale node를 검증한다.

완료 증거는 실제 revision·명령·실행 수·기대/실제 상태·semantic trace·팩 fingerprint·남은 제약을 포함한다. DG 완료와 test PASS를 혼동하지 않는다.

## 8. 금지·비범위

소환물 태그=동일 Unit 구조, zero movement validation 우회, 소환으로 reward/wave 권한 암묵 획득, 고기벽에 일반 회복 적용.

이 작업은 기본 생성·매개체 계약이며 유물 연쇄 통합은 CA15/CA20에서 검증한다.

## 9. 인수 산출물

구분된 object/actor 정의와 생성 경로, 함정 진화·벽 배치·일반 소환의 RON fixture.

추가로 현재 코드 조사 기록, 채택한 L 상세 설계, DG 검토 근거, 발생한 설계 변경 이력, 실제 검증·완료 검토를 연결한다. 해당 파일명은 현재 저장소 workflow에 맞춘다. 이 카드 자체는 실행 기록이 아니다.
