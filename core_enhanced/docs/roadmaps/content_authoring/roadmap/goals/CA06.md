# CA06 — 의미 있는 전투 사건·피해 해결 결과

계획 v2.1 · 2026-09-09 · 단계 M2 · **실행·DG·구현·프로젝트 검증 모두 미수행**

계획상 선행 후보: CA04, CA05  
공유 계약: K01, K06, K08, K09  
권장 설계: [03_RUNTIME.ko.md](../architecture/03_RUNTIME.ko.md)

> **순서 근거:** 위 선행은 계획상 후보다. [의존성 기준](../DEPENDENCIES.ko.md)에 따라 선택 범위의 실제 코드·중간 상태를 P2G-20/40에서 검토하고, GEX 인수에서 current 선행 결과를 확인한다. 이 카드는 정식 Goal·실행 준비 증거가 아니다.

## 1. 목표와 범위

요청·접수·적중·HP 손실·흡수·회복·비용·처치를 분리하고 효과 간 연결에 충분한 결과를 제공한다.

Action/Strike/Segment/Target별 occurrence identity와 source kind·원효과·제공자·modifier 이력·credit을 연결한다. 적중 접수 전후, 피해 계산 전후, 실제 HP 변화, 회복 유효량, 자원 변화, 사망 직전 상태와 사망 확정의 내부 확장 지점을 둔다. 기존 OnAttack/OnHit의 기본 공격 의미를 새 범용 damage event로 재해석하지 않는다. death 전에 관찰할 상태 snapshot과 실제 사망 finalize/부가 트리거를 분리한다. core 결과 receipt와 UI용 로그를 분리한다.

## 2. 권장 구조와 선택 이유 — R

**채택안:** 명령·계산 전 modifier·확정 후 fact를 분리하고 Action/Strike/Segment를 보존한 Damage/Heal/Cost/DeathReceipt를 제공한다.

**이유:** 이미 가한 피해를 사후 수정하거나 hit와 death를 무조건 둘 다 발동시키는 구현을 방지하기 위해서다.

## 3. 실제 코드에서 확인할 질문 — D1

execute_committed_damage, OnAttack/OnHit 수집 시점, buff cleanup·death finalize, wave death epoch, result 통계·공명 반영을 종단 조사한다.

연결 후보: `core_enhanced/src/game/battle/core/damage_runtime.rs::execute_committed_damage; battle/core/commands.rs; battle/core/triggers.rs; battle/core/death_runtime.rs::finalize_unit_death; battle/damage.rs::DamageSourceSnapshot; battle/event_log.rs`

위 경로는 조사 입구다. 실제 선택 작업에서는 관련 호출자·검증기·소비자·상태·테스트를 모두 연결해 읽고 확인한 범위를 적는다. 새 설계 타입을 현재 API로 가정하지 않는다.

## 4. 구현 전에 작성할 상세 설계 — D2/DG

event envelope/result schema, 타격 인정 시점·중복 key, pre-death snapshot, 부분 순서표, preformula 제한 연산, suppression과 subscriber dispatch authority.

공통 [설계 절차](../DESIGN_WORKFLOW.ko.md)의 DG 표를 충족한다. R을 변경하면 현 코드 근거·대안·영향 소비자·P 정책 보존 여부를 기록한다. exact 함수·자료구조는 구현자의 L 설계이며, K 의미 변경은 L1 검토, gameplay 변화는 L2/PG다.

## 5. 구현·시험 묶음

receipt 타입 → 기존 damage/heal 경로 연결 → pre-death facts → reactive queue → 중복·동시 시험.

새 상태의 snapshot/rollback/save 영향은 이 작업에서 동반한다. CA19에 모든 저장 구현을 미루지 않는다. 작업 범위에 해당하지 않으면 “해당 없음”과 근거를 적는다.

## 6. 정책 결정 지점

PG02, PG03, PG04. shield·parry 동작 자체는 CA09, 사건 계약은 이 단계의 책임이다.

이미 합의한 사본별 개화·외부 팩·레거시 없음 등의 P 정책은 재질문하지 않는다. 미확인 구현 사실은 D1 조사로 해결한다.

## 7. 필수 검증과 완료 증거

T07. 한 직접 타격의 여러 segment가 타격 횟수를 중복 증가시키지 않는다. HP 비용은 OnHit가 아니다. 냉기 상태가 있었던 적의 사망을 막타 owner와 별개로 관찰한다. lethal hit의 hit/death 이중 발동을 승인 정책에 따라 분리한다.

**v2 추가 기준:** 깊은 쐐기의 이번 타격 카운터가 계산 전에 정해지며 한 타격의 segments가 중복 count되지 않는다. narration/log 제거가 인과 사실을 제거하지 않는다.

완료 증거는 실제 revision·명령·실행 수·기대/실제 상태·semantic trace·팩 fingerprint·남은 제약을 포함한다. DG 완료와 test PASS를 혼동하지 않는다.

## 8. 금지·비범위

parent log 존재를 연쇄 방지 구현으로 간주, 일반 스킬 피해를 기본 공격으로 둔갑, 사망 상태 제거 뒤 없는 정보로 판단.



## 9. 인수 산출물

typed occurrence/result와 pre-death fact 계약, HP/흡수/회복/비용/처치 분리 검증.

추가로 현재 코드 조사 기록, 채택한 L 상세 설계, DG 검토 근거, 발생한 설계 변경 이력, 실제 검증·완료 검토를 연결한다. 해당 파일명은 현재 저장소 workflow에 맞춘다. 이 카드 자체는 실행 기록이 아니다.
