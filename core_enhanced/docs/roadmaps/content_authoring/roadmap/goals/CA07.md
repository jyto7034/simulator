# CA07 — 대상·전달·단계·분기·반복 실행

계획 v2.1 · 2026-09-09 · 단계 M2 · **실행·DG·구현·프로젝트 검증 모두 미수행**

계획상 선행 후보: CA05, CA06  
공유 계약: K02, K04, K06  
권장 설계: [02_AUTHORING_AND_COMPILER.ko.md](../architecture/02_AUTHORING_AND_COMPILER.ko.md) / [03_RUNTIME.ko.md](../architecture/03_RUNTIME.ko.md) / [08_WORKED_EXAMPLES.ko.md](../architecture/08_WORKED_EXAMPLES.ko.md)

> **순서 근거:** 위 선행은 계획상 후보다. [의존성 기준](../DEPENDENCIES.ko.md)에 따라 선택 범위의 실제 코드·중간 상태를 P2G-20/40에서 검토하고, GEX 인수에서 current 선행 결과를 확인한다. 이 카드는 정식 Goal·실행 준비 증거가 아니다.

## 1. 목표와 범위

스킬을 시간 offset 목록을 넘어 조건·결과·반복의 조합으로 표현한다.

Unit/Tile/Object와 자신·아군·적·원천별 상태 대상 query, 수 제한·우선순위·재선정·방향을 제공한다. 시전 사거리·탐색 범위·효과 footprint·발생 원점은 별개다. Sequence/Branch/Parallel와 유한 Repeat, 이전 작업 완료 상대 지연, 반복 인덱스, 마지막 회차, 무대상 기회 소모를 구현한다. Instant/Projectile/Area kernel을 재사용하고 각 결과로 다음 동작을 진행한다. 피해와 자기 회복은 독립 effect로 컴파일한다. 새 동작의 취소·중단과 released delivery의 존속을 분리한다.

## 2. 권장 구조와 선택 이유 — R

**채택안:** Structured FlowRunner를 result slot/continuation과 명시 completion milestone으로 실행한다. target·anchor·scope·carrier를 별도 바인딩한다.

**이유:** 현재 offset step 목록을 늘리는 것만으로 “피해 완료 뒤 회복”이나 “유한 기회 반복”의 의미를 설명할 수 없기 때문이다.

## 3. 실제 코드에서 확인할 질문 — D1

cast acceptance→step scheduling→projectile/area progress→step finalization와 action lock을 추적한다. 실제 반영 시점·retarget 제약·facing 결손을 조사한다.

연결 후보: `core_enhanced/src/game/ability.rs; data/skill_data.rs; battle/core/sim.rs::execute_skill_step; battle/core/skill_runtime/cast.rs; battle/core/skill_runtime/projectile.rs; battle/core/skill_runtime/area.rs; docs/skill_target_contract.md`

위 경로는 조사 입구다. 실제 선택 작업에서는 관련 호출자·검증기·소비자·상태·테스트를 모두 연결해 읽고 확인한 범위를 적는다. 새 설계 타입을 현재 API로 가정하지 않는다.

## 4. 구현 전에 작성할 상세 설계 — D2/DG

Flow node/result frame, sequence/branch/parallel join, Repeat count·cadence·no-target 소비, timeout/cancel, Delivery handle와 hit summary, typed query 소비자 제약.

공통 [설계 절차](../DESIGN_WORKFLOW.ko.md)의 DG 표를 충족한다. R을 변경하면 현 코드 근거·대안·영향 소비자·P 정책 보존 여부를 기록한다. exact 함수·자료구조는 구현자의 L 설계이며, K 의미 변경은 L1 검토, gameplay 변화는 L2/PG다.

## 5. 구현·시험 묶음

E01 단순 sequence → result branch → explicit repeat → parallel/join → 취소·stale·방향 시험.

새 상태의 snapshot/rollback/save 영향은 이 작업에서 동반한다. CA19에 모든 저장 구현을 미루지 않는다. 작업 범위에 해당하지 않으면 “해당 없음”과 근거를 적는다.

## 6. 정책 결정 지점

PG03과 PG04. 새 selection/retarget 조합을 허용하면 현재 rejection 계약 변경도 명시한다.

이미 합의한 사본별 개화·외부 팩·레거시 없음 등의 P 정책은 재질문하지 않는다. 미확인 구현 사실은 D1 조사로 해결한다.

## 7. 필수 검증과 완료 증거

T08. 영역 피해 후 자기 회복은 1회다. 반복 간격 변경이 횟수를 바꾸지 않는다. 고정 탐색 구역과 낙하 시 고정한 타일이 섞이지 않는다. 같은 시각 병행 결과가 안정된 순서로 해결된다.

**v2 추가 기준:** 동시 실행은 무질서한 공유 mutation이 아니다. 무대상 기회는 임의 재시도하지 않으며 자기 회복은 AoE 대상 수만큼 반복되지 않는다.

완료 증거는 실제 revision·명령·실행 수·기대/실제 상태·semantic trace·팩 fingerprint·남은 제약을 포함한다. DG 완료와 test PASS를 혼동하지 않는다.

## 8. 금지·비범위

Times를 시간 반복과 동일시, 자기 회복에 공격 footprint 상속, 무대상 자동 재시도로 수명을 연장, 효과마다 디스크 재조회.



## 9. 인수 산출물

typed skill flow와 target/delivery 확장, 나무꾼·풍운승려·루돌타 구조의 최소 RON 시험.

추가로 현재 코드 조사 기록, 채택한 L 상세 설계, DG 검토 근거, 발생한 설계 변경 이력, 실제 검증·완료 검토를 연결한다. 해당 파일명은 현재 저장소 workflow에 맞춘다. 이 카드 자체는 실행 기록이 아니다.
