# 구현 AI 인수 지침 — v2.1

이 패키지는 권장 구조와 순서 후보다. 코드 의존성 전수 검토, current Phase Plan·Goal·실행 준비·완료 evidence가 아니다. 실제 첫 진입점은 [ROADMAP_STATUS.md](../ROADMAP_STATUS.md)다.

## 1. 시작과 읽기

사용자가 현황 문서를 읽고 다음 작업을 진행하라고 요청하면 그 문서의 요청 시작 시 Next 카드와 원본 근거를 먼저 확인한다. 연결된 [운영 규칙](../OPERATING_RULES.md)을 처음 인수하거나 변경됐을 때 읽고, 로드맵·설계·현재 P2G/GEX의 필요한 부분만 추가한다.

현황은 오래되거나 잘못될 수 있다. exact Topic/Goal·현재 Phase Plan·실제 선행 결과를 확인하고 불일치는 원본에서 복구한다. CA 번호를 실행 권한이나 완료 증거로 사용하지 않는다.

## 2. 첫 인수 작업

기존 작업을 확인하지 않고 CA00부터 새로 시작하지 않는다. 기존 진행이 없으면 CA00의 기준 상태·요구 추적과 주요 공유 경계 의존성 1차 확인을 진행할 후보로 삼는다. 다음 첫 Topic은 현재 코드와 유효한 중간 상태를 근거로 제안한다. CA01은 첫 후속 계약 후보이며 자동 선택된 구현 Goal이 아니다.

초기 조사는 전체 24개 작업의 모든 세부를 동결하기 위한 것이 아니다. 조사한 범위, 실제 확인한 관계, 미확인 관계와 다음 직접 의존 범위를 구분한다. 인수 조사가 P2G-20/40을 대체하지 않는다.

## 3. 실제 순서와 Goal 인수

[DEPENDENCIES](DEPENDENCIES.ko.md)와 `GOALS.json.dependencies`는 계획상 후보 목록이다. 선택 Topic의 P2G-20에서 관계의 코드 근거를 확인하고 P2G-40에서 Work Package·Atomic Group·Phase와 순서를 확정한다. 필수 기능·동시 전환·검증 선행·진행상 권장을 구분한다.

정식 Goal이 작성된 뒤 GEX가 exact Handoff·Goal member·current 선행 감사·범위·권한을 확인한다. 새로운 원문 전제로 Phase 경계가 무효이면 summary를 고쳐 강행하지 않고 올바른 P2G owner로 반환한다. 승인된 선행 구현의 예상 delta 자체는 전체 재계획 사유가 아니다.

## 4. 설계·구현·감사

권장 구조 R을 실제 관련 코드에 대조해 정확한 타입·입출력·상태 key·수명·순서·실패/취소·전환·시험을 설계한다. [DESIGN_WORKFLOW](DESIGN_WORKFLOW.ko.md)의 D0–A는 기존 P2G/GEX 안의 활동 설명이다. 새 전역 승인 단계나 임의의 감사 예외를 만들지 않는다.

현재 GEX가 요구하는 실행 기록과 `COMPLETION_AUDIT.md` 등 실제 파일명을 따른다. 과거 로드맵의 파일명을 이유로 다른 감사 계약을 만들지 않는다. 필수 독립 reviewer를 구할 수 없으면 그 요구를 self-review로 대체해 통과시키지 않는다.

## 5. 변경·권한

승인 의미를 보존하는 내부 선택은 코드 근거와 검증으로 판단한다. 공유 계약·Phase·Goal의 의미나 경계를 바꾸려면 해당 owner의 수정 절차를, 새로운 gameplay나 scope는 사용자 결정을 따른다. 사용자 변경은 보존한다.

P2G의 Goal·Handoff 작성은 production 코드·RON 수정 승인이 아니다. 명확한 구현 카드에 대한 사용자 실행 요청을 현재 GEX가 받아들일 때 해당 Goal 범위의 구현·검증·감사를 진행한다. 감사 pass에서 source를 수정하지 않고 발견한 결함은 별도 구현 pass에서 교정한다. 하나의 Next 작업이 끝나면 결과와 다음 카드를 기록하되 같은 요청을 다른 Topic/Goal로 확대하지 않는다.

## 6. 기록과 금지

원래 정책·실행·감사 문서에 결과를 먼저 기록하고 현황에 요약·근거·재개 지점을 연결한다. 실제 revision·관련 dirty·명령·실행 수·결과·미실행·실패를 남기고 유효한 근거는 변경 영향에 맞춰 재사용한다.

구형 parser/alias/dual runtime, 콘텐츠 ID별 전용 실행 분기, global immutable catalog 변경, 별도 조합기 validator, test-only builder로 최종 인수 대체, 미정 정책의 silent default, 사용자 저장의 임의 삭제, 없는 빌드·테스트·감사 PASS는 금지다. 보스/스킬/wave의 책임과 CA16·CA21의 보스 독립 제작 기준을 유지한다.

## 7. 요청 예시

> ROADMAP_STATUS.md를 읽고 다음 단계를 진행해 주세요. 현재 원본과 선행 근거를 확인하고, 로드맵 순서를 코드 검증 완료로 가정하지 마세요. 선택 카드의 범위·끝점 안에서 현재 P2G/GEX 절차를 따르고, 결과와 다음 작업을 기록해 주세요.

이 예시는 미래 실행 요청이며 이번 문서 작성으로 실제 Topic·Goal·구현이 시작된 것은 아니다. 다른 작업자와 같은 dirty 경계를 사용한다면 통합 담당·파일 소유·실제 실행 상태를 확인한다.
