# 범용 선택적 단계검토와 구형 연속 구현 요청 폐기

2026-09-13 · 문서 편집 기록. P2G/GEX 실행·Goal activation·구현·감사 승인이 아니다.

사용자 요청: “원래에는 로드맵의 r24 까지 한 번에 구현하려고 만든 문서/내용이 있어. 그것들을 제거해주고 우리가 합의한 안으로 문서를 수정 진행해줘.”

## 현재 규칙과 소유 문서

- P2G-60 검토·상세 계획·검증·인계 완료 후 종료하고, 모델을 선택한 사용자의 별도 구현 요청을 기다린다.
- 기본 구현은 선택 Goal의 내부 구현·자체 검증을 중간 검토 대기 없이 마친 뒤 전후 target을 고정하고 최종 감사 요청을 기다린다.
- 명시적인 “단계검토 과정을 포함해줘” 지시가 있을 때만 빌드 가능한 중간 지점에서 고정·종료한다. 단순 예시·모델 변경은 활성화 근거가 아니다.
- 검토는 읽기 전용이며 PASS여도 다음 구현을 자동 시작하지 않는다. 필요한 교정·재검토·다음 구현은 별도 사용자 요청을 따른다.
- 구현 전/후 Git·경로별 해시뿐 아니라 복원 가능한 원본/diff와 검증 출력·잔여 범위를 보존한다. 부분 검토는 전체 완료 감사가 아니다.
- “감사까지 끝까지 수행해줘”처럼 명시 위임한 경우 기본 최종 감사 인계 경계만 해제할 수 있다. opt-in 중간 경계·독립성·정책·권한·Phase 선행은 유지한다.

실행 원본은 [GEX gex-r6](../../../../goal_execution_pipeline%281%29.md), 계획 인계는 [P2G r6](../../../../policy_to_goal_pipeline_revised_v2.md)다. [운영 규칙](../../OPERATING_RULES.md)·[단일 R 계획 요청문](../../AUTORUN_REQUEST.ko.md)·[현황](../../ROADMAP_STATUS.md)·사용 가이드·문서 인덱스는 이를 연결한다. 기존 schema/validator는 변경하지 않았다.

## 제거 범위와 복원

활성 위치 `core_enhanced/docs/roadmaps/content_authoring/AUTORUN_REQUEST.ko.md.bak`을 제거하고 원문을 [retired/AUTORUN_REQUEST.ko.md.bak](retired/AUTORUN_REQUEST.ko.md.bak)으로 이동했다. 원문 제목은 `R00–R24 범위 한정 연속 실행 요청`이며, 전체 로드맵 구현·감사와 다음 자격 작업 자동 착수를 지시하던 폐기본이다.

이 retired 파일과 `before/`는 역사·복원 전용이며 읽거나 검색했다고 현재 요청으로 채택하지 않는다. 복원하려면 해당 원본을 원래 경로로 복사할 수 있지만 최신 파일을 덮어쓰기 전에 변경과 권한을 확인해야 한다. 원본 내용을 다시 활성 실행 지침으로 사용하려면 별도 사용자 결정이 필요하다.

R00–R24 로드맵 요구·R 카드·최종 완료 기준 자체는 삭제하지 않았다. 과거 REQUEST_INTAKE·감사 target·history·연구 배포본에 남은 당시 연속 실행 요청은 증거로 보존했다. 현재 활성 요청문은 단일 R 계획 전용이며 전체 로드맵 자동 실행 권한을 갖지 않는다.

`before/`에는 이번에 바꾼 9개 문서의 편집 직전 원본을 저장소 상대경로 그대로 보관했다. [DOCUMENT_VALIDATION.json](DOCUMENT_VALIDATION.json)에 전후 SHA-256과 폐기 원문의 현재 보관 identity를 기록한다. 편집 후 문서는 현 위치의 bytes가 대상이며 추후 변경 시 이 영수증의 해시와 대조한다. 이 기록은 자기 자신/영수증의 해시를 target에 포함하지 않는다.

## 적용과 검증의 한계

R06 재검토의 frozen 계획·Handoff·close baseline·검증 결과와 기존 R01–R05 감사 원문을 편집하지 않았다. 이번 문서 개정은 R06의 중간 단계검토 옵션을 실제로 켠 요청도, 새 실행 PLAN도 아니다. 다음 구현 요청을 인수할 때 구·신 governance revision·source drift·검증 영향과 실제 옵션을 새 실행 PLAN에 기록해야 한다. 과거 검증은 과거 target에만 귀속하며 새 문서로 바뀌었다고 현재 전체 감사 PASS를 주장하지 않는다.

문서 diff를 읽고 다음 흐름을 대조했다. 이는 실제 모델 전환/runner 동작 시험이 아니라 지침 의미 검토다.

| 요청/상태 | 문서가 요구하는 결과 |
| --- | --- |
| 계획 인계 완료 | P2G-60에서 종료, 구현은 별도 요청 |
| 일반 구현 요청 | Goal 내부 구현·자체 검증 후 target 고정, 감사 대기 |
| 단계검토 명시 요청 | 실제 빌드·관련 검증이 통과한 checkpoint에서 종료 |
| checkpoint 빌드 실패 | 허용된 교정·재검증 또는 실제 blocker 보고; 준비 완료 주장 금지 |
| 부분 검토 PASS / 모델 변경 / 자동 재개 | 다음 구현 시작 금지, 사용자 요청 대기 |
| 부분 검토 수정 요구 | 별도 교정·새 snapshot·재검토 요청 대기 |
| 중간 경계 없는 Atomic Group | 임의 분할 금지, 최소 결합 범위와 최종 인계만 가능한 이유 보고 |
| Set 전체 구현 요청 | 필수 선행 감사를 건너뛰지 않고 다음 합법적 Phase 인계에서 종료 |
| 감사까지 위임 + 중간 단계검토 opt-in | 중간 경계 유지, 최종 감사 자동 전환만 조건부 허용 |

[validate.mjs](validate.mjs)는 전후 문서 manifest, 배포 사본 일치, 새 링크/anchor, 현황의 기존 이력 보존 및 핵심 문구 존재를 검사하는 읽기 전용 보조 도구다. 자연어 지침의 완전한 논리 증명이나 실제 AI의 준수를 보장하지 않는다. 기존 P2G validator 회귀 테스트는 37/37 통과했다. [실제 테스트 출력](P2G_VALIDATION_TEST.txt)을 보존한다. 게임 코드/RON 변경·컴파일·runtime 시험·GEX 실행은 수행하지 않았다.
