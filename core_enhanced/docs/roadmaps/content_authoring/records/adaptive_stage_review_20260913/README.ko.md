# 중간 검토 지점의 구현 중 선택

2026-09-13 · 후속 문서 편집 기록. 게임 구현·P2G/GEX 실행·R06 옵션 활성화가 아니다.

사용자는 사전 checkpoint 확정 대신 “구현 중에 진전이 어느정도 되었고, 빌드가 가능해지면 중단 후, 검토”하는 의도를 설명했고, 중단 조건은 사전 확인하되 실제 지점은 구현 중 선택하는 수정안을 승인했다.

## 변경

- [GEX gex-r7](../../../../goal_execution_pipeline%281%29.md): 사전 checkpoint 위치·개수·작업 범위 확정 의무를 제거했다. PLAN은 중단 조건·검증 기준을 연결하고 후보는 선택적으로 남긴다.
- 구현자는 검토할 만한 의미 있는 부분 진전·실제 빌드·해당 변경의 관련 검증을 확인한 지점에서 다음 큰 작업 전에 멈춘다. 사소한 패치/컴파일 성공만으로 매번 멈추거나 남은 구현을 이유로 충족한 중단 조건을 미루지 않는다.
- 부분 검토에는 Goal 전체의 미래 기능·전체 완료를 요구하지 않되 영향받는 기존 동작과 공유 계약의 회귀 검증은 유지한다.
- [P2G r7](../../../../policy_to_goal_pipeline_revised_v2.md)과 배포 사본: 중간 지점 후보는 선택 사항이다. 후보 미작성은 P2G exit·계획 인계·구현 진입의 차단 조건이 아니다.
- 운영 규칙 v1.9, 요청문 single-r-v6-plan-only, 사용 가이드 v2.1.2, 현황 v1.85와 문서 인덱스도 같은 기준으로 정렬했다.

구간 시작 전 baseline은 여전히 먼저 고정한다. 실제 중단 지점을 선택하면 그 범위·선정 근거·구현 후 target·검증 출력·잔여 작업을 고정한다. 해시뿐 아니라 복원 가능한 원본/diff를 보존한다. 다음 중단 지점은 미리 정하지 않아도 된다.

기본 전체 구현 후 감사 인계, 명시적 단계검토 opt-in, 검토의 읽기 전용 경계, PASS 뒤 별도 진행 요청, 최종 전체 감사와 독립성·Phase 선행·정책·권한 제한은 변경하지 않았다. 사용자가 특정 중단 지점을 직접 지정한 경우도 그대로 지킨다. 실제 중간 지점이 없다는 판단은 코드 의존성 근거가 필요하며 사전 후보 부재만으로 중간 검토를 생략하지 않는다.

## 보존과 적용

이번 편집 직전 8개 문서 원본은 `before/`에 저장소 상대경로대로 보관했다. [전후 해시·검증 기록](DOCUMENT_VALIDATION.json)으로 변경을 대조할 수 있다. [이전 개정 기록](../optional_stage_review_20260913/README.ko.md)·당시 영수증·retired 요청문은 수정하지 않았다. 이전 영수증은 그때의 bytes에만 귀속하며 현재 문서 통과 증거로 재사용하지 않는다.

기존 R06 frozen 계획·Handoff·기준선과 과거 감사 원문은 편집하지 않았다. 새 실행 인수에서 구·신 지침 revision과 실제 요청·영향을 연결하며, 이 문서 편집을 게임 실행이나 옵션 활성화로 해석하지 않는다.

## 검증

[validate.mjs](validate.mjs)는 읽기 전용으로 전후 manifest, P2G 사본 일치, 새 링크/anchor, 기존 현황 이력 보존과 사전 확정 문구 제거를 확인한다. 출력은 위 JSON에 보관한다. 문구 검사는 자연어 규칙 전체의 논리 증명이나 실제 모델/runner 동작 시험이 아니다.

의미 검토에서는 사전 후보 없음→구현 가능, 사소한 컴파일 성공→중단 의무 없음, 의미 있는 부분 변경+빌드/관련 검증 통과→중단, 미구현 후속 기능→부분 검토 가능, 빌드/관련 검증 실패→교정 또는 blocker 보고, 부분 검토 PASS→다음 요청 대기의 흐름을 대조했다.

기존 P2G validator 회귀 테스트의 실제 출력은 [P2G_VALIDATION_TEST.txt](P2G_VALIDATION_TEST.txt)에 보관한다. 게임 코드·RON·검증기 소스는 변경하지 않았으며 게임 컴파일·runtime 시험·GEX 감사는 수행하지 않았다.
