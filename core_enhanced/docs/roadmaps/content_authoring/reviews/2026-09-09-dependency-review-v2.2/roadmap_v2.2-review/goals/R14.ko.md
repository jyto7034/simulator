# R14 — 유물 관리 + 최소 수치 합성의 실제 실행 연결

**2.2-review.1 · 2026-09-09 · 조사·개정 권고 / 저장소 미적용 / 게임 구현·Goal 실행 미승인**

이 문서는 **로드맵 작업 카드**다. 정식 P2G Goal 또는 GEX activation이 아니다. 기존 CA 대응: CA11, CA12, CA17, CA19. 기본 순서 번호: 14. 현재 상태: `proposed_not_implemented`.

## 1. 목적과 먼저 필요한 설계

K07 selector/property/effective plan; 사본/직원/효과별 source binding; loadout와 휴면.

## 2. 구현 선행과 검증 선행

기능상 선행: [R01](R01.ko.md), [R05](R05.ko.md), [R07](R07.ko.md), [R10](R10.ko.md).

검증 선행: 없음.

진행상 권장: [R13](R13.ko.md).

이 목록은 선행 단위 전체의 모든 기능을 요구하는 것이 아니다. [관계별 producer output와 consumer](../DEPENDENCIES.ko.md)가 필요한 최소 계약을 특정한다. 기본 순서는 별도로 보수적인 순차 진행을 택했다.

## 3. 동반 전환 범위

RelicCopy/직원공용3slot/rule profile + grant/이전/회수/확인분쇄/기존dust/save + 최소 typed numeric compose + immutable effective plan + cast/queued step/projectile/area/readiness/preview/평가입력 전 소비자 + RON tests 관리 aggregate와 Composer의 책임은 분리한다. 유물 판매 금지, 직원 내 중복/비호환, 무료 장착·이전, 기존 장비 가루로 분쇄를 보존한다.

최소 동시 전환 묶음: AT14. 서로 다른 atomic group이나 한 카드의 여러 기능을 모두 단일 runtime transaction으로 합치라는 뜻은 아니다.

## 4. 재사용·교체·제거

**재사용:** 장비 loadout transaction·EconomyGrantState·save/entry·R01주소/R10plan.

**교체·제거 방향:** 전역 SkillId 재조회가 개인별 plan을 덮는 모든 direct consumer를 같은 전환에 교체; normal Weapon/Armor/Accessory 슬롯은 유지.

## 5. 직후 유효 상태

유물을 정상 획득·장착·저장하고 지원한 수치 변형이 즉시/지연 실행에 실제 반영된다. 요구 효과가 없는 유물은 슬롯 유지·휴면.

다음 단계를 전혀 수행하지 않아도 이 약속이 충족되어야 한다. 미지원 후속 기능은 publication/descriptor에 명시하고 빈 executor·임시 성공·조용한 fallback으로 완료하지 않는다.

## 7. 조건·미정·범위

정책 gate: PG01, PG05, PG06, PG08.

관리 aggregate 자체는 파편 사본화와 독립 설계 가능하다. 기본안은 공용 파일 재작업을 줄이고 실제 유물 가치까지 증명하려고 R07 뒤에 최소 numeric composer와 묶는다. 아직 reactive grant/구조 변환을 지원했다고 말하지 않는다. 전역 definition catalog는 계속 원형 설명을 제공한다. 개인별 effective preview/설명은 binding context를 받는 별도 projection이며 전역 catalog를 개인 plan으로 덮지 않는다.
