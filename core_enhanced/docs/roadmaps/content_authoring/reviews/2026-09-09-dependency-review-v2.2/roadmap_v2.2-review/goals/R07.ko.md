# R07 — 파편 사본·개화 선택·정상 획득/장착/저장 동시 전환

**2.2-review.1 · 2026-09-09 · 조사·개정 권고 / 저장소 미적용 / 게임 구현·Goal 실행 미승인**

이 문서는 **로드맵 작업 카드**다. 정식 P2G Goal 또는 GEX activation이 아니다. 기존 CA 대응: CA10, CA17, CA19. 기본 순서 번호: 7. 현재 상태: `proposed_not_implemented`.

## 1. 목적과 먼저 필요한 설계

K01 fragment definition와 OwnedFragment; K05 copy resource/form; K07 효과 계획 invalidation; 저장 의미.

## 2. 구현 선행과 검증 선행

기능상 선행: [R01](R01.ko.md), [R05](R05.ko.md).

검증 선행: 없음.

진행상 권장: [R06](R06.ko.md).

이 목록은 선행 단위 전체의 모든 기능을 요구하는 것이 아니다. [관계별 producer output와 consumer](../DEPENDENCIES.ko.md)가 필요한 최소 계약을 특정한다. 기본 순서는 별도로 보수적인 순차 진행을 택했다.

## 3. 동반 전환 범위

종류→count/progress 장부를 단일 copy aggregate로 교체 + grant/UUID/장착/선택/개화 recipe/분쇄/사망 회수 + employee profile/compatibility/표시 + checkpoint/entry/restore invariant + 최신 RON/시험. 파편 일반 강화 제거 intrinsic/passive+active 조합의 slot·공명·등록을 같은 profile binding에서 구별하며, 고급 channel/override 기믹은 R11이 확장한다..

최소 동시 전환 묶음: AT07. 서로 다른 atomic group이나 한 카드의 여러 기능을 모두 단일 runtime transaction으로 합치라는 뜻은 아니다.

## 4. 재사용·교체·제거

**재사용:** EquipmentLoadoutTransition의 clone/검증/commit 패턴, EconomyGrantState 및 UUID ownership.

**교체·제거 방향:** definition 공통 progress·장착 definition ID·일반 파편 강화 경로를 이번 새 schema 안에서 제거; 개인 기존 파일 삭제/자동변환 금지.

## 5. 직후 유효 상태

같은 정의 A만 개화·형태 선택, B 미개화; 이전 후에도 A identity 유지. 현재 지원 기능의 기본/개화 form이 실제 전투에 적용되고 저장된다.

다음 단계를 전혀 수행하지 않아도 이 약속이 충족되어야 한다. 미지원 후속 기능은 publication/descriptor에 명시하고 빈 executor·임시 성공·조용한 fallback으로 완료하지 않는다.
