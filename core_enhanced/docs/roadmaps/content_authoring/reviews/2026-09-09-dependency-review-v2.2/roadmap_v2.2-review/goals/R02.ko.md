# R02 — 외부 다중 팩·검증 세대·새 런/저장 결속

**2.2-review.1 · 2026-09-09 · 조사·개정 권고 / 저장소 미적용 / 게임 구현·Goal 실행 미승인**

이 문서는 **로드맵 작업 카드**다. 정식 P2G Goal 또는 GEX activation이 아니다. 기존 CA 대응: CA02, CA19, CA22. 기본 순서 번호: 2. 현재 상태: `proposed_not_implemented`.

## 1. 목적과 먼저 필요한 설계

K02 최신 authored schema와 owned source 위치; K03 resolved fingerprint·run pin·profile 보존; PG07 explicit override.

## 2. 구현 선행과 검증 선행

기능상 선행: [R01](R01.ko.md).

검증 선행: 없음.

진행상 권장: 없음.

이 목록은 선행 단위 전체의 모든 기능을 요구하는 것이 아니다. [관계별 producer output와 consumer](../DEPENDENCIES.ko.md)가 필요한 최소 계약을 특정한다. 기본 순서는 별도로 보수적인 순차 진행을 택했다.

## 3. 동반 전환 범위

파일 snapshot/manifest/namespace/dependency/명시 replace/remove → effective 참조/compile/generated setup → immutable publication. CoreApplication/factory·briefing/starter부터 run pin·save fingerprint reader/writer/검증·공식 pack 패키징·A/B fixture 동시 전환.

최소 동시 전환 묶음: AT02. 서로 다른 atomic group이나 한 카드의 여러 기능을 모두 단일 runtime transaction으로 합치라는 뜻은 아니다.

## 4. 재사용·교체·제거

**재사용:** 현재 load_live_sources 검증 후 게시·Arc 데이터·generated setup 검증·state transaction의 원리.

**교체·제거 방향:** 고정 borrowed source inventory/include_str production 경로와 고정 파일수 권한을 외부 pack 경로로 교체. state-only commit에 game_data를 몰래 넣는 방식 금지.

## 5. 직후 유효 상태

외부 A로 시작한 기존 런은 A를 유지하고 새 런은 검증된 B를 선택. 실패 B는 미게시·기존 session/profile 무변경. 새 format만 읽는 전환은 이 단위 범위에서 소유.

다음 단계를 전혀 수행하지 않아도 이 약속이 충족되어야 한다. 미지원 후속 기능은 publication/descriptor에 명시하고 빈 executor·임시 성공·조용한 fallback으로 완료하지 않는다.

## 7. 조건·미정·범위

정책 gate: PG07.

새 generation은 pending briefing부터 pin해야 한다. 현재 PreparedApplicationCommit은 state와 seed만 commit하므로 generation-aware commit 또는 profile을 넘기는 새 factory를 명시적으로 택한다. 기존 런 메모리 세대 보존은 legacy parser 지원이 아니다.
