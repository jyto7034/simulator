# R13 — 소환 actor·정지 trap·field object·진화

**2.2-review.1 · 2026-09-09 · 조사·개정 권고 / 저장소 미적용 / 게임 구현·Goal 실행 미승인**

이 문서는 **로드맵 작업 카드**다. 정식 P2G Goal 또는 GEX activation이 아니다. 기존 CA 대응: CA14. 기본 순서 번호: 13. 현재 상태: `proposed_not_implemented`.

## 1. 목적과 먼저 필요한 설계

K09 spawn와 reward/wave authority 분리; K05 source snapshot/수명; HP비용·생성 transaction.

## 2. 구현 선행과 검증 선행

기능상 선행: [R04](R04.ko.md), [R05](R05.ko.md), [R07](R07.ko.md), [R10](R10.ko.md), [R12](R12.ko.md).

검증 선행: 없음.

진행상 권장: 없음.

이 목록은 선행 단위 전체의 모든 기능을 요구하는 것이 아니다. [관계별 producer output와 consumer](../DEPENDENCIES.ko.md)가 필요한 최소 계약을 특정한다. 기본 순서는 별도로 보수적인 순차 진행을 택했다.

## 3. 동반 전환 범위

공통 SpawnKernel adapter + Actor/Trap/FieldObject 별 capability/schema + 배치/점유/정지/형태 진화 + segmented HP/HP fallback + 삭제/철수/source binding + 보상권한/fixture.

최소 동시 전환 묶음: AT13. 서로 다른 atomic group이나 한 카드의 여러 기능을 모두 단일 runtime transaction으로 합치라는 뜻은 아니다.

## 4. 재사용·교체·제거

**재사용:** SpawnKernel의 정규화·idempotent request·원자적 commit·기존 actor summon.

**교체·제거 방향:** boss-only pending task/Side::Opponent 가정은 공통 actor adapter에서 분리. zero-speed validation 우회 대신 정지매개체 계약.

## 5. 직후 유효 상태

아군/적 actor와 정지 함정·벽이 각 기능에 맞게 생성된다. 작은→큰 진화는 논리적 형태 전환이다. node ID 유지/교체는 기술 설계에서 선택하되 source 권한과 stale link/event 무효화를 함께 보장한다..

다음 단계를 전혀 수행하지 않아도 이 약속이 충족되어야 한다. 미지원 후속 기능은 publication/descriptor에 명시하고 빈 executor·임시 성공·조용한 fallback으로 완료하지 않는다.
