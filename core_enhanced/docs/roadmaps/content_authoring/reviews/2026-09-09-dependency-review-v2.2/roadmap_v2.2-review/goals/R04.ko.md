# R04 — 사건·실제 결과·출처·현재 전달체의 ActionHandle

**2.2-review.1 · 2026-09-09 · 조사·개정 권고 / 저장소 미적용 / 게임 구현·Goal 실행 미승인**

이 문서는 **로드맵 작업 카드**다. 정식 P2G Goal 또는 GEX activation이 아니다. 기존 CA 대응: CA01, CA06, CA07, CA13, CA22. 기본 순서 번호: 4. 현재 상태: `proposed_not_implemented`.

## 1. 목적과 먼저 필요한 설계

K01 definition/copy/activation/strike/segment; K04 request/milestone/terminal; K06 receipt/pre-death/suppression; K08 인과 포트.

## 2. 구현 선행과 검증 선행

기능상 선행: [R01](R01.ko.md).

검증 선행: 없음.

진행상 권장: [R03](R03.ko.md).

이 목록은 선행 단위 전체의 모든 기능을 요구하는 것이 아니다. [관계별 producer output와 consumer](../DEPENDENCIES.ko.md)가 필요한 최소 계약을 특정한다. 기본 순서는 별도로 보수적인 순차 진행을 택했다.

## 3. 동반 전환 범위

damage/heal/cost/death의 결과 생성·구독 dispatch 분리; current cast/step/projectile/area의 fallible request와 bounded handle/epoch/terminal; equipment persistent copy→draft→RuntimeItem source binding; log와 실행 사실 분리; 취소/실패 fixture.

최소 동시 전환 묶음: AT03, AT04. 서로 다른 atomic group이나 한 카드의 여러 기능을 모두 단일 runtime transaction으로 합치라는 뜻은 아니다.

## 4. 재사용·교체·제거

**재사용:** DamageSourceSnapshot·cast_seq·pending start_seq·step progress·death/wave 흐름.

**교체·제거 방향:** 기존 무응답/단순 로그를 typed 완료 계약으로 대체할 해당 호출자; copy provenance를 base UUID/index로 추정하지 않음.

## 5. 직후 유효 상태

기존 스킬/전달체를 그대로 쓰면서 Accepted/Released/FlowFinished/EffectsSettled와 실제 HP/회복/처치·비용을 관찰한다. 보스 adapter나 새 Flow 전체는 아직 필요 없음.

다음 단계를 전혀 수행하지 않아도 이 약속이 충족되어야 한다. 미지원 후속 기능은 publication/descriptor에 명시하고 빈 executor·임시 성공·조용한 fallback으로 완료하지 않는다.

## 7. 조건·미정·범위

정책 gate: PG02, PG03, PG04.

현재 파편에는 아직 사본 ID가 없으므로 가짜 사본을 만들지 않는다. 장비 사본 연결은 실제 소유 ID로 하고 파편 copy binding은 R07이 확장한다. 이 단계의 새 handle 상태는 attempt-local로 종료/후퇴 때 회수한다.
