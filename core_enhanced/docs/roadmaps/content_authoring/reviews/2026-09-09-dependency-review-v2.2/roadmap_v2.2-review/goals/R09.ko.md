# R09 — 파편 침식·강제 시계·직원 대가/Breakdown 동시 전환

**2.2-review.1 · 2026-09-09 · 조사·개정 권고 / 저장소 미적용 / 게임 구현·Goal 실행 미승인**

이 문서는 **로드맵 작업 카드**다. 정식 P2G Goal 또는 GEX activation이 아니다. 기존 CA 대응: CA18, CA19. 기본 순서 번호: 9. 현재 상태: `proposed_not_implemented`.

## 1. 목적과 먼저 필요한 설계

K06 mandatory death vs optional dispatch; 실제 시전 시작과 Pause/준비/공명 관계; K05 attempt→result; host-clock·Breakdown node 정책.

## 2. 구현 선행과 검증 선행

기능상 선행: [R04](R04.ko.md), [R05](R05.ko.md), [R07](R07.ko.md).

검증 선행: 없음.

진행상 권장: 없음.

이 목록은 선행 단위 전체의 모든 기능을 요구하는 것이 아니다. [관계별 producer output와 consumer](../DEPENDENCIES.ko.md)가 필요한 최소 계약을 특정한다. 기본 순서는 별도로 보수적인 순차 진행을 택했다.

## 3. 동반 전환 범위

시전 대체 transaction + 현재 적 집합 capture/특수 kill + Withdrawn/trauma100/Breakdown attempt 상태 + 모든 mutation의 강제정지 guard/host elapsed + terminal/result/노드 countdown/회복/사망 자산회수/checkpoint + fake-clock tests.

최소 동시 전환 묶음: AT09. 서로 다른 atomic group이나 한 카드의 여러 기능을 모두 단일 runtime transaction으로 합치라는 뜻은 아니다.

## 4. 재사용·교체·제거

**재사용:** withdraw·finalize death bookkeeping·attempt roster/result commit·entry restore의 기존 경계.

**교체·제거 방향:** 기존 condition에는 없는 collapse countdown을 필요한 owner에 추가; 전투불능 대가나 일반 playback pause로 침식을 흉내내지 않음.

## 5. 직후 유효 상태

시전 자격과 실제 실행이 연결되고 현재 적만 처치하며 미출현 wave 유지. 대가가 즉시 종료 전투에서도 한 번 반영되고 강제 정지 중 읽기만 가능.

다음 단계를 전혀 수행하지 않아도 이 약속이 충족되어야 한다. 미지원 후속 기능은 publication/descriptor에 명시하고 빈 executor·임시 성공·조용한 fallback으로 완료하지 않는다.

## 7. 조건·미정·범위

정책 gate: PG03, PG04, PG05, PG06, PG09.

보스 전체·shared shield·유물 chain 전체는 필수 선행이 아니다. 이후 R12/R16/R18의 새 subscriber는 suppression/clock 회귀를 의무 인수한다. 실제 시전이 UI 접수/준비 시작/release 중 어디인지 무단 재해석하지 않으며 해당 계약이 확정되지 않으면 이 단위만 policy-pending이다. 룰북의 Pause 중 일반 cast 시작/자원 소비 즉시 반영은 유지한다. 침식 판정은 별도 실제 cast-start 결정 지점을 설계해야 하며 단순히 focus 종료/release와 같다고 확정하지 않는다. 해당 시점·비용 의미가 충돌하면 R09의 P2G-10 정책 owner에 반환한다; 현재 최소 Goal의 선행은 아니다.
