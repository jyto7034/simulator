# R20 — 런 결과·후퇴·재시도·저장·재접속 교차 검증

**2.2-review.1 · 2026-09-09 · 조사·개정 권고 / 저장소 미적용 / 게임 구현·Goal 실행 미승인**

이 문서는 **로드맵 작업 카드**다. 정식 P2G Goal 또는 GEX activation이 아니다. 기존 CA 대응: CA19. 기본 순서 번호: 20. 현재 상태: `proposed_not_implemented`.

## 1. 목적과 먼저 필요한 설계

K03fingerprint; K05lifetime; K06result exactlyonce; compiledindex 저장금지.

## 2. 구현 선행과 검증 선행

기능상 선행: 없음.

검증 선행: [R09](R09.ko.md), [R17](R17.ko.md), [R18](R18.ko.md), [R19](R19.ko.md).

진행상 권장: 없음.

이 목록은 선행 단위 전체의 모든 기능을 요구하는 것이 아니다. [관계별 producer output와 consumer](../DEPENDENCIES.ko.md)가 필요한 최소 계약을 특정한다. 기본 순서는 별도로 보수적인 순차 진행을 택했다.

## 3. 동반 전환 범위

각 R의 save/restore/입력거부 증거 대조 + result delta sourcecopy exactlyonce + 복수상태 rollback/retry/reconnect/mismatch 통합 fixture; 필요한 actual 누락만 수정.

이 카드가 소비하는 선행 atomic group은 이미 유효해야 한다. 통합 검증 카드는 새 상태 저장을 처음 도입하는 자리가 아니다.

## 4. 재사용·교체·제거

**재사용:** 현 capture/restore 및 result transaction.

**교체·제거 방향:** 새 저장을 이 단계까지 미루거나 full live battle durable save로 확대하지 않음.

## 5. 직후 유효 상태

이미 각 기능단계에서 유효했던 저장·복원 계약이 복합조합에서도 유효함.

다음 단계를 전혀 수행하지 않아도 이 약속이 충족되어야 한다. 미지원 후속 기능은 publication/descriptor에 명시하고 빈 executor·임시 성공·조용한 fallback으로 완료하지 않는다.

## 7. 조건·미정·범위

정책 gate: PG05, PG07.

이전 CA19도 이미 각 기능의 저장 동반을 요구했다. 본 개정은 그 의도를 R별로 구체화한 것이지 원래 로드맵이 저장을 전부 뒤로 미뤘다고 판정한 것이 아니다.
