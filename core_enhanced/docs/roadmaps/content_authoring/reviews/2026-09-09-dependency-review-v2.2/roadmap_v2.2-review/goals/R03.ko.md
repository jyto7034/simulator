# R03 — 공통 작성 API·CLI·설명·headless 최소 포트

**2.2-review.1 · 2026-09-09 · 조사·개정 권고 / 저장소 미적용 / 게임 구현·Goal 실행 미승인**

이 문서는 **로드맵 작업 카드**다. 정식 P2G Goal 또는 GEX activation이 아니다. 기존 CA 대응: CA03. 기본 순서 번호: 3. 현재 상태: `proposed_not_implemented`.

## 1. 목적과 먼저 필요한 설계

K10 source 진단/semantic receipt; K02 descriptor와 실제 executor 일치; K03 test session swap.

## 2. 구현 선행과 검증 선행

기능상 선행: [R01](R01.ko.md), [R02](R02.ko.md).

검증 선행: 없음.

진행상 권장: 없음.

이 목록은 선행 단위 전체의 모든 기능을 요구하는 것이 아니다. [관계별 producer output와 consumer](../DEPENDENCIES.ko.md)가 필요한 최소 계약을 특정한다. 기본 순서는 별도로 보수적인 순차 진행을 택했다.

## 3. 동반 전환 범위

library validate/describe/explain/simulate + 명시 Cargo binary 등록 + release 공개 로딩 + seed/input/clock/pack fingerprint receipt + 성공 후 시험 session 교체.

이 카드가 소비하는 선행 atomic group은 이미 유효해야 한다. 통합 검증 카드는 새 상태 저장을 처음 도입하는 자리가 아니다.

## 4. 재사용·교체·제거

**재사용:** CoreApplication/ValidatedGameData·기존 headless 시험 seam.

**교체·제거 방향:** test-fixtures 전용 builder를 제작자 production API로 오인하지 않음; 전용 콘텐츠 runner 금지.

## 5. 직후 유효 상태

독립 외부 RON 경로에서 production과 같은 검증·실행을 사용할 수 있다. 현재 지원 어휘만 공개하고 후속 primitive는 각 owner가 즉시 등록.

다음 단계를 전혀 수행하지 않아도 이 약속이 충족되어야 한다. 미지원 후속 기능은 publication/descriptor에 명시하고 빈 executor·임시 성공·조용한 fallback으로 완료하지 않는다.

## 6. 검증 owner·입력·기대 결과

| 항목 | 내용 |
| --- | --- |
| 구현·자체 검증 owner | R03 |
| 기존 수용 기준 | T04, T25, T29 |
| 시험 입력 | 같은 오류의 API/CLI 입력; release 실행; 정상/손상 reload; readonly explain 전후 state/RNG/revision |
| 기대 결과 | API와 CLI 오류 의미 일치, failed reload 이전 session 유지, 실제 nonzero 실행, readonly 조회 무변경 |
| 이번 실제 실행 | 없음. 아래는 향후 구현 owner의 시험 계획이다. |

새 RON/schema/opcode를 도입하는 범위는 실제 parser→validation→compiler→executor와 negative fixture를 함께 소유한다. 새 상태는 필요한 save/restore/entry/result·취소·실패 무변경 시험도 이 카드에서 닫는다. 실제 명령·선택된 test·nonzero 건수·exit code·source revision이 없으면 PASS로 기록하지 않는다.
