# R05 — 타입화 자원·owner×lifetime·원자적 소비

**2.2-review.1 · 2026-09-09 · 조사·개정 권고 / 저장소 미적용 / 게임 구현·Goal 실행 미승인**

이 문서는 **로드맵 작업 카드**다. 정식 P2G Goal 또는 GEX activation이 아니다. 기존 CA 대응: CA04, CA19, CA22. 기본 순서 번호: 5. 현재 상태: `proposed_not_implemented`.

## 1. 목적과 먼저 필요한 설계

K05 owner와 lifetime 별도; K06 CostReceipt; Run/Attempt/Deployment/Activation/Delivery/Chain 종료.

## 2. 구현 선행과 검증 선행

기능상 선행: [R04](R04.ko.md).

검증 선행: 없음.

진행상 권장: [R03](R03.ko.md).

이 목록은 선행 단위 전체의 모든 기능을 요구하는 것이 아니다. [관계별 producer output와 consumer](../DEPENDENCIES.ko.md)가 필요한 최소 계약을 특정한다. 기본 순서는 별도로 보수적인 순차 진행을 택했다.

## 3. 동반 전환 범위

resource store·reserve/commit/abort·cap/grant/decay·epoch/lease + 실제 persistent 장비/직원 owner와 battle binding + 필요한 Run 저장/entry restore/result delta + 실패/재배치 tests.

최소 동시 전환 묶음: AT05. 서로 다른 atomic group이나 한 카드의 여러 기능을 모두 단일 runtime transaction으로 합치라는 뜻은 아니다.

## 4. 재사용·교체·제거

**재사용:** 기존 battle attempt/entry/checkpoint transaction·장비 독립 소유.

**교체·제거 방향:** RuntimeUnit 또는 definition ID 하나로 모든 상태를 합치는 경로를 새 상태에는 사용하지 않음.

## 5. 직후 유효 상태

두 소유 사본의 자원이 분리되고 배치 stack만 재배치에 초기화된다. attempt 사용 횟수와 Run 자원은 지정된 수명을 따른다.

다음 단계를 전혀 수행하지 않아도 이 약속이 충족되어야 한다. 미지원 후속 기능은 publication/descriptor에 명시하고 빈 executor·임시 성공·조용한 fallback으로 완료하지 않는다.

## 6. 검증 owner·입력·기대 결과

| 항목 | 내용 |
| --- | --- |
| 구현·자체 검증 owner | R05 |
| 기존 수용 기준 | T05, T20, T23, T29 |
| 시험 입력 | 같은 정의 두 장비 사본; copy-owner deployment/attempt 자원; 비용 중 실패; retreat/retry; stale timer |
| 기대 결과 | 거부 시 자원·ID·RNG·queue·revision 모두 무변경. Run 자원은 round-trip 및 source-owner exactly-once 반영 |
| 이번 실제 실행 | 없음. 아래는 향후 구현 owner의 시험 계획이다. |

새 RON/schema/opcode를 도입하는 범위는 실제 parser→validation→compiler→executor와 negative fixture를 함께 소유한다. 새 상태는 필요한 save/restore/entry/result·취소·실패 무변경 시험도 이 카드에서 닫는다. 실제 명령·선택된 test·nonzero 건수·exit code·source revision이 없으면 PASS로 기록하지 않는다.
