# 로드맵 운영 규칙

2026-09-27 · v2.0 · 개발 진입점은 [ROADMAP_STATUS.md](ROADMAP_STATUS.md) 하나다.
이 문서는 작업 선택과 문서 갱신만 안내한다. 정책·Phase Plan·실행·감사의 원본은 P2G/GEX와 선택된 작업의 산출물이다.
cleanup 전 전체 운영 규칙은 [아카이브](archive/cleanup_20260927/README.ko.md)에 보존했다.

## 1. 문서별 책임

기존 roadmap/의 CA 카드와 reviews/의 R 연구 카드는 요구·의존성 근거로 보존한다.
CA/M↔R 대응은 기존 대응표에 맡긴다. 새 전체 복제 장부·별도 상태 기계·실행 DB를 만들지 않는다.
정책/실행 원문과 조회표가 다르면 exact source·후속 변경 관계를 확인해 조회표를 고친다. 원문을 표에 맞추어 바꾸지 않는다.

## 2. 요청 선택과 재개

사용자 최신 지시가 우선한다. 짧은 '계속/다음'은 요청 시작 시 현황에 연결된 대상과 범위 안에서 해석한다.
문서 파일의 존재·읽기·검토 PASS·모델 변경·현황 갱신만으로 구현 또는 다음 Topic의 실행 권한이 생기지 않는다.

- 개발 주작업과 이번 요청을 구분한다. 로드맵 cleanup이나 후속 기능 논의는 개발 주작업 변경이 아니다.
- 범위가 명확하면 실제 원본을 확인하고 진행한다. 모호하면 필요한 근거를 찾고 실질적인 선택만 질문한다.
- 계획·구현·감사 또는 특정 단계검토 등 사용자가 지정한 종료점을 우선한다. 일반 '계속'으로 계획→구현 경계를 넘지 않는다.
- 구현은 승인 범위의 수정·검증·필요한 기술 교정을 마친 뒤 대상과 증거를 고정한다. 감사만 요청받았으면 source를 수정하지 않는다.
- 요청 대상 내부 전환은 현재 P2G/GEX 계약을 따른다. 요청을 다른 R·Topic·Goal로 자동 확대하지 않는다.

### 사용자가 채택하는 단일 R 실행 요청

[AUTORUN_REQUEST](AUTORUN_REQUEST.ko.md)를 사용자가 명시적으로 채택한 경우에만 해당 단일 R 계획 요청을 적용한다.
대상 R을 최초 인수에서 고정하고 승인된 P2G-60 인계 완료까지 진행한 뒤 정상 종료한다. P2G 내부 통상 전환마다 재승인을 반복하지 않는다.
구현은 별도 명시적 요청으로 인수한다. 과거 R00–R24 연속 실행 요청을 현재 범위 확대 근거로 사용하지 않는다.
현재 R이 구현 중이면 과거 계획 문구의 '구현 요청 대기'만 보고 처음부터 재시작하지 않고 최신 실행·교정·검토를 확인한다.

### 명시적으로 요청할 때만 중간 단계검토

기본 구현 종료점과 명시적 단계검토는 [GEX](../../goal_execution_pipeline%281%29.md#기본-구현-인계와-선택적-단계검토)를 따른다.
사용자가 단계검토를 요청했다면 중단 조건·검증 기준을 먼저 연결하되, 의미 있는 부분 구현·빌드·관련 검증 후 중단 지점을 선택할 수 있다.
구현 전 기준선과 구간 종료 target·증거·남은 범위를 고정하고 검토 요청 대기에서 종료한다. 지정된 중단 지점은 준수한다.
부분 검토를 Goal 전체 감사로 대체하지 않는다. 감사까지 명시 위임되지 않았다면 구현·자체 검증 후 감사 요청 대기에서 종료한다.

### 정책 의논 시 주 작업 대기와 실행 중인 독립 작업

사용자 선택이 필요한 정책은 [P2G §8.6](../../policy_to_goal_pipeline_revised_v2.md#86-blocker와-중단-조건)과 현재 요청을 따른다.
이미 합의된 의미의 통상적 기술 판단은 해당 owner에 근거를 남겨 수행하며 재확인을 반복하지 않는다.
사용자 답변이 필요한 작업은 답변 전에 진행하지 않는다. 같은 정책과 무관하고 이미 승인·배정된 독립 작업만 기존 범위 안에서 처리한다.
새 작업·위임·후속 전환의 근거로 정책 대기를 이용하지 않는다. 답변이 없다는 사실은 승인이나 정책 결정이 아니다.

## 3. 현재 근거와 의존성

현황 → 선택 작업의 최신 근거 → 현재 P2G/GEX의 필요한 절 → 관련 source·시험 순으로 확인한다.
이미 읽은 불변 자료를 반복해서 전부 읽거나, 유효한 선행을 새 작업인 것처럼 재실행하지 않는다.

계획상 선행, 코드로 확인한 생산자/소비자 관계, 실제 구현·감사 충족을 구분한다.
후행의 입력·상태·수명·오류/복원·저장·검증을 확인하며 번호가 가깝다는 이유로 필수 의존이나 병렬 가능을 단정하지 않는다.
선택 범위의 실제 순서는 current Phase Plan이 소유한다. 동결된 Plan 변경은 해당 owner의 변경 절차를 거치며 현황표로 우회하지 않는다.
후속 모든 단계의 상세 설계를 첫 작업의 선행으로 요구하지 않는다. 현재 범위를 좌우하는 근거 부족은 후속으로 숨기지 않는다.

과거 hash·test count는 당시 source에 귀속한다. 현재 선행 충족·target/검토 대상 일치·권한·파일 충돌은 실제 인수 때 확인한다.
같은 파일의 다른 작업자 변경을 덮어쓰지 않는다. dirty나 오래된 '진행 중' 표지만으로 재개를 영구 차단하지 않는다.

## 4. 현황 갱신

1. 실제 결과·남은 문제는 선택 작업의 원래 소유 문서에 기록한다.
2. 현황에는 현재 R·세부 위치·다음 개발 작업 하나와 최신 원본 링크를 반영한다.
3. 별도 조사/문서 작업은 이번 요청에 기록하고, 사용자가 전환하지 않은 개발 주작업은 유지한다.
4. 최근 기록은 간결하게 유지하고 오래된 기록은 history/로 옮긴다. 원래 기록 번호·판정·링크 목적지는 보존한다.

요약에는 무엇이 완료됐고 남았는지, 다음 담당자가 읽을 실제 위치와 종료점을 적는다.
문서 작성·구현 종료·시험 통과·독립 감사 완료를 같은 완료로 표시하지 않는다. 미확인을 임의 미착수로 바꾸지 않는다.
source·정책·범위가 달라진 부분만 재확인하고 전체 원문/콘솔을 현황에 복제하지 않는다.
실제 링크가 없으면 찾아 확인하고, 없는 Ref·완료 판정·검증 결과를 만들어 넣지 않는다.

## 5. 원본 보존과 정리

정리 대상은 역할·참조·사용 여부로 정한다. 더 오래됐다는 이유만으로 요구사항·의존성·동결 증거를 삭제하지 않는다.
폐기한 배포 보조물은 archive에 실제 bytes와 원래 경로를 남긴 뒤 활성 위치에서 제거한다.
현재 참조와 해시 검사가 필요한 roadmap/·reviews/·관련 guides/·동결 목표/감사 자료는 원래 위치를 유지한다.
원문 이동이 필요하면 복원 자료와 링크 목적지·검증 영향을 함께 처리한다. 개인 저장 데이터는 정리 대상이 아니다.

[P2G 원문](../../policy_to_goal_pipeline_revised_v2.md), [GEX 원문](../../goal_execution_pipeline%281%29.md)이 실제 절차를 소유한다.
배포 사본·과거 실행 이력·요청 예문으로 현재 계약을 대체하지 않는다.
