# ARK 통합 게임 위키

**[React 웹 위키 실행·빌드 안내](../../../wiki_site/README.md)** · [기존 오프라인 HTML 열기](index.html)

React + TypeScript + Tailwind CSS 기반 웹 위키는 저장소의 `wiki_site/`에서 개발한다. 공개 배포를 위한 정적 페이지 생성과 독립적인 에셋 묶음을 지원하며, 아래 HTML은 파일을 직접 여는 오프라인 버전으로 유지한다.

환상체·파편·장비·유물·태그, 게임 규칙, 장면별 플레이어 행동을 한 탐색 구조로 읽는다. HTML 파일을 직접 열어 사용하며 서버·인터넷·로그인이 필요 없다. 내부 설계용이므로 숨겨진 기믹도 포함한다.

## 정보 구조

| 구역 | 목록에서 찾는 정보 | 상세에서 이어지는 정보 |
| --- | --- | --- |
| 위키 홈 | 콘텐츠 분류, 장면별 진입, 최근 합의 항목 | 도감 또는 플레이 가이드 |
| 환상체 | 최종 보스·일반 보스·엘리트·도구 | 개요 / 조우 / 파편 / 장비 / 태그·유물 / 검토 기록 |
| 스킬 파편·장비·유물 | 항목별 검색과 목록 | 효과·조건·수치·미정 사항, 관련 환상체와 플레이 |
| 태그·조합 | 공통 태그와 개별 연결 | 태그 정의, 적용 지점, 유물 조합 |
| 장면·플레이어 행동 | 3개 장면 분류, 9개 화면·보기·모드, 66개 행동 | 화면 시안, 입력 → 결과, 결정 상태, 상세 기준 |
| 게임 규칙 | 원정·지도·전투·성장·장착·저장 | 현재 룰북과 주제별 규칙 |
| 화면 상세 | 화면별 명세와 공통 시각·통신 기준 | 해당 장면의 기준 문서 |
| 전체 화면 목록 | 74개 화면군, 250개 대표 상태 | 제작 범위와 시안 진행 기록 |
| 검토·기록 | 미합의 제안·이전 설계·이관 근거 | 현재 본문과 구분된 기록 |

목록 → 상세 본문 → 관련 콘텐츠를 기본 이동 구조로 사용한다. 상세 페이지는 제목·분류·본문·문서 정보·목차를 제공한다. 환상체의 관련 문서는 탭으로 연결하고, 파편·장비에는 로드아웃·메인터넌스·전투 가이드를 연결한다. 검색은 제목·본문·행동의 입력과 결과를 대상으로 하며 기록 포함은 선택 항목이다.

이미지는 기존 UI 시안을 사용한다. 시안의 이름·수치·비용·효과는 예시이며 현재 명세를 우선한다. 실제 캐릭터 이미지나 확정되지 않은 스탯을 임의로 만들지 않는다.

## 내용의 기준 위치

| 내용 | 편집할 원문 |
| --- | --- |
| 환상체·파편·장비·유물·태그 | [콘텐츠 설계 위키](../content/README.md) |
| 게임 판정·경제·저장 | [게임 룰북](../game_rulebook.md)과 `../game_rules/` |
| 화면의 표시·입력·전환·통신 | [UI 설계 위키](../../../../../unity%20projects/ark/docs/ui-layout/ui-layout.md)와 그 아래 `wiki/*.md` |
| 장면·행동 요약 | UI 프로젝트의 `docs/ui-layout/wiki/scene-guide.json` |
| 화면 제작 범위·상태 | UI 프로젝트의 `docs/ui-layout/screen-state-inventory.csv` |

통합 HTML은 위 원문에서 생성하는 읽기 화면이다. 본문을 HTML에서 직접 수정하지 않는다. 확정·기본 적용·초안·미정·보류는 원문 구분을 유지하며 구현 완료로 바꾸지 않는다. 조우·직원용 파편·장비·전용 유물의 경계를 유지한다.

## 갱신

simulator 저장소 루트에서 실행한다.

```bash
python3 core_enhanced/tools/wiki/build.py
```

기본 UI 위치는 현재 두 프로젝트의 배치인 `/mnt/f/unity projects/ark/docs/ui-layout`이다. 다른 배치에서는 경로를 지정한다.

```bash
python3 core_enhanced/tools/wiki/build.py --ui-root "/path/to/ark/docs/ui-layout"
```

생성기는 원문 Markdown·행동 JSON·화면 CSV를 읽어 검색 데이터와 본문을 HTML에 포함한다. UI 이미지와 원문은 상대 링크로 연결한다. 두 프로젝트의 상대 위치를 유지하거나 옮긴 위치에서 다시 생성한다. 원래 장면·행동 안내서는 계속 사용할 수 있다.

생성 시 문서별 SHA-256, 내부 페이지·앵커 연결, 행동의 기준 문서를 검사한다. [빌드 검증 기록](build-report.json)에 결과를 남긴다. 출처 파일은 생성 과정에서 수정하지 않는다. [콘텐츠 원문 보존 검사](../content/maintenance/README.md)는 별도로 유지한다.

화면 코드: [생성기](../../tools/wiki/build.py) · [HTML 템플릿](../../tools/wiki/template.html). 브라우저 검증: [검증 스크립트](../../tools/wiki/check.cjs).

브라우저 검증: [검증 결과](browser-report.json). 데스크톱 1440×1100·모바일 390×844에서 문서 220개, 행동 61개, 시안 25개, 검색·필터·목차·확대 보기·모바일 메뉴를 확인했다. 외부 네트워크 요청과 가로 넘침은 없었다.

## 현재 합의와 아카이브

현재 본문·도감·검색은 최신 합의와 남은 미정 사항을 표시한다. 이전 합의·검토안은 별도 아카이브에서만 탐색한다. 웹 위키는 `/wiki/archive/`, 오프라인 HTML은 아카이브 메뉴를 사용한다. 이전 문서 링크는 유지하며, 정리 전 전체 원문은 [아카이브](../content/archive/README.md)에 보존한다.
