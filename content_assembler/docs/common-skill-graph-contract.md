# 공통 스킬 그래프 계약

2026-10-20 · 게임 정책을 노드 작성·검증으로 연결하는 설계 기준.
현재 노드 편집기나 Core가 아래 기능을 모두 지원한다는 뜻은 아니다.
수치가 미정이어도 구조를 작성하되, 미정 값을 실행 기본값으로 대체하지 않는다.

9월의 개별 스킬 예시는 아래 10월 콘텐츠 원문과 대조한다.
이 문서는 조립기의 설계·차이 목록이다. Core 로드맵의 순서·진행 상태를 대체하지 않는다.

최신 유물 규칙에 이미 정해져 있다. Hello 재입력 자격과 만료 경계도 이번 사용자 답변으로
확정되어 전투 규칙과 파편 원문에 반영했다.
래티씨아의 옛 연결망 예시는 10월 20일 배치·합체·도약 폭발 리워크로 대체되었다.
기존 모델의 기술 구조를 재사용하되 폐기된 개별 기믹을 현재 요구로 되살리지 않는다.

## Forge Statescript 설계 참고

2026-10-21 사용자 합의로 [Forge Statescript 적용 기준](forge-statescript-reference.md)을
외부 설계 참고 기준으로 채택한다. 실행별 상태 분리, 실행 연결과 수명 소유권의 구분,
효과 인스턴스 정리, 종료 사유와 재실행 격리 원칙을 관련 노드·IR·런타임 계약에 반영한다.
검토한 커밋, 우리 시스템에서 보완할 차이와 검증 사례는 연결 문서에서 관리한다.
게임 판정은 현행 원문과 이 계약을 우선하며, Forge의 클래스나 저장·실행 방식을 그대로 도입하지 않는다.
이 결정은 설계 기준이며 새 노드의 Core 실행 지원 완료를 뜻하지 않는다.

## 그래프 컴파일과 RON 산출물

2026-10-20 후속 사용자 합의로
[프로젝트 최종 목표](project-purpose.md)를 다음과 같이 구체화한다.

**노드 그래프 작성 → Core의 그래프 탐색·의미 검증·컴파일 →
실행용 중간 표현(IR) 생성 → RON 저장 → 게임에서 로드·검증·실행**

| 단계             | 책임                                                                                                                      |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------- |
| 편집 원본        | 노드·포트·연결·설정·배치를 보존하여 재편집한다. 미완성 상태도 원본으로 저장한다.                                          |
| Core 검증·컴파일 | 값의 타입·단위·참조, 실행 순서, 분기·합류·반복, 결과 사용 시점과 수명을 검사하고 실행용 IR로 변환한다.                    |
| 실행용 IR        | 값 전달과 실행 흐름을 구분하고 조건·비용·효과·출처·수명을 명시한다. 표시 이름이나 캔버스 배치에서 의미를 추측하지 않는다. |
| RON 산출물       | 검증·컴파일한 실행용 데이터를 별도 파일로 저장한다. 편집 원본을 대체하지 않는다.                                          |
| 게임 로드·실행   | 산출물의 형식·참조를 검증하고 Core에서 정의한 의미대로 실행한다.                                                          |

RON은 직렬화 형식이다. 데이터 흐름의 평가 규칙, 실행 순서와 결과의 유효 범위는
IR·컴파일러·런타임의 계약으로 정의한다. IR 구조를 먼저 설계한 뒤 저장 스키마를 정하며,
노드 목록과 ID/인덱스 참조 등으로 그래프 관계를 보존할 수 있게 한다.
파일이 계층 구조를 표현할 수 있다는 이유로 공유 값·분기·합류를 중첩 트리에 억지로 맞추지 않는다.

실행에 필요한 미정 수치·정책, 지원하지 않는 연산, 잘못된 연결은 원본 노드·포트·연결을
찾을 수 있는 진단으로 알린다. 이런 오류가 있는 그래프를 실행 가능한 산출물로 발행하거나,
미정 값을 임의로 채워 컴파일에 성공한 것으로 처리하지 않는다.
지원하는 공통 노드의 조합으로 작성한 스킬은 스킬별 Core 코드 추가 없이 실행하는 것이 완료 기준이다.

최종 검증은 **원본의 의도 → 컴파일한 IR → RON 저장·재로드 → 실제 실행 결과**의 의미 일치를 확인한다.
값·참조·실행 순서·비용·수명과 실패·취소 처리가 전 과정에서 보존되어야 한다.

2026-10-22 P7/P8에서 지원 대상의 컴파일 경계·IR·RON 로더와 실행 연결을 구현했다.
편집 원본은 `.node-graph.json`이며 컴파일 RON은 별도 버전의 그래프 실행 산출물이다.
기존 스킬 RON과 같은 파일 스키마로 취급하지 않는다. 아래 초기 사전검토의 미실행 표시는
당시 기록이며, 최신 지원·검증 결과는 작업 파이프라인과 이 문서의 계열별 실행 계약을 따른다.

## 공통으로 표현할 규칙

공명과 공격 태세 등 직원 수동 파편의 접수 규칙은 실행 주체·진입 종류에 맞게 적용한다.
2026-10-20 후속 합의로 공명 만충·전량 소비는 기존 파편의 기본 방식이며 유일한 방식은 아니다.
기본 공격·장비 passive·보스 자동 행동도 같은 출처·결과·수명 모델을 사용하지만,
직원 수동 입력의 자격과 비용을 그대로 강제하지 않는다. 실행 주체와 진입 종류를 명시한다.

### 공명 조건과 소비 방식의 분리

[전투 규칙의 후속 합의](../../core_enhanced/docs/game_rules/combat.md#스킬별-공명-조건과-비용)를 따른다.
2026-10-20 후속 합의로 아래 방식들을 미리 표현할 수 있도록 작성 구조를 확장하고,
개별 스킬에서 나중에 선택한다. 아래 목록은 지원할 설계 범위다.
특정 파편에 채택한 비용·수치나 현재 구현된 노드 목록으로 읽지 않는다.

| 축        | 작성할 내용                                                                |
| --------- | -------------------------------------------------------------------------- |
| 저장 상한 | 얼마나 비축할 수 있는가. 기존 배치 초기 공명·충전 규칙과 연결              |
| 사용 조건 | 만충, 지정 최소량 이상, 이번 비용 지불 가능, 공명 조건 없음 등             |
| 소비량    | 고정량, 현재량 전부, 현재량/최대량의 명시 비율, 선택량·횟수 등에 따른 계산 |
| 지불 시점 | 입력 접수, 후속 단계 확정, 생성·발사마다, 유지 중 명시 주기 등             |

소비량과 지불 시점은 조합한다. `만충 필요 + 고정량 소비`, `비용 이상 보유 + 고정량 소비`,
`최소량 필요 + 현재량 전부 소비`, `시작 비용 + 유지 비용`을 서로 다르게 표현할 수 있어야 한다.
0비용은 사용 자격·대상·활성 권리까지 없애는 뜻이 아니다.

| 지원할 소비 방식    | 의미·주의점                                                                                       |
| ------------------- | ------------------------------------------------------------------------------------------------- |
| 고정량              | 한 번에 정해진 양만 소비하고 나머지는 보존. 여러 회분 비축 가능                                   |
| 현재량 전부         | 이번 지불 시점의 보유량 전부 소비. 만충 조건의 필요 여부는 별도                                   |
| 최대량의 일정 비율  | 최대 공명을 기준으로 비용 계산. 현재 보유량이 비용을 충족해야 함                                  |
| 현재량의 일정 비율  | 지불 직전 잔량에 비례. 반복 시 비용 감소, 항상 올림 후 최소 비용 적용                             |
| 선택한 양           | 허용한 최소·최대 안에서 플레이어가 투입량 선택. 실제 지불량을 결과로 제공                         |
| 횟수·생성 수에 비례 | 선택한 수량을 한꺼번에 지불하거나 실제 생성 단계마다 지불. 어느 방식인지 명시                     |
| 유지 중 소비        | 전투 시간의 명시 주기마다 지불. 시작 비용·최대 유지 시간과 조합 가능                              |
| 단계별 추가 소비    | 기본 발동 후 추가 공격·강화 단계에서 비용 지불. 중단 시 미실행 단계까지 차감하지 않도록 계약 명시 |
| 공명 소비 없음      | 후속 입력·사건 발동 등. 별도 자원·활성 권리·행동 제한은 그대로 검사                               |

비용 계산은 타입이 있는 읽기 전용 값이다. 지불 노드는 지불 가능 여부와 실제 비용을 다시 확인하고
해당 효과/단계와의 확정 경계를 소유한다. 위력·횟수가 투입 공명에 비례한다면 재조회한 잔량 대신
해당 지불의 실제 소비 결과를 읽는다. UI 예상 비용과 실제 비용의 의미도 같아야 한다.

유지·단계 비용이 부족할 때 종료할지, 낮은 단계로 마칠지 등의 정책을 명시해야 한다.
미정인 상태에서 자동 대출·음수 공명·환불·약화 발동을 만들어내지 않는다.
획득 잠금과 비용 지불은 별개이므로 일부 소비로 바꾸었다고 사용 중 자동 충전이 허용되지는 않는다.

### 공명의 정수·올림 계약

2026-10-20 후속 합의로 공명은 **정수만** 보유·획득·소비한다. 상한·현재량·요구량·
고정 비용·선택량·최소 비용에는 소수가 없다. 소비 비율도 0~100의 정수 백분율로 작성한다.
비율 소비 비용은 `max(최소 비용, ceil(기준 공명 × 비율 / 100))`로 고정한다.
최소 비용은 올림 뒤 적용하고, 지불 가능 여부는 이 최종 비용으로 검사한다.

- 현재량 30, 비율 25%, 최소 비용 0: 비용 8, 지불 후 22. 다음 동일 지불은 비용 6, 잔량 16.
- 현재량 1, 비율 1%, 최소 비용 0: 비용 1. 소수 잔량을 보유하거나 누적하지 않는다.
- 비율 0%, 최소 비용 0: 비용 0. 최소 비용이 2이면 비용 2이며 보유량이 부족하면 거절한다.
- 공명량 `0.5` 같은 직접 입력은 거절한다. 비율 계산의 올림 규칙으로 잘못된 입력을 자동 보정하지 않는다.

작성기 정수 필드는 JS에서 정확히 보존되는 안전한 정수만 허용하고, 빈 값은 미정으로 보존한다.
소수·안전 정수 범위 밖의 필드는 편집/읽기 단계에서 `field-integer`로 거절한다.
실행 입력의 선택 공명·실제 잔량·계산 결과에도 같은 정수 의미를 검사해야 한다.
Core 대상의 저장 범위가 더 작으면 컴파일/접수 경계에서 추가 검사하며 값을 잘라내지 않는다.
비율 계산 구현은 정수 곱셈과 몫·나머지로 올림을 계산해야 하며 overflow를 검사한다.
부동소수점 계산 뒤 `ceil`을 호출하는 것으로 정확성을 대신하지 않는다.

`rounding` 필드는 제거했다. 저장된 이전 비용 노드에 해당 필드가 남아 있으면 현재 파서는
`fields`로 거절한다. 읽으면서 기존 내림 비용을 올림 비용으로 몰래 변경하지 않는다.
기본 제공 예제는 새 계약으로 갱신했다. 소수 값과 이전 형식의 자동 이행은 제공하지 않는다.
배치 초기 공명의 기존 20% 내림은 비용 계산과 별도 규칙이며, 시간·피해 위력 등 다른 단위의
소수 허용 여부는 이번 공명 합의로 결정하지 않는다. Core 가변 비용 실행은 아직 미구현이다.

### 시간의 밀리초 정밀도 계약

2026-10-20 후속 합의: 작성 화면과 그래프 원본의 시간 단위는 초이며, **0.001초(1밀리초)
단위까지 허용한다.** `0.5`, `1.25`, `1.001`초는 유효하고 `0.0005`, `1.2345`초는 거절한다.
더 세밀한 값을 올림·내림·반올림하거나 허용 오차로 통과시키지 않는다. 공명의 올림 규칙을
시간 변환에 적용하지 않는다.

- `skill-seconds.value`와 `delay.seconds`는 0 이상의 시간이며 밀리초로 정확히 표현되어야 한다.
  유지 시간·공명 지불 주기는 같은 `seconds` 연결 타입을 사용한다.
- `skill-seconds`의 빈 값은 미정이다. 0은 명시적인 값이고, 양수 여부는 소비처가 검사한다.
  특히 공명 지불 주기에는 0초를 허용하지 않는다. 이 합의가 모든 효과에 0초 실행을 허용하는 것은 아니다.
- 작성기에서는 저장된 숫자의 표준 십진 표현으로 정수 밀리초를 계산하며, 밀리초가 JS 안전 정수
  범위를 벗어나면 거절한다. `1.001 × 1000`의 이진 부동소수점 오차를 반올림으로 보정하지 않는다.
  Core 필드별 u32/u64 범위 검사는 후속 컴파일·실행 경계에서 별도로 수행한다.
- 시간 필드의 잘못된 정밀도·범위는 `field-time`으로 편집/읽기를 거절하고 기존 문서·이력을 유지한다.
  일반 숫자 상수가 대기에 연결된 경우에는 경유점을 따라 `time-precision` 진단을 내며,
  원래 숫자와 연결을 보존한다. 일반 숫자를 모든 소비처에서 시간 단위로 제한하지 않는다.
- 임의 계산식이나 실행 시 생성되는 시간값은 현재 작성 검사에서 평가하지 않는다. 컴파일/실행의
  시간 소비 경계에서도 정수 밀리초 여부·범위·해당 연산의 0 허용 여부를 확인해야 한다.
  `0.1 + 0.2`를 JS로 계산한 근사값을 자동으로 `0.3`으로 고치는 규칙을 도입하지 않는다.

기존 파일의 더 세밀한 시간은 자동 변환하지 않는다. 저장 형식은 `node-graph` v1의 초 단위
숫자를 유지하며, 이번 변경은 작성 검사이다. Core 타이머·스케줄러나 시간 배속은 변경하지 않는다.
검증 기록은 [시간 정밀도 검증](../artifacts/time-precision-20261020/verification.json)에 둔다.

### 시간에 따른 위력의 정수·최종 올림 계약

2026-10-20 후속 합의: `skill-time-power`의 **기본 위력·초당 위력 증가·상한은 0 이상의
정수만 입력**한다. 빈 값은 미정으로 보존하고, 소수·안전 정수 범위 밖의 직접 입력은
`field-integer`로 편집/읽기를 거절한다. 비활성 상한도 값이 있으면 정수여야 한다.

고정된 잔여 시간을 밀리초 정밀도 그대로 사용하고 **최종 위력을 한 번 올림**한다.
초 단위 시간을 먼저 정수로 올림하거나 계산 중간마다 올림하지 않는다.
기본 위력 `B`, 초당 증가량 `R`, 고정 잔여 밀리초 `T`로 다음 계약을 따른다.

- 선형: `ceil(B + R × T / 1000)`.
- 상한 있는 선형: `ceil(min(C, B + R × T / 1000))`. 정수 상한 `C`는 기본 위력 이상이어야 한다.
  정수 상한이므로 최종 올림 후 상한을 적용해도 같은 결과지만, 실행 중 중간 반올림은 추가하지 않는다.
- 예시: `B=0, R=10, T=1250`이면 위력 13. `B=100`이면 113, 여기에 `C=110`이면 110.
- `B=0, R=1, T=1`이면 위력 1. `B=0, R=0`이면 0이며 최소 위력 1을 임의로 부여하지 않는다.

계산 구현에서는 정수 분자 `B×1000 + R×T`를 만들고, 필요한 상한을 적용한 뒤 몫·나머지로
최종 올림한다. 곱셈·합산 overflow와 대상 위력 범위를 검사한다. 입력이 각각 안전한 정수라는
이유만으로 그 곱도 안전하다고 가정하거나 JS 부동소수점 산술로 결과를 확정하지 않는다.
입력 잔여 시간은 이미 고정된 값이며 대상별로 다시 읽거나 흘러간 연출 시간을 빼지 않는다.

이 합의는 해당 노드의 위력 산출 규칙이다. 어떤 파편에 선형/상한식을 채택할지나 실제 수치는
확정하지 않는다. 기본 공격 profile, 공격/주문 계수, 방어력·감산·보호막 적용 이후의 실제 HP
피해와 회복의 반올림을 일괄 변경하지 않는다. 다른 수치 영역의 정책은 별도 합의 대상이다.
현재 구현은 정수 작성·저장 검사이며 Core 위력 실행은 미구현이다. 산출값 예시는
`cases.json`의 R08에 **미실행 기대값**으로 남긴다.
검증 기록은 [시간별 위력 정수 검증](../artifacts/time-power-integer-20261020/verification.json)에 둔다.

### 스킬 범위와 장판의 타일 패턴 계약

2026-10-20 후속 합의: **장판을 포함한 모든 스킬의 효과 범위는 타일 기반으로 작성한다.**
부채꼴·직사각형·원 같은 연속 도형을 실제 스킬 범위로 작성하지 않는다. 도형을 타일로
근사하는 중심점/겹침 규칙도 만들지 않는다. 연출 외형과 크기는 실제 효과 타일을 변경하지 않는다.

- `skill-area`의 `pattern`은 위쪽이 전방인 행 문자열이다. `@`는 기준점 하나,
  `X`는 포함 타일, `.`은 제외 타일이며 행 너비는 같아야 한다. 기준 타일 자체는
  `includeAnchor`로 별도 선택한다. 이 표현은 기존 `TileRangePattern`의 의미를 따른다.
- 편집기는 기준점 주변 타일을 눌러 선택하고 보기를 이동해 바깥 타일을 작성한다.
  보기 이동은 문서나 이력을 바꾸지 않는다. 선택 변경은 속성의 변경 적용 때 한 번에 확정한다.
  예제의 실제 범위 크기는 정하지 않으며 빈 패턴을 미정으로 유지한다.
- 빈 패턴 또는 선택 타일이 없는 패턴은 작성·저장이 가능하지만 `skill-value-unset`으로
  진단한다. 잘못된 문자·행 너비·기준점 수는 `field-tile-pattern`으로 편집/읽기를 거절한다.
  기존 필드 문자열 제한 16,384바이트는 편집 한계이며 게임 밸런스 상한이 아니다.
- 실제 효과는 기준 위치와 방향으로 투영한 타일 집합 및 대상의 판정용 타일을 따른다.
  전장 밖/void 제외 등 기존 타일 계약을 유지한다. 원점 선택, 방향 고정 시점, 지속 장판의
  추적·틱·대상 필터는 별도 속성이다. 이 합의로 미정인 값을 자동 확정하지 않는다.
- 이전 `skill-area`의 `shape/length/width/angle/facing` 형식은 정확한 기존 구조만 읽는다.
  `skill-area-legacy` 진단과 재지정 안내를 표시하며 열기/저장/이동/복사만으로 값을 버리거나
  타일로 바꾸지 않는다. 사용자가 타일을 지정하고 적용하면 기존 속성을 한 번에 교체하며
  실행 취소로 원래 도형 값을 복원할 수 있다. 새 노드에는 도형 선택지를 제공하지 않는다.

이전 형식 지원은 편집 원본을 보존하여 다시 작성하기 위한 경로다. 도형 실행이나 RON 변환을
지원한다는 뜻이 아니다. 기존 Core 실행·레거시 제거, 장판 동작 노드의 추가, 기본 공격 교체의
전달·관통 순서는 이번 편집기 변경에 포함하지 않는다. Core 컴파일과 실행은 여전히 미구현이다.

### 공통 스킬 범위와 배치·선택 분리

2026-10-20 후속 합의: **지정 타일 장판은 작성한 패턴의 방향을 그대로 유지한다.**
ㄱ자 패턴이면 시전자의 바라보는 방향과 무관하게 같은 ㄱ자로 놓는다. 패턴의 기준점만
접수한 타일로 평행 이동하고 회전하거나 뒤집지 않는다. 카메라 방향을 판정 입력으로 사용하지 않는다.

| 노드                                      | 작성 의미                                                          | 연결                                                          |
| ----------------------------------------- | ------------------------------------------------------------------ | ------------------------------------------------------------- |
| 스킬 범위 (`skill-range`)                 | 기준점·포함 타일만 정의하는 순수 패턴. 위치·방향·피해·수명 없음    | `tile-pattern` 출력                                           |
| 스킬 대상 선택 (`skill-target-selection`) | 자기 자신 또는 플레이어 지정 타일. 지정 타일은 별도 선택 범위 필요 | 패턴 → `target-selection` → 스킬 입력 사건                    |
| 효과 범위 배치 (`skill-range-placement`)  | 패턴을 시전자 또는 접수한 지정 타일에 놓는 설정                    | 패턴 → `area-profile` → 효과 동작                             |
| 지정 타일 장판 생성 (`skill-ground-area`) | 접수한 사용의 지정 타일에 유한 수명의 고정 장판 생성               | 이번 사용·배치 범위·유지 시간 → 생성 완료·이번 장판·연출 사건 |

- 선택 범위와 효과 범위는 다른 입력이다. 같은 패턴을 의도적으로 공유할 수 있지만,
  연결 없이 한쪽을 다른 쪽으로 추정하지 않는다. 위치가 없는 패턴을 효과 동작에 바로
  연결하면 타입 불일치로 거절한다. 효과 범위에는 배치 설정이 필요하다.
- 대상 선택 설정은 `skill-request.selection`으로 연결한다. 선택·미리보기는 접수 전이며
  최종 타일·자격·범위 재검증과 비용 지불은 기존 접수 경계에서 함께 확정한다.
  플레이어 지정 타일은 빈 타일도 가능하고 접수 이후 다른 타일로 재지정하지 않는다.
  선택 범위는 기존 타일 reach처럼 시전자 타일·방향 기준이다. 이번 추가는 자기 자신과
  지정 타일 작성만 지원하며 자동/수동 유닛 선택 노드는 아직 추가하지 않았다.
- 시전자 기준 효과 배치는 위치 고정과 방향 고정 시점을 각각 접수/방출 중 작성한다.
  지정 타일 기준에는 이 설정을 적용하지 않고, 접수한 타일·맵 기준 패턴 방향을 사용한다.
  숨긴 시전자 설정값이 저장돼 있어도 지정 타일 패턴을 회전시키지 않는다.
- 장판 생성 성공의 다음 흐름은 생성 완료를 뜻한다. 생성한 장판의 유지 시간은 0보다
  큰 전투 시간이며 사용 종료와 별개로 유지한다. 이 노드는 생성 자체에 자동 피해·회복·
  상태 효과·주기 틱을 추가하지 않는다. 장판의 사건·효과는 아래 별도 노드로 연결한다.
- 이번 장판은 지정 타일 접수 문맥을 가진 이번 사용에 연결한다. 다른 요청의 타일을
  가져오거나 거절 분기/종료된 사용에서 생성하는 경로를 진단한다. 범위 배치 값 자체는
  실행 권한이나 확정 대상이 아니며 소비 동작의 요청·사용 문맥에서 평가한다.
- 기존 `skill-area`는 예전 범위·방향 조합을 보존한다. 기존 JSON을 열 때 자동 분해하거나
  새 노드를 삽입하지 않는다. 새 그래프에서는 공통 범위와 배치 노드를 사용한다.
  이전 요청에 선택 설정이 없으면 기존 외부 정의 문맥을 유지하며 자기 대상으로 추정하지 않는다.

[전방 일격 예제](../content/range-front-strike.node-graph.json)와
[지정 타일 장판 예제](../content/range-selected-ground.node-graph.json)는 **범위 구조 검토용**이다.
범위 크기·유지 시간·위력·저장 상한은 미정이며, 전방 예제의 자기 대상 선택을 실제 Hello의
첫 입력 정책으로 채택하지 않는다. 장판 예제에는 효과가 아직 연결되지 않았다.
기존 Hello / Goodbye 콘텐츠 예제는 이 작업에서 수정하지 않는다.

Core의 현재 target-centered footprint 회전 불변 제한은 새 장판 방향 계약의 상한이 아니다.
비대칭 패턴도 그대로 배치하도록 후속 컴파일·Core 구현에서 의미를 보존해야 한다.
현재 구현은 노드 작성·연결·저장·진단이다. 게임에서 실제 회전/배치/장판 수명이 실행되거나
IR/RON으로 컴파일되는 것은 아니다. 검증 기록은
[공통 범위 검증](../artifacts/common-range-20261020/verification.json)에 둔다.

### 장판 사건·대상 효과·상태 수명

2026-10-21 사용자 합의:

- 주기 효과의 첫 발동은 **생성 즉시 / 한 주기 뒤**를 스킬별로 선택한다. 새 노드의 기본값은 미지정이다.
- 생성 순간 이미 범위 안에 있던 대상도 **진입 사건**을 발생시킨다.
- 장판 종료 시각에는 종료가 우선한다. 같은 시각의 주기 효과는 발생하지 않는다.
- 상태 효과별로 **합산 / 가장 강한 값**과 **이탈 시 해제 / 장판 종료까지 유지**를 선택한다.

**시간과 구독.** 사건 구독은 이번 장판 생성 성공에 결속하며, 생성 시 진입과 즉시 주기를
발행하기 전에 설치한다. 이후 사용 종료는 독립 장판을 취소하지 않는다. 생성 시각을 `t0`,
주기를 `P`, 종료 시각을 `E`라 하면 즉시 방식은 `t0 + nP (n ≥ 0)`, 한 주기 뒤 방식은
`t0 + nP (n ≥ 1)` 중 **`t < E`**인 시각만 사용한다. 예를 들어 유지 3초·주기 1초는
즉시 방식에서 0·1·2초, 한 주기 뒤 방식에서 1·2초다. 이는 의미 설명용 수치이며 콘텐츠
기본값이 아니다. 정지 중에는 전투 시간이 흐르지 않는다. 장판이 먼저 끝나면 이후 예약은 취소한다.
체류 시간은 같은 관계의 진입부터 세며 이탈·재진입·다른 장판 사이에 진행을 공유하지 않는다.

**관계와 대상.** 이번 대상 관계는 장판 인스턴스·대상 조건 정의·대상 전투 개체·진입 회차를
식별한다. 진입·체류·이탈과 현재 대상 조회는 같은 조건의 같은 체류 관계를 가리킨다.
지속해서 안에 머무는 대상에 대해 주기 조회가 새 진입을 만들지 않는다. 이탈 사건은 살아 있는
장판에서 범위·대상 자격을 잃은 관계를 알린다. 장판 자체가 끝나면 별도 종료 사건과 수명 정리가
담당하며 이탈 사건을 대신 발행하지 않는다. 대상 사망·소멸 시 상태 기여분도 정리한다.
대상별 실행은 그 시점의 유한한 대상 집합을 사용하고 각 후속 효과는 대상 유효성을 다시 검사한다.
대상 사이 값 전달·순서 의존 누적은 이 노드가 제공하지 않는다. P3에서 추가한 `completed`는
동기 대상 처리가 모두 끝난 뒤 빈 집합에서도 한 번 발생한다. 개별 대상 관계는 이 흐름에서 사용할 수 없다.

**효과와 출처.** 피해·회복·상태는 별도 동작이다. 피해 면역이 다른 상태 적용을 자동 취소하지
않으며 상태도 해당 종류의 면역을 따로 검사한다. 처리 완료 흐름은 피해 성공·처치·실제 회복량을
뜻하지 않는다. 피해 유형은 Physical/Magic/True이고 파편 스킬 출처와 별도다. 각 효과는 장판의
원천 사본·효과 지점과 이번 사건의 인과를 유지한다. 독립 주기는 매번 새 원인이며 같은 주기의
대상별 분기는 해당 원인을 이어받는다. 상태 정의는 실행 중 활성이나 전역 상태 이름이 아니다.

**상태 수명과 중첩.** 같은 상태 정의를 사용하는 장판 인스턴스별로 대상에 대한 기여분을
보존한다. 동일 장판·대상·정의의 반복 적용은 기여분을 복제하지 않는다. 여러 장판의 수치 기여분은
선택한 합산/최댓값으로 결합하며 한 장판이 끝나면 그 기여분만 제거하고 남은 값으로 다시 계산한다.
서로 다른 상태 정의를 표시 이름이 같다는 이유로 합치지 않는다. 서로 다른 정의의 스탯 결합과
유효 스탯 하한·면역은 공통 스탯/제어 계약에 속하며 이번 편집기에서 별도 공식이나 상한을 만들지 않는다.
기절에는 더할 수치가 없으므로 크기·중첩 입력을 숨기고, 유효 기절 기여분이 하나라도 남으면 유지한다.
숨긴 수치는 저장 원본에 보존하지만 기절에 적용하지 않는다.

- 이탈 시 해제: 해당 진입 관계가 닫히면 그 관계의 상태를 해제한다. 재진입은 새 관계다.
- 장판 종료까지 유지: 범위에서 나가도 장판·대상의 기여분을 유지한다. 재진입만으로 중복 부여하지 않는다.
- 두 방식 모두 장판 종료·대상 소멸에서 정리한다. 다른 장판의 상태는 제거하지 않는다.
- 명시 해제 동작은 자동 수명보다 먼저 기여분을 해제할 때 사용한다. 늦게 도착한 이전 관계의
  해제는 재진입 뒤 새로 적용한 기여분을 지우지 않는다. 이미 없어진 기여분의 해제는 무변경이다.

정적 검사에는 같은 사건/대상별 흐름의 지배 관계, 다른 장판으로의 대상 조회 우회,
종료 사건 뒤 현재 대상 조회, 이탈 관계의 새 상태 적용, 같은 장판·상태의 서로 다른 대상 조건,
해제 출처 불일치와 0초 주기/체류 시간 검사가 포함된다. 경유점도 같은 출처로 해석한다.
이 검사는 편집 오류 진단이며 임의 그래프의 모든 런타임 경로를 증명하는 컴파일러는 아니다.

예제는 [주기 피해](../content/ground-damage.node-graph.json),
[주기 회복](../content/ground-heal.node-graph.json),
[진입·체류 상태](../content/ground-status.node-graph.json)다.
범위·유지 시간·주기·위력·상태 크기와 선택이 필요한 정책은 미정으로 남긴다.
예제의 적군 피해/아군 회복은 구조 설명을 위한 선택이며 특정 실제 스킬의 정책을 확정하지 않는다.
기존 범위 전용 예제와 Hello / Goodbye 파일은 변경하지 않는다.

현재 완료 범위는 노드 작성·연결·속성·이력·저장·진단이다. **실제 시간 진행, 대상 조회,
HP/상태 적용, Core 컴파일·IR/RON·전투 실행은 미구현**이다. 여러 독립 사건이 같은 시각에
겹치는 전체 실행 순서, 공통 스탯 파이프라인 결속과 면역/처치 결과의 의미 일치는 후속 Core
계약·실행 검증 대상이다. 종료 우선 합의를 그 밖의 모든 사건 우선순위로 확대하지 않는다.
[장판 효과 작성 검증](../artifacts/ground-effects-20261021/verification.json)에 확인 범위를 기록한다.

### 집중·종속 장판·체류 둔화 — P1, 2026-10-21

[파고드는 천국의 기본형](../../core_enhanced/docs/content/abnormalities/burrowing-heaven/fragment.md)을
[실제 그래프](../content/burrowing-heaven.node-graph.json)로 작성한다. 노드 계약·작성 진단이며
전투 실행기는 아니다. 기존 장판 사건은 독립 장판과 집중 종속 장판을 모두 받는다.

| 노드                           | 작성 계약                                                                                                          |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------ |
| `skill-channel-begin`          | 접수 성공한 사용·양수 최대 시간 → 시작 흐름·이번 집중·연출. 기본 공격 중지/유지, 표준/외부 중단 보호를 명시한다.   |
| `skill-channel-cancel-request` | 이번 집중에 대한 플레이어의 직접 취소 입력. 새 시전 자격·공명 지불과 분리한다.                                     |
| `skill-channel-cancel`         | 같은 살아 있는 집중의 시작 후 흐름 또는 직접 취소 입력에서 종료한다. 이후 처리는 종료 사건에 연결한다.             |
| `skill-channel-ended`          | 종속 효과 정리·사용 잠금 해제 뒤 집중당 한 번 발생한다.                                                            |
| `skill-channel-area`           | 같은 집중의 시작 후 흐름·시전자 배치 범위 → 고정 장판. 위치·방향은 입력 접수 시 고정하고 수명은 집중에서 가져온다. |
| `skill-ground-ramping-slow`    | 장판·대상 조건·양수 체류 시간·0~100% 최대 둔화율 → 대상별 선형 둔화와 도달 흐름·이번 대상 관계.                    |

집중은 최대 시간·직접 취소·사망·철수·전투 종료에서 종료한다. 표준 집중은 Hard CC에서도
취소하며 외부 중단 보호는 현재 집중만 보호한다. 침묵은 새 시전을 막고 진행 중인 집중은 유지한다.
전술 이동·교대 및 사용 중 공명 획득은 공통 규칙에 따라 제한한다. 종료는 같은 시각의 체류 도달보다
우선하며 구독·관계·출처별 상태를 정리한 뒤 잠금을 해제한다. 종료 연출 연결을 빠뜨려도 정리는 수행한다.
직접 취소 입력은 `skill-channel-cancel`로 연결해야 한다. 취소에 종료 후 다음 흐름을 붙이지 않으며
한 번만 발생하는 `skill-channel-ended`를 사용한다. 별도의 `skill-resonance-end`를 붙여 잠금을
일찍 해제할 수 없다. 상태·타이머를 가진 실제 구현은 후속 Core 연동 대상이다.

점진 둔화는 장판 생성 당시 대상도 진입으로 보고 0부터 시작한다.
`최대 둔화율 × min(체류 시간 / 필요 체류 시간, 1)`이며 필요 시간에 관계당 한 번 도달한다.
부동소수점 계산 순서·엔진 정수 속도로의 반올림은 Core 변환 시 명시할 실행 경계다.
둔화 면역과 체류 진행은 분리하고 후속 상태의 면역도 독립 판정한다. 이탈은 둔화·진행을 해제하고
재진입은 새 관계를 만든다. 도달 후에는 이탈까지 최대 둔화를 유지한다. 같은 점진 둔화 정의의 출처별
기여분은 가장 강한 값으로 결합한다. 정지 중 진행·재개 시 보충은 없으며 종료한 장판에서 도달 사건을 내지 않는다.

기절은 기존 `ground-status`의 `effect=stun, lifetime=area`와 상태 적용으로 연결한다.
강제 이동으로 범위 밖에 나가도 그 출처의 장판 종료까지 기절한다. 진입 20% 증폭은 별도 진입 흐름과
`lifetime=membership, overlap=strongest`로 연결하여 제어 면역과 분리한다. 이탈·재진입·여러 출처의
정리는 기존 장판 계약을 따른다. 직접 피해 노드는 연결하지 않으며 빨간 눈은 시작·종료의 연출 포트에만 연결한다.

현재 진단은 사용의 성공 경로·수명 소유자, 취소 입력의 처리, 다른 집중/장판/대상 관계 혼용,
종료 사건으로 장판 재생성, 잘못된 위치 고정 정책, 0초·숫자 범위·밀리초 정밀도와 미정 값을 구분한다.
임의의 모든 실행 그래프에 대한 검증 증명이나 게임 실행 성공을 뜻하지 않는다.

유물 연결 대조는 다음 경계를 유지한다. P1 파일은 기본형이며 장착 유물의 자동 변형은 P6에서 대조한다.

### 일회 대상 조회·시간제 대상 상태 — P2, 2026-10-21

기존 노드를 사용한다. 새 노드는 대상별 상태를 조합하는 작성 계약이며 실제 전투 실행은 후속이다.

`skill-target`, `target-effect-profile`, `target-state-profile`, `target-state-instance` 포트와
네 종류의 경유 노드가 조회 대상·효과 정의·상태 정의·실제 대상 활성을 구분한다.
활성은 사용·시전자·대상·상태 정의·적용 회차를 보존한다. 종료 시 그 활성의 기여분만 제거하며
과거 속도·공격 대상·저지 관계를 저장해 덮어쓰지 않는다. 오래된 종료가 새 활성을 지우지 않는다.

도발은 적 조회와 `sourceExit=end`가 필요하다. 명시적 도발 면역이면 묶음 전체를 거절하고
기존 저지도 유지한다. 새 도발이 성공하면 이전 도발 활성 전체를 종료하며 이전 도발은 복원하지 않는다.
도발 시작 시 미방출 대상 공격은 무환불 취소하고 이미 방출한 효과는 유지한다.
경로가 없으면 정상 대기하며 높이·보스 분류만으로 대상을 제외하지 않는다.
시전자 Hard CC·침묵은 이미 적용한 상태를 끝내지 않는다. 상태는 범위 밖에서도 수명을 유지한다.
세부 게임 정책과 판단 근거는 파편 원문이 소유한다.

이 P2 적 도발·이동 속도 상태는 전체 부여 완료에서 사용을 종료해 공명 충전을 재개하고, 대상 상태의 타이머는 별도로 유지한다.
아군 시간제 강화의 `recipient-buff-plan`은 별개다. 현행 전투 규칙에 따라 기본 공격은 계속하되 마지막 버프가 끝날 때까지 공명 사용 잠금을 유지한다.
Pause 동안 시간은 진행하지 않고 만료가 같은 시각 후속 처리보다 우선한다.
현재 동기 대상별 흐름에는 대기·단계 시간·중첩 대상 조회를 두지 않는다.
실행기에서 대상 처리 순서와 같은 시각 사건의 확정 순서를 보존해야 한다.

진단은 접수 실패/종료한 사용의 조회, 다른 조회·완료 분기에서의 적용, 다른 활성의 해제,
종료 사건의 재적용, 대상별 사용 종료·대기, 중복 효과 종류, 도발의 적/출처 종료 정책,
0 이하 값·밀리초 정밀도·미정 값을 검사한다. 경유·복사·Undo/Redo·파일 왕복에서 같은 검사를 적용한다.
임의 그래프의 실행 안전성을 증명하거나 실제 면역·저지·이동을 실행한 검사가 아니다.

P6 연결 대조에서 넓어진 지평은 조회 범위만, 긴 호흡은 공통 지속 시간을 한 번 변형한다.
도전자의 갑주·응징의 표식은 이번 시전자의 도발 관계를 피해 출처/대상 조건에 결속해야 하며
현재 그래프의 피해 감소·증폭으로 구현하지 않았다. 두 겹의 수확은 무기 인스턴스의 질량 획득이며
파편 상태와 분리한다. 깨진 균형은 제외한다. 이들 유물의 자동 변형·피해 관측·무기 성장은 후속이다.

| `attack-speed-buff`, `pair-intersection`                            | 양수 공격 속도 포인트, 같은 시전 쌍 → 교집합 기여분             | 중립 100 기준 기본 공격/치료 속도. 실제 교집합 진입에 부여, 이탈·소멸·영역 종료/교체에 해당 출처만 제거. 회복 성공과 무관. 여러 사본의 동일 버프는 가장 강한 값                                       |

위 표의 kind에는 `skill-` 접두사를 붙인다. 각 새로운 의미 타입에 같은 의미를 보존하는 경유 노드가 있다.
기존 공명 자격에는 선택적 `terms`, 접수에는 `counterReceipt` 출력만 추가했으므로 이전 파일의 필드 구조는 유지한다.
기존 장판 피해/회복의 `out`은 여전히 **처리 완료**이고 `result`만 실제 결과다.
장판 대상 조회는 동기 대상 처리 후 `completed`를 한 번 내보내며 빈 집합도 완료한다.
개별 `member`는 `out` 대상 흐름에서만 유효하고 `completed`에는 가져갈 수 없다.
단순 다중 흐름 입력을 병렬 작업의 완료 대기로 해석하지 않는다.

**두 영역의 예산.** 각 쪽의 HP 상한 초과분 합계에 전달률을 곱해 내림한 정수를 반대 소속 영역에 보낸다.
기본 회복이 거절된 양·빈 영역은 예산을 만들지 않는다. 반대편의 남은 결손 HP에 비례해 배분하고
정수 잔여는 안정된 ID 순서로 배분한다. 수혜자 부재·소멸·HP 상한 초과로 남은 양은 버린다.
시전자의 동일 회복 증가를 재적용하지 않고 수혜자의 받는 회복 보정은 따른다.
추가 회복/초과분을 다시 전달하지 않는다. 이 규칙의 실제 정수 계산과 HP 변화 검증은 P8 대상이다.

**정적 검사.** 잘못된 성공 분기, 서로 다른 자원·접수·집중·단계·주기 결과, 중복 시전 보상/주기 예산,
수동 상한 입력과 자동 공명 비용, 종료 사용 재개, 수명 소유자 중복, 개수별 범위 누락/축소,
대상별/두 영역 동기 흐름의 지연·새 시전·사용 종료를 진단한다. 정적 연결 검사는 런타임 ID 중복 억제나
실제 대상 선택·HP 계산의 증명이 아니며, 향후 컴파일·실행에서도 같은 계약을 재검증해야 한다.

**실제 작성 사례.** [기본형 여왕](../content/queen-of-hatred.node-graph.json)은 103노드/150연결,
[개화형 여왕](../content/queen-of-hatred-bloom.node-graph.json)은 126노드/180연결,
[음양](../content/yin-yang.node-graph.json)은 21노드/32연결이다. 여왕은 2초 광선·0.5초 판정·15초 획득,
2초 블랙홀과 개화형 3초 빛기둥을 명시했다. 효과 범위/위력/회복/증가율·흡인 거리와 기본형 폭주 광선 시간 등은
각 18/25개의 미정 작성값으로 남겼다. 음양의 최대 공명·선택/효과 범위·수명·주기·회복량·전달률·공격 속도는
8개의 미정 값이다. 연출 설명을 전투 예고 UI 구현으로 취급하지 않는다. 유물 변형·장비 연결·침식형은 P6의 전체 대조 대상이다.

### 공명 노드와 연결 타입의 확장

소비 방식별 전용 실행 노드를 각각 만드는 대신, 아래 공통 노드의 설정과 연결로 표현한다.
2026-10-20 후속 구현으로 공명 작성 카탈로그·연결 타입·정적 검증을 추가했다.
실제 전투 실행·차감·Core 내보내기는 아직 구현하지 않았다.
기존 `skill-qualify`·`skill-begin` 계약은 이전 파일 열기를 위해 유지한다.
새 Hello 예제는 `skill-resonance-qualify → skill-resonance-admit → skill-resonance-install`로
검사·접수와 지불·효과 설치를 구분하며 만충·전량 소비를 그대로 연결한다.

| 노드 책임               | 설정·입출력                                                                           | 변경 여부      |
| ----------------------- | ------------------------------------------------------------------------------------- | -------------- |
| 공명 설정·양 값         | 스킬의 저장 상한 등 매개값과 공명 단위 값. 미정 수치는 그대로 보존                    | 정의만 작성    |
| 공명 조회               | 요청 또는 이번 사용의 소유자·출처를 통해 현재량·최대량과 관측 시점을 읽음             | 읽기 전용      |
| 공명 요구 조건          | 만충·최소량·지불 가능·공명 조건 없음 중 선택. 공통 행동 자격과 함께 사용              | 읽기 전용      |
| 비용 계산               | 고정량·전량·비율·선택량·횟수 비례·0을 선택해 계산 기준과 매개값을 가진 비용 명세 생성 | 읽기 전용      |
| 접수와 지불 / 후속 지불 | 첫 입력 접수 또는 사용 중 특정 단계의 확정. 최신 자격·비용 재검증 후 한 번만 지불     | 성공 시 변경   |
| 지불 결과 조회          | 실제 지불량·지불 직후 잔량·이번 지불의 주체와 단계 참조                               | 확정 결과 읽기 |

첫 접수의 지불과 후속 지불은 서로 다른 실행 계약이다. 후속 지불이 새 사용을 만들거나,
스스로 활성 수명·재입력 권리를 갱신하지 않는다. 유지 비용과 단계 비용은 비용 계산 방식을
추가하는 대신, 명시한 주기 사건·유한 단계 흐름에 후속 지불을 배치한다.
주기·반복 횟수·종료·비용 부족 분기를 함께 작성해야 하며 현재 일반 지연 노드만으로
유지 비용 실행이 지원된다고 보지 않는다.

노드 종류(`kind`)와 연결 값의 타입(`Port.valueType`)을 함께 확장한다.
기존 숫자·시간·이번 활성만으로 아래 의미를 대체하지 않는다.

| 연결 값 타입   | 보존할 의미                                                              |
| -------------- | ------------------------------------------------------------------------ |
| 공명량         | 공명 단위의 비음수 값 또는 미정 매개값. 초·피해 위력과 직접 연결 불가    |
| 공명 조회 결과 | 현재량·최대량, 소유자·출처·관측 시점. 이후에도 유효한 지불 허가가 아님   |
| 공명 요구 조건 | 조건 종류와 해당 매개값. 비용 명세와 별도로 연결                         |
| 공명 비용 명세 | 계산 방식·기준·매개값·기준 시점. 조회한 숫자를 그대로 차감할 권한이 아님 |
| 지불 결과      | 실제 지불량·직후 잔량·요청/사용/단계 식별. 성공한 흐름에서만 이용 가능   |

공명량으로부터 최대량·최소 요구량·고정 비용을 각각 작성할 수 있다.
최대량 정의는 스킬 설정의 한 원본을 참조하고 검사·지불 노드마다 복제하지 않는다.
일반 숫자로 비율·횟수를 받더라도 각 입력의 범위·정수 여부와 공명량 변환을 명시한다.
비율 비용은 항상 올림한다. 최소 비용과 선택량의 허용 범위가 미정이면 이를 진단하며 값을 임의로 정하지 않는다.

예를 들어 다음 두 설정은 같은 노드 구성을 사용한다.

- 기존 방식: `요구 조건 = 만충`, `비용 계산 = 현재량 전부`, `지불 시점 = 접수`.
- 비축 방식: `요구 조건 = 비용 지불 가능`, `비용 계산 = 고정량`, `지불 시점 = 접수`.

흐름은 `입력 → 공통 자격·공명 조건 검사 → 접수와 지불 → 효과`이며,
요구 조건과 비용 명세는 검사·지불로 연결되는 값이다. 첫 검사 뒤 공명이 바뀔 수 있으므로
접수 노드가 같은 규칙을 최신 상태로 재검증한다. 지불 실패에는 비용·사용 자격·효과가
변경되지 않는다. 접수 뒤 취소는 기존 무환불 규칙을 따른다.

현재 작성 검사는 방식별 필수 필드·연결, 단위, 요청 참조와 공명 설정의 일치,
지불 성공 분기·중복 지불 선언·명시적인 사용 종료 뒤 지불을 확인한다.
실제 직원 ID, 처리 시점의 잔량·선택 범위, 동시 접수 중복 방지와 원자적 지불은 Core 실행 계약이다.
임의 그래프의 모든 효과·수명을 증명하거나 지불을 실행하는 검사기가 아니다.
`GraphNode.kind`·포트 카탈로그·공통 캔버스 렌더러와 version 1 저장 형식을 재사용한다.
미정·오류가 있는 초안도 저장하고 복원할 수 있으며, 기존 문서는 자동 변환하지 않는다.

공명 관련 작성 노드는 다음 14종이다. `resonance-catalog.ts`가 필드·타입·설명의 원본이고,
방식별 활성 필드 판정은 속성 화면·카드·진단이 공유한다.

| kind (`skill-` 접두어)                               | 작성 책임                                           |
| ---------------------------------------------------- | --------------------------------------------------- |
| `resonance-amount`, `resonance-settings`             | 공명량과 저장 상한 정의                             |
| `resonance-read`, `resonance-input`                  | 요청에 묶인 공명 조회와 플레이어의 선택 투입량·횟수 |
| `resonance-requirement`, `resonance-cost`            | 사용 조건과 소비 계산 방식 분리                     |
| `resonance-qualify`, `resonance-admit`               | 공통 수동 자격 검사와 접수·지불 확정                |
| `resonance-install`                                  | Hello의 접수한 사용에 상태·타이머·공격 교체 설치    |
| `resonance-stage`, `resonance-periodic`              | 유한 후속 단계 또는 사용 수명에 묶인 주기 사건      |
| `resonance-pay`, `resonance-result`, `resonance-end` | 후속 지불·확정 결과 조회·명시적 사용 종료           |

연결 타입은 공명량·설정·조회·요구 조건·비용·허가·이번 사용·단계 권리·지불 결과 9종이며,
각 타입의 경유 노드도 제공한다. 조건 없음과 비용 0은 서로 별개로 작성한다.
비율은 0~100의 정수 %와 최소 비용을 명시하고 항상 올림하며, 선택량은 같은 요청의 투입량과
최소·최대 공명 입력을 받는다. 횟수는 요청 선택값 또는 숫자 연결로 작성하며 실제 지불 전에
0 이상의 안전한 정수인지 확인한다. 비활성 방식의 입력 연결·필드는 보존하지만 계산에 사용하지 않는다.
주기는 양수 전투 시간과 지정 회수/사용 종료까지 중 하나를 명시한다.
정상 주기 완료 흐름은 지정 회수 방식에서만 사용한다. 비용 부족은 이번 사용 종료/이번 단계 생략을
선택하며, 미정이면 진단한다. 생략은 그 회차의 효과도 실행하지 않는다는 의미다.

**노드 → 그래프 목록**의 `resonance-*.node-graph.json` 9개는 고정된 검증용 예제다.
전량·고정량·최대/현재 비율·선택량·횟수·무비용·주기·단계를 비교할 수 있다.
예제의 100 공명·25%·2초 등은 게임 수치가 아니며, 실제 스킬 효과는 포함하지 않는다.
Hello의 실제 저장 상한·유지 시간과 기존 미정 항목도 이 검증 수치로 채우지 않는다.

### 사용 잠금과 효과 수명

[전투 규칙의 사용 종료 표](../../core_enhanced/docs/game_rules/combat.md#공명과-스킬-사용)를
모든 스킬에 공통 적용한다. 공명 최대량과 구체 계수가 미정이어도 이 구분은 작성할 수 있다.

| 유형                       | 사용 종료 기준             | 별도로 남을 수 있는 것          |
| -------------------------- | -------------------------- | ------------------------------- |
| 즉발                       | 효과 적용과 사용 동작 종료 | 후속 독립 효과가 있다면 그 계약 |
| 발사체                     | 발사 동작 종료             | 비행·충돌·피해 정산             |
| 연속 공격                  | 마지막 공격 동작 종료      | 이미 방출한 전달                |
| 시간제 버프                | 실제 버프 수명 종료        | 별도로 방출한 전달              |
| 채널                       | 채널 종료                  | 명시적으로 독립시킨 전달        |
| 독립 장판·소환물·지속 피해 | 생성·부여 동작 종료        | 생성물·부여 효과의 수명         |
| 영구 버프                  | 부여 동작 종료             | 영구 효과                       |

`EffectsSettled`를 공명 잠금 해제와 동일시하지 않는다.
여러 잠금 의무가 있으면 하나의 종료가 나머지를 해제하지 않는다.
Hello는 시간제 공격 교체가 유지되는 동안 잠금을 유지한다. Goodbye로 Hello를 끝내도
남은 Goodbye 사용 동작이 있으면 그 의무까지 고려한다. 정확한 공격 교체 전환점은 별도 미정이다.

### 상태·출처·결과

상태 선언에는 타입·초기값·소유자·수명·변경 권한·종료/복원 규칙을 둔다.
구체 실행 값은 활성 등의 인스턴스가 소유한다. 현재 편집기의 빈 상태 선언 노드에
실행 잔여 시간을 저장하는 방식으로 해결하지 않는다.

| 상태 예                    | 소유·수명                              | 분리할 것                          |
| -------------------------- | -------------------------------------- | ---------------------------------- |
| Hello 마무리 권리          | 이번 활성                              | 같은 스킬의 다음 활성·다른 직원    |
| 관통 피해 증가 이력        | 개별 공격/전달의 명시된 단위           | Hello 전체·전투 전체 누적          |
| 천국 체류 진행             | 장판 출처와 대상별 활성 관계           | 다른 장판·다른 대상·재진입 전 진행 |
| 시체산 무기 성장           | 실제 무기 사본의 Run 수명              | 파편 상태·배치 전투 개체           |
| 흑조 피해 감소와 실패 빈틈 | 파편 사본의 배치 효과와 해당 사용 상태 | 장비의 별도 피해 감소              |

Hello 기본 공격의 제공자는 무기이며 Goodbye는 파편 스킬이다.
`Physical` 같은 피해 유형과 무기/파편 같은 출처는 서로 다른 축이다.
원천 사본·형태·effect site와 실제 실행 occurrence를 보존하며, 종료된 사용의 전체 로그를
후속 계산의 상태 저장소로 삼지 않는다.

### 유물 변형과 사건 연쇄

유물은 식별 가능한 효과 지점의 타입·태그·공개 속성에 적용한다.
스킬 전체에 붙인 이름 하나로 모든 내부 효과를 일괄 증폭하지 않는다.
단위·수정 가능한 속성·선택 범위와 충돌을 검사한다.

- 활성은 실제 제공 효과에서 시작한다. 서로의 조건만 제공하는 순환은 활성의 시작점이 아니다.
- 선행 유물은 같은 직원에게 장착되고 스스로 활성이어야 한다. 획득 순서를 제한하지 않으며
  선행 관계의 직접·간접 순환은 오류다.
- 동일 피해 효과의 고정 증가는 먼저 합산하고 동일 종류 비율 증폭을 합산해 적용한다.
  이 공식을 다른 모든 속성에 일반화하지 않는다.
- 한 연쇄 경로가 같은 사본의 같은 효과로 되돌아오지 못한다. 분기는 기존 이력을 이어받고
  이후 이력은 갈래별이다. 실제 합류는 참여한 경로의 이력을 합친다.
- 독립 주기 사건은 매번 새 원인이다. 적중에서 파생한 지연 공격·지속 피해는 원래 이력을
  이어받는다. 시간이 흘렀다고 초기화하지 않는다.
- 공통 게임플레이 증폭·연쇄 횟수 상한을 임의로 추가하지 않는다. 실행 안전 한도와
  게임 규칙을 구분한다.

## 노드 계약의 공통 형식

아래 항목은 카탈로그를 일반화할 때 사용할 설계다. 현재 `Definition`에 모두 구현되어 있지는 않다.
문자열 설명을 남기되 검증에 필요한 부분은 구조화된 데이터가 소유해야 한다.

| 항목        | 작성할 내용                                                       |
| ----------- | ----------------------------------------------------------------- |
| 식별과 역할 | 안정된 kind/버전, 사건·조회·조건·동작·값·연출, 관련 규칙 ID       |
| 입출력      | 의미 타입, 단위, 참조 대상, optional 여부, 값이 존재하는 분기     |
| 관측 시점   | 접수·방출·개별 적중·확정 결과 등. Snapshot/Live와 읽는 주체       |
| 권한과 변경 | 읽는 상태, 바꾸는 상태, 소유자·출처·원자적 확정 경계              |
| 수명        | 생성한 action/delivery/activation handle, 사용 잠금과 종료 책임   |
| 결과와 오류 | 성공·거절·중단·빈 결과·내부 오류, 후속 실행 여부                  |
| 중복과 인과 | 요청/활성/타격 단위, 한 번 처리 key, 원인 계승·분기·합류          |
| 공개 범위   | 공통 조합 기능, 내부가 보이는 복합 구성, 계약을 공개한 전용 모듈  |
| 작성 위치   | 노드·포트·속성·효과 지점에서 진단과 Core 의미를 추적할 수 있는 ID |

값 계산은 읽기 전용이다. 비용 지불·상태 변경·추첨·피해를 값 평가의 숨은 부작용으로 만들지 않는다.
미정 수치는 단위가 있는 미정 매개값으로, 미정 정책은 선택되지 않은 정책으로 구별한다.
0·false·기본 선택지로 자동 채우지 않는다. 합의된 초기값도 최종 밸런스 확정값과 구분한다.

### 최소 공통 노드군

기존 모델의 유한 Flow를 사용한다. 일반 재귀·임의 callback·무한 while을 새 요구로 추가하지 않는다.
오래 유지되는 상태와 주기 사건은 활성·구독·타이머가 소유한다.

| 노드군         | 계약과 대표 소비자                                                                    |
| -------------- | ------------------------------------------------------------------------------------- |
| 입력·접수      | 요청, 명시 대상 선택, 자격 확인, 비용과 접수 자격 확정. 모든 수동 스킬                |
| 흐름           | 순차, 배타 분기, 유한 반복/대상별 실행, 병행과 명시 합류, 전투 시간 대기              |
| 값·조회        | 타입·단위 계산, 명시 subject 조회, 유한 대상 집합, 시점 고정                          |
| 효과·전달      | 피해·회복·제어·자원, 공격 원점과 전달 방식, handle과 완료 지점                        |
| 상태           | 선언, 조회, 설치, 원자적 권리 확보/전이, 출처 한정 해제, 만료·이탈 구독               |
| 결과·반응      | 실제 HP 손실·처치·적중 결과, 인정 단위와 인과를 보존한 후속 반응                      |
| 피해 전 중재   | 패링·보호막·생존 등 허용된 중재 지점. 사후 피해 사건으로 이미 확정한 피해 취소 불가   |
| 관계·영역      | 대상별 진입·이탈·체류, 관계 handle, 대상 강제·이동/저지 정책 연결                     |
| 전용 입력/모듈 | 두건 다중 배치·조준 등 host와 주고받는 명시 계약. 내부가 비어 있는 이름만의 노드 금지 |

같은 타입을 연결했다는 것만으로 유효하지 않다. 값을 만든 분기를 통과했는지,
소유자·출처가 맞는지, 완료 전에 최종 결과를 읽는지, 합류 전에 형제 결과를 읽는지,
자기 완료를 기다리는 순환인지도 검사 대상이다.

## 현재 편집기와의 차이 및 적용 순서

현재 Hello 예제의 요청·분기·허가·활성 참조 검사는 재사용할 수 있다.
다만 포트 타입과 설명만으로 전체 공통 계약이 구현된 것은 아니다.
2026-10-20 코드 대조와 입력·진단 초안은 [컴파일러 준비 검토](#컴파일러-준비-검토--2026-10-20)에 정리했다.

| 우선 작업                           | 현재 차이                                                                         | 완료 판단                                                                                       |
| ----------------------------------- | --------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| 1. 공통 계약을 카탈로그에 구조화    | 노드별 설명에 권한·수명·완료가 섞여 있음                                          | 계약 조회와 진단이 같은 정의 사용. 미정 수치/정책/미지원 연산 구분                              |
| 2. 접수와 적용을 구분               | 공명 접수·지불과 Hello 설치를 작성 노드로 분리함. 다른 효과 설치·Core 실행은 후속 | 일반 `Admit`은 공명 소비·자격을 소유하고 `Install`은 효과 설치를 소유. 접수 뒤 취소 무환불 보존 |
| 3. 유한 Flow·값·결과 확장           | 임의 스킬의 순차/병행/결과 대기와 관측 시점은 미지원                              | 나무꾼 순차·대상별 값과 두건 병행 발사로 분기/완료/중복 검증                                    |
| 4. 활성·설치·관계·피해 전 중재 확장 | Hello 전용 상태/종료를 전체 수명 모델로 일반화해야 함                             | 래티씨아 설치·합체, 천국 출처별 정리, 시체산 저지 관계, 흑조 첫 타격 중재를 각 계약으로 표현    |
| 5. Core와 대응                      | 새 그래프의 컴파일·IR·RON 산출물 연결은 미구현                                    | 노드와 Core 계약의 대응을 정리하고 그래프→IR→RON 저장·재로드→실행의 의미 일치 검증              |

접수와 효과 적용이 같은 시각에 일어나는 스킬은 합쳐 표현할 수 있지만, 그것을 모든
스킬의 접수·준비·방출 규칙으로 일반화하지 않는다. 이전 파일의 `skill-begin` 설명은
그 제한된 복합 계약이며 새 Hello 예제는 접수·지불과 설치를 분리했다. 접수 완료 후 실패까지 비용을 되돌리는 계약으로 읽으면 안 된다.

아직 미정인 공통/개별 정책은 영향받는 기능만 보류한다. 잔여 시간 고정·피격 인정 단위·
다중 중재 우선순위·공격 교체 경합을 임의로 결정하지 않는다.
이번에 확정한 재입력 자격·만료 경계는 다시 미정으로 취급하지 않는다.

## 검증 기준

- 접수 전 거절은 무변경, 접수 후 취소는 무환불, 이미 방출한 독립 효과는 자기 수명 유지.
- 시간제 버프 중 Hard CC·Silence와 사용 잠금, 만료 직전/정각/이후 재입력, 같은 활성 중복 입력.
- 다른 직원·사본·활성의 참조 혼용, 선택하지 않은 분기의 값, 완료 전 결과와 잘못된 단위.
- 여러 대상·여러 탄환·반복 타격에서 결과와 상태를 올바른 단위로 구분.
- 출처 한정 정리, 재배치 identity, 독립 주기와 파생 지연의 연쇄, 실제 합류의 이력 결합.
- 미정 값 저장·재열기·진단을 보존. 작성 가능과 Core 실행 가능을 별도로 표시.

이는 후속 실행 구현의 수용 기준이다. 현재 작성·파일·UI 검사가 이 전투 실행 시험의 통과를 뜻하지는 않는다.
공명 노드의 실제 작성 검증 기록은 [Hello 안내](hello-goodbye-node-guide.md#공명-노드-확장-검증-2026-10-20)를 따른다.

**절망의 기사.** 가호는 자신을 포함한 한 아군의 메뉴 지정·해제·교체다. 피해 감소와 검 생성 주기는
현재 관계에 종속하지만 긴급 보호막 전투당 1회 기록은 사본에 남는다. 보호막은 부여 뒤 독립 15초이며,
관계 교체로 옮기지 않는다. HP 0 퇴각만 전환을 예약하고 수동 철수는 제외한다. 전환 시 가호를 정리한 뒤
검당 최대 HP 5% 고정·보호막 무시 자기 피해를 내며 검은 보존한다. 죽은 소유자의 새 행동을 만들지 않는다.

기본형 일반은 첫 실제 강화 공격 시작의 검 수 S를 고정한다. 찌르기 뒤 네 단계마다
`c=max(1,floor(S/4))`를 지불하고, 각 단계 전체 공격 뒤 주 대상에 실제 소비 c만큼 상처를 더한다.
검 부족·대상 사망·중단은 미시작 단계 비용을 내지 않는다. 마지막 반복의 총시간과 기본 타수 n은
미정으로 남긴다. 절망은 n+S회 타격을 같은 총시간에 배분하고, 같은 시전·같은 대상의 다음 타격부터
누적 10%p 증가를 적용한다. 일반 상처와 구분하며 검을 소비하지 않는다.

개화 일반은 큰 검 준비 뒤 방출 때 전량을 소비한다. 큰 검 1회와 실제 소비 수만큼 작은 검을 같은
전체 범위에 순차 적용하며 큰 검만 2초 기절이다. 작은 검 0회는 바로 완료한다. 개화 절망은 0.5초 뒤부터
범위 피해 후 상처 1개를 주며, 1초 뒤부터 최대 HP 10% 물리 자기 피해를 별도로 준다.
유지 시간은 기본+S×개당 시간이며 두 시간은 미정이다. 종료와 같은 시각의 주기는 제외한다.
직접 중단·Hard CC·침묵·사망·철수에 두 주기를 정리하며 이미 붙인 상처는 자체 5초 수명을 따른다.

**붉은 두건.** 일반/강화 재고는 독립 전투 저장소다. 일반 창 주기와 늑대 출현은 장착 중 진행하고
Pause에는 멈춘다. 늑대는 일반 경로를 따라 아군/방어 대상을 공격·탈출하며 실제 남은 적에 포함된다.
유효 출현 경로를 안정된 순서로 순환하고, 미래 주기는 필수 웨이브로 세지 않는다. 승패 확정이 동시 출현보다
우선한다. 아군 귀속 처치마다 원래 생성 사본에 강화 창 1개를 지급한다. 탈출·종료 정리는 보상이 아니다.
두건 파편/무기 계열에서 나온 피해에만 +50% 약점을 적용하고 착용자의 모든 피해로 확대하지 않는다.

재고 합계 0이면 준비를 시작하지 않는다. 준비 동안 Core 시간은 정지하고 배치·조준만 기록한다.
같은 타일 중복은 거절한다. 이전 성공 배치의 종류/수량/순서/타일이 하나라도 맞지 않으면 전체 직접 배치로
돌아가고 방향은 항상 새로 정한다. 영벡터는 재입력한다. 마지막 방향까지 유효한 계획에만 공명 허가를 내고,
`plan-commit`이 두 재고 전량·공명 전량·전 탄환 동일 시각 방출·성공 배치 기억·전투 재개를 함께 확정한다.
일반 `resonance-admit`으로 먼저 지불할 수 없다. 일반 취소는 이전 배속/정지를 복원하고 단절은 정지를 유지한다.
성공 확정은 이전 진행 배속으로, 원래 Pause였다면 1배속으로 재개한다. 확정 응답 유실은 재청구·재방출하지 않는다.
강화탄은 기본 위력+양수 추가 위력이며 속박 2초는 타격 뒤 별도 판정이다. 실제 방향 고정 물리 탄환이며
공중 포함·장애물 정지·대상별 1회·작성한 관통 수를 따른다. 폭/거리/속도/수/수명은 미정이다.

**탐욕의 왕.** 사본의 시작 잔고는 10−직전 미상환액이다. 직전 전투에서 새 대출을 썼으면 이번 대출은
금지하고, 허용 전투의 자동 대여 하한은 −20이다. 이번에 빚을 갚아도 대출 사용 이력은 남는다.
양수 잔고는 이월하지 않는다. 전투 진입 장착 사본은 배치 여부와 무관하게 승패 확정에 한 번 정산한다.
미장착 전투는 정산하지 않으며 Retreat는 진입 전 savepoint, 원정 종료는 초기 상태로 돌아간다.
원장 승계는 아래 P6/P7 연결 계약을 따른다.

2026-10-22 연결 정책: 장착 해제·재장착·직원 간 양도·형태 선택은 기존 파편 UUID를 유지하므로
같은 원장을 유지한다. 실제 공개 `TransferSkillFragment` 경로와 Continue 후 재진입을 검사했다.
현재 지원 파편 API에는 여러 사본을 합쳐 새 UUID를 만드는 합성 연산이 없다. 새로운 합성 기능에
부채 소멸·합산 정책을 추정해 부여하지 않으며, 해당 기능을 추가할 때 별도 승계 계약이 필요하다.
사본 제거 시에는 그 UUID의 원장을 정리하고 새로 획득한 사본에는 이전 원장을 붙이지 않는다.

포탈이 실제 생성될 때마다 1을 내고, 최대 수에 따른 선형 가속 간격·유예·전체 기한·오래된 순 붕괴를
명시한다. 기한/붕괴는 동시 재입력보다 우선한다. 사출 재입력은 추가 공명을 요구하지 않고 남은 목록을 고정해
추가 생성과 붕괴를 멈춘다. 각 보구의 착탄/소멸·피해·상태·사망·회수 정산이 끝난 뒤 다음 적을 선택한다.
자기 회수 상태 없는 적 → 루트 진행도 → 출현 순서/ID의 안정된 순서를 사용한다. 대상이 없으면 남은 목록을
무환불 폐기한다. 방출한 탄환은 원래 대상만 추적하며 사망한 표적을 다른 적으로 바꾸지 않는다.

회수 상태는 소유자 귀속 양수 실제 HP 피해에만 붙이고 보호막만 손상·피해 0은 제외한다. 치명타격도 사망 정산
전에 부여한다. 다른 아군의 막타도 자기 상태가 남아 있으면 사본당 한 번 +1이며 빚부터 갚는다.
미방출 취소는 비용을 환불하지 않고 방출 탄환은 독립 정산한다. 기본형에는 별도 자기 HP 비용이 없다.

위 수명·동률·피해 유형·세부 입력 정책은 2026-10-21 통상 정책 위임을 적용한 작업자 결정이다.
늑대의 실제 적·아군 공격·장착 중 주기 출현은 2026-10-22 사용자 확인이다. 두 근거를 혼동하지 않는다.
장비·범용/전용 유물·복수 사본 조합과 원장 승계는 P6 대조, 컴파일/IR/RON은 P7, 전투 실증은 P8이다.

작성 진단은 획득 권리의 출처·중복·흐름, HP 0 분기, 프로그램과 접수의 일치, 종료한 사용 참조,
소비량 문맥, 준비/조준 분기·합류·확정의 일치, 두 재고 구분, 고정 전 사출·중복 사출,
회수 원장 일치, 투사체/시간/반복 설정을 검사한다. [모델 사례](../tests/model/p4.spec.ts)와
[UI 사례](../tests/ui/hello-goodbye.spec.ts)는 이 작성 경계를 검사하며 전투 시뮬레이션이 아니다.

현재 경로는 `기존 RON → 팩 조합/참조 검증 → Flow·수치식·보스 등 도메인별 컴파일 →
검증된 콘텐츠 세대 → 장착 조합의 파생 계획 → 전투 실행`이다.
보스의 상태·패턴·신호 컴파일은 [별도 catalog](../../core_enhanced/src/game/data/boss_runtime_data.rs)가
소유하므로, 이를 직원 스킬의 Flow와 같은 모델로 간주하지 않는다.
에디터는 JSON 저장까지 연결되어 있으며 새 그래프를 받는 Core 경계는 아직 없다.

`CompiledSkillFlow`는 Serialize만 제공하고 원본·검증용 step 정보 일부는 직렬화에서 제외한다.
`CompiledAmountPlan`과 유물의 실행 소유자도 저장에서 그대로 복원하는 공개 실행 형식이 아니다.
따라서 **새 portable IR/산출물 로더**와 **현재 세대에 결속된 내부 실행 계획**을 구분해야 한다.
파일을 읽었다는 이유로 내부 인덱스나 캐시를 실행 권한으로 신뢰하지 않는다.

### 전체 노드 대응표

분류는 그래프 컴파일 지원표가 아니라 **연결 작업의 종류**다. 현재 그래프→Core 변환은
모든 행에서 미구현이며, A/B 판정도 그래프의 즉시 실행을 뜻하지 않는다.

- **A 기존 기능:** 명시한 제한 범위에서 같은 의미의 Core 원시 기능이 있다.
- **B 변환 필요:** 단위·구조·출처·메타데이터를 보존하는 변환이 필요하다. 조건부 확장은 행에 적는다.
- **C Core 확장:** 일부 기반은 있지만 현재 노드의 전체 계약을 제공하는 실행 포트/정책이 부족하다.
- **D 의미 미정:** 문자열·공간·연출 등의 의미나 결속 정보가 부족해 대응을 확정할 수 없다.

판정은 kind 단독이 아닌 **kind + 활성 설정 + 연결 + 실행 문맥**에 적용한다. 예를 들어
비용의 all/full 부분은 기존 경로가 있지만 다른 모드까지 같은 방식으로 실행할 수 없다.
기본값·명시적인 0·미정 빈 값, 사용하지 않는 방식의 필드도 구분한다.

### 컴파일 입력 계약 초안

#### 입력과 결과의 경계

입력 본문은 현재 `GraphDocument` v1의 스냅샷이다. 기존 문서에 실행용 필드를 임의로 추가하지 않는다.
컴파일 요청에는 본문과 별도로 다음 **논리 정보**가 필요하다. 아래 항목명은 배포 API/Serde
스키마를 확정한 것이 아니라 누락을 막기 위한 계약이다.

| 정보           | 책임·규칙                                                                                                                                                                                  |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 원본 식별      | document ID와 전달한 전체 원본의 digest. 편집기는 자신의 epoch/revision을 함께 결속하되 문서 파일에 저장하지 않는다. 이름·배치도 바뀐 원본은 구별한다                                      |
| 작성 계약      | node-graph 버전과 해석에 사용한 노드 의미 계약 버전. v1 파일이라는 이유만으로 모든 후속 kind/정책을 지원한다고 하지 않는다                                                                 |
| 정의·진입 문맥 | 결과가 속할 콘텐츠 정의 ID와 직원 수동/기본 공격/보스 등 진입 종류, 필요한 타입·참조. 문서 표시 이름이나 첫 노드 위치에서 추정하지 않는다. 같은 값 비교 사례는 같은 정의 바인딩을 전제한다 |
| 외부 참조      | 참조하는 스킬·buff·자원·유물·장비 등 해석된 콘텐츠 세대/조합 identity. 파일 하나만으로 검사할 수 없는 참조는 이 문맥에서 해결한다                                                          |
| 대상 실행 계약 | 지원하는 backend 기능/산출물 schema 버전과 적용 실행 한도 profile. 버전 불일치·미지원·비용 한도는 서로 다른 실패로 보고한다                                                                |

컴파일은 게임 상태·자원·편집 문서·Undo를 변경하지 않는 작업이다. 성공 결과에는 원본/대상
식별과 검증된 산출물 정보를 함께 반환한다. 실패·취소 결과에는 진단만 반환하고 **실행 가능한
부분 산출물을 발행하지 않는다.** 파일 쓰기는 컴파일 뒤 별도 저장 단계로 다룬다.

편집 중 새 revision이나 다른 문서로 바뀌면 이전 결과를 현재 결과로 설치하지 않는다.
이전 스냅샷의 결과로 보관할 수는 있어도 최신 저장/컴파일 완료 표시를 갱신하지 않는다.
내용 identity와 실행 한도 profile도 결과의 적용 기준에 포함한다.

#### 검증·변환 순서

1. **문서 구조:** JSON/format/version, 크기, 노드·연결·프레임의 ID 유일성, 알려진 kind와 필드,
   존재하는 포트·방향·연결 수·정확한 타입을 검사한다. 현재 저장 규칙은 구조적으로 유효한
   미완성 문서를 허용한다. 구조 거절과 미완성 작성 진단을 같은 오류로 합치지 않는다.
2. **표현 정규화:** 원본을 보존한 채 경유점을 축약하고 배치·프레임·메모와 실행 의미를 분리한다.
   노드 배열 순서나 좌표는 실행 순서가 아니다. 경유점과 원래 edge의 출처는 남긴다.
3. **정적 의미:** 값 단위·관측 시점, 설정별 필수 입력, 실행/데이터 순환, 성공 분기의 결과,
   소유자·사본·활성·사용/단계 권리, 완료 조건과 종료 뒤 사용을 검사한다. 반대 분기 값이나
   이전 activation을 타입이 같다는 이유로 통과시키지 않는다.
4. **문맥·지원 확인:** kind와 활성 설정이 대상 backend에서 실제로 실행되는지 확인한다.
   임의 event/action 문자열, 미정 정책/필수 값, 표현할 수 없는 수치·공간·합류는 발행 차단이다.
   어떤 근거가 부족한지 진단하며 기존 동작으로 바꾸거나 자동 기본값을 넣지 않는다.
5. **실행 표현 생성:** 검증된 의미를 Flow/수치/상태/입력/결과 등 해당 실행 계층으로 변환하고,
   참조·수명·실행 한도를 다시 검증한다. 노드 하나가 여러 연산으로 내려가거나 여러 노드가
   하나의 원자 동작이 되어도 원본 위치와 권한을 보존한다. 전체 IR 배치는 이 후속 구현에서 결정한다.
6. **발행·재로드:** portable IR과 명시 버전을 RON에 담고 게임 로더에서 형식·참조·지원 기능을
   다시 확인한다. 기존 authored RON과 새 산출물은 같은 형식으로 간주하지 않는다.

일반 흐름의 중복 입력을 무조건 병렬 join으로 만들지 않는다. 배타 경로 합류인지 실제 병렬
완료 대기인지 증명되지 않으면 `graph.flow_merge_unspecified`로 남긴다. 현재 카탈로그에 없는
일반 Repeat/Parallel/Action-result 노드를 이번 문서만으로 구현된 것으로 추가하지 않는다.

명시적인 비활성 비용 입력·필드는 원본에 남기되 실행 계산과 그 계산의 소유자 의존성에서 제외한다.
이는 해당 mode가 정의한 예외다. 그 외 미지원/미정 노드를 임의로 도달 불가 처리해 성공을 만들지
않는다. 별도 실행 진입이 없는 작업 중 노드나 미정한 사건 연결은 진단하고 작성 원본으로 보존한다.

정적 통과는 런타임 자격의 증명이 아니다. 접수·지불 직전에 실제 소유자·출처·generation·
잔량·대상·만료·중복 권리를 다시 검사한다. 접수 전 거절의 무변경, 접수 후 게임 중단의 무환불,
독립 전달의 수명은 유지한다. 엔진 fault의 명령 후보 롤백은 게임상 정상 취소와 구분한다.

### 진단과 원본 위치 계약 초안

현재 에디터 `Diagnostic`은 code/nodeId/portId/message이고, Core `LiveRonError`는
file/definition/action/effect/field/phase 등의 위치를 제공한다. 새 컴파일 경계는 두 형식을
같다고 가정하지 않고 다음 정보를 연결해야 한다.

| 정보                 | 필요한 의미                                                                                                                                 |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |

#### 이번 준비 작업의 검증 범위

카탈로그를 실제로 읽어 대응표의 kind 241개가 누락·중복 없이 일치하는지 확인한다.

문서 링크·JSON 형식·프로젝트 정적 검사를 수행한다. 결과 기록은

정수 공명 합의 이후 G13은 더 이상 미정 정책 사례가 아니라 읽기 거절 사례다.

않는다. 최종 보스 합의 뒤에는 이 대응표에 필요한 의미를 추가하고, IR 구조와 대상 기능을
정한 다음 작은 종단 실행으로 계약을 검증한다.

## 출처별 표식·연속 위력·폭발 계획 — P5, 2026-10-22

녹아내리는 사랑 공격형과 죽을 나비의 장례 기본/개화형의 작성 계약이다. 보류된 고기벽은 포함하지 않는다.
구체적인 콘텐츠 정책은 각 파편 원문의 P5 보완 절이 소유한다. 아래 노드 추가는 아직 Core 실행 완료를 뜻하지 않는다.

기본 개화형의 무조건 발동 효과가 아니다. 무기 영구 승급·파편 교체 후 무기 상태·장비 및 유물 자동 연결은 P6에서 대조한다.

## P6 장착 조건과 명시적 변경 대상 — 작성 계약

`equipment-condition`은 소유 직원의 실제 정의 ID·장착 부위·일반/침식 변형과 선행 조건을 표현한다.
표시 이름으로 장착 여부를 추정하지 않으며 선행 조건 순환은 진단한다. 같은 유물 조건은 여러
변경에서 참조할 수 있지만 대상 정의·출처·적용 사건은 각 연결에 남긴다. 미장착 상태에서 원본
작성값을 덮어쓰거나 모든 동종 태그에 자동 전파하지 않는다.

`modifier-*`는 조건과 **변경할 정의**를 받는 선언이다. 사건의 실제 호출이나 실행 흐름을 만드는
노드가 아니다. `resource-grant`·`ground-member` 입력을 받는 변경도 연결한 생산자의 **정의**를
지목하며 임의의 실행 중 영수증을 가져오는 뜻이 아니다. 실행에서는 해당 정의가 만든 실제 사건의
소유자·사본·대상·사용·회차를 보존한다.

- 시간·수량·개수·회복·피해·범위·재고 상한 변경은 각각의 typed 생산자에 연결한다.
- 폭발 규칙과 최종 이동 효과의 피해 증폭은 공유 기초 위력 계산과 분리한다. 감염 주기 피해나
  다른 직접 타격이 같은 위력식을 쓴다는 이유로 폭발 증폭을 받지 않는다.
- 자원 획득, 무기 적중의 새 표식 부여, 타격 뒤 새 상처 스택은 서로 다른 입력 타입/정의에 연결한다.
  기존 재고·사망 이전·소비 영수증·스택당 효과를 새 부여로 재분류하지 않는다.
- 진행 중 시전 보호, 주 대상 사망 뒤 연결, 주 대상 피해의 타일 범위화는 행동 정의를 지정한다.
  시전 자격·원래 비용·남은 단계·개별 후속 효과의 대상 범위는 유지한다.
- 실제 제어 성공/소환 피해 뒤 약화는 각각 5초의 독립 시간을 연결한다. 같은 장착 사본의 갱신과
  다른 사본 기여를 구분한다. 면역 실패·피해 0·사망 대상에는 새 약화를 만들지 않는다.
- 실제 회복 뒤 버프는 별도의 시간제 능력치 상태를 요구한다. 남은 온기의 미정 버프 종류/계산/수치/
  시간은 그대로 미정 진단에 남는다. 증오의 여왕에는 아직 없는 보호막 생성 효과를 추가하지 않는다.

작성 helper는 일반 노드와 typed edge만 생성하며 실행 코드를 담지 않는다. 변경 카드 제목은
`유물 이름 → 변경 대상 이름`으로 표시한다. 조건은 한 번 작성해 공유하고 원본 값은 원래 노드에서
수정한다. 조건/배율 변경은 한 번의 이력 편집으로 취소·저장·재열기 할 수 있다.
일반 세부 판정의 근거는 `core_enhanced/docs/game_rules/relics.md`의 2026-10-22 작성 정책에 남긴다.
이 절은 P7 Core 컴파일과 P8 전투 검증의 완료 기록이 아니다.

## 조건부 전환·탄환 부가 효과 — P6 2026-10-22

`conditional-effect-catalog.ts`의 조건은 같은 소유자의 실제 장착 사본을 검사한다. 탄환 후속 상태·
밀어내기·출처별 스택 약화·관통 폭발은 연결한 투사체 정의에만 적용하며, 파생 폭발을 직접 탄환으로
재분류하지 않는다. 스택 약화의 새 부여 배율과 스택당 증폭은 별도 선언이다. 조건부 후속 상태도
독립 투사체의 문맥을 따르므로 다른 소비 단계의 영수증이나 재고 스냅샷을 읽을 수 없다.

HP 비용 직렬 사출은 같은 포탈 시작 설정을 전환하며 원래 공명 접수·중단·회수 원장을 보존한다.
단일 지원은 범위 행동의 대상 선정을 바꾸고 효과별 대체 기여/개인 보호량 배율을 명시한다.
두 중심 일치 전환은 같은 사용의 영역 생성을 대체하며, 정상 두 영역·회복·버프를 먼저 만들지 않는다.
각 원문의 2026-10-22 작성 정책에 순서·대상·수명과 위임받아 결정한 세칙을 기록했다.
수치 공백과 미정 피해 유형·공중 자격은 명시 진단이며 실행 기본값으로 채우지 않는다.

### 단독 고정값 접기

현재 저장 모델의 `values`는 노드 정의의 필드이며 임의 입력의 리터럴 저장소가 아니다. 입력은
typed edge로 생산자·단위·참조 대상을 구분한다. 이 단계에서는 `고정값 접기`로 입력 하나에서만 쓰는
스칼라 값을 입력 옆에 표시·편집한다. 값 노드·연결·ID는 보존하고 문서·진단·Undo에는 영향을 주지 않는다.
공유값, 계산·경유, 다중 입력, 변경 규칙의 대상은 접지 않는다. 탐색으로 원본 노드를 선택하면 다시 보인다.
접은 상태에서 소비자를 복사·복제·삭제·그룹 편집할 때 그 단독 값도 함께 처리하여 값만 유실되지 않게 한다.
접기 자체는 데이터 모델의 직접값/참조 전환이나 저장 파일의 노드 제거가 아니다. 자동 배치는 여전히 전체
작성 노드를 대상으로 하므로 접힌 자리의 여백을 자동으로 압축하지 않는다.

### 무기 사본 상태와 파편 형태 — P6

`weapon-evolution`은 파편 개화 해금과 명시한 무기 사본의 단계 변경을 같은 거래로 선언한다.
일반 강화·공명·전투 진입으로 대신하지 않으며 대상 선택/소유/비용 재검증이 실패하면 무변경이다.
`weapon-mark-owner`는 표식의 owner를 실제 무기 사본+상태 ID로 연결하고 기본/승급 단계의
`mark-weapon-hit`을 상호 배타적으로 구독한다. 같은 단계 중복·다른 승급 정의·파편 owner 혼용은 오류다.
표식은 전투 수명이고 `weapon-kill-growth`는 원정 수명이다. 성장 획득량은 별도 정수 생산자를
통해 유물 배율에 연결하며 기존량·스택당 피해·주변 계수와 분리한다. 원본 값과 기존 ID는 보존한다.

이 선언들은 실제 무기·파편 정의 ID를 문맥에서 검증해야 하며 존재하지 않는 장비를 생성하지 않는다.
같은 상태 ID를 여러 형태에서 선언할 때 저장 규칙이 다르면 컴파일 오류다. 에고 침식은 파편의
일반 피해로 실행하지 않고 최신 공통 정책의 대상 분류·부가 효과 억제·철수·트라우마·연출 정지를
Core 진입 경계에서 적용한다. 옛 세트 보유/별도 입력/모든 적 처형 문구를 컴파일하지 않는다.

### 고정 중심 지연 광역의 Core 연결 세칙 — 2026-10-22

접수 고정 선택은 후보 검사 때 후보의 현재 타일을 사용하고, 비용을 확정한 뒤에는 해당 사용에 저장한 타일을 사용한다.
이 둘을 같은 미확정 anchor 조회로 취급하면 접수할 수 있는 적도 잘못 거절되므로 구분한다. 준비 중 취소는 방출을 막으며,
방출 뒤 지연은 기존 독립 area 전달의 유한 수명으로 소유한다. 원래 대상의 이동·사망과 시전자의 사망·Hard CC는 방출된
전달을 취소하지 않는다. 전투 종료는 전달을 정리한다.

`유효 적중 때 후속 행동`의 유효 타격은 본문 직접 피해가 실제 HP 또는 보호막을 감소시킨 판정이다. 완전 감면·무적·빗나감과
HP 비용은 포함하지 않는다. 지연 단발 범위의 자기 회복은 모든 대상의 피해 뒤 한 번이며, 사망한 시전자를 부활시키지 않는다.
무기 Attack 비례 위력은 준비가 끝나 본문을 방출할 때 고정하고 회복률의 최대 HP는 착탄 뒤 실제 회복 시점 값을 사용한다.

### 유한 주기 기회와 독립 착탄의 Core 연결 세칙 — 2026-10-22

`scheduled-plan`의 첫 기회는 시작 즉시이며, 각 기회마다 접수 시 고정한 탐색 구역에서 루트 진행도·스폰 순서·유닛 ID 순서로 대상을 새로 고른다.
대상이 없어도 기회를 소비한다. 한 기회에서 방출한 타격은 다음 기회를 기다리게 하지 않으며, 자신의 목표 타일·공격력·낙하 지연을 별도로 저장한다.
공격력은 각 방출 시 읽으므로 시전 한 번의 모든 타격에 처음 값을 고정하지 않는다. 모든 타격은 원래 시전의 직접 스킬 피해다.

이 생성기는 기본 공격을 허용하며 Hard CC·Silence에도 계속된다. 사망·철수는 미래 기회를 중단하고 이미 방출된 착탄은 유지한다.
같은 시전자·파편 사본/장비·정의의 재시전도 같은 경계로 교체한다. 전투 종료는 생성기와 이미 방출한 범위 전달을 함께 정리한다.
정리할 때 해당 예약의 유한 전달 소유권도 종료해 결과에 미완료 전달이 남지 않게 한다. 실패 시 영역·예약·전투 사실을 함께 복구한다.

현재 컴파일 경로는 시작 즉시의 지연 범위 본문, 양수 간격, 1~10,000개의 기회를 지원한다. 수치 미정이나 그 밖의 본문/시작 방식은 진단하며 조용히 생략하지 않는다.

### 다음 정상 기본 공격 준비의 Core 연결 세칙 — 2026-10-22

`next-basic-plan`은 시전 시 별도 공격을 만들지 않고, 부여 뒤 새로 시작하는 정상 무기 기본 공격 하나에 결속한다.
기존 windup·Triggered 공격·기본 회복에는 적용하지 않는다. 준비에는 임의 시간 만료가 없으며 원래 시전의
동작 종료 뒤 공명 사용을 잠그지 않는다. 공격 시작 취소는 준비를 복원하고 release는 소비를 확정한다.
방출 뒤 빗나감은 환불하지 않으며, 철수·사망·전투 종료는 준비를 정리한다. 방출한 투사체의 피해 스냅샷은 유지한다.

같은 시전자·사본/장비·정의의 재부여는 미결속 준비를 교체한다. 결속한 공격은 기존 캡처로 마치며,
재부여 뒤 취소되면 오래된 준비를 복원하지 않는다. 서로 다른 정의는 부여 순서대로 공격당 한 개씩 결속한다.
피해 배율은 기존 무기의 기본 피해 확정 시점에 적용하고 소수점을 내린다. 기본 공격이라는 분류와
무기의 피해 유형·사거리·표적/전달 방식을 유지하며 준비 출처는 별도 modifier 출처로 기록한다.

처치 보상 상태는 본체 피해가 보호막을 통과해 직접 처치한 경우에만 행동당 한 번 부여한다.
장비 부가 피해의 마무리·proc·지속·연쇄·다른 행동의 처치는 제외한다. 보상 상태의 속성·기간·출처 이탈
정책은 연결한 `target-state`를 재사용한다. 원래 시전의 유한 전달 소유권은 공격과 후속 보상이 끝날 때까지
결과 추적을 유지하되 공명 사용 잠금으로 해석하지 않는다. 배율 또는 연결한 보상 상태가 미정이면 컴파일 진단이다.

### 패링 파편의 상시 출처와 유한 상태 — P8 실행 연결

`passive-guard`와 연결된 `direct-reflection`, `parry-plan`은 하나의 파편 출처를 참조한다.
컴파일한 상시 정책은 native Parry 선언에 보존하며, 실제 장착 사본·정의·형태·스킬 연결이
일치할 때만 배치 중 파생한다. 공명 수치나 사용 중 여부로 상시 효과를 켜고 끄지 않는다.
기존 파편 metadata에도 정책이 있으면 두 선언의 불일치를 로드 시 거부한다.
감면은 일반 수신 피해에 적용하지만 HP 비용은 피해 경로를 거치지 않는다. 반사 자격은
별도로 직접 적 타격으로 제한한다. **반사는 대상별 첫 양수 구간의 실제 HP 손실 기준**이다.
초기 작성 설명의 ‘보호막 전’ 문구가 기존 게임 규칙과 충돌하여 설명을 정정했다.

패링 창은 첫 eligible 직접 타격을 선점하고, 성공하면 그 시점부터 면역 시간만 유지한다.
실패하면 창 종료부터 실패 빈틈까지만 유지한다. 이 실제 종료 시점에 사용 의무를 해제한다.
고정된 최장 시간까지 기다리는 별도 사용 잠금은 없다. 기존 native 유한 감면 Parry는
명시한 전체 지속 시간을 유지하며, 새 `end_on_resolution` 설정으로 두 계약을 구분한다.
성공 후에는 직접·지속·반사 피해와 새 행동제어를 차단한다. HP 비용과 비제어 효과 부착은
정상 처리한다. 피해 전 선점과 면역 중 적용 차단은 사후 관찰 이벤트로 피해를 되돌리는 작업이 아니다.

반사 확률·감면·반사율은 현재 native 정책의 0..100 범위를 검증한다. 받아치기 위력은
양의 정확한 유리수로 표현한 무기 Attack 배율이며 원래 공격자에게만 적용한다.
fixture의 30% 감면·100% 확률·50% 반사·2.5배 받아치기·30ms 창/빈틈은 검증용 수치다.
원문의 미정 밸런스를 확정한 값으로 저장하지 않는다.

### 개인 보호막·집중 지원의 Core 연결 정책 — 2026-10-22

기본 지원 범위와 유물의 단일 선택 범위는 서로 다른 authored 타일 마스크다. 거리 반경으로 근사하지 않는다.
개인 보호막은 release 때 시전자 최대 HP 비율을 내림하여 대상별 같은 초기량을 만든다. 단일 전환은 그 개인량에
명시한 정확한 배율을 곱하고 다시 내림한다. 대상 수를 곱하지 않는다. 같은 출처의 새 보호 대상만 교체하며, 새 범위
밖의 이전 대상은 원래 잔량·만료를 유지한다. release 뒤 범위 이탈·재진입은 재부여나 제거 사유가 아니다.

우선순위·시작 순서 선택은 기본 설정으로 보존한다. 이미 시작한 공격은 고정한 기여와 원천 사본을 유지한다.

단일 전환은 실제 같은 직원의 장착 유물 사본·정의·변형을 immutable effective plan에서 검사한다. 소유만 하거나

검사한다. 단일 집중 대상의 범위 이탈·무효화는 집중과 사용 의무를 끝내고 재진입·다른 대상으로 이전하지 않는다.

충돌로 거절한다. 외부 중단 보호는 진행 중 스킬의 취소만 막으며 제어 상태 부착·기본 공격 취소·자발적 철수·사망을
막지 않는다. 쐐기는 실제 양수 타격으로 대상별 회차를 세고 명시 상한을 적용하며 다음 시전에 초기화한다.
약화 기록은 원래 효과 소유권과 별도로 실제 보정 유물 사본·정의·규칙 출처를 관측할 수 있다.

### 집중 소유 장판·점진 둔화의 Core 연결 — 2026-10-22

`skill-channel-begin/area/cancel-request/cancel/ended`와 진입·체류·이탈 상태를
`ResonanceChannelGround`로 연결한다. 자기 위치 선택과 접수 시 위치·방향 고정을 검사하며,
장판은 이번 집중의 유한 수명을 소유한다. 일반 장판의 독립 수명과 구분한 `ChannelGround` delivery로
표현한다. 장판 delivery가 남아 있는 동안 사용·공명 획득 의무를 유지하고, 직접 취소·Hard CC·시전자 이탈·
전투 종료에서는 해당 장판·관계·기여분·예약만 정리한다. 외부 중단 보호는 현재 집중에 적용하며
직접 취소·사망·철수는 보호하지 않는다. 침묵과 단순 강제 이동은 이 고정 장판을 종료하지 않는다.
기본 공격 중지/유지 정책을 구분하며 중지형도 이미 사출한 공격의 권한을 회수하지 않는다.

점진 둔화는 기존 native 정수 백분율 경계에서 내림한다. 기본 필요 시간 `D`, 경과 시간 `t`,
최대율 `M`, 진행 배율 `N/Q`에 대해 `floor(M × min(t × N / (D × Q), 1))`이다.
분수 배율을 먼저 정수 시간으로 바꾸지 않는다. 도달 사건만 `ceil(D × Q / N)` 밀리초에 발생한다.
수치가 바뀌는 다음 정수 백분율 경계를 예약하므로 대상·진입 회차마다 최대 100개의 수치 경계가 있고,
매 프레임 검사나 무한 주기는 없다. 이탈 시 둔화와 진행을 제거하고 재진입은 0부터 시작한다.

기절은 성공한 도달 사건에 한 번 부착한다. `UntilAreaEnd` 기여는 강제 이탈 후에도 자기 장판 종료까지
유지하며 다른 출처의 기절을 제거하지 않는다. `SlowImmune`와 `StunImmune`을 따로 판정하고,

합성 경로를 사용한다. 종료 시각과 도달 시각이 같으면 종료가 우선한다.

실제 장착 유물의 범위 교체·최대 집중 시간 증가·외부 중단 보호·진행 배율·기절 성공 후 독립 약화를
기존 immutable effective plan에 결합한다. 긴 호흡은 최대 수명만 늘리고 진행 시간에 다시 적용하지 않는다.
깨진 균형은 실제 기절이 새로 부착된 경우에만 별도 5초 약화를 만들며 장판 밖·집중 종료 후에도 자기 수명을 따른다.
같은 정의의 장착 사본은 한 번 적용한다. 서로 다른 진행 배율의 동시 쓰기는 충돌로 거절한다.
효과가 없는 장판 action의 변경도 설명 DTO의 `action_modifiers`에 실제 사본·규칙·변경 대상으로 노출한다.

  자동 연결하지 않는다. 미정 수치는 원본에 보존하고 검사 전용 사본에서만 채운다.

공개 관측에는 선택 가능한 아군, 현재 관계·검·모드·전환 예약·보호막 사용,
준비/행동 계획과 남은 주기, 적용 유물 사본을 제공한다. 관측은 실행 권리를 포함하지 않는다.

가장 가까운 적/ID 동률로 도약을 시작하고 목적지 타일을 고정한다. 이미 도약한 효과는 합체하지
않으며 소유자 이탈 후에도 도착·폭발을 마친다. 전투 종료는 대기·도약·선물·예약을 모두 정리한다.

선물은 실제 일반 유물 장착으로만 활성화한다. 정상 적중에 치명 여부와 관계없이 사망 전에 부여하고,
같은 출처 재부여는 만료를 갱신한다. 같은 시각의 사망을 모두 수거한 뒤 생성·합체하고 탐지한다.
후속 효과는 부모 activation과 실제 유물 사본을 보존하며 다시 선물을 부여할 수 있다. 긴 호흡은
선물 시간만 바꾼다. 폭발 증폭·범위 교체는 해당 구체 등급에 한 번 적용하고 소환 피해 약화는
양수 HP 피해 뒤 살아남은 대상에 실제 유물 사본별로 갱신한다. 약화 자체의 시간은 연장하지 않는다.

원본의 미정 수치는 컴파일 거절로 유지한다. 숫자를 명시한 검증 입력·RON·실행·UI 근거는
`p8-fusion-placement-20261022` 산출물과 작업 파이프라인에 연결한다.

### 방향 타격·상태 전환·추격 효과 실행 계약 — 2026-10-22

`StatusStrike`는 방향 선택, 소유 피해 상태 구독, 타격 전 상태 캡처와 전환, 타격 뒤 이동 효과
생성을 구성하는 실행 프로필이다. 작성 선언의 참조·기간·범위·공통 상한과 실제 유물 조건을
검증해 IR에 보존한다. 표시 제목이나 특정 콘텐츠 이름으로 런타임을 분기하지 않는다.
`PlayerDirection`은 접수한 방향을 고정하며 대상이 없는 방향도 정상적인 빈 타격이다.

실제 HP 손실이 있는 생존 대상에만 냉기/혹한을 적용한다. 빙결에 성공한 뒤 캡처한 원래
기여분을 제거하며 실패하면 유지한다. 공개 상태의 `status_transition`에는 전환 전 activation·
소유 직원·파편 사본·정의를 남기고 현재 상태의 출처도 보존한다. 같은 정의의 빙결은 재갱신하지
않으며 공통 Hard CC 자격을 따른다. 둔화는 출처별 기여분 중 최댓값을 능력치 합성기에 반영한다.

추격은 생성 당시 Attack을 고정한 독립 효과다. 현재 전투 이동 정책 간격에서 최근접 적을
선택하고 직선 이동하며 생성 시 고정한 만료 시각에 현재 위치에서 폭발한다. 타격당 상태·사망
정산 뒤 기본 생성하고, 사망 생성과 같은 소유자·계열 상한을 공유한다. `mobile_effect` 공개
출처는 실제 activation·motion·기본/사망 생성의 원래 상태와 유물 사본을 보존하며 파생 피해에도
전달한다. 이것은 실행 권한을 주는 토큰이 아니다. 기존 출처 JSON은 새 정보가 없을 때 원래
필드 생략 규칙을 유지한다. 유물 재생성에서 반응/추격 계보/침식 처치를 제외한다.

방향 접수·전환·이동·폭발·사망 생성의 실패와 취소는 전투 후보 트랜잭션으로 복구한다.
소유자 이탈 후 방출 효과와 기존 유한 상태는 유지하고 새 소유 피해 구독은 중지한다. 기존 상태의
사망 생성 자격과 장비 미정 수치의 범위는 눈의 여왕 파편 원문의 후속 정책을 따른다.

### 지원 집중의 시간·범위 유물 경계 — 2026-10-22

지원 집중의 지속시간 modifier는 집중 정의의 시간 입력에, 범위 modifier는 지원 효과의 범위
입력에 명시적으로 연결한다. 전자는 기본/단일 전환 모두에 적용하고 후자는 기본 범위 지원에만
적용한다. 단일 대상 선택 범위에 연결한 지원 범위 변경은 컴파일을 거절한다. 정상 유물 사본
한 개의 조건을 기록하고 단일 전환으로 사라진 지원 범위 변경은 비활성 receipt로 남긴다.
타일 마스크 교체는 authored 결과이며 연속 반경의 자동 확대·반올림을 암시하지 않는다.

### 자기 감면 축적·패링 방출 — 2026-10-22

`guard-charge`는 같은 감면 정의와 패링 계획, 정상 유물 장착 조건, 명시한 상한·주 대상/주변
배율·주변 타일 마스크를 참조한다. Core는 감면 전후의 동일 피해 성분 계산으로 이 감면의 실제
기여만 기록한다. 다른 감면·면역·패링 방어·환경·반응 피해·자기 비용은 축적하지 않는다.
유한 보호막이 나머지를 막아도 앞서 발생한 감면 기여는 유지한다. 반격의 파생 출처는 독립 반응
경계를 지나도 방출 계보를 보존하여 다시 축적·반사·패링하지 않는다.

축적은 직원·파편 사본·정상 유물 사본별 유한 전투 상태다. 성공한 패링은 전량 소비하고,
실패와 일반 반사는 보존한다. 주 대상에는 원래 받아치기 위력과 축적 배율을 합쳐 한 번 타격하고,
주 대상 타일 기준 world-up 주변 마스크에는 주변 배율을 한 번 적용하며 주 대상은 제외한다.
철수·사망·침식·장착 출처 변경·전투 종료에는 정리한다. 원본의 미정 상한·배율·범위를
임의 기본값으로 실행하지 않는다. 공개 관측에는 실제 유물 사본과 축적량·소모량·방출 기여를 남긴다.

### 독립 검토 후 입력·위치 경계 보완 — 2026-10-22

주 대상 직접 타격 계획은 `range` 연결을 사용하지 않는다. 다른 계획과 공유한 범위라도 이 입력에

감염 전파의 숙주·후보 거리와 경로 진행도는 피격/사망 시점의 이동 위치를 사용한다. 감염 기폭과
