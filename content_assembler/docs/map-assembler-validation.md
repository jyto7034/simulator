| ----------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |

| 구독자 예외가 확정 후 호출자에게 전파되고 다음 구독자 호출을 중단했다. 저장 시작 알림은 `try/finally` 밖에 있었다.            | 구독자별 예외를 기록하고 알림을 계속하며 확정 결과를 유지한다. 저장 시작 알림도 busy 해제가 보장되는 구간에 둔다. |

## 구현 결과

새 맵 → 기본 정보 → 브러시/사각형 영역·지형 → 구역·경로·이름 있는 지점 → 임시 슬롯과
웨이브 조건 → 진단 이동·수정 → 실행 취소/다시 실행 → JSON 다운로드·파일 재열기 흐름을 구현했다.
다섯 조건, 대체 발동 시각, 적 구성, 순서·복제·삭제를 폼으로 편집한다.
세부 조작과 문서 규칙은 [프로토타입 안내](map-assembler-prototype.md)를 따른다.

주요 파일은 `src/editor/model.ts`, `coordinates.ts`, `operations.ts`, `history.ts`,
`serialization.ts`, `diagnostics.ts`, `files.ts`와 패널별 TSX다. `App.tsx`가 문서 교체와
단축키·대화상자를 조정한다. SVG 캔버스와 기존 Radix UI를 사용한다.

기본값은 16×12 전체 유효 셀, 좌측 상단 원점, 타일 중심 스냅이다. 고급 N=2/4/8은
셀 내부 분할선 교점을 사용하며 중심도 포함한다. 시간은 화면 초/문서 밀리초다.
문서는 `battle-map` 버전 1, 최대 128×128셀·UTF-8 5MB, 이력은 최근 100개 변경이다.
삭제와 크기 축소는 다른 참조를 자동 변경하지 않으며 보존된 데이터의 문제를 진단한다.

UI 실행 초기에는 샌드박스의 로컬 소켓 권한 때문에 실패했고, 허용된 환경에서 검사했다.
WSL에서 닫힌 포트의 HTTP 확인이 지연되어 Vite의 준비 출력으로 대기하도록 검사 설정을 수정했다.
전용 포트 1422와 `--strictPort`를 유지하여 기존 서버를 재사용하지 않는다.

순수 검사는 한 획 이력·변경 없는 연산·분기, 미저장 기준 복귀, 레이어 잠금,

참조 삭제·복원·복제, 순환/값 진단, 저장 실패·중첩·추가 편집·오래된 완료,
파일 읽기 순서 역전, 정렬되지 않은 셀 집합, UTF-8 저장/읽기 크기 제한을 검증한다.

UI 검사는 실제 파일 선택/다운로드 결과를 읽어 값을 확인한다. 브러시·사각형,

## 남은 제한

- 파일 저장은 브라우저 다운로드 요청이다. 디스크 완료는 사용자 확인으로만 기록한다.
  네이티브 덮어쓰기·파일 대화상자 어댑터는 구현하지 않았다.
- Windows WebView2, Tauri IPC, Windows 배율·설치 프로그램, 실제 한글 IME 조합은 미검증이다.
- 적 카탈로그와 보스 슬롯 바인딩, 실제 경로 이동/조건 평가, 전투 실행·코어 내보내기는 범위 밖이다.
- 128×128 전체 셀과 매우 많은 객체의 제작 성능은 추가 측정이 필요하다. SVG의 겹치는 경로는
  작성한 선분 그대로 표시되며 자동 분리/경로 탐색을 수행하지 않는다.
