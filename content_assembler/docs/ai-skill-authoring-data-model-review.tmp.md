# AI 스킬 작성 데이터 구조 자체 재검토 — 2단계 임시

작성일: 2026-10-23

작성자가 초안을 고정한 후 읽기 전용으로 수행한 자체 재검토다. 독립 감사가 아니다.
[실행 지침](ai-skill-authoring-execution-guide.tmp.md)의 고정→발견 기록→교정→재검토 순서를 따른다.
대상은 [구조 초안](ai-skill-authoring-data-model.tmp.md)이며 제품 코드 검증과 구분한다.

## 1. 고정 대상과 검토 범위

- 최초 초안 SHA-256: `02c46930e98bdd2bceee9e36f5d4b1a1eaf0388bf82b630dd70958ebbcaa6272`.
- 입력 요구사항 SHA-256: `a37d5f60e34696aeeb4460cb69ba34d60d749a8ff2ba2a7e8292d947ea2e648b`.
- 초안과 직접 참조 파일 34개의 지문을 고정했다. 작업 트리의 기존 변경 때문에 HEAD만으로 검토 대상을 식별하지 않는다.
- C01~C13, 스킬·장비·형태 67행, K01~K13, U01~U10을 입력으로 사용했다. 코드 추가 조사는 초안 B01~B06의 범위다.
- 최초 대응 점검: 요구 ID 67개와 구조 대응 ID 67개 일치, 누락·추가·중복 없음. 이는 의미 보존 판정을 대신하지 않는다.
- 최종 포맷·문법·라이브러리 선택, 전체 스킬 작성, 제품 코드·Unity 실행은 검토 범위 밖이다.

## 4. 남은 사항과 단계 판정

현재 검토에서 미해결로 남은 **2단계 필수 구조 결함은 없다**. 이는 전체 스킬 작성이나 실행의 입증이 아니다.
구조 초안 D01~D07은 다음처럼 구분해 인계한다.

- 콘텐츠 대기: 최종 계수·범위·장비 연결·시체 경합·잠정 엘리트의 게임 의도. 미정 자리로 보존하며 사용자 합의로 위장하지 않는다.
- 3단계 검증: 전체 스킬의 참조/종료·조합 부담, 실제 수정 위치와 진단 대조. 표현 불가능이 드러나면 모델 결함으로 되돌린다.
- 4단계 결정: 포맷·문법·부분 텍스트 왕복·파일 묶음 저장 방식. 이 단계에서 선택하지 않았다.
- 구현 조사/5단계 검증: 새 typed 계약·확률 재현/저장·원자성·런타임 추적의 실제 지원, Unity 전달/소비.
- 연출 정책 미정: 미정 연출을 포함한 실행 허용 기준과 자산·시계/전송 세부. 기본값으로 성공시키지 않는다.

종료 판정은 **2단계 구조 초안과 자체 재검토 완료**다. 다음 단계와 사용자 점검은
[계획](ai-skill-authoring-plan.tmp.md) 및 [구조 초안 §15](ai-skill-authoring-data-model.tmp.md#15-3단계에-넘길-순서와-사용자-점검)에 연결했다.
