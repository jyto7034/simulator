# AI 스킬 작성 요구사항 — 1단계 임시 기록

작성일: 2026-10-23  
상태: **1단계 완료**. 최신 원문 대조·별도 자체 재검토·교정 후 재검토 완료. 구현·실행 검증 완료를 뜻하지 않는다.

[계획](ai-skill-authoring-plan.tmp.md)의 1단계 산출물이다. [전제](ai-skill-authoring-premises.tmp.md)와
[실행 지침](ai-skill-authoring-execution-guide.tmp.md)을 적용한다. 종료점은 요구사항과 자체 재검토다.
포맷·스키마·네이티브 API 확정, 제품 코드 구현과 대표 스킬의 새 작성 입력 제작은 다음 단계다.
[자체 재검토 기록](ai-skill-authoring-requirements-review.tmp.md)은 대상 기준선·발견·교정·재판정을 별도로 보존한다.

## 1. 기준과 판정의 의미

2026-10-23 사용자 정정에 따라 [현재 파편 목록][roster]에서 연결되는 최신 위키를 사용한다.
일반보스는 10월 17~20일 리워크와 21~22일 작성 정책을 포함한 합의 구조다.
**엘리트 전체는 현재 안대로 진행하는 잠정 요구사항**이다. 본문에 과거 ‘합의’ 표기가 있어도 최종 사용자 검토를 마친 것으로 보지 않는다.
추가 검토에서 변경되면 해당 요구·예시·Core 경로를 다시 대조한다.
[이관 전 사본][archive]은 변경 경위 확인용이며 최신 파편을 대체하지 않는다.
[위키 관리 기준][maintenance]에 따라 보존 사본과 고정 외부 Forge 사본은 수정하지 않는다.

- **구조 합의 / 잠정안**과 **작업 수치 / 미정**을 별도로 유지한다. 수치 예제·테스트 fixture는 밸런스 확정 근거가 아니다.
- **부분 확인**은 K 표에 명시한 실제 입력·변환·실행 구간만 확인했다는 뜻이다. 이름·타입·과거 완료 기록으로 전체 지원을 주장하지 않는다.
- **미확인**은 조사 증거 부족이며 미구현 판정과 다르다. **필요 개선**은 현재 작성/실행 경계가 요구를 보존하도록 할 과제다.
- 각 표의 확인 사례는 **후속 검증 시나리오**다. 이번에 Rust 테스트·UI 편집·Unity 재생을 실행한 결과가 아니다.
- 원문 위치는 파일 링크와 절/검색어를 함께 쓴다. 해당 파일 하단의 최신 작성 정책이 상단의 오래된 미정·후보를 구체화한 경우 그 정책을 적용한다. 해결되지 않은 충돌은 §8에 남긴다.

## 2. 전체 목록과 범위

태그·유물의 ‘범위’, ‘스택’, ‘지속시간’은 스킬 전체가 아닌 지정 효과에 적용한다. 개화 선택과 침식 공통 자격·비용은 공통 계약을 참조한다.

## 5. 스킬별 표현 요구사항

연출 열의 **원문**은 이미 서술된 표현 의도이며 자산 제작 완료를 뜻하지 않는다.
**기반**은 연결을 위해 보존할 사건/대상이고 구체 자산·타이밍·블렌딩은 미정이다.

## 6. 장비·유물의 독립 요구와 공유 참조

archetype·피해 type·배치 층·대공·저지·targeting·windup/release/delivery를 각각 보존한다.

## 7. 작성·편집·진단과 연출 연결

**확정 제품 요구(C12)**: AI 텍스트와 속성 패널은 같은 작성 원본을 바꾼다. 생성 그래프는 흐름/참조를 보여 주고
초기에는 선택·속성 편집을 지원한다. 노드 추가/삭제/연결 편집은 후속이다. 계산식과 계산 결과를 구분하고,
공유값 수정의 영향 범위를 찾을 수 있어야 한다. 그래프 배치·표시명 변경이 실행 ID를 바꾸지 않아야 한다.

**2단계 검토 대상**: 값의 타입/단위·평가 시점, 안정 ID와 이름 참조, 원문 위치→그래프 요소→컴파일 진단→실행 사건의
대응, 부분 변경과 Undo/Redo·dirty·저장·비동기 revision을 하나의 변경으로 확정하는 경계.
미정 값·끊어진 참조·미지원 동작·잘못된 타입은 다른 진단이다. 미완성 원본 보존과 실행 산출물 생성 허용은 분리하며
‘0’·빈 효과·다른 동작으로 조용히 치환하지 않는다. 아직 문법/포맷·원본 span 표기법을 선택하지 않는다.

**연출 기반의 필수 보존 의미(C13)**: 이펙트/사운드/애니메이션의 자원 참조, 발생 사건과 시점,
실행/동작/효과 ID, 재생 대상·위치·방향·부착 관계, 생성과 갱신 매개변수, 소유자·수명·종료/취소 이유.
게임플레이 판정은 Core 결과를 사용하며 Unity가 적중·범위·소유권을 다시 추론하지 않는다.

## 10. 2단계에 전달할 항목과 종료 범위

1. C01~C13의 의미와 §5~6 행 ID를 구조 초안의 근거로 사용한다. 실행 순서·평가 시점·소유권·수명을 암묵 규칙으로 숨기지 않는다.
2. 값/식/상태/동작/참조와 공통 계약의 경계를 검토하되, 특정 노드/포맷/라이브러리를 아직 선택하지 않는다.
3. 미정 값과 잠정 콘텐츠 상태를 보존하고, 미지원 backend·잘못된 참조와 구분하는 진단 구조를 만든다.
4. 포큐버스→Hello/Goodbye→여왕으로 구조를 확인하고 A~F 추가 사례 및 나머지 경계로 빠진 의미를 찾는다.
5. K01~K13에서 재사용 가능한 경로와 미확인 소비자를 이어 조사한다. 특히 같은 작성원본 편집·장비/유물 결합·저장/복원·연출 추적을 별도 완료로 검증한다.
6. 사용자 점검은 최신 일반보스 의도·보류범위와 엘리트 잠정안이다. 코드 지원 사실의 확인을 사용자에게 떠넘기지 않는다.

1단계 완료 판정은 [별도 자체 재검토 기록](ai-skill-authoring-requirements-review.tmp.md)에서 관리한다.
구조/포맷 선택·새 작성 입력·Core 구현·UI/Unity 검증·전체 콘텐츠 전환은 이번에 완료했다고 주장하지 않는다.
