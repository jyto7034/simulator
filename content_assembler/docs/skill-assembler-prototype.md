# 스킬 조립기 첫 화면

2026-10-19. 콘텐츠 조립기 상단의 **맵 / 스킬**에서 작업 공간을 전환한다.
각 공간의 문서·선택·편집 이력은 앱이 열린 동안 유지한다. 자동 디스크 저장은 하지 않는다.

## 작성할 수 있는 것

- 기본 설정: 스킬 이름과 설명.
- 상태: 이름, 상태가 붙을 대상, 초기값, 수명·종료 규칙.
- 동작: 사용·피해·사망·전투 시간 주기·탄환 적중의 시작 사건과 출처 조건.
- 블록: 조회, 집계·계산, 상태 변경·이전, 대기, 조건 분기, 유한 반복,
  동시 실행, 플레이어 입력, 소비·실행 확정, 발사, 피해, 제어 효과.
- 블록 순서 변경·하위 절차 추가·복제·삭제, 문서 단위 실행 취소·다시 실행.
- 미지정 항목과 끊어진 상태 참조의 진단 및 해당 속성으로 이동.

가운데 노드 그래프에서 모든 시작 사건과 절차를 왼쪽에서 오른쪽으로 읽는다.
분기·반복·동시 실행은 처음에는 접혀 있으며 노드의 펼치기 버튼으로 내부 절차를 확인한다.
분기는 조건/아니면 두 경로, 동시 실행은 나란한 경로로 표시한다.
합류·반복 끝 노드는 화면 설명용이며 문서에 저장하거나 실제 실행을 판정하지 않는다.

노드를 누르면 오른쪽 속성을 편집한다. 노드의 `+` 또는 상단 ‘블록 추가’로
블록 선택 창을 열며, 시작 사건은 절차 끝에, 일반 블록은 바로 뒤에 추가한다.
속성 패널의 ‘안쪽 절차에 추가’, ‘아니면 절차에 추가’로 중첩 절차에 추가한다.
기본 설정·상태·동작 목록은 ‘스킬 구성’에서 연다. 작성 진단은 하단에서 펼친다.
접힌 내부 블록의 진단을 선택하면 해당 절차를 펼치고 속성 입력란에 포커스를 옮긴다.

캔버스 이동·확대/축소·전체 보기를 지원하며 미니맵은 도구줄에서 켜고 끈다. 검색은 현재 펼쳐진 노드를 찾는다.
노드의 제목·요약 부분을 드래그하면 원하는 위치로 옮긴다. ‘자동 정렬’은 수동 위치를 지우고
흐름 순서에 따라 다시 배치한다. 옮긴 위치는 속성 편집·접기/펼치기·맵 전환 중 유지되며,
문서를 새로 만들거나 파일/예제로 교체하면 초기화된다. 위치는 현재 화면에서만 유지하고 JSON에 저장하지 않는다.
노드를 우클릭하거나 노드에 포커스를 두고 Shift+F10을 누르면 편집 메뉴를 연다.
시작 사건은 마지막 블록 추가·동작 삭제를, 블록은 뒤/안쪽/아니면 추가·순서 변경·복제·삭제를
제공한다. 분기·반복의 접기/펼치기와 진단 이동도 메뉴에서 사용할 수 있다.
삭제는 확인 후 적용하며 기존 실행 취소 이력을 공유한다. 합류·반복 종료는 화면용 노드이므로
원본 블록 보기만 제공한다. Escape로 메뉴를 닫으면 해당 노드로 포커스가 돌아간다.
노드 접기·펼치기, 위치 이동과 자동 정렬은 문서 변경이나 실행 취소 이력에 포함하지 않는다.
드래그는 화면 위치만 바꾸며 실행 순서는 바꾸지 않는다.
순서는 속성 패널의 위/아래 버튼으로 같은 절차 안에서 바꾼다.
현재 임의의 선 연결·노드 위치 저장·다른 절차로 이동은 제공하지 않는다.

속성은 Enter 또는 포커스를 옮길 때 확정하고 Escape로 입력을 취소한다.
상태 삭제는 기존 참조 ID를 보존하여 오류를 표시하며 실행 취소하면 같은 ID로 복구한다.
블록 복제는 하위 블록에도 새 ID를 발급하고 외부 상태 참조는 유지한다.

## 예제의 지위

첫 진입은 죽나장 개화형 설계 예제다. ‘예제’ 메뉴에서 두건 기본형으로 바꿀 수 있다.
교체 전 미저장 변경이 있으면 확인하며 맵 문서는 바꾸지 않는다.

- 죽나장: 무기 피해로 유닛 스택 축적, 사망 타일로 이전, 사용 시 타일별 집계.
  등급 공식·반복 횟수의 실행·소비 정책 등은 빈 값이나 설계 메모로 남긴다.
- 두건: 시간/늑대 처치의 창 획득, 배치와 정밀/집중 조준, 전체 소비·발사·재개 확정,
  강화탄 피해와 2초 속박. 2026-10-19 파편 설계를 참조한다.
  일반탄 전체 정의·늑대 출현·재사용 정책·중단 경로 전체를 모델링한 것은 아니다.

예제는 편집 동작을 검토하기 위한 초안이다. 현재 게임 RON이나 모든 콘텐츠 규칙의
완전한 표현으로 간주하지 않는다. 문서 모델 자체도 후속 모델링에서 개선한다.

## 저장과 검증

`skill-design`, version 1의 편집용 JSON을 사용한다. 맵 파일과 구분하며,
정상 구조를 가진 미완성 문서도 저장한다. 파일 열기에서는 형식·필드·ID·블록 중첩을
검사한 뒤 문서를 교체한다. 구조 오류·미지원 버전·오래된 파일 읽기 결과는 현재 문서를 보존한다.
편집기 지원 크기는 파일 5MB, 블록 1,000개, 블록 중첩 16단계다. 게임 규칙의 상한은 아니다.

‘저장’은 다운로드 요청이며 파일 저장 완료를 자동 확인하지 않는다. 파일을 확인한 뒤
‘다운로드 확인’을 누르면 해당 출력 문서를 저장 기준으로 삼는다. 다운로드 중 추가 편집은
미저장 상태로 남는다. Ctrl+S, Ctrl+Z, Ctrl+Shift+Z/Ctrl+Y, Ctrl+O를 지원한다.
입력 필드·메뉴·대화상자 안에서는 해당 위젯의 키보드 동작을 유지한다.

**현재 검증은 구조와 미지정·상태 참조에 한정한다.** 수식·대상 조건 등은 설계 문자열이며
타입이 있는 실행 수식이나 확정된 스크래치 언어가 아니다. 이름 붙인 결과의 참조 해석,
반복의 유한성, 합류·시점·비용의 실제 의미, Core 지원 여부는 아직 검사하지 않는다.
화면의 ‘미지정 항목 없음’은 실행 가능 판정이 아니다.

Core 연동, 전투 시뮬레이션, RON 내보내기, 네이티브 파일 저장은 미구현이다.

## 구현 경계

`src/skill/model.ts`는 편집 문서·블록 목록·순수 편집 연산을,
`validation.ts`는 구조 검사와 작성 진단을 소유한다. `session.ts`는 초안의 검증 후
문서·선택·이력·리비전을 함께 확정한다. `files.ts`는 다운로드와 파일 교체의 시점을 관리한다.
화면은 같은 원본을 읽으며 별도 스킬 런타임이나 게임 판정을 만들지 않는다.
`graph-model.ts`는 문서의 그래프 표현, `graph-layout.ts`는 ELK 자동 배치,
`SkillGraph.tsx`는 React Flow 캔버스와 화면 상태를 담당한다. 배치는 Web Worker에서
수행하며 실패 시 문서를 유지하고 재시도를 제공한다. 스킬 화면은 처음 열 때 지연 로딩한다.

`MapEditor`는 기존 맵 편집기를 보존하고 `App`은 작업 공간 전환만 담당한다.
비활성 공간의 전역 단축키는 동작하지 않는다. 기존 폼·버튼·대화상자·테마와 다운로드 함수를 재사용한다.

## 검증

순수 모델: `tests/model/skill.spec.ts`. 중첩 편집·삭제 복구·미정 저장·참조 보존,
실패 시 부분 변경 방지, 저장 도중 편집과 오래된 열기 결과 거부를 검사한다.

화면: `tests/ui/skill.spec.ts`. 두 예제, 순서·중첩·복제·Undo, 맵 문서 보존,
파일 왕복·오류 보존·진단 이동, 빈 문서·긴 이름·60개 블록, 키보드 확인 취소를 검사한다.
첫 화면의 기록은 [초기 검증](skill-assembler-validation.md), 노드 그래프 전환 결과는
[그래프 검증](skill-graph-validation.md)에 남겼다.

두건의 규칙·모델·화면 대조 결과와 별도 편집용 JSON은
[두건 조립 모델 검토](hood-authoring-review.md)에 있다.
