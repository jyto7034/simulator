# 노드 편집기 기반

2026-10-20. TypeScript 이관 반영. Blender의 노드·소켓·연결·배치 구조와 Godot의 편집 요청/Undo 경계를
참고해 독립적인 노드 작업 공간을 만든다. 현재 [Hello / Goodbye 작성 요소](hello-goodbye-node-guide.md)를
추가했으며 실제 스킬 실행은 후속 단계다.

## 책임

- `src/nodes/core/`: React·Tauri에 의존하지 않는 TypeScript 문서·명령·검증·이력 코어.
- `src/nodes/store.ts`: 동기 편집 결과를 화면에 알리는 로컬 저장소.
- Tauri: 데스크톱 호스트. 노드 편집용 IPC와 개발 브리지는 제거했다.
- React Flow: 확정 문서의 표시, 선택·줌, 드래그 중 미리보기. 편집 규칙을 재구현하지 않는다.
- 기존 스킬 초안과 맵은 각자의 작업 공간을 유지한다. 노드 파일은 별도 형식이다.

노드와 포트의 ID로 연결을 식별한다. 문서에는 노드 위치·속성·연결·시각적 프레임을 저장한다.
선택과 뷰포트는 저장/Undo에서 제외한다. 프레임은 배치용 묶음이며 실행 그룹/함수가 아니다.
기본 노드 카탈로그는 TypeScript 코어에서 제공하며 데이터/실행 포트를 구분한다. 계산·분기·동작 노드의
실제 평가나 게임 실행은 이번 편집기에서 하지 않는다.

## 확정과 이력

명령은 문서 사본에 준비하고 구조와 참조를 검사한 뒤 문서·리비전·이력을 함께 확정한다.
실패와 변화 없는 명령은 이력을 만들지 않는다. 드래그는 놓을 때 한 번만 확정한다.
연결 변경, 연결된 노드 삭제, 다중 이동·복제·붙여넣기는 각각 하나의 Undo 단위다.
드래그와 파일 읽기·클립보드 작업에는 문서 세대·리비전을 확인해 오래된 결과가 현재 문서를
수정하지 못하게 한다. 원격 세션이나 통신 응답 검사는 필요하지 않다.

연결은 출력→입력, 같은 포트 종류/자료형이어야 한다. 단일 입력의 기존 연결 교체는 한 명령으로
처리한다. 연결하지 않은 필수 입력과 그래프 순환은 진단으로 표시하며 작성 중 문서는 보존한다.
문서 내부의 없는 노드/포트 참조와 잘못된 타입은 구조 오류로 거부한다.

## 구현 완료를 확인할 사용자 동작

노드 추가/검색, 포트 연결·재연결·해제, 다중 선택과 복제/복사/붙여넣기/삭제,
배치와 프레임, 속성 편집, Undo/Redo, 저장·재열기, 잘못된 파일/오래된 요청의 문서 보존.
960×640·1280×800·1920×1080 및 밝은/어두운 테마, 실제 TypeScript 코어를 거치는 UI 검사를 수행한다.
성능은 드래그 프레임과 명령 확정을 구분해 확인한다. 대규모 성능은 측정한 범위만 보고한다.

## TypeScript 이관 결정

Rust는 현재 편집 기능에 필수적이지 않으며, 실제 성능 병목이나 게임 코어 공유 요구가
확인되지 않았다. 사용자 승인에 따라 문서·검증·편집·패치 이력·저장 확인을 TypeScript로
옮기고, 노드 전용 Rust crate·IPC 명령·개발 브리지·전송 타입·통신 복구 UI를 제거했다.
별도 워커나 범용 편집 프레임워크는 도입하지 않는다.

기존 맵·스킬 세션의 불변 문서와 확정 후 알림 원칙을 따르되, 문서 형식과 부분 패치 이력이
다르므로 세 편집기를 하나의 세션 클래스로 합치지 않는다. 기존 파일 다운로드 도구와
공통 UI 컴포넌트는 계속 사용한다. 기존 Rust가 내보낸 파일과 카탈로그를 고정 fixture로
보존해 자료형·기본값·저장 형식 호환성을 검사한다.

확인한 동작은 [사용 안내](node-editor-guide.md), 검사 결과와 미검증 범위는
[검증 기록](node-editor-validation.md)에 정리한다. 스킬 전용 실행 규칙, 게임 Core 연결,
함수형 노드 그룹·플러그인 시스템은 후속 범위다.
