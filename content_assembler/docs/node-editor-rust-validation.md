# 초기 Rust 노드 편집기 검증 기록

이 문서는 TypeScript 이관 이전 구현의 역사적 검사 기록이다. 현재 상태는
[노드 편집기 검증](node-editor-validation.md)을 따른다.

2026-10-20. [설계](node-editor-design.md)와 [사용 안내](node-editor-guide.md)에 해당하는
구현을 WSL에서 검증했다. 실제 Rust 코어와 브라우저 UI의 연결까지 확인했으며,
Windows 네이티브 검증과 스킬 실행 모델 적용은 남아 있다.

## 검사 결과

| 검사                   | 결과      | 범위                                           |
| ---------------------- | --------- | ---------------------------------------------- |
| `npm run check`        | 통과      | TypeScript, ESLint, Prettier                   |
| `npm run build`        | 통과      | 프런트엔드 빌드와 고지 생성                    |
| Rust 코어              | 18건 통과 | 편집·검증·이력·저장 확인·세션과 stdio RPC      |
| 모델 테스트            | 34건 통과 | 기존 모델과 노드 클라이언트의 비동기 응답 경계 |
| 노드 UI                | 30건 통과 | 5개 시나리오 × 3개 화면 크기 × 2개 테마        |
| 기존 UI 회귀           | 60건 통과 | 맵·스킬·작업 공간 관련 시나리오                |
| 브라우저 성능 시나리오 | 1건 통과  | 500노드·499연결, 드래그 30단계                 |

UI 행렬은 960×640, 1280×800, 1920×1080의 밝은/어두운 테마다.
Vite 브리지가 `node-core::protocol::Host`를 실행하는 실제 Rust 프로세스를 호출했다.
Windows의 `node_modules`와 분리한 WSL 작업 폴더에서 검사하고, 검사한 소스를 원본에 반영했다.
주요 소스의 [SHA-256 목록](../artifacts/node-editor-20261020/source-sha256.txt)을 보존했다.

처음 90건 실행은 88건 통과, 2건 실패였다. 두 실패는 저장 확인 요청이 끝나기 전에
잘못된 파일을 열던 테스트 순서 문제였다. 미저장 교체 확인창이 올바르게 표시되었지만
테스트는 파일 오류를 바로 기대했다. 저장 확인 버튼이 사라지는 실제 완료 상태를 기다리도록
테스트를 수정했고, 노드 UI 30건 전체가 재실행에서 통과했다. 기존 UI 60건은 첫 실행에서
모두 통과했다. 따라서 90건은 두 실행의 서로 다른 관련 시나리오를 합한 수이며,
한 번의 90건 실행이 모두 통과한 것으로 기록하지 않는다.

결과는 [집계](../artifacts/node-editor-20261020/summary.json),

## 확인한 동작과 화면

노드 이동·다중 이동·취소·Undo/Redo, 속성 적용·취소와 잘못된 숫자 입력 보존,
저장·재열기의 좌표/속성/연결 일치, 검색과 추가, 포트 연결·재연결·취소,
연결 끝에서 노드 추가와 한 번의 Undo, 경유 노드 삽입, 프레임 이동·복제·삭제,
복사/붙여넣기, 키보드 메뉴·Escape와 포커스 복귀를 확인했다.
로딩 중 작업 공간 전환, 빈 문서, 미완성 진단, 잘못된 파일의 기존 문서 보존도 포함한다.

## 접근성 진단과 남은 확인

노드 30건과 기존 회귀 60건 모두 브라우저 오류·경고, 보고서 오류, axe `violations`가 0건이다.
자동 판정이 불가능한 `incomplete`는 별도로 남았다. 아래 수는 캡처별 반복 발생을 포함하며
고유 결함 수가 아니다. 상세 대상은 [진단 목록](../artifacts/node-editor-20261020/incomplete-targets.json)에 있다.

| 범위      | 규칙                    | 발생 횟수 | 대상 노드 발생 횟수 | 수동 검토와 제한                                                                                                        |
| --------- | ----------------------- | --------: | ------------------: | ----------------------------------------------------------------------------------------------------------------------- |
| 노드      | `aria-prohibited-attr`  |        42 |                  42 | React Flow 확대 도구 컨테이너의 `aria-label`. 개별 버튼의 이름과 조작은 확인했으나 컨테이너의 ARIA 판정은 미완료로 남김 |
| 노드      | `color-contrast`        |        38 |                 343 | 축소된 그래프·프레임·겹치는 영역. 대표 PNG에서 텍스트와 포트 식별을 확인했으나 모든 대상의 대비 수치를 측정한 것은 아님 |
| 노드      | `aria-hidden-focus`     |         6 |                  18 | Radix 대화상자 주변 숨김 루트와 포커스 가드. 대화상자 키보드 조작·Escape·복귀 확인                                      |
| 기존 회귀 | `color-contrast`        |        42 |               1,314 | 기존 그래프 화면의 대표 이미지 검토. 전 대상 대비 수치 검증은 아님                                                      |
| 기존 회귀 | `aria-valid-attr-value` |         6 |                   6 | 테마 메뉴의 `aria-controls`. 메뉴 대상과 키보드 포커스 검사 통과                                                        |

자동 위반 0건을 접근성 전체 검증 완료로 해석하지 않는다. Windows 보조 기술 동작은 확인하지 않았다.

## 성능 측정

Rust release 코어에서 연결된 계산 노드 그래프를 각 30회 편집했다.
명령 적용과 응답 직렬화를 분리해 측정했다.

| 노드 / 연결   | 편집 중앙값 | 편집 p95 | 직렬화 중앙값 |     응답 크기 |
| ------------- | ----------: | -------: | ------------: | ------------: |
| 100 / 99      |     0.164ms |  0.235ms |       0.054ms |  35,201바이트 |
| 500 / 499     |     0.994ms |  1.428ms |       0.302ms | 176,681바이트 |
| 2,000 / 1,999 |     4.754ms |  6.096ms |       1.431ms | 709,311바이트 |

원자료: [코어 측정](../artifacts/node-editor-20261020/core-performance.json).

WSL Chromium 1280×800 밝은 테마, Vite 개발 모드와 Rust debug 프로세스에서
500노드·499연결의 드래그를 측정했다. 30단계 드래그 동안 문서 확정은 1회였고,
수집한 164개 프레임 간격의 중앙값은 16.7ms, p95는 33.4ms였다.
확정 요청 왕복은 19.702ms였다.
원자료: [브라우저 측정](../artifacts/node-editor-20261020/performance/measurement.json).

이는 한 환경의 표본이며 Windows WebView2나 2,000노드 UI 성능을 보장하지 않는다.
코어 명령 시간과 브라우저 프레임 간격은 측정 조건과 의미가 다르다.

## 미검증 범위

Tauri 연결 코드는 추가했지만 네이티브 빌드는 완료하지 못했다. 로컬 캐시에 없는 의존성
(`adler`)과 GTK/WebKit 개발 라이브러리 부족으로 WSL 호스트 검증이 막혔다.
Windows MSVC 대상 환경도 없어 Windows 빌드·WebView2·Tauri IPC·한글 IME·
실제 파일 다운로드·설치 프로그램은 검증하지 않았다.

브라우저 저장은 다운로드 후 사용자가 파일을 확인하고 저장 기준을 확정하는 방식이다.
네이티브 파일 대화상자와 원자적 디스크 저장은 구현·검증 범위에 포함하지 않았다.
계산·분기·동작의 실행, 스킬 모델 적용, 게임 Core 연결, 함수형 그룹과 동적 포트도 후속 범위다.
