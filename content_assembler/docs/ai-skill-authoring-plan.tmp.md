# AI 스킬 작성·Core 기능 조합 개선 계획 — 임시

작성일: 2026-10-23

상태: **기존 1~3단계 완료, C0 목적 확장·구체화 작업 중**.
요구사항·작성 데이터 구조·대표 스킬 예시와 단계별 재검토 기록은 유지한다.
2026-10-23 후속 요청으로 C0~C3을 포맷 선택 앞에 배치했다. C1~C3과 기존 4~5단계는 미착수다.

단계별 검토·구현·검증·결함 교정과 재감사는
[실행 지침](ai-skill-authoring-execution-guide.tmp.md)을 따른다.

자율 위임을 위한 [하네스](skill-authoring-autonomy-harness.tmp.md)와 [작업 기록](skill-authoring-worklog.tmp.md)을 준비했다.
하네스의 권장 위임 범위는 제안이며 실제 작업 범위는 최신 사용자 요청을 따른다. C0의 단계 상태는 그대로다.

## 목적과 기준

[합의한 전제와 작성·편집 방향](ai-skill-authoring-premises.tmp.md)을 바탕으로,
AI가 스킬을 작성하고 사람이 그래프와 속성 패널에서 확인·수정하며,
**작성자가 새 기능을 정의하고 조합할 수 있도록 작성 모델과 Core를 개선**한다.
[확장 목표 초안](skill-authoring-core-goals.tmp.md)에서 필요한 능력과 책임 경계·성공 기준을 구체화한다.
기존 요구와 예시를 사용해 Core 실행 기반의 작은 범위를 검증한 뒤 구체적인 작성 포맷을 선택한다.

현재 순서: **기존 1~3 → C0 목표 구체화 → C1 정의·실행 계약 → C2 작은 실행 검증 → C3 조합 검증 → 4 포맷·도구 → 5 통합 검증**.
1~3단계 완료는 당시 의미 설계·대조 범위다. 새 실행 모델의 적합성이나 Core 지원 완료를 뜻하지 않는다.

- [현재 스킬 파편 목록](../../core_enhanced/docs/content/skills/README.md)에서 연결되는 파편·장비·유물 문서를 기준으로 한다.
  일반보스는 합의된 최신 리워크이며, 엘리트는 현재 안대로 진행하는 잠정안으로 추가 검토와 변경 가능성을 남긴다.
  이관 전 보존 사본은 최신 제작 기준을 대신하지 않는다.
- 최종보스는 미합의 상태이며, 현재 단계의 확정 요구사항에서 제외한다.
- Core는 미완성이며 명세도 확정되지 않았다. 합의된 스킬 구조를 표현·실행하도록
  작성 모델과 Core를 개선한다. 현재 구현의 한계에 맞추어 스킬 의미를 축소하지 않는다.
- Rust Core를 Unity에 네이티브 방식으로 연결하는 계획을 전제로 한다.
  연출의 세부 명세는 미정이지만, 이펙트·사운드·애니메이션과 스킬 실행을 연결할 데이터 기반을 포함한다.
- AI와 사람은 하나의 작성 원본을 수정한다. 초기에는 그래프 선택과 속성 편집을 지원하고,
  그래프의 노드 추가·삭제·연결 변경은 후속 단계에서 다룬다.

## 1. 스킬별 표현 요구사항 정리

일반보스·엘리트 전체에서 필요한 기능을 추출하고, 공통 기능과 특정 스킬에 필요한 기능을 구분한다.
발동 조건, 대상 선택, 수치·계산식, 실행 순서, 반복, 상태 전환, 재입력,
소유자·수명·종료·취소, 공유 참조 등을 살핀다.

요구사항마다 근거가 되는 스킬과 원문 위치를 연결하고, 현재 Core 지원 여부와 필요한 개선을
별도 항목으로 기록한다. 지원 여부가 불명확하면 미확인으로 남긴다.
연출 연결에 필요한 사건과 대상도 함께 검토하되, 합의되지 않은 개별 연출을 새로 확정하지 않는다.

산출물: **스킬별 표현 요구사항 표**. 최소한 다음 열을 둔다.

| 스킬·원문 위치 | 표현할 동작과 의미 | 필요한 공통 기능·참조 | 연출 연결 검토 사항 | Core 지원·차이 | 확인할 사례 |
| -------------- | ------------------ | --------------------- | ------------------- | -------------- | ----------- |

완료 기준: 일반보스·엘리트의 검토 범위와 누락·미확인 항목이 드러나고,
각 요구사항을 원문과 연결할 수 있다. 원문 간 충돌이나 해석이 필요한 부분은 별도로 기록한다.

## 2. 작성 데이터 구조 초안

요구사항을 바탕으로 수치, 계산식, 상태, 동작과 이름 있는 참조의 정의 방법을 정리한다.
타입, 실행 순서, 값을 읽는 시점, 소유자와 수명 등 실행에 필요한 의미를
작성 데이터 또는 찾아볼 수 있는 공통 계약으로 표현한다.

다음 편집·진단 요구도 함께 다룬다.

- AI가 필요한 동작과 의존 관계만 찾아 읽고 부분 수정할 수 있는 구조.
- 사람이 수정할 속성과 공유 값의 영향 범위, 계산식과 결과의 구분.
- 원본 동작과 그래프 요소, 컴파일 진단, 실행 결과를 연결할 식별 정보.
- 미정 값·끊어진 참조·미지원 동작을 보존하고 원인을 구분하여 진단하는 방법.
- 실행 의미와 별도로 보관할 그래프 배치 정보.

연출 기반에는 자원 참조, 시작·갱신 사건과 시점, 재생 대상·위치·부착 관계,
수명·종료·취소, 재생 매개변수와 실행 추적의 연결을 검토 항목으로 둔다.
구체적인 연출 명세와 네이티브 API, 연출 미정 상태의 컴파일 처리 기준은 미정으로 표시한다.

산출물: **작성 데이터 구조 초안**. 필수 의미, 공통 계약, 편집 가능한 속성,
미정 사항을 구분한다. 이 단계의 표기법은 검토용이며 최종 포맷으로 확정하지 않는다.

## 3. 대표 스킬 작성과 대조

포큐버스로 기본 형태를 잡고, Hello / Goodbye와 증오의 여왕으로
상태 전환·재입력과 복잡한 동작 관계까지 표현되는지 확인한다.
1단계에서 이 사례들이 다루지 못하는 요구사항을 찾으면 추가 사례를 선정한다.

각 예시에 다음 내용을 붙인다.

- 원문의 동작과 작성 데이터의 대응 관계.
- 생성할 그래프의 구조와 사람이 수정할 속성.
- 공유 참조와 공통 규칙의 적용 위치.
- 잘못된 참조나 미정 값이 있을 때 진단할 원본 위치와 이유.
- 스킬 실행과 연결할 연출 정보 및 아직 정하지 않은 항목.

산출물: **대표 스킬 작성 예시**와 의미 보존 대조 결과.
완료 기준: 원문의 동작을 생략하거나 다른 동작으로 바꾸지 않고 표현하며,
표현할 수 없는 부분은 구조 초안의 개선 사항으로 남긴다.

## C0. 확장 목적·범위·성공 기준 구체화 — 진행 중

기존 문서의 역할과 읽는 순서를 정리하고, 요구·예시에서 작성자가 정의할 기능과 사용처를 찾는다.
사용자 정의 타입뿐 아니라 계산·동작·상태·사건·수명·재사용 관계를 후보로 대조한다.
Core의 기본 동작과 작성 데이터의 책임, 첫 검증 범위, 기존 기반의 재사용·전환 쟁점을 구분한다.

산출물: [목표 초안](skill-authoring-core-goals.tmp.md), 요구·사례와 후보 능력의 대응, 첫 범위와 통과 기준.
완료 기준: 첫 구현 대상을 선택할 근거와 관측 가능한 기대 결과, 제외한 범위와 미정이 드러난다.
현재는 목표 초안·문서 역할·후속 순서 정리를 마쳤으며 사례 대응과 첫 범위 선정은 남아 있다.

## C1. 기능 정의 단위와 Core 실행 계약

C0의 선택 범위에서 입력·출력·상태 소유·호출·결과·사건·대기·취소·종료 계약을 정한다.
기존 M 요소를 실행 명령에 일대일로 옮기지 않고 실제 생산자·소비자에 필요한 단위를 선택한다.
타입·단위·필드 참조 검증, 원본 위치와 호출 맥락 추적, 오류·부분 실패를 함께 정한다.

산출물: 선택한 의미 모델·Core 계약, 현재 코드와의 차이, 검증 사례·기대 결과와 유효한 전환 범위.
완료 기준: 저장 구조나 새 타입만 제안한 상태를 넘어 작성 입력이 실행·정리까지 이어지는 책임을 설명할 수 있다.
최종 텍스트 문법·VM·DLL·라이브러리를 선결 조건으로 고정하지 않는다.

## C2. 작은 범위의 컴파일·Core 실행 검증

필요한 최소 내부 표현으로 선택한 기능을 작성 데이터 → 검증·컴파일 → 산출물 → 로드 → 실제 Core 실행에 연결한다.
시험 입력과 제품 계약을 구분하고, 기존 자원·결과·효과 상태의 원본 권한을 중복시키지 않는다.
성공뿐 아니라 잘못된 참조·타입, 선택 범위의 취소·퇴장·재배치 등 실패·종료 사례를 확인한다.

산출물: 실행 가능한 작은 경로와 기대 결과 대조, 영향받는 기존 기능의 회귀 결과, 원본 진단·추적 근거.
완료 기준: 우회 helper나 새 저장소만의 단위 시험으로 완료하지 않고 실제 생산자·소비자를 연결한다.
최종 편집 포맷·UI 검증은 후속이며, 임시 입력 경로의 역할과 전환·제거 조건을 기록한다.

## C3. 서로 다른 스킬에서 정의·조합·재사용 검증

같은 기반을 두 번째 스킬의 다른 의미에 적용하고 공유 정의·개별 매개변수·독립 실행 상태를 확인한다.
기본 동작이 이미 지원되는 조합에서 조건·순서·사용처 변경을 데이터로 처리할 수 있는지 검증한다.
스킬명·fixture에 맞춘 제품 분기로 성공시키지 않으며 새 기본 동작이 필요하면 차이와 확장 근거를 명시한다.

산출물: 둘 이상의 사용처와 공유 정의, 변경 과제·상태 격리·수명·진단 결과, 표현하지 못한 요구 목록.
완료 기준: 계수만 바꾼 동일 사례 이상의 조합 차이를 표현하고 전체 스킬 지원과 검증된 범위를 구분한다.
필요한 구조 보완은 C1/C2에 반영한 뒤 관련 검증을 다시 수행한다.

## 4. 포맷과 편집 도구 비교·선택 — C3 이후

C1~C3에서 검증한 의미 모델과 기존 스킬 예시를 사용하여 후보 포맷을 비교한다.
JSON·YAML 등은 비교 후보이며, 문법이나 라이브러리를 미리 확정하지 않는다.

후보 조사와 작은 표현·편집 실험은 C0~C3과 병행할 수 있다. 이 단계는 최종 비교·선정의 위치다.
현재 JSONC·제한된 YAML 1.2·KDL 우선 비교 제안과 공식 출처는 [작업 기록](skill-authoring-worklog.tmp.md)에 남겼으며,
실제 AI 작성 성능·원문 보존 시험이나 채택을 완료한 것은 아니다.

- AI의 읽기·설명, 수치 수정, 조건·동작 추가, 진단에 따른 오류 수정.
- 타입 검증과 원본 오류 위치 표시, 참조 탐색.
- 속성 패널의 부분 수정과 원본 보존, 불필요한 전체 재작성 여부.
- 변경 내역의 가독성, 공유 값의 영향 확인, 그래프 생성 가능성.
- 의미 정확성, 의도하지 않은 변경, 재시도와 입력 부담.

비교 전에 대상 모델·과제·통과 기준을 정하고, 실제 결과와 한계를 기록한다.
문서 길이나 노드 수 감소만으로 저성능 AI의 사용 가능성을 입증했다고 판단하지 않는다.

산출물: 포맷 비교 결과와 선택 근거, 사용 도구의 제약 및 남은 과제.

## 5. 선택한 작성 포맷·편집·Core 실행의 통합 검증

선택한 포맷으로 대표 스킬 하나를 작성·속성 편집 → 원본 반영 → 검증 → 실행 데이터 → Core 실행까지 연결한다.
C2/C3의 실행 근거를 재사용하되, 최종 작성·편집 경로에서도 합의된 의미가 보존되는지 대조한다.
기존 기반의 재사용 범위와 Core 개선 사항을 구분하고 저장·재로드·진단·원본 추적을 확인한다.

성공 사례와 함께 컴파일 거부의 위치·원인 추적을 확인한다.
연출은 확정된 데이터 계약 범위에서 실행 사건과의 연결을 검증하고,
Unity의 실제 재생을 검증하지 않았다면 그 범위를 명시한다.

산출물: 작성·편집과 실제 실행의 통합 검증 결과, 남은 Core·컴파일러·편집기 개선 목록.
단일 사례의 성공을 전체 스킬 지원이나 미리보기 완성으로 보고하지 않는다.

## 바로 다음 작업과 후속 범위

**1단계 요구사항 표와 별도 자체 재검토를 완료**했다.
[요구사항](ai-skill-authoring-requirements.tmp.md)에서 최신 대상·출처·Core 근거·미확인·대표 사례를 정리한다.
일반 파편 10계열·엘리트 잠정 파편 11계열과 장비 22계열을 검토했고, 공통 요구 13개·Core 근거 13묶음·추가 대표 사례를 연결했다.
원문 대조 → 읽기 전용 자체 재검토 기록 → 교정 → 재검토 결과는 [별도 기록](ai-skill-authoring-requirements-review.tmp.md)에 남겼다.

**2단계 작성 데이터 구조 초안과 자체 재검토를 완료**했다.
[구조 초안](ai-skill-authoring-data-model.tmp.md)은 M01~M12 표현 요소·P01~P08 공통 계약의 입력/결과와
67개 요구 묶음의 대응, 같은 원본 편집·공유 영향·미정 보존·원본에서 연출까지의 추적을 제안한다.
[별도 자체 재검토](ai-skill-authoring-data-model-review.tmp.md)에 초안 고정·발견 선기록·교정·재검토를 남겼다.
설계 제안과 실제 Core 지원, 콘텐츠 미정과 구현 미확인을 구분했다. 포맷 선택이나 제품 코드 구현은 진행하지 않았다.

당시 요청의 종료점인 **3단계 대표 스킬 작성·의미 대조·구조 보완과 별도 자체 재검토를 완료**했다.
[예시 진입점](ai-skill-authoring-examples.tmp.md)에서 포큐버스→Hello / Goodbye→증오의 여왕 전체 작성과
각 도식·수치/대상/조건 편집·공유 사용처·미정/오류 진단·연출 추적을 찾을 수 있다.
[추가 경계](ai-skill-authoring-examples-boundaries.tmp.md)는 다중 입력·순환 회복·영구 승급·사망 연쇄·원정 빚을
초기 상태/입력/관측/반례로 대조하고 67개 요구 묶음과 C01~13의 남은 검증을 구분한다.
결과 집계의 실행 범위·닫힘/취소와 접수 영수증/실제 침식 대체 참조를 구조 초안에 보완했다.
[별도 재검토](ai-skill-authoring-examples-review.tmp.md)에 고정→발견 선기록→교정→재검토와 검사 결과를 남겼다.
콘텐츠 수치/합성/연출 미정은 그대로이며 전체 실행 지원을 입증한 단계가 아니다.

바로 다음 행동은 **C0의 후보 능력과 기존 요구·대표 사례를 연결하고 첫 검증 범위와 기대 결과를 고르는 것**이다.
목표 초안과 문서 역할·순서를 정리했으며, 기능 단위·Core 계약·저장 방식은 아직 선정하지 않았다.
현재 요청은 목적 확장·구체화이며 이번 정리에서 제품 코드는 변경하지 않았다.

기존 4단계 포맷 비교는 C3 이후로 옮긴다. 세 예시·A1~A5·편집/진단 과제를 보존하고,
대상 AI·반복 횟수·허용 도구·시간/비용·통과 기준은 비교 전에 정한다.
기존 5단계의 실행 검증 목적은 C2/C3과 최종 5단계로 나누어 유지한다.

전체 콘텐츠 전환, 미리보기 UI, Unity 연출의 완성, 그래프 구조 편집은
이번 초기 설계·검증 결과를 바탕으로 후속 범위와 순서를 정한다.
이 개선 작업의 현재 상태와 순서는 이 계획을 원본으로 관리한다.
[기존 작업 파이프라인](skill-authoring-pipeline.tmp.md)은 기존 그래프 경로의 구현·검증 이력으로 참조한다.

## 단계 마무리의 사용자 점검

사용자는 게임 의도와 작성 경험을 확인하고, 실행자는 코드 경로·누락·검증 근거를 확인해 보고한다.
매 단계 전체 문서 재독을 요구하지 않고 완성 결과·중요한 선택·남은 미정·판단 필요 항목을 추려 전달한다.
기존 합의 안의 진행에 단계별 승인을 새로 요구하지 않는다. 새로운 게임 의미나 범위 변경이 필요한 지점만 판단을 요청한다.

| 단계 | 사용자에게 제시할 점검 사항                                                             |
| ---- | --------------------------------------------------------------------------------------- |
| 1    | 최신 일반보스 리워크·제외/보류 범위의 일치, 엘리트 현재 안의 의도·변경 가능 표시        |
| 2    | 수치·대상·조건을 수정할 위치, 공유 값의 영향, 미정 정보 보존이 이해되는지               |
| 3    | 대표 스킬의 흐름이 의도대로 읽히는지, 그래프·속성에서 원하는 부분을 찾고 고칠 수 있는지 |
| C0   | 작성자가 새로 정의·조합할 능력과 첫 검증 범위·성공 기준이 목적에 맞는지                 |
| C1   | 정의의 입출력·상태·수명과 Core의 책임, 미정·전환 경계가 명시되어 있는지                 |
| C2   | 작은 경로의 실제 실행·거절·종료 근거와 아직 연결하지 않은 범위                          |
| C3   | 서로 다른 스킬의 재사용·조합·상태 격리와 스킬별 코드 추가 여부                          |
| 4    | 실제 작성·수정 사례의 가독성, 변경 내역·오류 설명과 AI 비교 결과의 한계                 |
| 5    | 실제 대상·순서·재입력·중단 동작의 일치, 연출 연결 검증과 Unity 실제 재생 범위의 구분    |
