## 2. 검토용 작성 표기와 원본 책임

정의표·실행표를 합쳐 **하나의 논리적 작성 원본**을 제시한다. 표의 ID와 속성 경로는 추적용 검토 표기다.
JSON/YAML/DSL 문법, 파일 조직, Rust 타입·IR 또는 노드 종류를 선택한 것이 아니다.
도식·수작업 결과표·속성 화면 설명은 그 원본의 파생 설명이며 별도 수정 원본이 아니다.

| 표기                                      | 의미                                                                      |
| ----------------------------------------- | ------------------------------------------------------------------------- |
| `PC.*`, `HG.*`, `QH.*`, `A1.*` 등         | 문서 안의 안정된 정의 ID. 표시 이름 변경과 구분. 앞부분은 검토용 이름공간 |
| `정의.속성`                               | 원본에서 고칠 자리. 배열/문법의 정확한 위치 표시는 4단계 과제             |
| `@접수`, `@방출`, `@피해후`, `@완료`      | 값을 읽고 고정하는 사건. 현재 값을 무조건 계속 읽는 뜻이 아님             |
| `미정〈종류; 이유; 근거〉`                | 원본에 보존할 타입 있는 공백. 0·false·빈 효과가 아님                      |
| `S.*`                                     | 아래 공통 계약의 참조. 스킬별 입력과 예외는 각 호출 행에 둠               |
| `합의 / 작업값 / 잠정 / 미정 / 구조 제안` | 콘텐츠 상태와 이 문서의 설계 선택을 구분. 작업값도 최종 밸런스 확정 아님  |

실행 맥락 `ctx`는 직원 identity·현재 배치 ID·파편 사본·장비/유물 사본·전투 ID·전투시각·전장 조회 권한을 받는다.
현재 HP·공명·장착 상태는 Core가 소유한다. 작성 원본은 그 상태를 읽는 규칙만 소유한다.
정의 참조는 문서/정의 ID와 버전, 실행 참조는 시전/action/활성 ID와 유효 범위를 구분한다.
시험용 조건은 `case.*`에 따로 적고 원본 미정값을 자동 채우지 않는다.

단계가 ‘전체 작성’이라는 것은 알려진 모든 동작과 미정 의존을 진입부터 종료까지 연결했다는 뜻이다.
미정 계수가 남은 예시를 즉시 실행할 수 있다는 뜻은 아니다. 각 예시의 미정 목록이 선택 실행의 거부 위치를 보여 준다.

공통 계약에 적히지 않은 숫자나 게임 정책을 숨은 기본값으로 보충하지 않는다. 각 스킬의 ‘추가 공명 없음’,
개인막 사용 종료, Hello 버프 전체 잠금, 여왕 집중 등은 호출에 명시한다. 콘텐츠마다 다른 행위 종료를 하나로 합치지 않는다.

정상 수동 사례는 공통 에고 침식 대체가 발생하지 않는 맥락이다. 대체가 가능한 선택 실행은
[QH.ego.*의 공통 참조](ai-skill-authoring-examples-queen.tmp.md#6-정식-침식의-별도-연결)를 함께 검증한다.
공명 접수 영수증과 실제 시전 판정을 나누며 파생 세트/별도 침식 버튼을 조건으로 추가하지 않는다.
자동/재입력을 공명 만충 접수로 재분류하지 않는다. 트라우마 임계치와 정확한 runtime 연결 미정은 해당 분기에 남긴다.

## 4. 같은 원본을 수정하는 공통 절차

1. 그래프 요소 선택 → 원본 정의/속성 위치와 참조한 공유 정의를 찾는다. 값 출처와 현재 진단을 함께 보여 준다.
2. 기준 원본 리비전·의존 지문과 변경 집합을 준비한다. 공유값 수정과 이 사용처만 분리하는 작업을 구분한다.
3. 구조/타입/참조·선택 실행 의존을 검증한다. 저장 가능한 의미 오류는 진단과 함께 보존하며 실행 성공으로 처리하지 않는다.
4. 원본·역참조 색인·Undo 이력·리비전을 함께 확정한다. 충돌/구조 손상은 확정 원본을 보존하고 입력 수정안을 남긴다.
5. 영향받은 그래프·진단·산출물은 새 기준으로 갱신한다. 소비자 본문이 같아도 공유 의존이 바뀌면 이전 결과는 오래된 상태다.
6. Undo/Redo는 같은 변경 묶음을 복원한다. 저장 완료는 저장한 snapshot에만 적용하고 이후 편집의 dirty를 지우지 않는다.

텍스트 문법 자체가 해석 불가하면 원시 버퍼를 보존하고 마지막 해석 성공 그래프임을 표시한다. 다중 파일 쓰기·복구 방식은
4단계 과제이며, 메모리 확정을 디스크 저장 성공으로 간주하지 않는다. 도식 좌표는 별도 배치 정보로 의미 지문에서 제외한다.

각 예시의 `*.U*`·오류 과제는 이 판정과 해당 원본 위치를 함께 사용한다.

| ------------------------- | -------------------------------------------------- | ------------------------------------------------------------------------------- |
| V01 미정                  | 정상 구조 원본 저장·진단 요청 가능                 | 선택 실행의 필수 계수/행동/정책이면 거부. 미정 자리+사용 동작+근거              |

| V03 타입/단위/식          | 구조적으로 해석 가능한 오류 식 보존                | 필수 의존이면 거부. 기대/실제 타입과 피연산자 위치                              |

## 6. 연출과 추적의 공통 연결

원본 문서/리비전/정의/속성 → 그래프 역할 → 산출물 동작/원본 기여 집합 → 실행/action/효과/발생 ID → cue ID를 잇는다.
컴파일에서 여러 동작을 합치면 모든 원본 역할을 보존하고, 분해하면 각각의 역할을 기록한다.
연출 자원은 이펙트·사운드·애니메이션 역할별 미정 참조를 둘 수 있다. 재생 핸들과 gameplay 활성은 같은 소유 상태가 아니다.
단발·지속·갱신·종료, fixed 위치/대상 추적, 전투/별도 시계는 각 예시 cue 표에서 지정한다.
거절에 실제 시작 연출을 내보내지 않으며 조준 preview와 확정 사건을 구분한다. 사건 누락/중복·복구의 실제 전달 계약은 후속이다.

미지원과 작성 의미 미정·장비 종단 미확인을 비교한다. 이 거부 분기는 정적 확인이며 실행 시험은 하지 않았다.
새 조합을 기존 operation으로 의미 보존 변환할지 Core 계약/IR을 확장할지는 5단계의 선택 경로에서 구체화한다.
어려움의 예상은 결과 순서·수명·공유 거래·변형 조합에 대한 설계 위험이며, 실행으로 재현한 Core 결함 목록이 아니다.

## 8. 후속 인계와 사용자 확인

2026-10-23 후속 목적 확장으로, 바로 다음 작업은 [계획](ai-skill-authoring-plan.tmp.md)의 C0 목적 구체화다.
이 예시들은 C1 정의·실행 계약, C2 작은 실행 검증, C3 서로 다른 스킬의 조합 검증에 재사용한다.
그 뒤 아래 4단계 비교와 5단계 통합 검증으로 진행한다. 3단계의 의미 대조·과거 검토 기록은 유지한다.

4단계는 동일한 PC/HG/QH 의미와 각 문서의 편집 과제·오류 사례를 후보 포맷으로 옮겨 비교한다.
필수 비교 항목은 미정/주석 보존, 식과 결과 분리, 공유값 영향, 참조 탐색, 부분 수정의 무관 변경,
진단 위치, 읽기·설명·수정 정확성이다. 대상 AI·반복 횟수·허용 도구·시간/비용·통과 기준은 비교 전에 정한다.
문서 길이나 노드 수가 줄었다고 실제 AI 사용성을 검증했다고 하지 않는다.

사용자는 각 예시의 도식과 속성 표에서 흐름이 의도대로 읽히는지, 수치·대상·조건을 원하는 위치에서 고칠 수 있는지,
공유값과 미정이 구분되는지 확인하면 된다. 코드 경로·근거·미확인 조사는 실행자가 맡는다.
