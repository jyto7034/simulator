# ARK Wiki

React + TypeScript + Tailwind CSS로 구성한 게임 위키다. 기존 Markdown 문서, 장면·행동 JSON, 화면 상태 CSV를 원본으로 사용한다. 최신 합의와 아카이브 문서, 66개 행동을 통합하며 각 문서를 독립된 HTML로 미리 생성한다.

## 실행

```bash
cd wiki_site
npm ci
npm run dev
```

개발 주소는 `http://127.0.0.1:4178`이다. Node.js 24 이상과 Python 3.9 이상이 필요하다. 콘텐츠 생성기는 Windows에서 `py -3`, `python`, `python3` 순서로 실제 실행 가능한 Python을 찾고, Linux/macOS에서는 `python3`, `python`을 찾는다. 한글 문서는 UTF-8 모드로 처리한다. UI 문서가 기본 위치와 다르면 `ARK_UI_ROOT`에 `ark/docs/ui-layout` 경로를 지정한다.

Windows와 WSL은 실행 파일과 네이티브 패키지가 다르므로 `node_modules`를 그대로 공유하지 않는다. 실행 환경을 바꿨다면 사용할 터미널에서 `npm ci`를 다시 실행한다.

상단의 달/해 버튼으로 밝은 테마와 어두운 테마를 전환한다. 처음에는 시스템 테마를 따르며, 직접 고른 테마는 브라우저에 저장하여 다음 방문에도 유지한다.

모든 도감·규칙·기록 분류, 장면·플레이어 행동, 전체 화면 목록과 검색 결과에서 카드·비교표·접이식 목록 보기를 제공한다. 선택한 보기는 목록별로 저장하며 검색·필터는 보기 전환 중에도 유지된다. 환상체·스킬 파편·장비·유물 도감은 작은 아이콘 옆에 이름과 분류를 배치한 프로필 카드를 사용한다. 높이는 내용에 맞추며, 요약은 3줄과 주요 태그를 보여준다. 같은 행의 하단 링크를 정렬하고 긴 내용은 빠르게 보기에서 읽는다. 다른 목록은 기존 카드 구성을 사용한다. 빠르게 보기에서 생략 없는 상세 내용을 읽거나 원문으로 이동할 수 있다. 문서 요약·상태·주요 조건은 콘텐츠 생성 때 현행 Markdown에서 추출하므로 별도의 설계 요약을 중복 관리하지 않는다.

```bash
npm run build
npm run preview
```

`dist/`가 정적 배포 결과다. Node/Python 서버 없이 정적 웹 호스팅에서 제공할 수 있다. 프레임워크 버전은 HTTP로 실행하며, 파일을 직접 여는 기존 [오프라인 HTML](../core_enhanced/docs/wiki/index.html)은 별도로 유지한다.

## 구조

| 위치 | 역할 |
| --- | --- |
| `src/components/` | 탐색 메뉴, 검색 입력, 문서 표시, 공통 카드·배지 |
| `src/pages/` | 홈, 분류, 문서, 장면·행동, 검색, 화면 목록 |
| `src/styles.css` | 색상 토큰(밝은 골분지·먹색 / 어두운 흑색·황동), Tailwind 테마와 Markdown 본문 스타일. 본문은 Pretendard, 제목은 Noto Serif KR을 npm 패키지로 자체 제공하며 외부 글꼴 요청은 없다 |
| `scripts/export_content.py` | 기존 보존·링크 검사기를 사용해 데이터·이미지·출처 파일 생성 |
| `scripts/prerender.mjs` | React 정적 렌더링, 문서별 HTML·메타데이터·404 생성 |
| `site.config.json` | 사이트 이름, 배포 하위 경로, 기준 도메인, 검색 수집 설정 |

화면은 React 컴포넌트이며 기존 HTML을 iframe으로 감싸지 않는다. 본문은 원문을 검증한 Markdown 렌더러의 결과를 사용한다. 문서 데이터는 페이지별 JSON, 전체 검색 자료는 검색 화면에서 불러오는 별도 파일로 분리한다. 각 페이지는 JavaScript 실행 전에도 본문을 읽을 수 있다.

React Router는 문서 주소·클라이언트 이동, Radix Dialog는 모바일 메뉴·시안 확대의 포커스와 키보드 처리, Lucide는 아이콘을 담당한다. 원문 링크·이미지는 배포 결과에 포함하여 로컬 디스크 경로에 의존하지 않는다. 생성물은 Git에서 제외하고 빌드할 때 갱신한다.

## 원문 갱신

콘텐츠는 [콘텐츠 위키](../core_enhanced/docs/content/README.md), 판정은 [룰북](../core_enhanced/docs/game_rulebook.md), 화면·행동은 Unity 프로젝트의 UI 위키에서 수정한다. `npm run content` 또는 `npm run build`가 반영한다. 생성된 React 데이터나 HTML에서 설계 내용을 별도로 수정하지 않는다.

현재 도감과 일반 검색에는 최신 합의 및 남은 미정 사항을 표시한다. 이전 합의·미채택 검토안·최종 확정 전 시험값은 `/wiki/archive/`와 별도 `/wiki/archive/search/`에서 확인한다. 일반 검색 데이터에도 아카이브 본문을 포함하지 않는다. 이전 문서 주소는 아카이브 주소로 연결하며 앵커를 유지한다. 원문 정리 전 사본과 SHA-256은 `core_enhanced/docs/content/archive/preservation.json`으로 검사한다. 출처 해시와 통합 검사 결과는 `.generated/content-report.json`, 정적 생성 결과는 `.generated/build-report.json`에 남긴다.

태그 사전과 기존 조합 예시는 설계 기준의 참고 문서로 둔다. 파편별 유물 적용 관계는 각 환상체 상세의 관련 문서에서 확인하며, 별도의 ‘태그·조합’ 메뉴는 두지 않는다. 기존 `/categories/tags/` 주소는 태그 사전으로 연결한다.

### 장면·행동 변경의 반영 완료 기준

**상세 문서에 내용을 추가한 것만으로 ‘위키 반영 완료’로 보고하지 않는다.** 실제 사용자가 찾는 목록·검색·상세 화면까지 변경이 전달되었는지 확인한다. 2026-10-20 전투 종료 화면의 상세 명세는 갱신했지만 `scene-guide.json`에 등록하지 않아 ‘장면·플레이어 행동’에서 누락된 사례를 기준으로 둔다.

1. **기준 문서 수정:** Unity UI 위키의 해당 `wiki/*.md`에 현재 합의·행동·남은 작업을 기록한다. 화면 설계 마무리와 구현·검증 완료를 구분하고, 추후 변경 가능한 항목은 그대로 명시한다.
2. **탐색 색인 동기화:** 화면·행동을 추가·삭제·변경하면 `docs/ui-layout/wiki/scene-guide.json`의 해당 화면과 행동을 함께 갱신한다. 새 화면은 적절한 장면 분류에 등록하고, 제목·진입·종료·행동·결정 상태·기준 문서 앵커·현재 시안·후속 작업을 연결한다. 상세 본문에 링크만 추가하는 것으로 대신하지 않는다.
3. **주변 요약 확인:** `ui-layout.md`의 화면 표, 시안 목록과 남은 작업에서 관련 요약을 맞춘다. 화면·행동 수는 가능한 한 원본 데이터에서 계산하며, 고정 숫자가 남은 문서와 검사 코드도 확인한다.
4. **생성물 갱신:** 아래 명령으로 변경의 영향을 받는 안내서·통합 위키를 다시 생성한다. 생성된 HTML·JSON을 직접 고쳐 원문과 다른 규칙을 만들지 않는다.
5. **사용 경로 확인:** 실제 ‘장면·플레이어 행동’ 목록에서 해당 항목을 찾아 상세 화면을 연다. 관련 장면 필터·행동 검색·현재 시안 로딩·상세 기준 링크를 확인하고, 좁은 화면의 목록과 상세에도 접근할 수 있는지 확인한다. 새 화면은 직접 주소로만 열리는지 확인하는 것으로 끝내지 않는다.
6. **검증한 범위로 보고:** 원문·색인·생성물 중 반영한 범위와 확인한 경로를 구분한다. 생성이나 브라우저 확인이 막혔다면 해당 범위를 남은 작업으로 알리고 전체 반영 완료라고 표현하지 않는다.

| 대상 | 갱신 명령과 실행 위치 |
| --- | --- |
| Unity 장면·행동 안내서와 Markdown 색인 | Unity 프로젝트 루트에서 `python3 Tools/UiArt/build_scene_guide.py` |
| 통합 오프라인 HTML | simulator 루트에서 `python3 core_enhanced/tools/wiki/build.py` |
| 통합 웹 위키 데이터와 정적 페이지 | `wiki_site/`에서 `npm run build` (`content`와 `build:app` 포함) |

검증은 변경 범위에 맞춰 수행한다. 생성기의 출처·링크 검사와 해당 화면의 목록 → 상세 → 기준 문서 이동을 확인하고, 필요한 검색·필터·모바일 회귀 검사 결과를 남긴다. 단순 오탈자 수정처럼 화면·행동에 영향이 없는 변경은 관련 없는 색인 수정이나 전체 브라우저 검사를 요구하지 않는다.

## 배포 준비

현재 작업은 로컬 준비 단계이며 공개 배포를 수행하지 않는다. 아카이브를 포함한 내부 문서를 보존하므로 공개할 내용의 범위는 실제 공개 단계에서 결정한다. `indexable`은 현재 `false`이며 공개 시점에 `canonicalOrigin`과 함께 설정한다. 기준 도메인을 설정하면 canonical·공유 메타데이터·사이트맵을 생성한다.

하위 경로에 배포할 때는 `basePath`를 `/ark/`처럼 설정하고 다시 빌드한다. 페이지마다 `index.html`을 생성하므로 정적 디렉터리 인덱스를 지원하는 호스팅에서 직접 주소·새로고침이 동작한다. 없는 주소는 생성된 `404.html`을 사용하도록 호스팅에서 연결한다.

## 확인

```bash
npm run typecheck
npm run build
npm run test:browser
```

브라우저 검사는 설치된 Playwright Chromium을 사용한다. 처음 사용하는 환경에서는 `npx playwright install chromium --only-shell`을 실행한다. 검사는 임시 정적 서버를 열고 종료하며, 데스크톱·모바일·검색·필터·이미지 확대·문서 링크·정적 본문을 확인한다. 결과와 스크린샷은 `artifacts/`에 남긴다.

유물·파편은 효과 태그, 유물 대상 태그, 합의한 유물 연결 태그를 제공합니다. 태그는 변경 가능한 효과 단위이며 유물 이름과 구분합니다. 파편 없음·검토 제안 등의 문서 분류는 효과 태그에 포함하지 않습니다. 태그를 여러 개 골라 모두 포함(AND) 또는 하나 이상 포함(OR)으로 찾고, 검색어·분류와 함께 사용할 수 있습니다. 선택한 태그는 URL에 남아 새로고침·뒤로 가기·링크 공유가 가능합니다. 카드·비교표·목록과 빠르게 보기·본문에서 태그를 확인하고, 태그를 클릭해 해당 목록을 필터링합니다. 프로필 카드에는 대표 태그 세 개와 나머지 개수를 보여주며, 태그가 줄바꿈되면 필요한 만큼 높이를 늘립니다.

태그 메타데이터는 `scripts/content_tags.py`에서 원문 근거와 함께 관리합니다. 명시적으로 합의한 열두 파편의 유물 연결 표와 42개 현행 유물 문서의 대상 태그·생성 효과 태그를 원문에서 읽고, 아무 것도 없는의 꿰뚫는 송곳 연결은 해당 유물 원문을 근거로 기록합니다. 미채택 무기 강화 9종 제안은 아카이브로 분리했습니다. 태그 사전의 41개 공통 분류에 없는 이름·변경 명령이 효과 태그로 들어오면 빌드를 실패시킵니다. 현행 파편·유물 69개 항목 중 파편이 없는 2개와 고유 규칙으로 관리하는 백야 파편은 문서 분류만 가지며, 나머지 66개는 효과 또는 적용 태그를 갖습니다. 백야의 사도화·원정 누적은 설명용 분류이며 파편·사도에 효과 태그나 전용/범용 유물 연결을 부여하지 않습니다. 실낙원의 호환은 독립 장비 설계에서 별도로 정합니다. 서로 다른 효과를 합쳐 엔진 호환을 판정하지 않으며, 증오의 여왕 보호막 연결 미정 등 기존 설계 상태를 유지합니다. 유물 이름·요약·조건·상태는 각 문서의 ‘유물 정의’ 표를 읽습니다.

태그 색상은 `src/components/tagPalette.ts`의 성향별 매핑과 `src/tag-colors.css`의 밝은/어두운 팔레트를 공유합니다. 공격·위험은 붉은색, 회복은 초록, 방어·반격은 파랑, 제어·약화는 보라, 소환·영역은 청록, 강화·축적은 금색, 시간·변형은 남색, 설계 상태는 회색입니다. 선택한 필터는 같은 계열의 진한 배경과 체크 표시로 구분합니다.

카드의 제목·요약·빈 공간을 누르면 빠르게 보기가 열립니다. 태그와 상세 보기 링크는 각 링크의 동작을 유지합니다. 카드에서는 별도의 빠르게 보기 버튼을 표시하지 않습니다. 카드에 키보드 초점을 두고 Enter/Space로 열고 Escape로 닫을 수 있으며, 닫은 뒤 카드로 초점이 돌아옵니다. 마우스 호버 시 카드가 살짝 올라오고 테두리·그림자가 강조되며, 동작 줄이기 설정에서는 이동 애니메이션을 생략합니다.

통합된 유물의 이전 문서는 `<!-- wiki-category: history -->` 표기로 기존 주소를 유지하며 아카이브에 표시합니다. 넓어진 폭심은 넓어진 지평으로 통합되어 현행 유물 도감·태그 연결에서 별도로 집계하지 않습니다.
